# 筛选

**筛选**会隐藏你不关心的行，例如某种载具类别或某类事件，画面会立即更新。面板会列出加载时在*保留用于筛选*下保留的列（[列映射](column-mapping.md)），以及加载了多个文件时的*来源文件*。

## 试用 {#try-it}

1. 加载一个数据集，并在侧边栏中打开**筛选**。
2. 在**载具类别**下，取消勾选*坦克*。画面会立即改变。
3. 按**清除所有筛选**即可撤销。

![The Filters panel: the viewer's own columns (Event type, Vehicle class) first, then the columns from your file](../assets/img/en/filters.webp)

最前面的行是查看器自己的列（见下文）。之后的行来自你的文件。

## 查看器添加的列 {#columns-the-viewer-adds}

加载时，查看器会推算出四个自有列，并将它们**列在最前**，名称和值使用你的语言显示，因此同一筛选适用于每款游戏和每种数据来源：

| 列 | 值 | 推算依据 |
|---|---|---|
| **事件类型** | 23 种：位置、射击、发射（导弹、火箭、炸弹）、命中、未命中（武器结束时附近没有目标）、爆炸、伤害、击杀、死亡、摧毁、坠毁、弹射 / 跳伞、出生、消失、起飞、着陆、接触地面、停在地面、重新装填 / 加油、占领 / 目标、诱饵、消息、其他 | 名为 `event`、`events`、`event_type` 或 `event_name` 的列；每款游戏自己的用词（`shot`、`burst`、`fired`、`struck`、`flare`、`plant` ……）会被映射到这些类别。完整表格：[事件类型与类别](ref-event-types.md)。 |
| **玩家或AI** | 玩家、AI | 名为 `ai`、`is_ai`、`bot` 或 `actor` 的列；否则为 `is_player` / `human`；否则为账号 ID（`user_id`、`steam_id`；为空或 0 即 AI）；对于 Tacview 录像，则看该对象是否有飞行员 |
| **载具类别** | 17 类：战斗机、攻击机、轰炸机、其他飞机、直升机、坦克、装甲车、防空、火炮、卡车 / 汽车、舰船、潜艇、步兵、武器、诱饵、建筑、其他 | 载具或单位名称（与[图形目录](figures.md)匹配）以及类型列 |
| **目标类别** | 同样的类别 | 另一方的载具（`other_vehicle`、`target_vehicle`、`victim_type` ……） |

只列出实际出现的类别。数值列（`cost_*`、`earn_*`、`net_*` 以及*成本来源*，参见[数值加权](value-weighting.md)）与任何数字列一样可以筛选：例如，在*成本来源*下取消勾选*估算*，即可只保留有价格的行。

类别列表超过 12 个值时会出现搜索框（*搜索 n 个值*），以及一个**仅这些**按钮，可以只允许与之匹配的值。

哪些列可以筛选是在加载时决定的，因为必须在那时读取它们。如果没有保留的列，面板会说明这一点，并指向*保留用于筛选*。

## 数值列（范围）{#numeric-columns-range}

![A range filter (money lost) with both ends dragged in](../assets/img/en/filters-numeric.webp)

| 部分 | 含义 |
|---|---|
| 名称，以及 `min ... max` | 该列，以及当前范围（未设置筛选时为该列的完整范围）。 |
| 第一行：数字框和滑块 | 下限。将滑块拖过上限时，上限会被一起推动。 |
| 第二行：数字框和滑块 | 上限。拖到下限以下时，下限也会被一起推动。 |
| **重置 *列*** | 移除此筛选。 |

滑块以 1,000 个步长覆盖该列从最小到最大的范围；数字框可以接受任意值。当行的值位于范围之内（两端都包含）时，该行通过筛选。较大的值以指数形式显示（`1.23e6`）。

## 类别列 {#category-columns}

| 部分 | 含义 |
|---|---|
| 名称，以及 `允许数/总数` | 该列，以及允许的值的数量。 |
| 值列表 | 每个值一个复选框；空值显示为 *(空)*。 |
| **全部** / **无** | 允许所有值 / 不允许任何值。 |

允许所有值即可移除筛选。

## 规则 {#rules}

- **同时最多四个筛选。** 标题显示 `active/4`。第五个筛选不会被应用，面板会说明这一点。[实体](entities.md)中的选择（或对局标签页的玩家聚焦）也会占用四个中的一个。覆盖整列的筛选则不占用。
- **一个类别列最多 4,096 个值**；超过此数量的列在加载时不会被保留。
- **筛选之间为逻辑与**，并与队伍可见性、差值拆分、时间窗、距离剔除和[切片](slice.md)组合。
- **更改筛选会重新开始累积**，并在几帧之后重新测量曝光，因为筛选可能极大地改变密度（[颜色与曝光](colour-and-exposure.md#auto-exposure)）。
- **清除所有筛选**会移除每个列筛选。在其他地方设置的队伍可见性和玩家选择会被保留。
- 列筛选会改变热度模式。它不会改变[图形回放](box-replay.md)的图形，后者遵循队伍可见性和实体选择。实体选择会同时改变两者。
- 在[线条热度](line-heat.md)中，筛选是针对每段线段*终点*所在的行进行测试的。
- 每次加载新数据集时，所有筛选都会被清除。

## 开发者信息 {#for-developers}

**槽位。** 每个激活的筛选占用四个 GPU 槽位之一（[`MAX_FILTER_SLOTS`](https://github.com/Holdi601/3DHeat/blob/main/src/render/types.ts)），即每行 4 字节的纹理。槽位按筛选最近一次更改的顺序分配（[`filterSlots`](https://github.com/Holdi601/3DHeat/blob/main/src/render/filterTables.ts)，由着色器和两个面板共享）。超过四个时，会出现错误提示：*仅应用前 4 个筛选。请清除其中一个 - 其余筛选被忽略，而不是被静默合并*，超出的筛选名称显示为 *列（未应用）*。筛选在顶点着色器中逐行运行，因此更改阈值无需重新解析，也无需重新上传。

**面板不显示的筛选。** 应用状态中还存在另外两种筛选（[`FilterSpec`](https://github.com/Holdi601/3DHeat/blob/main/src/state/types.ts)）：

- **分组**筛选，由对局标签页在聚焦某一方时设置。它会在每种模式中隐藏其他分组，包括按列拆分的[差值](difference.md)。
- **人员**筛选，由[实体](entities.md)面板以及对局标签页在聚焦某一名玩家时设置。它限制图形回放和热度模式。在热度中，它是对人员 ID 的类别筛选，占用四个槽位之一。其掩码最多容纳 65,536 个 ID（[`FILTER_MASK_CAPACITY`](https://github.com/Holdi601/3DHeat/blob/main/src/render/types.ts)）；超过该数量的人员在筛选激活时不会在热度中绘制，即使被选中也是如此。图形回放仍会显示他们。
