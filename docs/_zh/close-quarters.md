# 近距离交战与回合

对于以回合为单位的射击游戏（首先是 Counter-Strike，以及任何带有回合、阵营和击杀的数据），洞察会衡量交战是如何赢得的：谁拿下了开局对决，它们的价值如何，死亡是否被交换，推进到一个角落的玩家是否胜过守在那里的玩家，交叉火力和闪光弹是否奏效，回合胜率如何随每次击杀而变化，以及哪些门口杀死了进入其中的玩家。用它来了解回合为什么会赢，而不仅仅是谁拿到了击杀。

这些度量来自清剿房间和城市作战的条令（致命漏斗、控制点、交叉火力），以及电子竞技和体育分析（胜率、行动价值、调整后的正负值）。每一项都通过[知识视角](knowledge.md)来解读，并附有引用。

## 试一试 {#try-it}

1. 载入一场或多场带有回合的对局（CS2 转换结果已包含所需的一切）。
2. 打开 **洞察**，然后按 **查找洞察**。
3. 在 **视角指标** 下，阅读从 *回合胜率* 到 *玩家影响力* 的各行；每一行都有它的数字、95% 区间、它的 q 值，以及它所依据的来源。
4. 选择 **电子竞技** 或 **城市战** 视角，以该文献来解读它们；**用 AI 撰写** 会把它们随报告一并发送。

## 它衡量什么 {#what-it-measures}

| 度量 | 它说明什么 | 如何计算 |
|---|---|---|
| 回合胜率 | 在每一时刻，每一方赢得回合的可能性有多大 | 对每一方存活的玩家、炸弹或目标及其时间、回合时钟和购买情况进行逻辑回归，拟合到所载入的数据；校准则按回合在折外检验（Brier 分数与技巧、对数损失、十个分箱上的校准误差、重新校准斜率、AUC） |
| 行动价值 | 一次击杀、一次开局击杀、一次交换、一次闪光后的击杀、一次下包或一次闪光，如何改变该方赢得回合的机会 | 行动之后的胜率减去之前的胜率；交换、开局击杀和闪光击杀通过置换检验与其他击杀进行比较 |
| 开局对决 | 哪一方赢得第一次对决，这如何经常地决定回合胜负，以及哪一方在哪些地点的开局胜率远高于其自身平均水平 | Wilson 区间；各地点以精确二项检验与该方的份额比较，各地点的 q 值 |
| 交换 | 在 5 秒内被队友击杀杀手所回应的死亡、所花的时间，以及首个死亡被交换时赢得的回合数 | Fisher 精确检验，Newcombe 区间 |
| 推进者对守点者 | 一名玩家进入战斗（最后一秒内速度为 1.5 m/s 或更快），而另一名玩家保持静止（0.75 m/s 或更慢）的对决：推进者所占的份额 | 对一半的精确二项检验 |
| 交战前的瞄准 | 在击杀前 0.75 秒，每名玩家的视线与指向对方的方位的比较；哪一方瞄得更准，以及该玩家赢得的频率；守点者在其角度上（15° 以内）与不在其角度上的比较；击杀距离 | 精确二项检验；Fisher |
| 交叉火力 | 守点者在推进者 25 米内有一名静止的队友，并且其指向推进者的视线与自身方向相差 35° 或更多，与单独守点者的比较 | Fisher，Newcombe |
| 道具与进攻 | 在己方闪光（3 秒内、15 米内）或烟雾（18 秒内）后推进的玩家，与没有道具的推进相比；只有一方有闪光的开局对决；被致盲的受害者 | Fisher，二项 |
| 人数优势 | 对于回合中首次达到的每一种存活玩家状态（5 对 4、4 对 5、2 对 1……），从该状态赢得回合的占比 | Wilson 区间 |
| 残局 | 一方只剩最后一名玩家的回合：相对于模型预期胜场，按对手人数统计的胜场 | 观测值与预期值的正态检验 |
| 扎堆、轮转、潜伏 | 开局对决时 10 米内最大的一群（3 人或以上：扎堆）；距离首次交战或已下包目标超过 30 米的玩家，以及他们多快进入 12 米以内；距每个队友都超过 30 米时的时间和击杀与死亡之比 | Fisher；优势比及 Woolf 区间 |
| 下包后与夺回 | 安放炸弹一方赢得的回合，按安放时的人数统计，以及其在下包后的对决占比 | Wilson 区间 |
| 致命漏斗 | 进入每个地点（地点列变化，否则为 8 米的格子）的次数，以及进入后 2.5 秒内的死亡，与地图的比率相比较 | 精确二项检验，各地点的 q 值；比率按地图比率以 20 次进入进行收缩 |
| 玩家影响力 | 每名玩家（击杀、死亡、安放炸弹）每回合增加的胜率，经经验贝叶斯收缩；回合结果的岭调整正负值（相对模型的起点）；按地点和武器计算的击杀价值，并收缩 | 通过五折交叉验证选择惩罚项 |

同一次分析的所有检验共享一个错误发现率（Benjamini-Hochberg），包括所尝试的每一个地点，而不仅仅是所显示的地点；所显示的 q 值是针对所有地点的。模型及其校准是拟合到所载入的数据上的，因此它们描述的是该群体：专业选手的模型会误判休闲游戏，反之亦然。

在带有已植入效应的合成回合（推进者的优势、交叉火力、闪光、一个致命漏斗、瞄准更好的一方获胜）上检查，并在 100 个没有这些效应的相同回合数据集上检查——已植入效应的检验的错误发现率必须保持在名义上的 5%（在一定范围内）（`src/insights/cqb/cqb.test.ts`）；在约一千个真实回合上，模型的 Brier 分数为 0.14，而基准率为 0.25，校准误差为 0.03，重新校准斜率为 1.0。

## 所需的数据 {#data-it-needs}

- **time**（时间）、**player**（玩家）、**side**（阵营）和 **round**（回合，即会话）列，以及事件列中的击杀和死亡；没有人死亡两次的回合被视为淘汰回合（人数优势、残局和模型都需要它们）；
- 一个 **对方** 列（`other`、`victim`、`killer`、`attacker`），在击杀时注明受害者，在死亡时注明杀手（没有它，同一时刻的击杀和死亡会被配对）；
- 用于瞄准度量的 **视线方向**；
- 一个原始的 `event` 列，注明 `flash`、`smoke`、`he`、`molotov`、`plant` 和 `defuse`，用于道具和下包；
- 数据中有的 `won`（该行的阵营赢得回合）、`place`（呼叫的地点）、`weapon`、`buy` 和 `state_flashed`。

位置应每秒采样数次；速度、瞄准和交叉火力读取每次死亡之前的最后两秒。

## 在细分中 {#in-the-breakdown}

[细分](breakdown.md)将其中四种情况作为因素进行衡量，比较有与无：*被致盲*、*死亡被交换*、*开局对决*，以及人数（*多一人*、*人数相等*、*少一人*），每项都按 K/D、赢得的回合、存活和每分钟击杀数统计。

## 多场对局 {#many-matches}

[批量分析](mass-analysis.md)中，每一场带有回合列的数据的对局摘要，都以计数的形式携带同样的度量（摘要中的 `cqb`）：开局对决、交换、推进、交叉火力、被闪光的进入、瞄准、人数优势、下包，以及进入次数最多的 40 个地点，附其进入和死亡次数。计数会在多场对局中累加，因此一千场对局给出的份额与一次大型分析相同。面板的 **近距离交战** 标签以份额及其区间显示它们，可按所有地图或按地图查看；点击某一行会加载其来源的对局。

## 开发者信息 {#for-developers}

`src/insights/cqb/`：`walk.ts`（按时间顺序对行进行一遍扫描，回合分开保存，对决连同其状态一并记录）、`finish.ts`（度量和每场对局的计数）、`model.ts`（以 IRLS 实现的逻辑回归、校准、以共轭梯度实现的岭回归、经验贝叶斯、Fisher、Newcombe、置换检验）、`run.ts` 和 `worker.ts`（查看器：其自身的 worker，与洞察扫描并列）、`summary.ts`（多场对局摘要的收集器）、`factors.ts`（细分的情况）、`shows.ts`（视角读取的内容）、`synth.ts`（测试回合）。知识条目位于 `src/insights/knowledge/cqb.ts`，模式位于 `patterns-cqb.ts`。结果以 `lens.cqb` 的形式写入报告。
