# 会话、人员与分组

**人员** 是一个在移动的对象（一名玩家，一辆车）。**队伍 / 分组** 是他们所属的一方。**会话** 是一场对局或一圈。参见[术语表](glossary.md)。

文件的一行可以同时指定这三者：

| x | y | time | player | team | match |
|---|---|---|---|---|---|
| 10.5 | -30.2 | 12.0 | Blue 1 | Blue | Match 01 |

`player` 是人员，`team` 是分组，`match` 是会话。

三个可选列描述一行属于 *谁* 以及属于 *故事中的哪个部分*。每一列在加载时都会进行字典编码：文本值在每一行变成一个小整数编号，外加一份标签列表，并在本次加载的每个文件之间共享。

## 人员 {#person}

**人员 ID** 列指明一行所属的移动对象：一名玩家、一个机器人、一辆车。它以每行一个 32 位编号的形式保存。

有了人员列和时间列，加载时会为每一行计算其 **生命周期**：直到同一人员在 *同一会话* 中的下一个样本之间的时间；若没有下一个样本——该人员死亡、离开，或日志结束——则为 "无"（一个哨兵值，-1）。生命周期是[时间线](timeline.md)中 **生命周期** 历史的依据，也是[盒式回放](box-replay.md)中插值和陈旧判断的依据，同时决定[线条热度](line-heat.md)中路线的断点。没有后继的行如何处理，是一个查看设置（*后备寿命*），而不是写入数据的内容。

每个人员会被赋予其在时间上 **第一** 行所属的分组；这一赋值决定了盒式回放中他们方框的颜色，并决定哪个分组的可见性开关会在那里隐藏他们。热度模式则改用每一行自己的分组。

### 同时由多个对象使用的名称 {#names-worn-by-several-things-at-once}

一个名称并不总是对应一个实体：在某些导出中，每场比赛的每个机器人都以同一个名称记录。若把两个这样的"人员"样本连接起来——通过插值、拖尾或路线——就会在地图上两个不同的生物之间画出一条线。

加载时（[`computeLifetimes`](https://github.com/Holdi601/3DHeat/blob/main/src/data/builder.ts)），当某个名称的两条记录满足以下全部条件时，该名称会被标记为 **共享**：

- 位于同一会话中，
- 时间相同，
- 属于同一种类（每个保留的类别列都具有相同的值），并且
- 彼此距离超过数据范围对角线的 1%。

共享名称会被绘制为单个样本——不插值、不拖尾、不使用线条热度路线。它们的其他一切（它们的热度）不受影响。数据集面板会列出被标记的名称数量，并给出最多三个示例；盒式回放面板则重复显示这一数量。

## 会话 {#session}

**会话 / 对局** 列指明一行属于哪场对局、突袭、回合、运行或圈。正是它使一个人的样本成为一条连续的轨迹：真实的遥测数据常常交错着同时进行的多场对局，而播放头之前和之后的玩家样本可能来自相距数百米的不同对局。有了会话列之后：

- 插值、拖尾和线条热度路线永远不会跨越会话的变化；
- 一行的生命周期在其所属会话的结束处终止；
- 侧边栏顶部、模式栏下方会出现 **会话** 选择器。

会话列 *常常* 是一个 *时间戳*——对局的开始时刻，在该对局的每一行上重复出现。自动映射器因此在人员和分组之前寻找会话名称（[列映射](column-mapping.md#session-person-group)）。赛车的一圈或一段行程同样是会话：同一辆车的两圈绝不能被连接成一条轨迹。

### 会话选择器 {#the-session-picker}

![打开的会话选择器，显示一个含十场对局的文件：所有会话（10），对局 01，对局 02，依此类推](../assets/img/en/sessions-persons-groups-picker.webp)

*一个文件中的十场对局：选择一场，或同时查看全部。*

当数据集列出了会话时显示（见下方的上限）。

| 部分 | 含义 |
|---|---|
| 右侧的标签 | 所选会话的行数，或 *全部同时*。 |
| 菜单 | *所有会话（N）*，然后是每个会话，最繁忙的在前，格式为 `标签 - N 行，跨度`（跨度在 90 秒以下用秒，在 90 分钟以下用分钟，以上用小时）。 |
| 琥珀色提示 | 在 *所有会话* 时显示：位置仍然从不跨会话连接，但同时进行的对局会把互不相关的玩家一起放到地图上。 |
| 提示 | 在热度模式下选中一个会话时显示：此选择只移动播放头。 |

加载时会选中最繁忙的会话。选择一个会话会将播放头移到该会话的开始处。

所选会话会改变以下内容：

- 在 **[盒式回放](box-replay.md)** 中，它决定播放哪个会话：只绘制该会话的方框和拖尾，并且时间线的范围变为该会话自身的跨度。
- 在 **热度模式** 中，它不会限制热度，选择器下方的提示会说明这一点：*在热度模式中，这只会把播放头移到会话的开始处；热度仍会统计每个会话。盒式回放则只播放所选会话。* 若要将热度限制在一个会话中，请同时将会话列保留为筛选列（*保留用于筛选*）并按它筛选。一列既可以是会话列，也可以是筛选列：加载器会单独读取每个勾选的筛选列，无论它同时扮演什么角色。

### 会话过多 {#too-many-sessions}

最多列出 **100,000** 个会话。超过此数时，该列实际上是一个编号（一个文件夹中有数百万个会话，每个会话只有几行），而将如此多的标签从 worker 发送到页面，会耗尽标签页的内存。因此，加载时会保留会话的 **编号**——边界依然在各处被强制执行——但会丢弃标签和选择器，数据集面板会对此加以说明。

## 分组 {#group}

**队伍 / 分组** 列是任何低基数的列：一支队伍、一方、一个小队、一个阵营、一个玩家对 AI 的标志，或一个车辆等级。它以每行一个 16 位编号的形式保存，并驱动：

- [队伍列表](teams-list.md)（每个分组的可见性，+ / − 各方），
- [队伍热度](team-heat.md)（每个分组一种色调），
- 按分组的[差值](difference.md)拆分，
- [盒式回放](box-replay.md)中的方框颜色（每个分组一个色系，每个成员一个深浅）。

### 限制 {#limits}

最多 **4,096** 个不同的分组。分组编号位于 GPU 上每行位置纹素的第四个通道中，而着色器读取的 4,096 宽符号表中，每个分组都需要一个纹素，用来决定 *隐藏*、*相加* 还是 *相减*。不同值更多的列是编号而非分组：**加载时会保留每一行，只丢弃分组**，并在数据集上给出警告，建议改为将其映射为人员列，或保留为筛选列。

同样的 4,096 限制也适用于保留的 *类别* 筛选列；更宽的列不会被保留，数据集会说明这一点。数值列（例如时间戳）作为 *范围* 筛选时没有这种限制。

分组值 `0`、空值、`none`、`unknown`、`null` 和 `-1`（不区分大小写）对[队伍热度](team-heat.md)而言表示"无分组"，它们会被绘制为中性灰色，而不是一种确定的颜色。

## 实体大小 {#entity-size}

一个被追踪对象的大小——一名玩家的碰撞盒、一辆车——决定了[盒式回放](box-replay.md)中方框和视线射线的绘制大小。面板中没有它的字段；它来自文件的 [`heat3d` 提示](data-formats.md#the-heat3d-hints)（`entity.size`，以文件自身的单位计；CS2 转换器写入 32）。加载时会将其乘以单位缩放。

每次加载时（[`calibrate`](https://github.com/Holdi601/3DHeat/blob/main/src/data/calibrate.ts)），*范围* 取数据在 X 和 Z 方向跨度中较大的那个：

| 设置 | 有实体大小时 | 没有时 |
|---|---|---|
| 立方体大小 | 实体大小 | 范围 / 500 |
| 视线射线长度 | 实体大小 × 4 | 范围 / 200 |
| 精灵半径 | 范围 / 120 | 范围 / 120 |
| 饱和点 | 解析估计（然后计量） | 相同 |
| 飞行速度 | 范围 / 12 | 相同 |
| 远平面 | 范围 × 12 | 相同 |
| 近平面 | max(0.05, 范围 / 20,000) | 相同 |

## 数据集面板 {#the-dataset-panel}

位于数据源面板下方。加载了数据集时显示：

- 数据集的 **名称**——所选内容、行数、文件数，以及使用时的抽取步长；
- **`N 个队伍 · N 人 · N 秒跨度`**；
- 加载产生的每一条 **警告**，以琥珀色显示，只要数据集处于加载状态就会保留：因值过多而被丢弃的分组或筛选列、未列出的会话、共享名称、缺失的行、被跳过的文件；
- [合成数据生成器](synthetic-generator.md)；
- **卸载**，用于移除数据集。

行数显示在面板的标题上。
