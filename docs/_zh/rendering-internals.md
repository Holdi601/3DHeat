# 渲染内部原理

查看器把数百万个点画成发光的光斑并把它们加起来。本节解释让这一过程保持快速的技巧，以及统计浮层中数字的含义。如果查看器感觉慢，或你想改进渲染器，请阅读本节。

```
数据 -> 时间窗口 -> GPU 过滤 -> 采样计划 -> 喷溅 -> 累积 -> 着色 -> 屏幕
```

要了解你自己的电脑运行状况，请看视图右上角的统计框：[性能面板和统计浮层](performance-and-stats.md)。新词（GPU、行、精灵、热力图）见[术语表](glossary.md)。

## 核心问题 {#the-core-problem}

一组重叠的径向渐变之和，每帧的代价是 *N* × π*r*² 个混合片段。以 1 亿个半径为 8 像素的精灵计算，就是 2 × 10¹⁰ 个片段——在高端 GPU 上大约需要一秒的工作量。不能每帧都用暴力方式计算，所以查看器结合了以下做法：

- **按时间排序的行**——时间线窗口只需两次二分查找，播放的代价只跟随窗口中的行，而不是整个数据集；
- **CPU 每帧不处理任何单行**——行以量化形式保存在 GPU 内存中；过滤器、组符号、生命周期测试、窗口、剔除和切片都在顶点着色器中计算；
- **分层采样**，当一帧无法绘制每一行时，使用补偿权重；并且在视图保持不动时，使用**渐进累积**收敛到精确的"所有行"结果（[采样和预算](sampling-and-budgets.md)、[累积](accumulation.md)）；
- **两阶段节流**，先牺牲每帧的精灵数，再牺牲热度分辨率，以换取帧率（[采样和预算](sampling-and-budgets.md#the-adaptive-budget)）；
- **强制执行的内存预算**，因此放不下的数据集会被明显地截断，而不是崩溃（[GPU 内存驻留](gpu-memory.md)）。

## 一帧 {#one-frame}

帧循环是 [`Engine.frame`](https://github.com/Holdi601/3DHeat/blob/main/src/render/engine.ts)。所有随帧率变化的内容——相机、播放头、预算——都保存在引擎中，而不在应用状态中，所以一帧不产生 React 工作；状态每帧读取一次，只为低频读数写回。

1. **有新数据吗？** 新数据集在一帧中被宣告（*正在把 N 行上传到 GPU*），并在下一帧上传，因此消息会在工作阻塞线程之前先被绘制出来。新关卡交给渲染器；线路热度路线会被构建或释放。
2. **播放头**前进（每帧最多 0.1 秒的墙钟时间），循环或停止。
3. **相机**读取键盘、鼠标和手柄；轴镜像折叠进视图矩阵；在 WebGPU 上，深度重映射矩阵把 three.js 的 OpenGL 风格深度范围转换为 WebGPU 的范围。
4. **可见内容**：来自时间线和历史的时间范围；组符号表（仅在按列拆分时可见）；最多四个过滤器——列过滤器和实体选择；差异拆分。
5. 如果颜色和曲线表的设置有变化，**颜色和曲线表**会被重建。
6. **预算**：自适应控制器设定本帧的精灵预算和热度分辨率；如果开启 *每帧绘制所有行*，预算会被提高，以覆盖每个候选行。
7. **签名**决定累积缓冲区仍然代表什么：任何改变行如何贡献的内容（*几何*）、时间窗口，或仅仅改变结果着色的方式（*合成*）的更改。见[累积](accumulation.md#what-restarts-it)。
8. **采样计划**：绘制哪些行块（[采样和预算](sampling-and-budgets.md)）。
9. **累积模式**：重置、扩展、移动平均、滚动均值或空闲。
10. **盒子回放几何**（立方体、轨迹）在 CPU 上计算，仅在该模式下、且不是空闲时。
11. **渲染**：后端绘制场景（关卡、网格、坐标轴、盒子、轨迹、标尺），把热度喷溅到热度目标，合并进累加器，并把热度叠加到场景上合成到画布。
12. **自动曝光**在其倒计时归零时触发；标尺的热度探针最多每 120 毫秒读取一个像素；读数被发布。

空闲帧——已收敛、没有任何变化——会跳过场景和喷溅，但仍然**重新合成**：创建时没有设置 `preserveDrawingBuffer` 的 WebGL 画布，在合成之后内容是未定义的，所以指望它保持显示上一帧并不安全。场景和热度目标是查看器自己的帧缓冲区，会保留内容，所以空闲帧只需一次全屏处理。
