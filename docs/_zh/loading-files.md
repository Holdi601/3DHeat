# 加载文件

本页说明如何把你的文件交给 3DHeat，以及它如何处理这些文件。拖入一个文件夹，它会挑出保存位置的文件，并把它们合并成一幅图。

1. 在热力图侧边栏顶部打开 **数据源**。
2. 把文件或文件夹拖到拖放区，或按 **多个文件…** 或 **文件夹…**。
3. 阅读选择行和 **内存估算**（见下图）。
4. 按 **加载**。

![拖入十场对局的文件夹后的数据源面板：1 选择行，2 内存估算显示为“可容纳”，3 加载 10 个文件](../assets/img/en/loading-files-source.webp)

*拖入一个文件夹后，3DHeat 会告诉你它找到了什么，以及是否放得下。*

文件在热力图标签侧边栏顶部的 **数据源** 面板中加载。一次选中的所有文件会成为 **一个** 数据集。

## 选择文件 {#choosing-files}

| 控件 | 作用 |
|---|---|
| **将文件或文件夹拖放到这里**（拖放区） | 可以拖入任意组合的文件和文件夹。文件夹会被逐层遍历。点击拖放区会打开与 **多个文件…** 相同的选择器。 |
| **单个文件…** | 用于选择单个文件的文件选择器。 |
| **多个文件…** | 可以选择多个文件的文件选择器。 |
| **文件夹…** | 文件夹选择器（浏览器的 `webkitdirectory` 选择器）；文件夹树中的每个文件都会被提供。 |

选择器接受[可加载文件列表](data-formats.md#files)中的文件类型。简而言之：`.parquet`/`.pq` 按 Parquet 读取，`.csv`/`.tsv`/`.txt` 按分隔文本读取，`.acmi`（Tacview）、OCAP `.json`/`.json.gz` 以及 GPS 格式（GPX、KML、KMZ、NMEA、IGC、FIT）各自通过其专用读取器处理，`.3dheat` 对局容器则作为其中保存的表格载入（[每场比赛一个文件](container.md)）。无法读取的容器会被跳过，原因显示为 *不是 csv/parquet 文件*。

拖入的文件夹最多遍历 12 层、最多 20,000 个文件，以防止符号链接循环和失控的目录树。

## 保留哪些文件 {#which-files-are-kept}

在读取任何内容之前，会先对选择进行筛选（[`filterDataFiles`](https://github.com/Holdi601/3DHeat/blob/main/src/data/filePick.ts)）：

- 扩展名不同的文件会被跳过：*不是 csv/parquet 文件*。
- 大小为 0 字节的文件会被跳过：*空文件（0 字节）*。
- **转换器附属文件**——转换器保存在某场比赛表格旁边的原始数据，即 `<对局>.messages.parquet`、`.events.parquet`、`.raw.parquet` 以及 [转换器保留全部数据](converters.md) 中列出的其他文件——会被跳过：*转换器的附属文件*。若要打开其中之一，请单独选择或拖入它（或只选附属文件）：只包含附属文件的选择会像其他表格一样载入它们。表格旁边的 JSON（`.match.json`、`.course.json`、`.level.json`、`.meta.json`、`.summary.json`、`.session.json` 和 `.hints.json`）从不会被当作位置数据提供。
- **运动文件规则。** 如果选择中的任何文件名为 `movement*.parquet`、`movement*.csv`（以及其他扩展名）——`movement.parquet`、`movement_1.parquet` 等——那么所有其他数据文件都会被跳过：*不是运动文件，且此文件夹中有运动文件*。遥测导出通常会有一张位置表，旁边是几十张没有位置的表，而只有前者能被绘制。不含任何运动文件的文件夹会载入其所有数据文件。例如：一个包含 `movement_1.parquet`、`kills.parquet` 和 `shop.parquet` 的文件夹只载入 `movement_1.parquet`；另外两个会被列为已跳过。
- 保留的文件按其在选择中的路径排序，因此同一文件夹总会生成相同的数据集和相同的颜色。

面板随后会显示该选择（单个文件的名称，或使用最长公共文件夹的 `文件夹（N 个文件）`）、文件数量、总大小和总行数——当所有文件都是 Parquet 时为精确值，只要有任何 CSV 则标记为 `≈`。被跳过的文件会列出原因，前四个按名称显示。

## 读取架构 {#reading-the-schema}

选择中的 **第一个** 文件会被打开以描述架构（"正在读取架构"）：它的列名、前 50 行数据、哪些列看起来是数值，以及对 Parquet 而言，每列的逻辑类型和 `heat3d` 页脚条目。一个表格的一组导出文件共享同一架构，因此只需一个文件即可代表全部。然后会测量每个文件（"正在计数行"）：Parquet 页脚通过一次小读取即可给出精确的行数；CSV 的行数则根据其前一兆字节的平均行长进行估算。

[列映射](column-mapping.md)面板会以自动映射的猜测打开，[内存估算](memory-and-budgets.md)则显示在 **加载** 按钮上方。

## 加载前的提示 {#messages-before-loading}

在选择的下方，面板会根据 [`validateMapping`](https://github.com/Holdi601/3DHeat/blob/main/src/data/validate.ts) 列出：

- **错误**（红色）——加载无法开始：少于两个位置轴、两个轴使用同一列、映射的列不在文件中、位置列看起来不是数值、时间列的采样值为文本而单位为数字（每一行都会读作 NaN 并落在时间 0 处）、时间列设为 ISO-8601 而其采样值中没有一个能解析为日期、单位缩放为 0。
- **警告**（琥珀色）——仍会加载，但可能不是你想要的结果：分组列在大多数采样行上取不同的值（因此它是一个编号，而非分组）、`DATE` 时间列（一天中的每一行共享同一个瞬间）、设置了观察方向但未设置其列。
- **提示**——映射意味着什么：当一个轴未映射时在平面上绘制、没有时间列则没有时间线、没有人员列则没有轨迹，以及没有分组列时所有内容使用同一种颜色，而差值只能按为筛选而保留的列进行拆分。

## 加载 {#loading}

**加载** 按钮会读取 *加载文件*、*加载 N 个文件*，或在设置了[抽取步长](memory-and-budgets.md#decimation)时显示 *加载 N 个文件（每 K 个取 1 个）*。当[容量检查](memory-and-budgets.md#the-fit-check)表明加载放不下时，它会显示 *太大——请减少或抽取*，并处于禁用状态；映射有错误或另一次加载正在进行时，它同样被禁用。

加载期间，面板会显示当前步骤（多个文件时在前面加上 `[文件/文件数]`）、已读取的行数、进度条，以及 **取消**。取消会终止导入 worker，并同时终止它启动的任何解析 worker。

页面在加载时仍会继续绘制，因为工作是在后台进行的。你可以看到当前步骤、已读取的行数、进度条和 **取消**。最后一个文件读取完毕后，面板依次显示以下步骤：*按时间顺序排列行*、*重新排列列（第 n 个，共 m 个）*、*测量范围*、*建立名册*、*汇总会话*和*计算生命周期*，然后用一帧的时间 *将 N 行上传到 GPU*，这样较长的上传就不会被误认为是卡死。

### 工作原理 {#how-it-works}

加载在 Web Worker 中运行（[`ingestWorker.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestWorker.ts)）。当有多个文件且解析线程数多于一个（[解析线程](memory-and-budgets.md#parser-threads)）时，最多这么多个文件会 **同时** 解析，每个文件在其自己的解析 worker 中进行（[`parseWorker.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/parseWorker.ts)），只要内存预算允许；它们仍然按选择的顺序逐个合并，因此数据集与逐个加载的结果相同。当多个文件同时进行时，进度行会显示最近报告进度的文件，进度条和行数则累加所有进行中的文件。只有一个线程或单个文件时，文件会在导入 worker 本身中依次解析。只读取映射所指定的列：Parquet 文件中未映射的列不产生任何成本；CSV 会逐字节扫描，但只解码已映射的字段。

## 多个文件合并为一个数据集 {#several-files-become-one-dataset}

载入多个文件时（[`ingestFiles.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestFiles.ts)、[`builder.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/builder.ts)）：

- **一个名册。** 人员、分组、会话和类别值是所有文件共享的字典，因此两份导出中的同一玩家就是一个人，只有一条轨迹。
- **一个时间起点。** 合并时时间以 64 位秒保存，并重新以 *整个* 选择中最早的时间为基准，然后以 32 位秒的形式从该起点存储。来自四个下午的四份导出会按其真实顺序放置，而不是叠在一起。
- **一个时间顺序。** 所有文件的行都以基数排序按时间排序（见[排序上限](memory-and-budgets.md#the-sort-ceiling)）。
- **一个 `Source file` 列。** 每一行都记得它来自哪个文件，记录在名为 `Source file` 的类别列中。它会出现在[筛选](filters.md)中，并以 *Source file - 比较两次加载* 的形式出现在[差值拆分](difference.md)中。单文件加载不会得到这一列——常量列每行要花费 4 字节，却什么信息也不提供。
- **缺失的列。** 缺少某个 *筛选* 列的文件，只是不为该列提供任何值。缺少某个已映射 *角色* 列（X、时间、人员……）的文件会以 *文件缺少列 "name"* 失败；在多文件加载中，该文件会被跳过，其他文件仍会载入，被跳过的文件会列在数据集上。单文件加载失败时会报告错误。
- **不足警告。** 当载入的行数少于事先计数的行数的 95% 时，数据集会带有一条警告，注明缺失的比例——原因可能是无法读取的文件，或是没有可用位置的行（这些行在载入时被丢弃）。

## 加载之后 {#after-loading}

新的数据集会替换之前的数据集。每次加载时（[`setDataset`](https://github.com/Holdi601/3DHeat/blob/main/src/state/store.ts)）：

- 所有筛选和分组可见性都会被清除；
- 按分组的差值拆分会被重置：分组的前一半（向上取整）为正，其余为负；
- 精灵半径设为水平范围 / 120，饱和度设为解析估计值；立方体大小、视线射线长度、飞行速度和近/远平面则根据范围设定（见[会话、人员与分组](sessions-persons-groups.md#entity-size)）；
- 对局回放会话设为行数最多的会话；
- 线条热度的路线会重新猜测（[线条热度](line-heat.md)）；
- 如果当前视图模式不被新数据支持，则回退到 **热度**；没有时间列时时间线回退到 **全部**，没有生命周期时历史回退到 **累积**；
- 播放头停在起点，播放停止；
- 摄像机从默认方向（沿 -Z 方向观看，俯角约 36°）对整个数据集取景。

随后 **数据集** 面板会显示数据集的名称（选择、行数和文件数，以及使用时的抽取步长）、`N 个队伍 · N 人 · N 秒跨度`，以及加载时产生的每条警告（琥珀色），只要数据集处于加载状态就会一直显示。该面板中的 **卸载** 会移除该数据集。
