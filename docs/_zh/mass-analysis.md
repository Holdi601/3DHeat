# 大规模分析：一次分析数千场对局

**大规模分析**会告诉你整个文件夹的对局汇总起来是什么样子：哪种载具胜率最高，哪一方占优，战斗在哪里最集中。当你的对局远多于你能看完的数量时，就用它。

它基于每场对局的一份小摘要进行工作，因此一千场或一万场对局都能很快打开。只有你点击的对局才会加载完整的数据行。

## 试一试 {#try-it}

1. 在热力图侧边栏中打开**大规模分析**。
2. 按下**文件夹...**（或**多个文件...**），选择你的 `.3dheat` 对局文件。
3. 等待面板读取摘要（"摘要... n / N"）。
4. 按下**打开分析**。一个带有标签页的窗口会打开。
5. 设置筛选条件（游戏、地图、模式、从、到），然后查看一个标签页，例如"平衡"。
6. 点击一行、一个单元格或一条洞察：其对应的对局会加载到三维视图中，相机对准该地点。

![平衡标签页：按载具显示的胜率和每次死亡的击杀数](../assets/img/en/mass-balance.webp)

```
.3dheat 文件夹 -> 摘要 -> 窗口（标签页） -> 点击一行 -> 对局在三维中打开
```

一个 `.3dheat` 文件就是一场对局（[每场对局一个文件](container.md)）。*热力图*和*行*的含义见[术语表](glossary.md)。

## 获取摘要 {#getting-the-summaries}

对大多数人来说无需做任何事：面板会自行计算缺失的摘要。要提前为一个大文件夹准备好摘要，可以使用下面的离线工具。

每场 `.3dheat` 对局都会得到一份摘要（`src/mass/summarize.ts`），保存在容器中，名为 `<match>.summary.json` 的成员（角色为 `summary`，见[每场对局一个文件](container.md)）。离线工具会写入这些摘要，以及每个文件夹的索引。它是开发者工具；对大文件夹运行一次，可以省去面板的计算工作：

```
node tools/3dheat-summarize.mjs <folder>... [--jobs N] [--force] [--no-write] [--no-index] [--limit N] [--settle MIN]
```

- 已经摘要过的对局（格式版本相同）只会被读取；`--force` 会重新计算。`--no-write` 不改动容器。
- 在最近 `--settle` 分钟（默认 10 分钟）内改动过的文件会被跳过：转换器可能仍在写入它。
- `<folder>/3dheat-index.jsonl.gz`：每行对应一场对局——其路径、大小、时间和摘要，不含网格。`<folder>/3dheat-index.grids.jsonl.gz`：每行对应一场对局及其网格。
- 在存放文件的电脑上运行，并使用低优先级（例如在 Linux 上使用 `nice -n 19 ionice -c3`）。

对于每场对局，面板按以下顺序取第一个可用的结果：文件夹索引中的那一行（路径和大小相同）、浏览器缓存（IndexedDB，按名称、大小和时间）、容器的 `summary` 成员，或在工作线程池中计算并缓存的摘要。因此，没有索引的文件夹也能正常工作——第一次以读取数据表的速度进行，之后则从缓存读取。

## 面板 {#the-panel}

选择一个文件夹（或多个文件；**添加文件夹...**可加入另一个文件夹）。窗口中有筛选项**游戏**、**地图**、**模式**、**从**和**到**，一个**拆分依据**选项，**生命最少**和**仅玩家**，以及以下标签页。每个数字都来自摘要；点击某一行、某个单元格或某条洞察，都会以多对局叠加的方式把对应的对局加载到视图中，并使用能显示它们的筛选条件（载具、等级、武器、团队、玩家），相机对准该地点：

| 标签页 | 内容 |
|---|---|
| 概览 | 对局数、小时数、玩家数、生命数、行数、日期；每天的对局数；按游戏、地图、模式；事件总数；按货币统计的经济；对局中各事件发生的时间 |
| 平衡 | 按载具、等级、武器或团队；按地图、模式、段位或游戏拆分：K/D 及其约 95% 区间、胜率（Wilson）、存活率、每分钟击杀和命中、每分钟收入，以及 q 值——K/D 和胜率相对于该拆分中其余部分的 Benjamini-Hochberg 错误发现率。**生命最少**会隐藏生命数太少而不可信的行；**仅玩家**会排除任务中 AI 操控的部分 |
| 趋势 | 按天、周或月，顶尖载具或等级的使用率（在场占比）、K/D 或胜率 |
| 玩家 | 不同的玩家、每名玩家的对局数、每场对局的玩家数、最常出现的玩家 |
| 阵营 | 每张地图的每一方：相对于均分所赢得的对局数 |
| 近距离战斗 | 回合数据：按阵营的开局对决及其转化率、交换击杀、窥视者对守点者、交叉火力、致盲后的进入、瞄准、安放、人数优势，以及**按地图**统计：进入某地点的玩家在哪些地点被击杀——每项都是一个占比，附有 Wilson 区间，数据来自摘要中的 `cqb` 计数（[近距离战斗与回合](close-quarters.md)） |
| 地图 | 某张地图的网格汇总：在场、击杀、死亡、K/D、任何事件、流动，以及**在多少场对局中为热点**（稳定性）；按团队，单元格为 1、2、4 或 8 倍大小 |
| 地点 | 在数字中突出、但在热力图中不明显的地点（一大片整体繁忙的区域、通道、高度带）；**查找地点** |
| 细分群体 | 表现明显优于或劣于其他群体的分组（某地图上的某种载具，某高度的某个区域）；**查找细分群体** |
| 洞察 | 大规模检测器和地图检测器（见下文）；**复制报告（JSON）**提供语言模型所读取的 JSON |

## 多场对局的洞察 {#insights-over-many-matches}

**地点**标签页会找出在数字中突出、但在热力图中不明显的地点——一大片整体繁忙的区域、一条通道、一个高度带，或仅在对局某一部分繁忙的地点——并将那些普通热力图不显示的地点标记为**隐藏**，并在三维视图中勾勒出来；**加载**会飞到该处，并加载其中包含的对局。**细分群体**标签页会找出表现明显优于或劣于其他群体的分组（某地图和阵营上的某种载具，某高度的某个区域）；点击一个即可查看其细化分组。

**洞察**标签页会在所有对局中找出：交换或获胜情况明显优于或劣于其他载具的载具、在稳定比例的对局中为热点的地点、获胜比例超过均分的阵营、使用情况随日期变化的载具，以及击杀数多于均匀分布的对局部分。每项发现都附有其计数、效果、区间和错误发现率（控制在 5%），点击即可加载其对局。详情见：[开发者参考](#for-developers)。

## 规模 {#scale}

你可以自己运行一个小型版本：`node tools/demo-data.mjs` 会把 150 场合成的坦克对局写入 `tools/.shots/demo/mass`（每场约 1,000 行）。以下是在台式电脑上对 `tools/demo-data.mjs` 这 150 场合成演示对局的测量结果（真实对局要大得多）：

- `tools/3dheat-summarize.mjs` 使用 4 个工作线程：全部 150 场需 2.6 到 4.8 秒，工作线程内每场 8 到 21 毫秒；第二次运行只读取摘要，约需 2 秒。
- 在索引存在的情况下，在面板中打开文件夹，直到窗口显示：0.9 到 1.6 秒（工作线程自身的部分，即读取 150 行索引，为 20 到 40 毫秒）。
- 切换到某个标签页，直到其表格绘制完成：概览 10 到 30 毫秒，平衡 30 到 70 毫秒，趋势 30 到 45 毫秒，玩家 15 到 35 毫秒，阵营 15 到 20 毫秒，地图 55 到 130 毫秒。
- 存储这 150 场对局约占 0.5 MB。

打开窗口只占一个短暂的帧：所选文件每次 16 个发送给工作线程，日期字段和第一个标签页在窗口打开一帧之后出现。

存储中每场对局约占 15 KB，因此 10,000 场对局在工作线程中约占 150 MB；网格的保存永远不会超过地图所需的范围。

## 开发者参考 {#for-developers}

### 多场对局的洞察 {#insights-over-many-matches}

`src/mass/detect.ts`——每项发现及其计数、效果和区间、p 值与 q 值（对检测器尝试过的全部内容使用 Benjamini-Hochberg，控制在 5%）、加载其对局的下钻操作，以及带有数值的语句键；报告（`heat3d.mass/1`）是 `massReportForModel` 交给叙述器的内容，其格式与单场对局报告相同（`insights/seam.ts`）。

| 检测器 | 发现的内容 |
|---|---|
| `balance` | 某种玩家载具在某张地图或某种模式中，交换或获胜明显优于或劣于其他载具 |
| `hotspot` | 在稳定比例的对局中为热点的地点（热点对局数 / 所见对局数，与该地图其他单元格相比）——而不仅仅是总量上的热点 |
| `side` | 某张地图的某一方获胜数超过均分 |
| `meta` | 载具在玩家生命中的占比或其 K/D，在日期的前半段与后半段之间的变化——按地图计算，变化幅度足够大、随季度呈趋势、并且在大多数地图上方向一致（见下文） |
| `phase` | 对局长度的某一段承载的击杀、命中、发射……多于均匀分布 |
| `place` | 在许多对局中突出的地点（阶段 B，见下文）：某区域的比率或击杀占比，与各对局自身的比较；圆形、通道、扩展区域、高度带、阶段；当普通热力图未显示时才标为隐藏 |
| `niche` | 表现明显优于或劣于其他群体的分组（阶段 B，见下文） |
| `grid.*` | 在各地图的汇总网格上运行的单数据集检测器（电源位置、热点与冷点区域、按等级划分的地点）：`GridMerge.toInsightJob` 从摘要中填充洞察流程的网格；需要轨迹的检测器则跳过 |

### 摘要 {#the-summary}

纯 JSON（`src/mass/types.ts`），每场对局压缩后约 5–30 KB：

- 对局：游戏、地图、模式、任务、开始时间、时长、行数、生命、玩家、AI、团队（生命、玩家、在场、击杀、死亡、胜负、金钱）、胜者；
- 每个载具和团队：等级、段位、生命、玩家生命、在场、按标准类型划分的事件、按目标等级划分的击杀、胜场、金钱；
- 每名玩家（按用户 ID，否则按名称）：团队、生命、在场、击杀、死亡、命中、发射、胜负、载具；每件武器：按类型划分的事件；
- 经济的列（`cost_*`、`earn_*`）及其总计；
- 阶段：对局长度的 20 个区间内、以及按分钟统计的各类事件；
- 行为：对局的集体行为指标（一致性、路线聚集、车道、拥挤、领先者、掉队者、崩溃点、失利后的风险、连胜、购买一致性、压制），每项都有其自身的零模型、p 值和 q 值——见[集体行为](collective-behaviour.md)；
- 网格（见下文）。

计数方式与查看器相同：列按多场对局加载器的方式查找（`leanSpec`），事件按 `data/canonical.ts` 归类；Tacview 武器造成的击杀计入其射手；同时出现两次的死亡（`dead`、`death`）只计一次。

#### 网格：阶段 B 所依赖的基础 {#the-grid-what-stage-b-builds-on}

空间部分是为任意大小和形状区域的扫描统计而设计的，而不仅仅用于热力图画面：

- **金字塔。** 单元格是世界单位（x、z 按查看器的放置方式）中 2 的整数次幂对齐的方格。第 `k` 层是由 `ix >> k, iz >> k` 汇总的单元格——在单场对局内以及不同单元格大小的对局之间都是精确的——任何区域（方框、沿直线的通道、环）都是若干单元格之和。最细的一层会把对局稳健的范围（包含 99% 在场量的单元格）放入 128 个单元格中；落在其外的零散点会被保留。
- **每个计数旁的暴露量。** 每个单元格的在场秒数，按团队（`pt`）、按载具类别（`pc`）和按高度带（`ph`）统计，因此可以为任何子群体计算区域的比率、期望值和比值。
- **高度。** 高于对局地面（高度的第 1 百分位）的高度带：3 米以下、3–10、10–30、30–100、100–300、300–1000、1000–3000、以上；带有 `floor`/`storey`/`deck` 列的文件则按其楼层分带。`y` 是每个单元格的平均高度，`y0` 是其最低高度（即其楼层，用于高于它的高度）。
- **事件**以元组形式存储：`[cell, kind, team, class, band, count]`。
- **时间切片**：在粗略层级（每边 8 个单元格）上，按距对局开始的分钟数：`[cx, cz, minute, kind, value]`，在场秒数的类型为 `GRID_KINDS.length`；对局阶段是按长度划分的分钟。
- 稀疏存储，计数为整数，秒数精确到十分之一：其规模受限于实际发生的事件。

### 阶段 B：地点与细分群体 {#stage-b-places-and-niches}

阶段 B 寻找在数字中突出、却不引人注目的东西：一大片整体繁忙、其中却没有热点单元格的区域；在少量事件上异常的击杀死亡比；一条通道；一个高度带；仅在对局某一部分出现的集群——以及表现明显优于或劣于其他群体的分组（某张地图某一方的某种载具，某高度的某个区域）。一次**查找地点** / **查找细分群体** / **查找洞察**会运行所有检测器；三个标签页共享同一份报告。

#### 地点（`src/mass/scan.ts`） {#places-srcmassscants}

每张地图的对局会被逐场读取两次；内存中只保存在不超过每边 64 个单元格（时空扫描为 16 个）的栅格上的汇总，而不是对局本身。

- **度量。** 事件按在场每秒的比率计算——击杀、死亡、命中、发射、占领，对所有单位，按类别（事件最多的 4 类），按高度带——以及击杀在击杀与死亡中的占比（全部、按阵营、按高度带）。哪些类别和阵营被采用，由表头决定（`planOf`）。
- **按对局计算的期望。** 每场对局自身的比率，按其在某单元格中的在场量分摊，即该单元格的期望值（按对局分层、经协变量调整的 Kulldorff 扫描）：少数血腥的对局或一个繁忙的服务器不会构成地点。
- **离散度。** 对局之间的差异远超泊松分布。每场对局的残差按 1、2、4、8、16 个单元格的块进行汇总；每种块大小的离散度（残差平方除以零方差，合并计算，最差的 5% 的块剔除）会缩放该大小区域的每项检验：即拟似然比，比率用泊松，占比用二项式。
- **区域。** 半径 0.75 到 18 个单元格的圆形；六个角度的椭圆，长宽比为 3 倍和 6 倍，3 到 18 个单元格（通道；轴线即洞察中的 `place.path`）；从局部最强的 Getis-Ord Gi* 单元格出发、逐格扩展的区域，同时区域的 z 值增大（不规则形状）——在一半的对局上扩展，在另一半上检验，因此扩展的自由度不会带来虚假地点；每个高度带与该地图上其他高度带的对比（对聚类稳健）；时空圆柱体：在对局长度的五分之一或两份中的一个圆形区域，与对局自身的事件在地点和时间上的分布进行比较（时空置换扫描）。
- **检验。** p 值来自拟似然；对每张地图上尝试过的每个区域进行 Benjamini-Hochberg 校正（通常在三张地图上为 700,000 个），控制在 5%。通过检验的区域会被修剪（大部分包含在同一度量下更强区域之内的，说明的是同一件事），然后重新检查其**稳定性**——看到它的对局、其所在的对局、在对局的五折中的方向——并在对局本身显示的方差下再次检验（对聚类稳健，以对局为聚类，绝不假设泊松分布），再次进行 BH 校正。基数较少的安静地点（占地图出生点、起飞和降落的 2% 以下）会被剔除。
- **效果。** 比率（或几率比），经经验贝叶斯收缩（对地图的 2x2 数据块拟合的伽马先验），附带在该离散度下约 95% 的区间；在 1、2、4 个单元格上的 Gi*，以及中心的局部 Moran 指数。
- **视觉显著性。** 该区域在其事件的普通热力图中已经显示的程度（对数刻度，以最亮单元格为准，与视图绘制方式相同）：它与周围一圈的对比（调色板的十分之一难以看清，五分之二则清晰可见），以及一个承载超出部分的明亮峰值；比率从不由热力图绘制，因此占比按一半计。低于 35% 即为**隐藏**。排名：效果强度（效果在 4 倍时饱和，安静地点为 0.7）乘以 `1 - 0.7 x 显著性`，再乘以各折的一致程度。

**地点**标签页列出它们（默认仅显示隐藏的；可按地图、形状、方向筛选）；点击会在三维视图（`placeLines.ts`：引擎的顶线，只构建一次——隐藏为洋红色，普通为琥珀色，安静为青色，所选的为全线；高度带为从其地面到顶面的方框）以及地图标签页的画布上勾勒该地图的地点；**加载**会飞到该处，并加载其中大多数的 60 场对局，按其事件（以及等级）筛选。

#### 细分群体（`src/mass/niche.ts`） {#niches-srcmassnichets}

在三张表上进行束搜索（宽度 24，深度 3）：**生命**（玩家的生命：游戏、地图、模式、等级、载具、阵营、段位、日期的季度、对局长度的三分之一；K/D、胜率、生命被击杀的死亡、每小时击杀、每分钟收入）、**地点**（按地图、模式、日期、地图 4 x 4 的区域、等级、阵营、高度带统计的击杀与死亡）以及**阶段**（对局的区域和五分之一：K/D、每小时在场的死亡数）。一个分组以对局为聚类，与整体进行比较检验（按对局的残差三明治方差），其效果为几率比或比率，并由 20 个结果的先验进行收缩；它需要 8 场对局中的 30 个结果；细化分组的效果必须比其父分组强 10%；结果全无或全有（即未对其记录）的分组会被剔除。保留的条件为：在所有评估过的分组中 BH 校正后低于 5%，收缩后比率至少为 1.25（或 1/1.25），五折中有四折一致，并且不是仅重复其父分组的细化。**细分群体**标签页列出它们；点击一个会显示该分组的每一个单条件细化（探索器），**加载**则加载其对局。载具装备目前尚未包含在摘要中。

#### 具有实际意义的元变化 {#meta-shifts-with-practical-significance}

在日期混合的情况下，对生命的二项检验几乎把每一次变化都判定为显著。现在 `meta` 进行对聚类稳健的检验（每场对局的生命作为一个聚类），只保留使用率变化至少 2 个百分点且至少 25% 的变化，K/D 变化为 1.3 倍，日期的季度呈相同趋势（Kendall 的 tau 至少为 0.5），并且对于在多张地图上的载具，在大多数地图上方向相同。在普通检验几乎全部标记的测试集上，这只留下了少数几项变化。

#### 供模型使用 {#for-a-model}

`massReportForModel` 为每个地点提供其 `region`（形状、是否隐藏、显著性、高度、阶段），为每个细分群体提供其 `conditions`，以及尝试过的区域和分组数量。知识视角可以把地点当作杀伤区和进攻通道来读取：它们的类型是 `place.*` 和 `niche.*`。

#### 检查 {#checks}

`scan.test.ts` 在 240 场合成的过度离散对局中植入了一片弥散的区域（圆形 22 个单元格内的死亡率为 1.6 倍，在每个单元格中都很微弱）、一条通道、一个高度带，以及一个仅在某个阶段出现的集群——全部被找到，其中弥散的那片被隐藏——并且对八组零数据集（每组 60 场对局）运行，结果均无地点。`niche.test.ts` 能找到植入的载具 x 地图 x 阵营分组，而在五张零数据表中则一无所获。
