# 机动：群体如何移动

**洞察 → 机动** 追踪每一方的单位如何*以群体的方式*移动，并说出它们所做的机动：侧翼攻击、钳形攻势、突破、伏击、撤退、导弹防御、横切 T 字等。每个机动都会给出它的确定程度、依据的数字、是否奏效，以及它在条令和历史中的相似例子。**批量分析 → 机动** 则在数千场对局中统计它们：每张地图、每种模式、每一方各做了多少次，以及其中有多少次奏效。

这一切都在你的浏览器中计算，由它自己的 worker 完成（`src/insights/maneuver`）。一场有几百个单位的对局耗时 10-500 毫秒，一场有数千个对象、持续两小时的空战约需一秒。

## 使用方法 {#using-it}

- 打开 **洞察**，选择 **机动** 标签。首次打开时会自动计算；更改筛选条件后点 **重新查找**。
- **确定 / 可能 / 或许** 设定要列出的把握程度（默认为 **可能**）。
- **时间线** 每一方有一条轨道，每个机动有一根条；下方的 **列表** 内容相同，但按时间排列。点击一项会切换到回放的开始处，把摄像机飞到那里，并以 3D 绘制：每个群体的路径用箭头表示（钳形的两臂用它们的弧线表示），关键时刻的群体轮廓（敌方轮廓用其所属一方的颜色），敌方的前线用白线表示。**全部以 3D 绘制** 会额外用淡色绘制本场的其他机动。这些线条只在选择变化时送到显卡一次，而不是每一帧都送；在真实 GPU 上，播放时绘制 480 个机动的帧时间（WebGL2 和 WebGPU，p99 18.0-18.5 毫秒，最大 19.5-20.8 毫秒）与不绘制时一样。
- 打开一个机动后，会显示它的结果（它的单位在机动进行期间及之后不久的击杀和损失，与该方全场的交换情况相比）、它的依据，以及知识库中与之相关的条目：条令和历史上的相似例子（钳形对应坎尼，1940 年色当之于突破，对马海战之于横切 T 字，博洛行动之于佯攻……）。
- 末尾的小表格：按机动种类和一方统计，做了多少次、其中多少次奏效。

## 如何找出群体 {#how-groups-are-found}

每个单位都被放到一条共同的时间线上（步长在步行时为 1 秒，其他情况为 2 秒，文件很大时步长更长）。单位死亡时会保持静止，使重生不会在地图上画出一条线。在每一步，同一方、同一类别（飞机、车辆、舰船、步兵）的单位只要距离足够近，就会被连成一组——步行时 18 米、车辆 170 米、舰船 3 公里、飞机 5 公里——并且移动方向相近（速度的差不超过较快者速度的一半，或者两者都静止）。一个群体保留其多数成员所属群体的编号。没有类别的单位会根据速度被归为步行、车辆或空中。

群体的 **形状** 参照其前进方向来判断：沿前进方向与横向的散布决定它是纵队还是横队；中间领先则为楔形；成员向一侧依次后退则为梯次队形；占据四角则为方阵。

所有判断都以对局本身的尺度进行：**交战距离** `R` 是杀手与受害者之间距离的第 75 百分位数（限制在该领域的合理范围内），机动的时间按单位种类换算（步兵为地面的三分之一）。

## 它能找出什么 {#what-it-finds}

| 机动 | 找到的条件 |
|---|---|
| 队形 | 一个群体在 30 秒内，有 60% 的移动步保持同一形状 |
| 正面突击 | 一个群体从交战距离之外接近到接触，距离为 ¾ R 或更多，且来自敌方朝向 35° 以内 |
| 侧翼攻击 | 同样的接近，但角度为 50-130°（背后超过此角度）；只有当一支友军 *固定力量* 在那里与敌人交战时才算确定（无论哪方击杀） |
| 钳形攻势 | 同一方的两次侧翼攻击打向同一敌方主体，来自相反两侧（相隔 100° 或更多），且在 90 秒内完成；两臂都参与战斗时即确定 |
| 包围 | 一个紧凑的敌方群体，被另一方至少同样数量的单位在 1.5 R 内围住，来自两个或更多群体，包围圈上没有超过 100° 的缺口，持续一分钟，并与其自身一方切断联系；包围圈在 ½ R 内收拢并与口袋中的敌人交战时即确定 |
| 突破 | 一个群体穿过一条被守住的防线（敌人在其左右两侧各停留 30 秒，己方中心位于它们之外）；它前进了 ½ R、停留 20 秒并在那里交战时即确定；再往前推进一个 R 则为突破 |
| 交替掩护 | 在一个小群体中，一部分移动、其余停止，角色互换四次或更多，且停止的部分提供掩护火力 |
| 集中 / 分散 | 一方在其最密集处的兵力占比从 35% 升至 60%（单位以 1.5 R 或更远的距离汇聚，然后接触）——或者随着该方散开而下降 |
| 佯攻 | 一个在接触中的小单位吸引两个或更多敌人从别处赶来；随后一个更大的群体在四倍交战距离外、敌人较少的地方发起攻击 |
| 撤退 / 追击 | 一个接触中的群体转身离开，并在它交战的地点拉开 R 的距离；当那里的敌人刚刚击杀了它的一个单位，且该群体与这个击杀者拉开了 2 R 时即确定（步行时从不算，见下文）；同向移动并跟上的敌人则视为追击 |
| 纵深防御 | 两条或更多防线的静止单位横跨敌方的进攻轴线，纵深 R，敌人正在逼近，防线上的单位开火 |
| 反斜坡 | 静止单位在近距离击杀了三个或更多从山脊后方越过来的敌人 |
| 伏击 | 一个移动中的群体遇到静止了 45 秒的敌人；敌人先开火，移动的一方损失两个单位或一半的群体 |
| 掩护 | 一两个单位走在三个或更多单位组成的主体前方，先于主体遭遇敌人 |
| 内线 | 一方的群体挤在另一方的群体之间，其单位在它们之间来回转移 |
| 节奏 | 一方应对接触（转向、变速、首次开火）的速度快 1.5 倍，Mann-Whitney 检验的 p 值低于 0.05 |
| 卡位、缺口、拖拽、泵式 | 导弹发射的目标使发射者转向 35-70°、75-105°、超过 140°，或拖拽并转回 |
| 空中钳形、墙、前后尾随、绞杀 | 一对飞机分开合围同一个敌人；三机并排冲向敌人；一个单位落后另一个 5-20 公里；两架机绕同一点盘旋，间隔一点 |
| 战斗空中巡逻 | 围绕一个站点盘旋三分钟 |
| 能量 / 角度格斗 | 近距离格斗中——航向相差 30°，双方轮流把对方咬在机头前，或双方之间有一次击杀——使用高度并爬升，或保持平飞并急转同时减速；当其中一方击杀了另一方时即确定 |
| 打击包、压制防空 | 一个混合角色的空中群体，其中一些攻击地面目标；防空单位的击杀先于大多数其他地面击杀 |
| 战列线、横切 T 字 | 三艘舰船成纵队；一支纵队横向穿过敌方纵队的前端 |

每个机动都会说明它体现了知识库中的哪些 **模式**（`patterns-maneuver.ts`：队形、正面突击、双重包围、包围、突破、火力与机动、佯攻、撤退、追击、纵深防御、掩护、分散、导弹防御、角度格斗、战斗空中巡逻、打击包、战列线、横切 T 字），以及应先阅读的条目。较旧的条目通过 `knowledge/maneuver-tags.ts` 带上新的模式。参见 [知识视角](knowledge.md)。

**奏效** 会比较机动进行期间（及之后一分钟）这些单位的交换情况与其所在一方全场的交换情况：撤退在转身后损失的单位比转身前少时算奏效；导弹防御在飞机存活一分钟时算奏效；包围在口袋损失一半时算奏效。

## 多场对局的统计 {#over-many-matches}

每场对局的摘要（`src/mass/summarize.ts`，参见 [批量分析](mass-analysis.md)）包含一个小的 `maneuvers` 部分：按种类和一方统计，做了多少次（在可能或以上的把握程度）、其中多少次奏效、多少次未奏效、击杀和损失。**批量分析 → 机动** 会把筛选保留的对局加起来——按地图和模式分，或全部合计——并给出奏效率的 Wilson 置信区间；点击一行会加载该机动所在的对局。在该部分出现之前写入的摘要没有这些数据：运行 `node tools/3dheat-summarize.mjs <文件夹> --force` 即可补上。

## 有多确定 {#how-sure-it-is}

带有预设机动的合成对局（`synth.ts`，由 `maneuver.test.ts` 运行）：所有 28 种预设的机动都在可能或以上被找到；在报告的 50 个机动中，31 个是预设的种类，其余 19 个也确实存在（移动群体的队形、突破纵队的正面接近）；没有一个是错的。在 30 场空白对局——随机游走的分散与混合、随机静止的单位、沿直线飞行的飞机、一群漫无目的聚集的人——在可能或以上没有报告任何机动。

在真实数据上（数十场地面战斗、几次长时间的空战任务、十几场射击对局）：坦克战中的正面突击、侧翼、突破和包围；空战中的队形和近距离格斗；导弹防御、战斗空中巡逻的盘旋和前后尾随的飞机对；空战任务中的正面处决；射击游戏中的纵队，以及少量伏击和成对的掩护。阈值是按游戏的尺度取的条令形状；看单个发现时应结合其依据，看批量表中的比率时应结合其置信区间。

### 与同一对局的空白模型比较 {#against-null-models-of-the-same-matches}

探测器可能被地形和人群欺骗：在混战中，每个群体四周都有敌人。因此，每一种机动还会在从同一批对局构建的 **空白模型** 上运行（`nulls.ts`），在这些模型中双方不再像实际那样相遇：一方的时间线被旋转三分之一到三分之二场次（*移位*），或其轨迹绕地图中心旋转（*旋转*）；队伍标签被打乱（*队伍*，按构造会保留约一半真实的交战）。交战只按击杀与其对应的死亡配对计算——杀手在 2 R 之内、受害者在该地点——空白模型会打破这种配对。在可能或以上找到的次数，真实数据与空白模型对比（30 场坦克战；12 场射击对局）：

| 种类 | 坦克战：真实 / 移位 / 旋转 | 射击：真实 / 移位 / 旋转 |
|---|---|---|
| 包围 | 0 / 0 / 0（原为 1.3 / 1.2 / 0.8） | 0 / 0 / 0 |
| 突破 | 0.03 / 0.02 / 0.05（原为 1.6 / 1.8 / 1.4） | 0 / 0 / 0 |
| 侧翼 | 0.33 / 0.07 / 0.10 | 1.0 / 0.08 / 0.21 |
| 正面突击 | 0.87 / 0.47 / 0.12 | 14.4 / 6.5 / 4.3 |
| 撤退 | 0.03 / 0 / 0.02 | 0.08 / 0.08 / 0.5（因此在步行时从不确定） |
| 伏击 | - | 0.17 / 0.04 / 0.04 |
| 能量格斗 | 1.2 / 0.1 / 0.85 | - |
| 角度格斗 | 0.6 / 0.07 / 0.3 | - |

战场中心上空的近距离空战即使在绕该中心旋转后仍然存在，因此"旋转"一列对它们的削弱比对地面种类要小。一方内部的种类——队形、战斗空中巡逻、绞杀、打击包、压制防空、掩护、交替掩护、屏护——不依赖另一方，因此不以这种方式检验。`maneuver.test.ts` 检查：空白模型能从合成对局中去除预设的侧翼、钳形、包围、突破、伏击和撤退。

## 限制 {#limits}

- 群体需要随时间变化的位置；只有事件的文件没有位置。
- 朝向不是从数据中读取的：敌方的前线是固定力量与其交战的地方，否则是它移动的方向，再否则是进攻者来的方向。
- 地形是从单位自身的高度读取的（反斜坡）；没有视线测试。
- 非常大的文件以更长的步长采样；其中的短时空中机动仍然按 2-4 秒的步长读取。
