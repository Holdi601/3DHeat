# 地图图像

地图图像是一张平面图片——小地图、卫星照片、平面图——铺在你的数据之下，使你能看到热度位于何处。你告诉查看器这张图片应该放在哪里：在图片上钉住两个点，并把它们对应到世界中的两个位置（即“锚点”）。

## 载入并放置地图图像 {#load-and-place-a-map-image}

1. 先载入你的数据（[导入数据](getting-data-in.md)）。
2. 在**背景/关卡**中按**地图图像…**，然后选择图片。它会被拉伸铺满数据所在的区域。
3. 如果图片被移动过，按**适配数据范围**。锚点 1 会放在图片的左上角，锚点 2 放在它的右下角，位于数据的边缘。
4. 如果热度与图片对不上，请选两个相距较远的地标（例如一栋建筑的两个对角，或两个十字路口）。读出每个地标在图片上的像素位置，以及它的世界坐标（用[标尺](measure.md)悬停，即可读出 **X** 和 **Z**）。
5. 把它们输入**定位**：对于**锚点 1**，填入地标的 **px**、**py**、**世界 X**、**世界 Z**；**锚点 2** 同样填写。
6. 检查：一条你知道位于道路上的轨迹或热点，现在应该位于那条道路上。调整数字直到它如此为止。

![定位区，含两个锚点，热度绘制在地图图片上](../assets/img/en/map-images-placement.webp)

两个地标在像素的列和行上都必须不同，否则面板会显示*两个锚点位于同一像素行或列*。

## 载入 {#loading}

浏览器能够解码的任何图像格式都可以。长边超过 **8192 px** 的图像会被缩小到 8192（这是要求 GPU 保存的最大边长），面板会显示*已从 W×H 缩小为 w×h*。

载入时，图像会以北向朝上、位于数据最低 Y 处的方式，拉伸铺满数据集的 X-Z 范围（没有数据集时则为 ±1000 个单位）。默认值为**不透明度** 100%、**亮度** 0.7、**去饱和** 100%，并开启**南北翻转**：去饱和并降低亮度，因为背景的作用是让你找到热点的位置，而不是与热点争夺注意力。

## 控件 {#controls}

| 控件 | 默认值 | 范围 | 含义 |
|---|---|---|---|
| **不透明度** | 100% | 0-100% | |
| **亮度** | 0.7 | 0-2（拖动 64） | |
| **去饱和** | 100% | 0-100% | 灰色背景，饱和的热度。地图中的颜色会与数据中的颜色相互争夺。 |
| **南北翻转** | 开 | | 图像的哪一行是世界的最大 Z。在已载入数据集时切换它，还会把锚点重新适配到数据范围。 |
| **定位**：锚点 1、锚点 2 | 数据范围上的图像角点 | | 每个锚点是图像上的一个像素——**px**（从左起，0 到宽度）和 **py**（从上起，0 到高度）——以及它所在的世界坐标，**世界 X** 和 **世界 Z**。缩放和偏移由这一对点推算得出。 |
| **适配数据范围** | | | 把锚点 1 放在图像的左上角，锚点 2 放在其右下角，并对应到数据的 X-Z 范围。这是精确定位的起点。需要数据集。 |
| **高度** | 数据的最低 Y | 数据最小 Y - 500 到最大 Y + 500（拖动时最大为最大 Y + 100,000） | 地图平面的高度。把它设在数据略低的位置，使数据不会被它遮住。 |

名称行显示 `宽×高 px · x × z m/px`，即每个坐标轴上一个像素所对应的世界尺寸。

## 在场景中 {#in-the-scene}

图像在其高度上是单个带纹理的四边形。在完全不透明时，它会写入深度，因此它作为地面参与[遮挡](depth-and-culling.md)；不透明度低于 100% 时，它会被混合，且不写入深度，因此它不遮挡任何东西。[标尺](measure.md)在它的平面上进行测量。[关卡库](level-library.md)会把图像关卡连同它的锚点一起保存。

## Dota 2 地图 {#dota-2-map}

**地图图像…**旁边的 **Dota 2 地图** 会获取 [OpenDota](https://www.opendota.com) 在其对局页面上显示的当前 Dota 2 地图图样，并把它放在 [Watcher](https://github.com/Holdi601/3DHeat-Watcher) 从 Dota 2 回放中写出的表格之下（[`dotaMap.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/tactics/dotaMap.ts)）。按下按钮时才会从 opendota.com 获取该图像，它不属于 3DHeat 的一部分；最新补丁的图样取自 OpenDota 自己的列表，如果无法读取该列表，则使用 7.40 版的图样。

| | |
|---|---|
| 来源 | `opendota.com/assets/images/dota2/map/detailed_<patch>.webp`，900×900 px |
| 定位 | OpenDota 的校准：图像在两个轴上覆盖 Dota 世界单位 -8192 到 8064（128 单位的格子为 64 到 191），北在顶部。使用回放表格的坐标轴（Z 向上，Y 翻转）时，即世界 X 为 -8192 到 8064，世界 Z 为 -8064 到 8192。每个像素约 18 个单位。 |
| 高度 | 0。英雄站立于 0 到约 600 之间。 |
| 外观 | 亮度 0.8，去饱和 50%。 |

已在一场公开对局的 7.40 版回放上核对：每个英雄的轨迹都沿着所绘的车道行进，回放放置的防御塔、兵营和远古遗迹都落在所绘的基地上。**顶视**视图会以北在屏幕底部的方式显示地图，与它显示任何 Y 翻转的 Z 向上表格的方式相同。

该图样是 OpenDota 为 Valve 的地图制作的；Valve 并不认可 3DHeat。

### 3D 地图 {#the-3d-map}

安装了 Dota 2 后，独立的 [3DHeat Dota](https://holdi601.github.io/3DHeat-Ext-Dota/) 工具（`heat3d-dota-maps level -o dota.glb`；Watcher 的 [`dota-map`](https://holdi601.github.io/3DHeat-Watcher/dota-map.html) 命令也会运行它）会从游戏自身的文件生成 3D 地图：地面、悬崖、水、树木和建筑，采用回放数据表的单位和坐标轴。用 **3D 模型…** 加载该文件一次：查看器会根据它的部件（`ground:terrain`, `structure:tower`, `structure:ancient`, `structure:tree`；`dotaMap.ts` 中的 `isDotaLevel`）认出它，立即放入[关卡库](level-library.md)并替换较旧的一份，同时给出提示。此后 **Dota 2 地图** 会从关卡库加载这张 3D 地图，而不是下载图样；关卡库中没有时，它会下载图样并说明如何生成 3D 地图。该文件来自你自己的安装，并留在你的电脑上。

## 开发者信息 {#for-developers}

### 锚点如何放置图像 {#how-the-anchors-place-the-image}

来自 [`mapQuadFromAnchors`](https://github.com/Holdi601/3DHeat/blob/main/src/render/level.ts)，锚点为 *a* 和 *b*：

```
scaleX = (b.worldX - a.worldX) / (b.px - a.px)
scaleZ = (b.worldZ - a.worldZ) / (b.py - a.py)
pixel (0, 0) sits at  (a.worldX - a.px × scaleX,  a.worldZ - a.py × scaleZ)
```

两个锚点在每个轴上分别确定缩放和偏移，因此地图可以在 X 和 Z 方向上以不同比例拉伸，但不能旋转。锚点必须在**两个**像素坐标上都不同；如果它们在同一行或同一列，就无法推算出缩放，地图也不会被绘制，面板会显示*两个锚点位于同一像素行或列*。
