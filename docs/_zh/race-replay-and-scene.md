# 回放与 3D 场景

把你的圈像比赛一样一起回放，看一辆车在哪里拉开了差距。赛车分析标签页的 3D 视图中显示的一切，都在这里说明：行驶走线、画在赛道上的颜色、车辆和标签。

![以原因为主的地图：车辆在一个弯前 40 m 对齐，赛道上有颜色，两辆车和旗杆](../assets/img/en/race-replay-lined-up.webp)

## 回放时钟 {#the-replay-clock}

一个时钟驱动所有的圈：**参考**圈上的秒数。播放时，引擎每一帧都会推进它（帧时间 × 回放速度）；到达结尾时，若开启了**循环**，则回到 0，否则停止。时钟特意不放在存储中，以免侧边栏每一帧都重新渲染；HUD 和图表订阅它，并且每帧最多更新一次。

**回放的长度**是任何一圈在时钟上运行的最长时间：即每圈的圈时间（减去其在**对齐**中的偏移），在**并排**中则为参考圈的时间。

## 播放栏 {#the-transport-bar}

在视图下方，从左到右：

| 控件 | 作用 |
|---|---|
| ⏮ | 回到起点（也可按 **Home**） |
| ▶ / ❚❚ | 播放 / 暂停（也可按 **K**） |
| 速度 | 0.25×、0.5×、1×、2×、4× |
| 进度滑块 | 直接设置时钟，以 0.01 s 为步长 |
| 时钟 | `时间 / 长度 · 米数`：时钟显示为圈时间、回放的长度，以及参考车已沿参考圈行驶了多远 |
| *从起跑线开始* / *对齐* / *并排* | 回放模式（见下） |
| **在此对齐** | 把每辆车放在参考车当前所在的位置，然后从那里继续 |
| **循环** | 结束后从头开始（默认开启） |
| **隐藏图表** / **显示图表** | 播放栏下方的距离图表 |

在加载圈之前，这些按钮都是禁用的（一圈即可回放；比较则需要两圈）。

## 回放模式 {#replay-modes}

每圈自己的时间如何从时钟推导出来：

| 模式 | 每圈的时间 | 显示什么 |
|---|---|---|
| **从起跑线开始**（`start`） | 时钟本身 | 每圈都从它自己的起点开始：它们之间的比赛，差距随赛道上的情况逐渐拉开 |
| **对齐**（`anchor`） | 时钟加上该圈的偏移 | 每辆车都在同一个地点、同一时刻，然后放开——即从那一点开始发生的事，而不是从圈的起点开始 |
| **并排**（`locked`） | 该圈到达参考圈当前距离的那个时间 | 每辆车都保持在参考圈的距离上，整圈如此：逐米比较速度和操作 |

何时使用：

- **从起跑线开始**：你想看谁领先，以及差距如何拉开。
- **对齐**：你想知道一个弯或一段直道上发生了什么，所有人在那里都从同一起点开始。
- **并排**：你想在赛道的同一位置，比较各人对踏板和方向盘的操作。

**对齐中的偏移：**对于参考圈上距离为 `s` 米处的锚点，每圈的偏移是它在 `s` 处的自身时间，减去参考圈在 `s` 处的时间，两者都取自对齐后的圈（见[一条距离轴](race-corner-analysis.md#one-distance-axis)）。没有覆盖 `s` 的圈，偏移为 0。从模式按钮中选择**对齐**时，锚点设在参考车当前的距离上。

在**对齐**模式下，白色旗杆（14 m 高）标出锚点。

### 对齐 {#lining-up}

| 操作 | 锚点 | 时钟 |
|---|---|---|
| **在此对齐** | 参考车当前所在的位置 | 不变 |
| 在图表上按 Shift+点击 | 被点击的米数 | 参考车到达它之前 1.5 s |
| *哪里可以改进*中的一条发现、赛道上的编号标记、带发现的*逐弯对比*中的一行 | 发现原因开始处之前 40 m | 该点之前 1.5 s；然后开始播放 |
| 一个车辆控制事件、撞击的标签 | 事件之前 40 m | 之前 1.5 s；然后开始播放 |
| 赛道统计中的一圈 | 同其发现或事件 | 同上，并聚焦该圈 |

查看某条发现时，镜头也会将其框住——以发现范围中间为中心的一个球体，半径取 40 m 与其长度一半加 30 m 中的较大者（事件为 60 m）——除非镜头正在跟随一辆车。

### 追车镜头 {#chase-camera}

圈列表中的 ⌖ 会让镜头跟随那辆车：位于它身后 2.5 + 4 × 车辆大小 米、上方 0.9 + 1.1 × 车辆大小 米，沿其行驶方向观察，俯视对准车辆，并且每帧缓动（每帧移动 20% 的距离），因此不会随着每一次颠簸而抖动。再按一次 ⌖ 即解除跟随。被跟随的车会稍微变亮，地面上有一个白色圆环，其卡片也会高亮。

## 视图区 {#the-view-section}

| 控件 | 默认 | 作用 |
|---|---|---|
| **线条** / **时间图** / **原因图** / **失误图** | 时间图 | 沿赛道绘制的内容（见下）；*线条*则不绘制任何东西 |
| 图例 | - | 时间图为*获得 ↔ 损失*，原因图为各原因的颜色，失误图为*少数圈 ↔ 多数圈* |
| **行驶线** | 开 | 每条可见圈的线，以其颜色绘制 |
| **车辆** | 开 | 车辆，以及 HUD 卡片的数据来源 |
| **轮胎与悬挂** | 开 | 轮胎温度、滑移环、悬挂推杆及其他按车轮显示的标记，以及车辆上的车顶灯 |
| **标签** | 开 | 弯名、编号标记、撞击标签，以及失误图的弯标签 |
| **由圈生成的赛道** | 开 | 没有提取到赛道模型的赛道的路面（加载了**关卡**中的赛道模型时隐藏） |
| **卡片上显示所有数值** | 关 | 每张 HUD 卡片上列出每个通道 |
| **真实车型外形** | 开 | 每辆车以其对应车型的外形显示（见[车辆](#the-cars)）；关闭时显示开放式单座赛车，它不隐藏任何遥测数据 |
| **车辆大小** | 1× | 1× 到 10×，以 0.5 为步长；1× 是车辆的真实大小，与游戏中一样长、一样宽。只有此滑块会改变它 |

## 行驶线 {#driven-lines}

每条可见圈通过其自身采样点的路径，以其颜色绘制，位置比记录的位置低 0.12 m（车辆记录的位置是其参考点，在提取出的 Forza 赛道上，比路面高 0.28 至 0.47 m）。每 1.5 m 保留一个点；可见圈超过 10 圈时，未被查看的圈每 6 m 保留一个点（每个顶点每帧都要送到 GPU）。

## 地图 {#the-maps}

三者都是沿**参考**路径的色带，比记录的位置低 0.2 m，每个 2 m 网格步长一个四边形。

### 时间图（`where`） {#time-map-where}

对于聚焦的圈：每米相对于它所比较的那圈（其级别中最快的圈，或对参考圈而言为每段中最快的其他圈）所获得或损失的秒数，由对齐后增量在每个网格步长上的变化得出，并在 ±10 m 内平滑。损失时间处为红色，获得时间处为绿色，中间为灰色；颜色刻度取绝对值的第 95 百分位数，因此尖峰会被截断，大部分圈都在范围之内。宽 6 m。

### 原因图（`why`） {#cause-map-why}

对于聚焦的圈：每一项损失都绘制在其**原因**所在的范围上（而不是时间显示的位置），按原因所属的组着色，两者重叠时以代价最大的那项为准。宽度为 `3 + 9·√(代价 / 最大代价)` 米；没有损失的地方，画一条灰色的 2 m 带。在*哪里可以改进*中选中的发现，会被涂成白色。

| 组 | 颜色 | 发现 |
|---|---|---|
| 刹车 | 橙色 | 刹车阶段的驾驶损失 |
| 入弯 | 洋红 | 入弯及中段的驾驶损失 |
| 出弯 | 蓝色 | 出弯阶段的驾驶损失 |
| 直道 | 黄色 | 直道上的驾驶损失 |
| 车辆 | 灰色 | 车辆解释的部分 |
| 情境 | 深灰 | 情境（比赛起跑对飞行圈） |

### 失误图 {#mistake-map}

在所有圈（赛道统计中所选级别的圈）中，每一米有多少圈犯了失误——任何类型，或只是统计中所选的那一种。每圈在每米只计一次；每个失误的范围在两侧各扩大 6 m，使短的失误也能显示。宽度为 `3 + 10·(圈数 / 最多的圈数)` 米，颜色从暗棕色到亮橙色；没有任何圈犯失误的地方，为灰色的 2 m 带。见[赛道统计](race-course-statistics.md#the-mistake-map)。

## 由圈生成的赛道 {#track-from-the-laps}

对于尚未提取赛道的游戏，会在线条下方画出一条路面：宽度为各圈在参考圈上的横向分布（横向偏移在 25 m 之内的计入）加上两侧各 2 m，并且两侧至少各离参考线 4 m，在 ±8 个网格点（±16 m）内平滑，颜色为沥青灰色，带浅色边线，位于记录位置下方 0.3 m。在**关卡**中加载了赛道模型时隐藏。

## 撞击与事故，标在赛道上 {#hits-and-crashes-on-the-track}

每条可见圈的撞击与事故（见[车辆控制事件](race-control-events.md#hits-and-crashes)），只要绘制了线条或车辆，就会标在它们发生的地方：一个带尖刺的星形——事故为红色，撞击为琥珀色——立在一根柱子上，柱子底部有一个该圈颜色的圆环，大小随车辆大小变化（事故更大）。车辆经过撞击的那一刻，会从此处向外扩散出一圈冲击波，持续 0.8 s。

## 帮助模式 {#help-mode}

在语言选择器旁的 **?**，或 **?** 或 **F1** 键，会为三个标签页上屏幕中的每一种颜色打开一份说明（[`HelpPanel.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/help/HelpPanel.tsx)、[`RaceHelp.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/race/RaceHelp.tsx)）。选择会保留在此浏览器中。

- 视图角落中的**图例**列出当前标签页和模式所用的颜色。每个色带都来自视图获取它的地方，因此你编辑过的热力色带会显示为已编辑的样子。在赛车标签页上，只列出已加载的圈所携带的内容。
- **每辆车的卡片**增加一张表，按名称列出其车轮上绘制的内容，以及每个车轮的数值，颜色与绘制时相同。
- **焦点车**的每个车轮上都有一个标签，说明同样的内容，放在车角之外。当车在屏幕上太小、放不下这些标签时隐藏。

## 车辆 {#the-cars}

**每辆车都以其自己的外形显示**，颜色为其圈的颜色，大小为真实大小。外形来自一个车辆文件，它在游戏所在的机器上制作一次：

```
python -m heat3d_gamefiles cars -o forza.h3dcars
```

没有车辆文件时，每辆车都画成**查看器自带的车**，取其种类和年代：轿车、双门跑车、掀背车、旅行车、跑车、超跑、肌肉车、越野车、皮卡、厢式车或微型车，每种又分为经典款（1980 年以前）、80 和 90 年代的款式，或现代款（[`carBodies.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/race/carBodies.ts)）。这些都是根据一般比例在此构建的：没有标志、没有车型名称，也不取自任何游戏的文件，因此它们随查看器一起发布。种类来自车名，年代来自其中的年份；名称中两者都没有的车，则按其级别取。约一百个真实车型已知其公布的长、宽、高和轴距（[`carSpecs.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/race/carSpecs.ts)；每款一行，取整），因此 1990 年代的 3 系会得到该车的大小和姿态，但仍是一个没有徽标或格栅的普通外形。

车辆文件是在你自己的机器上，用你自己的游戏副本制作的。它包含每辆车的一个低细节模型，约 900 个三角形，以及车轮位置（见[提取工具的 `cars` 命令](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/docs/commands.md#cars)）。在视图设置中按**加载车辆文件...**，或把文件拖到赛车标签页上，即可加载；它保存在此浏览器中。它包含游戏的外形，因此不应转交他人，查看器本身也不附带任何此类文件。

每一圈对应的车由加载的内容在每次使用时推算，从不保存，因此今天没有对应车辆的车，会在更新的文件包含它时立即获得自己的外形（[`carMatch.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/race/carMatch.ts)）：

| 圈的车 | 绘制为 |
|---|---|
| 其编号在该游戏的文件中 | 那辆确切的车 |
| 同一品牌，且名称中有该车型的一个词 | 该车型，年份最接近的 |
| 同一品牌，同一代 | 该品牌中年份最接近的车 |
| 其他情况，有车辆文件 | 同一品牌中最接近的车（若有），否则同一种车身中年份最接近的 |
| 单座赛车（按名称判断） | 下面的单座赛车 |
| 前两者都不适用，且查看器知道这辆车的大小 | 查看器自己的车，大小为该真实车辆的大小，有没有文件都一样 |
| 其他情况，没有文件 | 同种、同年代的查看器自带的车 |

因此，在另一款游戏中的 1990 年宝马 3 系圈，会显示一辆约同年代的宝马；比文件更新的车，则显示其最接近的亲属车，直到重新制作了文件。圈的提示框，以及焦点圈车辆大小下方的那一行，会说明它被绘制成什么，以及与它有多接近。

查看器自己的车有深色车窗。车辆文件的模型整体为同一种颜色，因为文件中没有涂装或玻璃可依据。车轮、尾灯、灯具和下面的遥测标记，都与单座赛车一样绘制；推杆沿车轮外侧向上延伸，以便可见，而横臂则省略。

**单座赛车**是一辆开放式轮式赛车，颜色为圈的颜色，因此从任何角度都能看清车头，而且没有东西遮挡车轮：车身、发动机罩、侧箱、驾驶舱（带头盔）、头环、底板、前后翼；四个圆形车轮，前轮随转向转动（满打方向时最多 0.5 rad），每个车轮由两根横臂、一个转向节、前轮的转向拉杆或后轮的传动轴，以及一根推杆连接。模型相对记录位置下降 0.3 m，使其车轮贴在路面上，并由**车辆大小**缩放。

**车身随弹簧运动**：当圈带有全部四个悬挂行程时，每个角都会按其行程下降（为了从追车镜头中可见，从满压缩到满回弹被放大到 0.12 m），车身则沿四点所在的平面下沉、俯仰和侧倾。

**由遥测绘制的内容**（开启**轮胎与悬挂**时）遵循[通道表](race-charts-and-hud.md#the-channel-table)：

| 标记 | 来源 | 绘制 |
|---|---|---|
| 轮胎颜色 | `tireTemp` | 轮胎本身，在 40-130 °C 之间由蓝（冷）到青、绿（工作温度）、黄，再到红（过热） |
| 滑移环 | `slipRatio`、`slipAngle`、`combinedSlip`、`slipIndex`（取最大者） | 车轮下方路面上的一个环：有抓地力时为绿色，0.66 时为琥珀色，1 时为红色（即游戏报告的抓地力边缘）；低于 0.3 时几乎看不见 |
| 悬挂杆 | `suspension`（0..1） | 按行程着色的推杆：伸展为蓝色，中间为白色，压缩为红色 |
| 刹车辉光 | `brakeTemp`（100-900 °C） | 车轮外侧面上的一个刹车盘，由暗到橙 |
| 磨损带 | `tireWear`（0..1） | 胎面边缘的一圈带，从白色（新）到红色（磨损） |
| 载荷条 | `wheelLoad`（0-12 000 N） | 车轮旁边的一根柱子，与载荷等高 |

刹车灯（雨灯和翼端板）随刹车踏板亮起。每个处于开启状态（超过其范围一半）的 `lamp` 通道，都会在空气动力箱上方以其颜色点亮一盏灯：ABS 作用、牵引力控制作用、DRS、维修区限速器、手刹、在空中。

**人群中**（可见车辆超过 10 辆时），没有被查看的车只绘制为普通样式：车身、翼、车轮和刹车灯。

## 标签 {#labels}

固定在赛道上，每一帧根据摄像机投影放置（在屏幕外或摄像机后方时隐藏）。开启**标签**时：

| 标签 | 位置 | 点击 |
|---|---|---|
| 弯名（`T1`、`T2`……） | 参考圈上每个弯的弯心之上 | - |
| 编号标记 1-5 | 聚焦圈损失最大的五个驾驶失误，位于每个原因范围的中间，边框为该原因的颜色；悬停可看标题和代价 | 对齐并回放该发现 |
| 撞击 / 事故标签 | 聚焦圈每次冲击之上："事故 −45 km/h"、"撞击 −12 km/h"；悬停可看完整描述和提示 | 对齐并回放该撞击 |
| 失误图的弯标签（当该图为失误图时，代替弯名和编号标记） | 每个弯的弯心：“T3 · 5/40 过早刹车”（最常见的失误，犯此失误的圈数 / 驾驶该弯的圈数）、选择了某一类时为“T3 · 5/40”，都没有时为“T3 · 干净”；悬停可看该弯的损失和其五种最常见的失误 | 在赛道统计中打开或关闭该弯 |

## 镜像世界 {#mirrored-worlds}

查看器的世界是右手坐标系，Y 轴向上：从上方看，若车的行驶方向 `atan2(dx, dz)` 增大，则它在向左转。左手坐标系的世界（包括 Forza）会呈镜像：每个右转弯都画成左转弯，赛道与圈都是如此。

圈会自己说明（[`handedness.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/race/handedness.ts)）：每隔几米（3 m）检查每圈，将其路径的转向与外侧悬挂的压缩量（`suspension.FR` 减去 `suspension.FL`）比较；若没有悬挂数据，则与转向角比较（在每个适配器中，正值都向右）。总转向角不足 π 的圈不作判断；证据的数量超过转向量的 2% 时才计入。各圈投票；平局则为“无法判断”。

当圈的判断与当前的坐标轴反转（**摄像机与场景 → 反转世界坐标轴** 中奇数个反转的轴）不一致时，**圈**一节会在列表下方说明：

- 游戏是镜像的，且没有反转任何轴：“这些圈向右打方向，而赛道被画成向左弯……”，并给出**反转 X**；
- 轴被反转，但圈不是镜像的：“反转的轴把这些圈画成了镜像……”，并给出**重置坐标轴**。

只改变绘制：一个折叠进视图矩阵的镜像；数据、分析以及工具显示的每个坐标，都仍然是游戏自己的坐标。反转会保存在浏览器中。分析用相同的测量说明弯是左还是右（未知的世界按镜像处理，与 Forza 相同）。

### 某一时刻车辆处于什么状态 {#what-a-car-is-at-a-moment}

`stateAt` 在圈的时间前后两个采样点之间，对每个通道进行插值。阶梯型通道（挡位、旗帜）取最近的采样点。已经结束的圈停在终点线上。

**航向。** 行驶方向由相隔几米的位置得出（两侧至少 2 m，使轻微的晃动不会使车转向）。车身的航向只有在游戏的偏航角与行驶方向拟合之后才使用——符号和偏移量，取时速超过 10 m/s 的采样点（至少 20 个）的圆平均值——并且只有当它与行驶方向一致时（圆方差低于 0.05，约 18° 的散布）；否则车身指向行驶方向。这样即使不信任游戏的角度约定，也能看见侧滑（车身与行驶方向分开）。

**转向与左右。** 正向转向使车向哪边转，以及游戏的右侧车轮属于哪一侧，都从圈中测量得出：比较转向与路径的转向，并看哪一侧的悬挂在弯的外侧被压缩（没有悬挂数据时，Forza 游戏按镜像处理）。
