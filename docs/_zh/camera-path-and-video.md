# 摄像机路径与视频

把你的数据拍成一部影片：你把摄像机放在几个位置，查看器在它们之间飞行并保存为视频。每一帧都非常干净，没有颗粒感。摄像机和播放头一起移动，因此同一个面板也能做出延时摄影（[`PathPanel.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/panels/PathPanel.tsx)、[`campath.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/campath.ts)、[`record.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/record.ts)）。

## 制作飞越镜头 {#make-a-flythrough}

1. 飞到影片开始的位置，在**相机路径与渲染**中按**在此添加关键帧**。
2. 飞到下一个位置，再按一次。每个停靠点都重复此操作。
3. 勾选**沿路径预览**，拖动**路径上的位置**检查运动。

   ![相机路径与渲染面板，含三个关键帧、平滑插值、12 秒、30 fps 和 16 Mbps](../assets/img/en/camera-path-panel.webp)

4. 设定**时长**（视频有多长）。运动正确但太快时，只需加长时长即可。
5. 按**渲染视频**。等待进度条；渲染完成后文件会下载。

## 关键帧 {#keyframes}

| 控件 | 效果 |
|---|---|
| **在此添加关键帧** | 把当前摄像机的位置、偏航、俯仰和视场角添加为一个关键帧。 |
| **清除** | 删除所有关键帧。 |
| 关键帧列表 | 每个关键帧一行：它的编号（点击可让摄像机飞到那里，同时设定视场角）、位置、`偏航° / 俯仰°`，以及用来删除它的 **×**。 |

每当添加或删除关键帧时，关键帧都会沿归一化路径轴从 0 到 1**均匀**分布；随后输出时长会拉伸整个运动，因此运动正确但太快的镜头只需加长时长即可。关键帧之间的偏航会被展开，使摄像机沿较短的方向转动。

没有关键帧时，渲染会让当前摄像机在整个片段中保持静止——这是一段完全可用的延时摄影。

## 路径设置 {#path-settings}

| 控件 | 默认值 | 范围（拖动） | 含义 |
|---|---|---|---|
| **插值**（2 个以上关键帧） | *平滑* | *平滑* / *直线* | *平滑*：通过各关键帧的三次 Hermite 曲线，切线取自相邻关键帧，因此每个关键帧处的速度是连续的，线段相接处不会突然跳动。*直线*：关键帧之间的直线，可预测，但每个关键帧处都有可见的拐角。视场角始终线性插值。 |
| 行程线（2 个以上关键帧） | | | `N 个单位的行程 - 在此时长下每秒 M`，或说明所有关键帧都位于同一位置的注释。 |
| **沿路径预览**（1 个以上关键帧） | 关 | | 由路径驱动视口摄像机，并像渲染时一样同步移动播放头，因此可以在渲染前判断运动效果。 |
| **路径上的位置**（预览时） | 0% | 0-100% | 预览路径上的位置。 |
| **时长** | 12 s | 1-120 s（3600） | 视频的长度。 |
| **帧率** | 30 fps | 6-60（240） | |
| **码率** | 16 Mbps | 1-60 Mbps，对数刻度（400） | 码率较低时，热度渐变会严重出现色带：编解码器几乎没有细节可以用来掩盖误差。 |
| **收敛等待上限** | 240 帧 | 2-600（10,000） | 一个输出帧为了变得精确而最多可以等待的时长。达到上限的帧仍会写入，并被计数。 |
| 摘要 | | | `N 帧 · 窗口：累积/固定/生命周期`；当时间线处于**全部**模式时，还会显示：*（渲染会把“全部”切换为“播放”，使播放头具有意义）*。 |
| **渲染视频** / **取消** | | | 开始渲染；渲染期间显示 `第 i 帧 / 共 n · 等待 w · X MB`，以及有多少帧不精确。需要已载入的数据集。 |

## 提示 {#tips}

- 输出尺寸为设备像素中的画布尺寸（显示器的像素比，上限为 2）。调整浏览器窗口大小即可改变它。
- 累积历史会在片段中逐渐建立热度；窗口或生命周期历史则显示一段移动的时间切片。
- 关键帧位置是显示坐标：若使用了[反转的世界坐标轴](camera.md#invert-world-axis)，在切换之前制作的关键帧，切换之后会指向别处。

## 开发者信息 {#for-developers}

### 渲染做了什么 {#what-a-render-does}

1. 对帧进行一次测试捕获，以得知输出尺寸的精确设备像素值。
2. 通过 WebCodecs 选择编解码器：**VP9**（`vp09.00.10.08`），否则为 **VP8**，使用所选的码率和帧率。没有 `VideoEncoder` 时停止，并显示*此浏览器没有 VideoEncoder——写入视频需要 WebCodecs*；两种编解码器都不可用时，显示*没有受支持的视频编解码器（已尝试 VP9、VP8）*。
3. 接管渲染所需的设置：暂停播放，将**自适应预算关闭**，**渐进细化开启**，并把精灵预算设为每帧 6400 万（自适应预算保护的是帧率，而这里的目标恰恰相反：它会把每个缓慢收敛的帧都视为应当减少绘制行数的理由，而这样做需要更多帧才能收敛），并把时间线从**全部**切换为**播放**。历史设置（累积、窗口、生命周期）保持不变：渲染的目的，是把你正在看的内容播放一遍并记录下来。
4. 对于 *n* 个输出帧中的每一帧 *f*，取 *u* = f / (n - 1)：
   - 把摄像机放在路径上 *u* 处的位姿（如果有关键帧）；
   - 把播放头定位到时间线范围中相同比例 *u* 的位置（在方框回放中为所选会话的跨度）；
   - 强制进行新的估计，即使摄像机没有移动——沿用上一帧的累积会在画面中留下上一个窗口的残影；
   - 逐帧等待，直到画面精确（所有候选行在一帧内绘制完毕，或累积完成），最长不超过等待上限；
   - 捕获合成后的帧并编码，每 2 秒输出一个关键帧，使文件可以定位。
5. 把各帧封装为 WebM 文件（[`webm.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/webm.ts)），时间戳根据帧率选取——每一帧实际花费的挂钟时间与此无关。
6. 恢复预算、视场角、时间线模式、播放头以及之前是否正在播放。
7. 把视频下载为 `3dheat-<宽>x<高>-<帧数>f.webm`，并报告 `N 帧，尺寸 W×H，X MB - 每一帧都精确`，或达到等待上限的帧数。

**取消**会在当前帧之后停止（*渲染已取消。*），并恢复设置。
