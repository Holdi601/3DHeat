# 手柄与 HOTAS

你可以用 Xbox 风格的手柄代替键盘来飞行相机。当你想靠在椅背上环顾大场景时，就用它。它的输入**叠加**在键盘输入之上，所以你可以两者同时使用。

## 连接手柄 {#connect-a-controller}

1. 插上手柄（或与它配对）。
2. 点击视图，然后按手柄上的任意按钮。浏览器只有在手柄发出第一次输入后才会显示它。
3. 打开 **相机与场景 → 手柄**。设备列表会用 `●` 显示它。
4. 推左摇杆飞行，推右摇杆环视。如果摇杆在中央时相机仍在漂移，请提高 **死区**。

浏览器映射到标准手柄布局的任何设备都可以使用。飞行摇杆或油门（HOTAS）默认会被忽略；见下文。

## 按键映射 {#mapping}

| 控件 | 效果 |
|---|---|
| 左摇杆 | 移动：前进/后退和左右平移 |
| 右摇杆 | 环视：偏航和俯仰，满偏时每秒 *环视速度* 度 |
| `RT` / `LT`（模拟） | 上升 / 下降；在平行投影中，放大 / 缩小 |
| `RB`（按住） | 快 6 倍 |
| `LB`（按住） | 15% 速度 |
| `A`（按住） | 3 倍冲刺（可与 RB/LB 组合） |
| `Y`（按下） | 将视野对准数据 |

按钮编号遵循标准布局：A 为 0，Y 为 3，LB 为 4，RB 为 5，LT 为 6，RT 为 7；摇杆在轴 0–1（左）和 2–3（右）上。

## 手柄设置 {#the-gamepad-settings}

在 **相机与场景 → 手柄** 中。**设置** / **隐藏** 会打开或收起调节控件。

| 控件 | 默认值 | 范围（微调） | 含义 |
|---|---|---|---|
| **启用** | 开 | | |
| 设备状态 | | | 每个已连接的设备：被跟随时显示 `●`，未被跟随时显示 `○`；对于非标准设备，会显示 *- 不是 XInput 手柄，已忽略* 或 *- 不是 XInput 手柄，仍然使用*。如果没有任何设备：显示 *未检测到手柄。浏览器只有在手柄发出第一次输入后才会识别它——按一下手柄上的按钮。* |
| **使用设备** | *仅 XInput 手柄（推荐）* | | 连接了非标准设备时显示。按名称选择一个设备即可改为跟随它。 |
| **环视速度** | 150°/s | 20–540（5000） | 右摇杆满偏时的转动速率。 |
| **死区** | 12% | 0–50%（95%） | 径向：斜向推动不会只泄漏到某一个轴上。如果摇杆在中央时相机仍在漂移，请提高它。 |
| **摇杆曲线** | x² | 线性（1）到 x⁴（16） | 死区之后的响应指数：靠近中心时控制更精细，边缘处仍是全速。 |
| **反转摇杆 Y** | 关 | | |
| **交换摇杆** | 关 | | 右摇杆用于移动，左摇杆用于环视。 |

摇杆的整形方式：设偏转量为 *m*（摇杆向量的长度），死区为 *d*，则沿摇杆方向的输出 = ((m - d) / (1 - d)) ^ 曲线，死区之内为 0。

## 为什么默认只跟随标准手柄 {#why-only-standard-pads-by-default}

手柄 API 会报告**每一个**带轴的 HID 设备——飞行摇杆、油门、踏板、方向盘——而这些设备并不会停在中央：扭转轴或油门杆在没人触碰时也会停在满偏位置。如果把它当作摇杆读取，就会变成一个永久的满速输入，任何死区都压不住，页面一加载相机就会自己旋转（而且每种热度模式看起来也都会坏掉，因为移动的相机每帧都会重新开始累积）。

因此，只有当浏览器报告 `mapping: "standard"`（它的表示方式是"XInput 风格的手柄，轴位于你预期的位置"）时，设备才会被跟随。其他设备会被列出并标记为已忽略，而 **使用设备** 可以明确选择其中一个——例如用 HOTAS 飞行相机。一旦跟随了某个手柄，相机就会一直跟随它，因此两个控制器不会因枚举顺序而争夺相机。

**HOTAS：** 只读取轴 0–3（两个摇杆）和标准按钮。其他轴上的油门或踏板不起作用；轴不会停在中央的摇杆或油门可能需要更大的 **死区**。

在手柄发出第一次输入之前，浏览器会隐藏它，所以对页面而言，一个插着但未被触碰的手柄还不存在。
