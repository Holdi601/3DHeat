# 3D 关卡

3D 关卡是你的数据所处场所的模型——山丘、街道、建筑物。它让你看到热力位于哪一层、哪座山丘或哪个屋顶之上。查看器会把它分为地面（实体）、结构（半透明，以便你看到内部）和水面。

## 加载 3D 关卡 {#load-a-3d-level}

1. 先加载你的数据（[导入数据](getting-data-in.md)）。模型必须使用与数据相同的世界空间和单位，Y 轴向上。
2. 在**背景/关卡**中选择一个**简化目标**。除非模型非常大，否则保持为*完整 - 不简化*。
3. 按下**3D 模型…**，选择一个 `.glb`、`.gltf`、`.obj`、`.stl` 或 `.ply` 文件。
4. 等待进度行。**取消**可以停止加载。
5. 在视图中按 **F**。地面为实体，结构为半透明外壳，水面为平面。
6. 在[关卡外观](level-appearance.md)中调整外观。按下**保存到库**即可保留结果（[关卡库](level-library.md)）。

![已加载的 3D 关卡：带等高线的不透明地面，半透明的建筑物，平面的水面](../assets/img/en/model-levels-loaded.webp)

**3D 模型…**加载关卡网格。它在后台工作线程（[`modelWorker.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/modelWorker.ts)）中被解析、分类和简化，并显示进度行和**取消**按钮：*正在读取模型*、*正在解析文件*、*正在打包 N 张纹理*、*正在分类 N 个部件*、*正在简化地面（N 个三角形）*、*正在简化结构（N 个三角形）*、*正在构建线框*。

## 格式 {#formats}

| 格式 | 读取的内容 | 限制 |
|---|---|---|
| `.glb` | 每个 `mode` 为 4（三角形）或无 mode 的网格图元，并应用每个节点的世界变换；`POSITION`；`COLOR_0`（vec3 或 vec4）作为顶点颜色；材质的 `baseColorTexture` 及其 `TEXCOORD_n` 作为纹理；节点和网格的名称作为部件名称。 | 线和点会被跳过。 |
| `.gltf` | 同上。 | 仅限内嵌缓冲区：引用外部 `.bin` 的 glTF 会被拒绝，并提示*导出为单个 .glb，以便几何体被内嵌。* |
| `.obj` | 面，`o` 和 `g` 块作为部件。 | 仅几何体（无材质）。 |
| `.stl` | 二进制和 ASCII（`solid …`）。 | 一个部件。 |
| `.ply` | 仅 ASCII。 | 二进制 PLY 会被拒绝，并提示*转换为 .glb 或二进制 .stl。* |

仅几何体：位置、法线和三角形被焊接到一个缓冲区中，若存在颜色和纹理坐标则一并保留（[`modelParse.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/modelParse.ts)）。没有三角形的模型会被拒绝。模型必须与数据使用相同的世界空间和单位（Y 轴向上）：不会为了适配而进行任何变换。

## 地面、结构与水面 {#ground-structures-and-water}

关卡在导入时被分为三类，因为它们需要相反的处理方式（[`classify.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/classify.ts)）：

- **地面**——以不透明方式绘制，并带有地形起伏提示（坡度、等高线、海拔渐变），以便能对照它读取位置。
- **结构**——建筑物和道具位于摄像机与其内部热力之间，因此它们被绘制为**半透明外壳**（淡淡的面，加上明亮的边缘，以及去重后的棱边）——若带有纹理，则以其纹理呈现为实体。
- **水面**——平面，没有地形提示：横跨湖面的等高线毫无意义。

每个部件（glTF 节点、OBJ 对象或组）都会单独分类，依据第一条适用的规则：

1. **导出器的标签。** 以 `ground:`、`structure:` 或 `water:` 开头的名称（或用 `|` 代替 `:`）会被直接采用。项目自身的导出器就是以这种方式为每个部件加标签的。
2. **水面名称。** 作为单词的 `water`（但不包括 *water tower*、*-tank*、*-mill*、*-front*、*-fall*、*-pump*、*-pipe*），`ocean`、`sea`、`lake`、`pond`、`lagoon`、`river`。
3. **地面名称。** `terrain`、`landscape`、`ground…`、`…_ground`、`heightmap`、`floor…`、`map` / `map_…`、`base` / `base_…`、`road`、`street`、`pavement`、`sidewalk`。
4. **结构名称。** `house`、`building`、`bldg`、`wall`、`roof`、`door`、`window`、`stair`、`prop`、`asset`、`clutter`、`debris`、`crate`、`barrel`、`fence`、`tree`、`rock`、`bush`、`vehicle`、`car`、`truck`、`tank`、`bridge`、`tower`、`silo`、`hangar`、`bunker`。
5. **几何形状。** 占地图 X-Z 面积超过 25%，且三角形面积超过 60% 朝上的部件为地面。朝上的比例低于 45%，或高度超过关卡高度的 15% 而占地面积不足 10% 的部件为结构。朝上的比例按面积加权，因此房屋不会因为有屋顶而被判定为平面。
6. **否则为地面**——模糊的部件默认为地面，因为默认的近乎不可见的外壳会让关卡看起来像渲染故障。

若一个模型只有一个部件且被分类为结构，则改为地面（*单个未命名网格——按地面处理*）。

### 导航网格 {#navigation-meshes}

名为 `nav:…` 的部件（关卡导出器的 `nav:walkable`）是导航网格：即士兵可以站立的位置。它被列为地面（*导航网格——不绘制，因为它位于地面之上；点击仍能找到它*），但**不会被绘制**。它覆盖在生成它的地面之上，与地面的共面误差在厘米以内；若将其绘制为地面，两个表面会在每个像素上争夺显示：在带有烘焙地面纹理的关卡上，整个可游玩区域会显示为一块块带硬边的灰色和米色斑块，每个导航三角形一块。它会被完整保留、不做简化，以便[点击拾取](camera.md#click-to-pick)能够说明某处是否可以行走。库中的条目不保留它。

面板中的**显示部件分类 (N)**（仅对有多个部件的模型显示）会列出每个部件及其类别和原因——*由导出器标注*、*名称匹配模式*、*占地图 X%，朝上 Y%*、*朝上 Y%，占关卡高度 Z%*、*模糊——按地面处理*。若要更改某个部件，请在源模型中重命名该部件并重新导入；分类结果已被烘焙进索引缓冲区。

## 简化 {#simplification}

**简化目标**设置下一次导入的三角形预算（[`simplify.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/simplify.ts)）：

| 设置 | 三角形数 |
|---|---|
| *完整 - 不简化*（默认） | 全部 |
| *高 - 800 万三角形* | 8,000,000 |
| *中 - 300 万三角形* | 3,000,000 |
| *低 - 80 万三角形* | 800,000 |
| *轮廓 - 10 万三角形* | 100,000 |

预算按 **60% 分配给结构，40% 分配给地面**，并分别简化——结构在抽稀时最快失去其形状。水面不做简化。简化采用带二次误差度量的边坍缩（[meshoptimizer](https://github.com/zeux/meshoptimizer)，通过 WebAssembly），并在此之前先焊接重合的顶点，因此轮廓和硬边得以保留。导入说明会报告 `源 → 现有三角形数，偏差 X%`、各部件之间地面 / 结构 / 水面的划分，并且当对超过 800 万三角形的模型使用了*完整*时，会建议使用*高*（最多 3000 万）或*中*（更多）。若没有 WebAssembly，简化器不可用，导入时会说明这一点。

项目自身导出器生成的关卡已经带有预算；简化目标仅针对没有预算的原始素材而设。

## 纹理 {#textures}

若 `.glb` 的部件带有基础颜色纹理，则会以这些纹理绘制——例如，赛道导出会为每个地形瓦片和每个放置的模型各带一张纹理。

存在时默认显示地面纹理；带有纹理的结构则以**其自身的纹理实体显示**开始（路缘、护栏、轮胎墙和标志是道路的边缘，而不是需要看进去的建筑物），线框关闭，平面着色关闭。见[关卡外观](level-appearance.md)。

## 大型关卡 {#large-levels}

- 结构三角形超过 **30 万**个时，结构棱边默认关闭，面的不透明度设为 35%：若每个像素都有一条棱边，整个街区会显示为平白的白色。
- 摄像机的远裁剪面会扩展以容纳关卡（[关卡](levels.md#what-a-level-does-for-the-heat)）。

## 开发者参考 {#for-developers}

### 纹理图集 {#texture-atlas}

每张纹理都在导入工作线程中被打包进**一个图集**（[`atlas.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/atlas.ts)），因此关卡在两个后端上都只需一次绘制、一个采样器和一个纹理坐标属性：

- 每张图像以其自身大小按层排列，只有当整组图像在任一方向上都无法装入 **8192 px**（WebGPU 默认的纹理尺寸上限）时才缩小；
- 每张图像周围有 **16 像素的留白**，并且只使用该留白所保护的 5 级 mip，因此远处的标志永远不会采样到其相邻纹理；
- **可重复纹理保持可重复。** 对于 glTF 采样器为重复（glTF 默认值）且其纹理坐标超出 0..1 范围的图像——例如一面砖墙，其 UV 沿墙面从 0 变化到 40——会成为一个*瓦片*：其顶点保留自身的坐标，并带有一个 16 位的瓦片编号，着色器会在每个像素上将坐标折回瓦片的矩形内，并依据未折回的坐标来选择 mip 级别，因此接缝不会显示出来。瓦片的留白保存其对边的像素。采样器为钳制的轴保持钳制；坐标保持在 0..1 之内的图像则和以前一样绘制。含有瓦片的关卡每个顶点多占 4 字节。

### 导出器约定 {#the-exporter-contract}

无论由何种工具制作，查看器对关卡的要求如下：

- 一个自包含的 `.glb`；
- float32 的 `POSITION`，三角形图元；
- 节点名称为 `ground:*`、`structure:*` 和 `water:*`（其他名称按上述规则分类），以及导航网格的 `nav:*`（保留但不绘制）；
- 世界空间坐标，**Y 轴向上**，单位与遥测数据相同，使数据无需任何放置步骤即可位于关卡之上。
