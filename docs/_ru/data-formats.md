# Справочник форматов данных

Эта страница перечисляет каждый вид файла, который 3DHeat может открыть, и то, как должна выглядеть таблица внутри него. Таблица - это строки и столбцы, как в электронной таблице: каждая строка говорит, где что-то было и, если это известно, когда и кто.

Что вкладка «Тепловая карта» читает, столбец за столбцом, и подсказки, которые может нести файл Parquet. (Вкладка «Анализ заездов» читает файлы кругов, а вкладка «Матч» - сводки матчей; см. [Анализ заездов](race-analysis.md) и [Анализ матча](match-analysis.md).)

## Файлы {#files}

Это единый полный список файлов, которые можно загрузить. Панель **Источник** (**Файлы…**, **Папка…** или перетаскивание) принимает ровно их:

| Расширение | Что это | Читается |
|---|---|---|
| `.parquet`, `.pq` | таблица Parquet | читатель Parquet (ниже) |
| `.csv`, `.tsv`, `.txt` | текст с разделителями | читатель текста (ниже) |
| `.3dheat` | один матч в одном файле (ZIP, в котором таблица и её дополнения) | загружается как таблица, которую он содержит - [Один файл на матч](container.md) |
| `.acmi` (также `.txt.acmi`, `.zip.acmi`) | запись полёта Tacview | собственный читатель - [Записи Tacview](tacview-acmi.md) |
| `.json`, `.json.gz` | запись OCAP (в стиле Arma) | собственный читатель |
| `.gpx`, `.kml`, `.kmz`, `.nmea`, `.nma`, `.igc`, `.fit` | GPS-треки: GPX, KML/KMZ, журналы NMEA, журналы планеризма IGC, спортивные файлы FIT | собственный читатель; позиции берутся из широты и долготы |

Не загружаются как позиции: маленькие JSON-файлы, которые лежат рядом с таблицей и описывают её (имена, заканчивающиеся на `.match.json`, `.course.json`, `.level.json`, `.meta.json`, `.summary.json`, `.session.json`, `.hints.json`), и дополнительные таблицы конвертера (`<match>.events.parquet` и подобные, см. [Конвертеры](converters.md)), если только вы не выберете их отдельно. Всё остальное пропускается с указанием причины. Как фильтруется выбор, объясняется в [Загрузка файлов](loading-files.md#which-files-are-kept).

Пустые файлы пропускаются. В выборе, где есть файлы `movement*.<ext>`, загружаются только они ([Загрузка файлов](loading-files.md#which-files-are-kept)).

Данные - это **одна строка на точку**: позиция в момент времени, по желанию с тем, кто, какая группа, какая сессия, куда смотрели, и любые дополнительные столбцы. Строки событий (убийство, закладка, выстрел) могут находиться в той же таблице, что и строки позиций, и различаются по столбцу события.

## Текст с разделителями (CSV, TSV, TXT) {#delimited-text-csv-tsv-txt}

Самый маленький полезный файл, три строки:

```
x,y,z,t,player,team
10.5,2.0,-30.2,0.00,Blue 1,Blue
11.0,2.0,-29.8,0.25,Blue 1,Blue
-4.2,1.5,18.9,0.00,Red 3,Red
```

Столбцы сопоставляются сами ([Сопоставление столбцов](column-mapping.md)).

Разбирается сканером на уровне байтов, который декодирует только сопоставленные столбцы ([`csv.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/csv.ts)).

| Аспект | Правило |
|---|---|
| Заголовок | Первая непустая строка содержит имена столбцов. Пустое имя становится `column_N`. |
| Разделитель | Определяется по первым 20 непустым строкам первого 1 МиБ среди запятой, точки с запятой, табуляции и вертикальной черты по **согласованности**: побеждает разделитель, который даёт одинаковое число полей в каждой проверенной строке, затем тот, который даёт больше полей. Пробел никогда не определяется автоматически, но его можно выбрать; можно ввести любой одиночный символ ([Сопоставление столбцов](column-mapping.md#the-fields)). |
| Кавычки | RFC 4180: поля могут быть заключены в двойные кавычки, `""` внутри кавычек - это буквальная кавычка. |
| Пробелы | Начальные и конечные пробелы, табуляции и кавычки обрезаются у каждого поля. |
| Полей в строке | Не больше 4 096; больше - ошибка (*правильный ли разделитель?*). |
| Числа | Необязательный знак, цифры, необязательная `.` и десятичные знаки, необязательный порядок (`1.5e-3`). Десятичная запятая (`1,5`), разделители тысяч или завершающие единицы (`12 м`) не разбираются и считаются отсутствующими. Если в вашем файле десятичные запятые, замените их точками перед загрузкой (подойдёт поиск и замена в текстовом редакторе). |
| Числовой столбец | Столбец предлагается как числовой, когда больше 90% непустых значений первых 50 строк разбираются как числа. |
| Число строк | Оценивается до загрузки по средней длине строки первого 1 МиБ. |
| Кодировка текста | UTF-8. |

## Parquet {#parquet}

Читается с помощью [hyparquet](https://github.com/hyparam/hyparquet), блок столбца за блоком в типизированные массивы, запрашивая только сопоставленные столбцы ([`parquet.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/parquet.ts), [`ingestParquet.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestParquet.ts)).

| Аспект | Правило |
|---|---|
| Число строк | Точное, из футера, до загрузки. |
| Предпросмотр | Первые 50 строк, декодированные как объекты; их значения решают, какие столбцы выглядят числовыми. |
| Целые | `INT32`, а также `INT64` (декодируется как BigInt) становятся числами. |
| Числа с плавающей точкой | `FLOAT`, `DOUBLE`. |
| Логические | 1 и 0. |
| Строки | Используются для столбцов человека, группы, сессии и категории; строка, похожая на число, принимается для числовых ролей. |
| Логические типы `TIMESTAMP`, `DATE` | Декодируются в моменты времени (миллисекунды с 1970 года); при использовании как ось времени настройка единицы игнорируется. |
| Вложенные столбцы | Столбцы struct и list не предназначены ни для какой роли (в предпросмотре выглядят как текст JSON); не проверено. |
| Метаданные футера | Ключ `heat3d` читается как подсказки сопоставления (ниже). |

Столбец позиции, времени или взгляда, который содержит что-то кроме числа, декодируется как отсутствующий.

## Роли столбцов и типы {#column-roles-and-types}

| Роль | Тип в файле | Обязательна | Хранится как | Ограничения |
|---|---|---|---|---|
| X, Y, Z | число | две из трёх | 32-битное число с плавающей точкой, после [сопоставления осей](axes-units-and-time.md) | Строка без пригодной позиции отбрасывается. |
| Время | число в одной из [единиц времени](axes-units-and-time.md#time-units), метка времени Parquet или текст ISO-8601 | нет | 32-битные секунды с float от самой ранней строки | Сортировка отказывается выше 400 000 000 строк ([почему](memory-and-budgets.md#the-sort-ceiling)). |
| Человек | любой; со словарным кодированием | нет | 32-битный id | |
| Сессия | любой; со словарным кодированием | нет | 32-битный id | Подписи перечисляются до 100 000 сессий. |
| Группа | любой; со словарным кодированием | нет | 16-битный id | До 4 096 групп, иначе группировка отбрасывается. |
| Рыскание, тангаж | число, градусы или радианы | нет | 32-битное число с плавающей точкой, радианы | |
| Направление X, Y, Z | число | нет (все три вместе) | преобразуется в рыскание и тангаж | |
| Столбец фильтра, *диапазон* | число | нет | 32-битное число с плавающей точкой | До 4 фильтров активны одновременно. |
| Столбец фильтра, *категория* | любой; со словарным кодированием | нет | 32-битный id | До 4 096 значений, иначе столбец не сохраняется. |

Столбец Parquet `TIMESTAMP`, сохранённый как столбец фильтра, - это *диапазон* миллисекунд эпохи - ползунок, а не список.

## Столбцы итога {#outcome-columns}

Кто победил, в каждой строке, чтобы место, маршрут или приём можно было оценить по тому, как часто его сторона потом побеждала ([Доля побед](win-rate.md)). Просмотр сам сохраняет эти столбцы, показывает их первыми в [фильтрах](filters.md) на языке просмотра и читает их в [карте доли побед](win-rate.md), в [разбивке](breakdown.md) и в [статистике объёмов](volumes.md#statistics). Конвертер для игры с раундами (CS2, Valorant, Rainbow Six Siege) или с матчами (War Thunder) пишет все четыре:

| Столбец | Тип | Значение |
|---|---|---|
| `won` | 0/1 (пусто, где неизвестно) | сторона (команда) строки выиграла **раунд**; в игре без раундов - матч |
| `matchWon` | 0/1 (пусто, где неизвестно) | сторона (команда) строки выиграла **матч**; пусто, где запись не показывает конец |
| `round` | целое число, от 1 | раунд, к которому относится строка; в игре с матчами везде 1 |
| `roundEndReason` | текст | как закончился раунд (в игре с матчами - матч), словами ниже |

`won` и `matchWon` относятся к стороне строки: строки игрока T несут итог стороны T, строки юнита AI - итог его команды; строки, не относящиеся ни к одной стороне, оставляют их пустыми. Сторона, которая меняется в перерыве, сохраняет свой `matchWon` и берёт `won` каждого раунда так, как она его сыграла. Ничья - это 0 для обеих сторон.

Причины конца общие для всех игр, чтобы один фильтр работал для всех (собственное слово игры сопоставляется, где возможно, [`data/outcome.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/outcome.ts)):

| `roundEndReason` | Значение | Игры |
|---|---|---|
| `elimination` | выбыли все игроки одной стороны | CS2, Valorant, Rainbow Six Siege |
| `bomb` | бомба (spike, цель обезвреживающего) взорвалась | CS2, Valorant, Rainbow Six Siege |
| `defuse` | бомба (spike) обезврежена | CS2, Valorant, Rainbow Six Siege |
| `time` | время раунда вышло; War Thunder: решено, когда у обеих сторон ещё оставались очки | все |
| `surrender` | сторона сдалась | CS2, Valorant, Rainbow Six Siege |
| `draw` | без победителя | CS2 |
| `objective` | цель взята или удержана (заложник выведен, зона защищена) | Rainbow Six Siege |
| `capture` | очки истекли, пока победитель удерживал зоны захвата | War Thunder |
| `tickets` | очки потеряны из-за убийств | War Thunder |
| `destruction` | последняя техника потеряна сразу, возродиться больше некому | War Thunder |
| `other` | всё остальное | |

Указывайте их и в списке `extra` подсказок `heat3d`, как любой другой столбец. Имена столбцов `win`, `round_won`, `match_won`, `end_reason` и `win_reason` читаются как те же столбцы.

## Подсказки `heat3d` {#the-heat3d-hints}

Файл Parquet может нести собственные инструкции чтения в метаданных ключ-значение футера, под ключом **`heat3d`**, как JSON-объект ([`MappingHints`](https://github.com/Holdi601/3DHeat/blob/main/src/data/automap.ts)). Просмотрщик применяет их поверх собственных догадок, когда файл первый в выборе; каждая запись необязательна, и каждый результат всё равно показывается и редактируется на панели [Сопоставление столбцов](column-mapping.md#the-heat3d-hints-in-a-parquet-footer). Всё, что не разбирается как JSON-объект, игнорируется.

### Схема {#schema}

```
{
  "columns": {
    "x": string, "y": string, "z": string,          column names for the position
    "time": string,                                  the time column
    "timeUnit": "seconds" | "milliseconds" | "microseconds" | "nanoseconds"
              | "unix_seconds" | "unix_milliseconds" | "iso8601",
    "personId": string, "teamId": string, "sessionId": string,
    "lookMode": "none" | "yawPitch" | "vector",
    "yaw": string, "pitch": string,
    "dirX": string, "dirY": string, "dirZ": string,
    "angleUnit": "degrees" | "radians",
    "extra": [string, ...]                           filter columns to keep, most useful first
  },
  "axes": {
    "up": "y" | "z",
    "flipX": boolean, "flipY": boolean, "flipZ": boolean,
    "scale": number                                  must be > 0
  },
  "entity": {
    "size": number                                   size of one tracked thing in file units, > 0
  }
}
```

| Запись | Применяется, когда | Действие |
|---|---|---|
| `columns.x` … `columns.dirZ`, `time`, `personId`, `teamId`, `sessionId` | названный столбец есть в файле | Задаёт эту роль. |
| `columns.timeUnit` | это одна из семи единиц | Задаёт единицу времени. |
| `columns.angleUnit` | `"degrees"` или `"radians"` | Задаёт единицу угла. |
| `columns.lookMode` | `"vector"` при заданных dirX, dirY и dirZ; `"yawPitch"` при заданном yaw; `"none"` | Задаёт режим взгляда. |
| `columns.extra` | это массив | Заменяет автоматический список фильтров, оставляя только существующие столбцы, не используемые ролью; каждый становится *диапазоном*, если выглядел числовым в предпросмотре, иначе *категорией*. Без него автоматический список сохраняется за вычетом любого столбца, который подсказка назначила роли. |
| `axes.up` | `"y"` или `"z"` | Ось вверх. |
| `axes.flipX/Y/Z` | логическое значение | Отражения. |
| `axes.scale` | число > 0 | Масштаб единиц. |
| `entity.size` | число > 0 | [Размер объекта](sessions-persons-groups.md#entity-size) (умножается на масштаб единиц при загрузке). Единственный способ его задать. |

### Пример {#example}

Выдуманный экспорт шутера: ось Z вверх, сантиметры, левосторонний мир, игроки шириной около 72 см.

```json
{
  "columns": {
    "x": "pos_x", "y": "pos_y", "z": "pos_z",
    "time": "t", "timeUnit": "seconds",
    "personId": "player", "teamId": "side", "sessionId": "round_id",
    "lookMode": "yawPitch", "yaw": "view_yaw", "pitch": "view_pitch", "angleUnit": "degrees",
    "extra": ["event", "weapon", "map"]
  },
  "axes": { "up": "z", "flipY": true, "scale": 0.01 },
  "entity": { "size": 72 }
}
```

### Запись {#writing-it}

С помощью pyarrow пользовательские метаданные схемы записываются в метаданные ключ-значение файла:

```python
import json
import pyarrow as pa
import pyarrow.parquet as pq

table = pa.table({...})
hints = {"columns": {"x": "pos_x", "y": "pos_y", "z": "pos_z", "time": "t"}, "axes": {"up": "z"}}
meta = dict(table.schema.metadata or {})
meta[b"heat3d"] = json.dumps(hints).encode("utf-8")
pq.write_table(table.replace_schema_metadata(meta), "movement.parquet")
```

`npm run inspect -- file.parquet` выводит схему файла - быстрый способ проверить имена столбцов, на которые ссылаются подсказки.

## Что пишет вкладка «Тепловая карта» {#what-the-heatmap-tab-writes}

Ничего не записывается обратно в данные. Результаты такие:

- видео в формате WebM (VP9 или VP8) - [Путь камеры и видео](camera-path-and-video.md);
- положение камеры, скопированное в буфер обмена как текст - [Камера](camera.md#pose);
- уровни, сохранённые в [библиотеке уровней](level-library.md) браузера.
