# Пребывание в памяти GPU

У видеокарты есть лишь определённый объём памяти. Если ваши данные не помещаются, просмотрщик показывает то, что помещается, и говорит об этом: в оверлее статистики появляется янтарная строка **Не в памяти** с числом строк, которые не вошли. Укороченный набор данных, который выглядит полным, — худшая ошибка, какую может допустить инструмент анализа, поэтому эта строка никогда не скрывается.

![Оверлей статистики с янтарной строкой Не в памяти](../assets/img/en/gpu-memory-not-resident.webp)

Чтобы вошло больше, поднимите бюджет GPU в разделе **Бюджеты ресурсов** и загрузите данные снова ([Память и бюджеты](memory-and-budgets.md#raising-the-gpu-budget)), сначала сузьте данные или используйте видеокарту с большей памятью.

## Для разработчиков {#for-developers}

### Как строки хранятся на GPU {#how-rows-are-stored-on-the-gpu}

Строки загружаются один раз, когда приходит набор данных, **блоками** по 8 388 608 строк (2²³) ([`CHUNK_ROWS`](https://github.com/Holdi601/3DHeat/blob/main/src/render/types.ts)). Каждый блок квантуется относительно своей собственной ограничивающей рамки и промежутка времени:

| Данные | Формат | Байт на строку |
|---|---|---|
| Позиция X, Y, Z и идентификатор группы | четыре 16-битных беззнаковых целых (RGBA16UI в WebGL2); X, Y, Z внутри ограничивающей рамки блока | 8 |
| Время и время жизни (когда в наборе есть и время, и персона) | два 16-битных беззнаковых целых (RG16UI): время внутри промежутка времени блока; время жизни, где 65 535 означает «следующего отсчёта нет» | 4 |

Ограничивающие рамки каждого блока — это то, что делает 16 бит достаточными: блок обычно покрывает часть карты, поэтому шаг квантования получается намного меньше сантиметра на карте шириной в километры, гораздо ниже шума настоящей телеметрии. Идентификатор группы в четвёртом канале ничего не стоит — поэтому групп может быть не больше 4 096 ([Группы](sessions-persons-groups.md#limits)).

В WebGL2 каждый блок — это текстура шириной 8 192 текселя, дополненная до целых строк текстуры; к строкам обращаются из `gl_VertexID` через текстуру индексов блоков, которая обновляется каждый кадр. В WebGPU это буферы хранения.

Дополнительная память GPU на каждую строку, выделяется по мере использования:

- каждый активный [фильтр](filters.md) столбца: 4 байта на строку (значения 32-битной с плавающей точкой или идентификаторы категорий), загружаются по блокам при первом использовании фильтра;
- [линейное тепло](line-heat.md): 8 байт на строку (начало каждого отрезка, квантованное внутри ограничивающей рамки данных, и его флаги), пока включён режим линий.

Кроме того, цели рендеринга: цвет и глубина сцены, цель тепла и её рабочая копия (четыре канала в [Тепло команд](team-heat.md)), слои послойного удаления для [перекрытия](depth-and-culling.md), а также геометрия уровня.

### Бюджет соблюдается при загрузке {#the-budget-is-enforced-at-upload}

WebGL принимает выделения, которые не может обслужить, и затем либо теряет контекст, либо переходит на системную память с катастрофической стоимостью, поэтому бюджет GPU соблюдается при загрузке набора данных ([`setDataset`](https://github.com/Holdi601/3DHeat/blob/main/src/render/webgl2/renderer.ts)):

- блоки загружаются по порядку (то есть по времени), пока помещаются;
- первый блок, который не помещается, загружается **частично** — столько целых строк текстуры, сколько вмещает оставшийся бюджет, — а не совсем не загружается, поэтому бюджет, который не может вместить блок целиком, всё равно показывает столько, сколько может; и поскольку строки упорядочены по времени, показанная часть — связный отрезок времени;
- всё после этого **не в памяти**.

Нехватка не скрывается: оверлей статистики показывает строку **Не в памяти** с числом строк, которые не поместились, янтарным цветом, всякий раз когда оно больше нуля. Обрезанный набор данных, который выглядит полным, — худший сбой, какой может быть у инструмента анализа. [Проверка размера](memory-and-budgets.md#the-fit-check) перед загрузкой призвана этот случай предотвратить.

Бюджет, который использует рендерер, — это бюджет GPU из **Бюджеты ресурсов**, та же цифра, что использует проверка размера, — выше определённой цифры тоже, вплоть до предела ползунка (см. [Повышение бюджета GPU](memory-and-budgets.md#raising-the-gpu-budget)). Он применяется, когда загружается набор данных; если изменить его позже, это вступит в силу при следующей загрузке.
