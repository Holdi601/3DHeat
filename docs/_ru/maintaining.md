# Поддержка документации

Эта страница для тех, кто ведёт просмотрщик и этот сайт. Здесь перечислены шаги, которые держат страницы, картинки и переводы верными после изменений.

Этот сайт проверяется снова при **каждом выпуске** и всякий раз, когда что-то сильно меняется: сочетания клавиш, путь по интерфейсу, настройки, форматы файлов. Контрольный список:

1. **Пересоздать справочные страницы**: `node tools/docs-refs.mjs` (и `--lang <код>` для каждого языка). `node tools/docs-refs.mjs --check` завершается с ошибкой, если страница устарела.
2. **Пересоздать скриншоты** по [демо-данным](demo-data.md). Используйте компьютер или контейнер с регионом en-US, чтобы числа читались как `0.35`, а не `0,35` (поля чисел следуют региону браузера, пока его не изменили). Создайте демо-данные командой `node tools/demo-data.mjs`, запустите сервер разработки на порту 5321 **без** локального пакета фигур, `HEAT3D_FIGURE_PACK=none npx vite --port 5321 --strictPort --host 127.0.0.1`, затем выполните `node tools/docs-shots.mjs --lang <код>`. Посмотрите каждую картинку: там должны быть только имена демо (*Demo Valley*, *Blue 1*, *Red 3* ...), никаких настоящих карт, игроков или записей.
3. **Перечислить изменения** с последнего тега выпуска: `git log --oneline <последний тег>..HEAD`, и раздел **Docs** в `CHANGELOG.md`, который сопоставляет каждую функцию со страницей. Каждой новой функции нужна страница или раздел, а также картинка, если она видна на экране.
4. **Независимая проверка** английских страниц кем-то, кто их не писал, для трёх читателей: новичка, восьмилетнего ребёнка, эксперта. Полны ли шаги и в правильном ли порядке, те ли это слова, что в интерфейсе, актуальны ли картинки, верны ли подписи на диаграммах?
5. **Исправить то, что нашла проверка.**
6. **Перевести заново изменённые страницы** по их хешу исходника, затем провести проверку для каждого языка. См. `tools/docs-translate.md`.
7. **Проверить на конфиденциальные термины** изменённые файлы и убедиться, что на картинках нет ничего, кроме демо-данных.
8. **Публиковать** только когда выпуск одобрен.

Та же проверка охватывает сайты документации связанных репозиториев (см. страницу [Главная](index.md#related-repositories)).

## Инструменты в exporters/ {#the-tools-under-exporters}

Инструменты вокруг просмотрщика — отдельные открытые проекты, у каждого своя лицензия MIT, свои выпуски, вики и проверка обновлений; в этом репозитории они закреплены как git-подмодули:

| Папка | Репозиторий |
|---|---|
| `exporters/gamefiles/` | [3DHeat-GameFiles](https://github.com/Holdi601/3DHeat-GameFiles) — трассы и уровни из архивов самих игр |
| `exporters/gamecapture/` | [3DHeat-GameCapture](https://github.com/Holdi601/3DHeat-GameCapture) — записи телеметрии кругов; уровни по видео игры |
| `exporters/unreal/` | [3DHeat-UnrealExporter](https://github.com/Holdi601/3DHeat-UnrealExporter) — плагин для Unreal Editor |
| `exporters/cs2/` | [3DHeat-CS2](https://github.com/Holdi601/3DHeat-CS2) — демо и карты CS2 |
| `exporters/watcher/` | [3DHeat-Watcher](https://github.com/Holdi601/3DHeat-Watcher) — записывает игру в фоне |

**Закреплено** значит, что этот репозиторий хранит один точный коммит каждого инструмента. Копия просмотрщика получает эти коммиты:

```bash
git clone --recursive https://github.com/Holdi601/3DHeat
# или, после обычного клонирования:
git submodule update --init
```

Оба пути обновления выше после загрузки выполняют `git submodule update --init`, поэтому инструменты следуют за просмотрщиком до коммитов, которые закрепляет его новейшая версия, — а не до собственных новейших коммитов инструментов. Более новый выпуск инструмента доходит до просмотрщика, когда перемещается закрепление здесь: изменения инструмента сначала коммитятся и отправляются в его собственной папке (в его собственном репозитории), затем новое закрепление коммитится здесь. Каждый инструмент также проверяет собственные более новые выпуски; это описано в его собственном репозитории.
