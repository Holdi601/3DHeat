# Изображения карт

Изображение карты — это плоская картинка: миникарта, спутниковый снимок, план этажа. Она лежит под вашими данными, чтобы было видно, где находится тепло. Вы говорите просмотрщику, где картинка должна стоять: закрепляете на ней две точки и ставите каждую в место в мире (это «якоря»).

## Загрузить и разместить изображение карты {#load-and-place-a-map-image}

1. Сначала загрузите данные ([Загрузка данных](getting-data-in.md)).
2. В **Фон / уровень** нажмите **Изображение карты…** и выберите картинку. Она растянется по области данных.
3. Нажмите **Подогнать под границы данных**, если картинку сдвинули. Якорь 1 встанет в левый верхний угол картинки, якорь 2 — в правый нижний, на края данных.
4. Если тепло не совпадает с картинкой, выберите два ориентира, далеко разнесённых друг от друга (например, два противоположных угла здания или два перекрёстка). Найдите пиксель каждого ориентира на картинке и его позицию в мире (наведите курсор с [линейкой](measure.md), чтобы прочитать **X** и **Z**).
5. Введите их в **Размещение**: для **Якоря 1** — **px**, **py**, **мир X**, **мир Z** ориентира; то же самое для **Якоря 2**.
6. Проверьте: трек или горячая точка, о которой вы знаете, что она на дороге, должен теперь лежать на этой дороге. Меняйте числа, пока так не станет.

![Раздел «Размещение» с двумя якорями и теплом, нарисованным поверх картинки карты](../assets/img/en/map-images-placement.webp)

Два ориентира должны отличаться и по столбцу пикселя, и по строке пикселя. Иначе панель пишет *Два якоря лежат в одной строке или столбце пикселей*.

## Загрузка {#loading}

Любой формат изображения, который умеет открыть браузер. Изображение, у которого длинная сторона больше **8192 px**, уменьшается до 8192 (это наибольшая сторона, которую просят держать GPU). Панель пишет *Уменьшено с W×H до w×h*.

При загрузке изображение растягивается по границам X–Z данных (или по ±1000 единиц, если данных нет), север вверху, на самой низкой Y данных. По умолчанию: **Непрозрачность** 100%, **Яркость** 0,7, **Обесцветить** 100%, **Отразить север/юг** включено. Картинка обесцвечена и приглушена, потому что её задача — помочь найти горячую точку, а не спорить с ней.

## Элементы управления {#controls}

| Элемент | По умолчанию | Диапазон | Значение |
|---|---|---|---|
| **Непрозрачность** | 100% | 0–100% | |
| **Яркость** | 0,7 | 0–2 (прокрутка 64) | |
| **Обесцветить** | 100% | 0–100% | Серый фон, насыщенное тепло. Цвет на карте спорит с цветом в данных. |
| **Отразить север/юг** | включено | | Какая строка изображения соответствует максимальной Z мира. Если переключить при загруженных данных, якоря заново подгоняются под границы данных. |
| **Размещение**: Якорь 1, Якорь 2 | углы изображения на границах данных | | Каждый якорь — это пиксель на изображении, **px** (слева, от 0 до ширины) и **py** (сверху, от 0 до высоты), и координата мира, в которой он стоит: **мир X** и **мир Z**. Масштаб и смещение вычисляются по паре. |
| **Подогнать под границы данных** | | | Ставит якорь 1 в левый верхний угол изображения, а якорь 2 — в правый нижний, на границы данных X–Z. Это отправная точка для точного размещения. Нужен набор данных. |
| **Высота** | самая низкая Y данных | от min Y данных − 500 до max Y + 500 (прокрутка до max Y + 100 000) | Высота плоскости карты. Поставьте её чуть ниже данных, чтобы карта ничего не закрывала. |

В строке с названием показано `ширина×высота px · x × z м/px`: мировой размер одного пикселя по каждой оси.

## В сцене {#in-the-scene}

Изображение — это одна текстурированная четырёхугольная плоскость на высоте. При полной непрозрачности оно записывает глубину и участвует в [перекрытии](depth-and-culling.md) как земля. При непрозрачности ниже 100% оно смешивается и глубину не записывает, поэтому ничего не перекрывает. [Линейка](measure.md) измеряет по его плоскости. [Библиотека уровней](level-library.md) хранит уровень-изображение вместе с его якорями.

## Карта Dota 2 {#dota-2-map}

**Карта Dota 2** рядом с **Изображение карты…** загружает рисунок текущей карты Dota 2, который [OpenDota](https://www.opendota.com) показывает на страницах матчей, и размещает его под таблицами, которые [Watcher](https://github.com/Holdi601/3DHeat-Watcher) записывает из реплеев Dota 2 ([`dotaMap.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/tactics/dotaMap.ts)). Изображение загружается с opendota.com при нажатии кнопки и не входит в 3DHeat. Рисунок самого свежего патча берётся из списка OpenDota, а рисунок 7.40 — если список не удаётся прочитать.

| | |
|---|---|
| Источник | `opendota.com/assets/images/dota2/map/detailed_<patch>.webp`, 900×900 px |
| Размещение | Калибровка OpenDota: изображение занимает мировые единицы Dota от -8192 до 8064 по обеим осям (ячейки по 128 единиц, от 64 до 191), север наверху. При осях таблицы реплея (Z вверх, Y отражена) это мировой X от -8192 до 8064 и мировой Z от -8064 до 8192. Около 18 единиц на пиксель. |
| Высота | 0. Герои стоят на высоте от 0 до примерно 600. |
| Вид | Яркость 0,8, обесцвечивание 50%. |

Проверено на публичном реплее матча патча 7.40: треки каждого героя идут по нарисованным линиям, а башни, казармы и древние, которые ставит реплей, попадают на нарисованные базы. Вид **Сверху** показывает карту с севером внизу экрана, как и любую таблицу с Z вверх и отражённой Y.

Рисунок сделан OpenDota по карте Valve; Valve не одобряет 3DHeat.

### 3D-карта {#the-3d-map}

Если Dota 2 установлена, отдельный инструмент [3DHeat Dota](https://holdi601.github.io/3DHeat-Ext-Dota/) (`heat3d-dota-maps level -o dota.glb`; его запускает и команда [`dota-map`](https://holdi601.github.io/3DHeat-Watcher/dota-map.html) из Watcher) создаёт карту в 3D из собственных файлов игры: земля, скалы, вода, деревья и здания, в единицах и осях таблиц из повторов. Загрузите файл один раз через **3D-модель…**: программа узнаёт его по частям (`ground:terrain`, `structure:tower`, `structure:ancient`, `structure:tree`; `isDotaLevel` в `dotaMap.ts`), сразу кладёт в [библиотеку уровней](level-library.md), заменяя более старую, и сообщает об этом. С этого момента **Карта Dota 2** загружает эту 3D-карту из библиотеки, а не скачивает рисунок; если в библиотеке её нет, кнопка скачивает рисунок и объясняет, как сделать 3D-карту. Файл берётся из вашей собственной установки и остаётся на вашем компьютере.

## Для разработчиков {#for-developers}

### Как якоря размещают изображение {#how-the-anchors-place-the-image}

Из [`mapQuadFromAnchors`](https://github.com/Holdi601/3DHeat/blob/main/src/render/level.ts), с якорями *a* и *b*:

```
scaleX = (b.worldX - a.worldX) / (b.px - a.px)
scaleZ = (b.worldZ - a.worldZ) / (b.py - a.py)
pixel (0, 0) sits at  (a.worldX - a.px × scaleX,  a.worldZ - a.py × scaleZ)
```

Два якоря задают масштаб и смещение по каждой оси отдельно. Поэтому карту можно растянуть по-разному по X и Z, но нельзя повернуть. Якоря должны отличаться по **обеим** координатам пикселя. Если они совпадают в строке или в столбце, масштаб не вычисляется, карта не рисуется, и панель пишет *Два якоря лежат в одной строке или столбце пикселей*.
