# Один файл на матч: `.3dheat`

Файл `.3dheat` — это весь матч в одном файле, чтобы его копировать, хранить или передавать. Чтобы его открыть, просто перетащите файл на панель «Источник».

```
match.3dheat   (a ZIP file)
  manifest      what the match is, and the list of everything inside
  table         the positions (Parquet)
  match.json    the match document
  sidecars      what the converter kept whole (events, messages, ...)
```

Раньше конвертированный матч был несколькими файлами рядом: таблица `<match>.parquet`, документ матча `<match>.match.json` и служебные файлы `<match>.<what>.parquet` ([Конвертеры сохраняют всё](converters.md)). Файл `.3dheat` содержит их все в одном: один повтор, один файл — чтобы его копировать, хранить или передавать.

Он устроен так, что загрузка тысячи таких файлов так же быстра, как загрузка отдельных таблиц, и так, что будущие конвертеры смогут положить в него гораздо больше без нового формата.

## Загрузка {#loading-one}

Везде, где загружается файл или папка, загружается и `.3dheat`, а папка может смешивать контейнеры и отдельные файлы:

| Где | Что читается из контейнера |
|---|---|
| **Тепловая карта**, панель «Источник» (файлы, папка, перетаскивание) | его таблицы, как если бы это были отдельные `<match>.parquet` |
| **Тепловая карта → Много матчей сразу** (Файлы, Папка, Добавить папку) | его таблицы, которые читают на месте рабочие потоки загрузчика |
| **Матч**, вкладка (Загрузить или перетащить на вид) | документ матча |
| **Доска тактики**, телеметрия | его таблицы |

Открытие контейнера читает два небольших куска: его каталог в конце и его манифест в начале. Ничего из таблицы не читается, пока загрузчик её не прочитает. Служебные файлы и документ матча читаются, только когда что-то их запрашивает. Папка, в которой один и тот же матч лежит дважды — отдельно и упакованным, — загружает его один раз.

## Упаковка и распаковка {#packing-and-unpacking}

Новые конвертации по умолчанию пишут контейнеры: конвертер War Thunder (`heat3d-wt-replay`), конвертер CS2 (`heat3d_cs2 demos`) и инструмент Tacview (`node tools/acmi-to-parquet.mjs`). `--loose` оставляет отдельные файлы.

Матчи, сконвертированные раньше или другими инструментами, упаковываются так:

```
node tools/3dheat-pack.mjs <folder>... [--delete-loose] [--jobs N] [--settle MIN]
node tools/3dheat-pack.mjs unpack <folder|file.3dheat>... [--delete-container]
node tools/3dheat-pack.mjs verify <folder|file.3dheat>...
node tools/3dheat-pack.mjs update <file.3dheat> [--add <role>[:<name>]=<file>]... [--remove <name>]...
node tools/3dheat-pack.mjs repack <folder|file.3dheat>...
```

- **pack** находит в папках каждую таблицу `<match>.parquet` вместе с файлами, которые к ней относятся, и записывает `<match>.3dheat` рядом с ними. Уже упакованный матч пропускается. Каждый контейнер перечитывается целиком (sha256, размер, CRC и футер Parquet каждого члена), прежде чем что-либо ещё произойдёт. Отдельные файлы удаляются только с `--delete-loose`, а для матча, упакованного раньше, — только если они побайтно совпадают с тем, что лежит в контейнере. Матч, у которого какой-то файл менялся за последние `--settle` минут (по умолчанию 10), не трогается: конвертер может ещё его писать.
- **unpack** записывает члены обратно как отдельные файлы рядом с контейнером.
- **update** добавляет или заменяет члены, не переписывая уже лежащие в контейнере таблицы (см. ниже).
- **repack** переписывает контейнер целиком, отбрасывая то, что оставили обновления.

## Формат {#the-format}

`.3dheat` — это архив ZIP (его открывает любой инструмент для ZIP) со следующими правилами:

1. **`manifest.json` — первый член**, когда пишется контейнер, и он есть всегда. Его находят через центральный каталог ZIP, поэтому после `update` он может оказаться дальше в файле.
2. **Члены, которые читаются по диапазону байтов или уже сжаты, хранятся без сжатия** (метод ZIP 0): Parquet, Arrow, изображения, модели, аудио, видео, непрозрачные блобы. Хранимый член — один непрерывный диапазон байтов контейнера, поэтому читатель читает футер таблицы и её фрагменты столбцов на месте, через `File.slice` в браузере или HTTP-запрос диапазона, точно так же, как читал бы отдельный файл.
3. **Текст сжимается** (метод 8): JSON, CSV, обычный текст. Они небольшие и читаются целиком.
4. Имена в UTF-8 (флаг бит 11), относительные, с разделителем `/`, без `..`; они могут содержать папки (`analysis/heat.json`). Отдельный файл при упаковке сохраняет своё имя, поэтому распаковка возвращает те же файлы.
5. Члены больше 4 ГиБ или контейнеры из более чем 65 535 членов используют ZIP64, как обычно. Писатели не ставят дескрипторов данных после членов.

Члены, которые конвертеры записывают сегодня, в таком порядке:

| Роль | Член | Хранится без сжатия |
|---|---|---|
| `table` | `<match>.parquet` | да |
| `match` | `<match>.match.json` | нет (сжат) |
| `messages`, `flight`, `events`, `effects`, `objectives`, `packets`, `props`, `strings`, ... | `<match>.<role>.parquet` | да |
| `summary` | `<match>.summary.json`, сводка индекса массового анализа ([Массовый анализ](mass-analysis.md)), добавляется `tools/3dheat-summarize.mjs` | нет (сжат) |

Таблица идёт сразу за манифестом, поэтому первое чтение начала файла читателем захватывает и манифест, и локальный заголовок таблицы.

### Манифест {#the-manifest}

```json
{
 "format": "3dheat",
 "format_version": "1.0",
 "game": "warthunder",
 "source": "client replay",
 "converter": { "name": "heat3d-wt-replay", "version": "0.2.0" },
 "match": "<map>_RB_<date>_<session>",
 "map": "<map>",
 "mode": "RB ground",
 "started": "2026-01-01T12:00:00+00:00",
 "created": "2026-01-01T13:00:00.000Z",
 "roles": { "table": "<match>.parquet", "match": "<match>.match.json", "flight": "<match>.flight.parquet" },
 "members": [
  {
   "name": "<match>.parquet",
   "role": "table",
   "media_type": "application/vnd.apache.parquet",
   "compression": "stored",
   "bytes": 1738575,
   "rows": 38105,
   "sha256": "<64 hex digits>",
   "schema": { "id": "heat3d-table", "version": "1" }
  }
 ]
}
```

| Поле | Значение |
|---|---|
| `format` | всегда `3dheat` |
| `format_version` | `major.minor` (ниже) |
| `game`, `source`, `converter`, `match`, `map`, `mode`, `started` | что за матч и что его создало; `null`, где неизвестно |
| `created`, `updated` | когда записан и когда последний раз обновлён (`updated` появляется только после обновления) |
| `roles` | каждая роль — имя её первого члена: быстрый указатель |
| `members` | каждый член, кроме манифеста: полный список и тот, которому доверяет читатель |
| `matches` | необязательно: матчи контейнера, в котором их несколько (ниже) |
| `references` | необязательно: файлы, которые контейнеру нужны, но которых он не содержит |
| `extensions` | необязательно: собственные метаданные конвертера |

Каждый член:

| Поле | Значение |
|---|---|
| `name` | его путь в контейнере |
| `role` | для чего он (ниже) |
| `media_type` | `application/vnd.apache.parquet`, `application/json`, `image/png`, `model/gltf-binary`, `audio/ogg`, `application/octet-stream`, ... |
| `compression` | `stored` или `deflate` |
| `bytes` | его размер, несжатый |
| `sha256` | от его байтов, несжатых |
| `rows` | число строк таблицы |
| `schema` | соглашение, которому он следует, `{ "id", "version" }`: собственные `format` и `version` документа (`heat3d-wt-replay-match` 2), `heat3d-table` для таблицы, которую просмотрщик читает по её футеру `heat3d`, `heat3d-acmi-table` для инструмента Tacview |
| `match` | в контейнере из нескольких матчей — `matches[].id`, к которому он относится |

### Задумано для роста {#made-to-grow}

Формат рассчитан на то, чтобы нести гораздо более богатые повторы, чем сегодняшние, не ломая то, что читает их сейчас:

- **Версии.** `format_version` — это `major.minor`. Читатель читает каждую минорную версию своего major и игнорирует каждое поле, которое не знает. Минор растёт, когда что-то добавляется; major — только когда меняется раскладка так, что старый читатель прочитал бы её неверно (член больше не хранится, манифест вынесен из архива). Собственное соглашение каждого члена версионируется отдельно, в его `schema`, поэтому новая раскладка таблицы или новая версия документа не требует новой версии контейнера. Первые записанные контейнеры говорили `"version": 1`; читатели принимают это как 1.0.
- **Роли открыты.** Роль — любая строка. Читатели используют роли, которые знают, и сохраняют остальные: неизвестная роль перечисляется, но никогда не отвергается, а `update` и `repack` переносят её без изменений. У роли может быть много членов: несколько таблиц (треки по юнитам, телеметрия на других частотах), события, голос, синхронизация видео, ссылки на уровни, переопределения фигур, результаты анализа. Имена могут содержать папки.
- **Любой носитель.** Член может быть чем угодно, что имеет тип носителя: Parquet, JSON, Arrow, миниатюры PNG или JPEG, модели glTF, аудио, сырые блобы.
- **Несколько матчей.** Сессия или турнир могут уместиться в один контейнер: `matches` перечисляет их (`{ "id", "map", "mode", "started", ... }`), а каждый член называет свой `match`. Просмотрщик загружает каждый член с ролью `table`.
- **Ссылки.** Файлы, которые контейнеру нужны, но которых он не содержит, например уровень для одного из них, перечисляются в `references` по имени и sha256 (`{ "kind": "level", "name": "...", "sha256": "..." }`), так что нужный файл находится и проверяется, не копируясь в каждый матч.
- **Расширения.** `extensions` хранит собственные метаданные конвертера под его собственным ключом `"<vendor>/<name>": { ... }`, поэтому два конвертера никогда не сталкиваются, и ничего не нужно добавлять в общие поля.
- **Обновление на месте.** `update` добавляет или заменяет члены, не переписывая большие хранимые таблицы: новые члены и новый манифест дописываются после конца контейнера, за ними идёт новый центральный каталог. То, что заменено, остаётся как неиспользуемые байты до `repack`. Каждый член и каждое поле манифеста, известные или нет, сохраняются. Обновление, которое не удалось, откатывается к контейнеру таким, каким он был.

Тесты просмотрщика удерживают его к этому: контейнер формата 1.7 с неизвестной ролью, полем члена, расширением и аудиочленом в папке загружается и переживает обновление и repack со всем на месте; контейнер major 2 отклоняется.

## Писатели {#writers}

- Node: [`tools/container.mjs`](https://github.com/Holdi601/3DHeat/blob/main/tools/container.mjs) (запись, чтение, проверка, обновление, repack), его используют инструмент упаковки и инструмент Tacview.
- Python: `container.py`, около 140 строк на стандартном `zipfile`, один и тот же файл в каждом конвертере (`heat3d_ext_warthunder/container.py`, `heat3d_cs2/container.py`), поэтому ни один конвертер не зависит от другого. Новый конвертер просто копирует его.
- Просмотрщик читает через [`src/data/container.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/container.ts).
