# Загрузка файлов

Эта страница показывает, как передать 3DHeat свои файлы и что он с ними делает. Перетащите папку, и он выберет файлы, которые содержат позиции, и объединит их в одну картину.

1. Откройте **Источник** вверху боковой панели вкладки Тепловая карта.
2. Перетащите файлы или папку в зону перетаскивания или нажмите **Файлы…** или **Папка…**.
3. Прочитайте строку выбора и **Оценку памяти** (см. картинку ниже).
4. Нажмите **Загрузить**.

![Панель «Источник» после перетаскивания папки с десятью матчами: 1 — строка выбора, 2 — оценка памяти, которая подходит, 3 — кнопка «Загрузить 10 файлов»](../assets/img/en/loading-files-source.webp)

*После перетаскивания папки 3DHeat сообщает, что он в ней нашёл и подходит ли это.*

Файлы загружаются на панели **Источник** вверху боковой панели вкладки «Тепловая карта». Всё, что выбрано сразу, становится **одним** набором данных.

## Выбор файлов {#choosing-files}

| Элемент управления | Что делает |
|---|---|
| **Перетащите сюда файлы или папку** (зона перетаскивания) | Перетащите любую смесь файлов и папок. Папки обходятся рекурсивно. Щелчок по зоне перетаскивания открывает тот же выбор, что и **Файлы…**. |
| **Один файл…** | Выбор одного файла. |
| **Файлы…** | Выбор нескольких файлов. |
| **Папка…** | Выбор папки (выбор `webkitdirectory` в браузере); предлагается каждый файл в дереве папки. |

Выбор принимает типы файлов из [списка загружаемых файлов](data-formats.md#files). Коротко: `.parquet`/`.pq` читаются как Parquet, `.csv`/`.tsv`/`.txt` — как текст с разделителями, `.acmi` (Tacview), OCAP `.json`/`.json.gz` и GPS-форматы (GPX, KML, KMZ, NMEA, IGC, FIT) идут через свои читалки, а контейнеры `.3dheat` загружаются как таблицы, которые в них лежат ([Один файл на матч](container.md)). Контейнер, который нельзя прочитать, пропускается с пометкой *не csv/parquet файл*.

Перетащенные папки обходятся на глубину до 12 уровней и не больше 20 000 файлов — защита от циклических ссылок и бесконечных деревьев.

## Какие файлы остаются {#which-files-are-kept}

Прежде чем что-либо читать, выбор фильтруется ([`filterDataFiles`](https://github.com/Holdi601/3DHeat/blob/main/src/data/filePick.ts)):

- Файл с другим расширением пропускается: *не csv/parquet файл*.
- Файл размером 0 байт пропускается: *пустой (0 байт)*.
- **Служебные файлы конвертера** — сырые данные, которые конвертер хранит рядом с таблицей матча: `<match>.messages.parquet`, `.events.parquet`, `.raw.parquet` и другие, перечисленные в [Конвертеры сохраняют всё](converters.md), — пропускаются: *служебный файл конвертера*. Чтобы открыть один из них, выберите или перетащите его отдельно (или выбор из одних служебных файлов): такой выбор загружает их, как любые таблицы. JSON рядом с таблицей (`.match.json`, `.course.json`, `.level.json`, `.meta.json`, `.summary.json`, `.session.json` и `.hints.json`) никогда не предлагается как позиции.
- **Правило файла движения.** Если какой-либо файл выбора назван `movement*.parquet`, `movement*.csv` (и с другими расширениями) — `movement.parquet`, `movement_1.parquet` и так далее, — то все остальные файлы данных пропускаются: *не файл движения, а в этой папке есть файлы движения*. Экспорты телеметрии часто содержат одну таблицу позиций рядом с десятками таблиц без позиций, и рисовать можно только первую. Папка без файлов движения загружает все свои файлы данных. Пример: в папке `movement_1.parquet`, `kills.parquet` и `shop.parquet` загружается `movement_1.parquet`; два других перечисляются как пропущенные. Пример: в папке `movement_1.parquet`, `kills.parquet` и `shop.parquet` загружается `movement_1.parquet`; два других перечисляются как пропущенные.
- Отобранные файлы сортируются по пути внутри выбора, поэтому одна и та же папка всегда даёт один и тот же набор и те же цвета.

Панель затем показывает выбор (имя одного файла или `папка (N файлов)` по самой длинной общей папке), число файлов, их общий размер и общее число строк — точное, когда все файлы Parquet, и помеченное `≈`, когда есть хотя бы один CSV. Пропущенные файлы перечисляются с причиной, первые четыре — по имени.

## Чтение схемы {#reading-the-schema}

Сначала открывается **первый** файл выбора, чтобы описать схему («Чтение схемы»): его имена столбцов, первые 50 строк данных, какие столбцы похожи на числа и, для Parquet, логический тип каждого столбца и запись `heat3d` в футере. Папка экспортов одной таблицы делит одну схему, поэтому один файл представляет все. Затем измеряется каждый файл («Подсчёт строк»): футер Parquet даёт точное число за одно небольшое чтение; число строк CSV оценивается по средней длине строки в его первом мегабайте.

Панель [Сопоставление столбцов](column-mapping.md) открывается с автоматически угаданными сопоставлениями, а [оценка памяти](memory-and-budgets.md) появляется над кнопкой **Загрузить**.

## Сообщения до загрузки {#messages-before-loading}

Под выбором панель перечисляет из [`validateMapping`](https://github.com/Holdi601/3DHeat/blob/main/src/data/validate.ts):

- **Ошибки** (красным) — загрузка не может начаться: меньше двух осей позиции, одна и та же колонка на двух осях, сопоставленный столбец, которого нет в файле, столбец позиции, который не похож на число, столбец времени, где выборочные значения — текст, а единица — число (каждая строка читалась бы как NaN и попала бы на время 0), столбец времени в ISO-8601, ни одно выборочное значение которого не разбирается как дата, масштаб единицы 0.
- **Предупреждения** (янтарным) — загрузка пройдёт, но, вероятно, не так, как задумано: столбец группы, который принимает различное значение на большинстве выборочных строк (то есть это id, а не группа), столбец времени `DATE` (каждая строка дня имеет один и тот же момент), направление взгляда задано без своих столбцов.
- **Заметки** — что подразумевает сопоставление: рисование на плоскости, когда одна ось не сопоставлена; нет временной шкалы без столбца времени; нет треков без столбца человека; а без столбца группы — один цвет для всего и разность, которую можно разделить только по столбцу, оставленному для фильтрации.

## Загрузка {#loading}

Кнопка **Загрузить** читает *Загрузить файл*, *Загрузить N файлов* или *Загрузить N файлов (1 из K)*, когда задан [шаг прореживания](memory-and-budgets.md#decimation). Она показывает *Слишком большой — уменьшите или прорежьте* и отключена, когда [проверка по размеру](memory-and-budgets.md#the-fit-check) говорит, что загрузка не поместится; она также отключена, пока в сопоставлении есть ошибки или идёт другая загрузка.

Во время загрузки панель показывает текущий шаг (с `[файл/файлов]` впереди, когда файлов несколько), число прочитанных строк, полосу прогресса и **Отмена**. Отмена завершает рабочий поток загрузки и вместе с ним любые рабочие потоки разбора, которые он запустил.

Страница продолжает рисоваться во время загрузки, потому что работа идёт в фоне. Вы видите текущий шаг, число прочитанных строк, полосу прогресса и **Отмена**. После последнего файла панель показывает шаги *Упорядочивание строк по времени*, *Перестановка столбцов (n из m)*, *Измерение размаха*, *Составление списка*, *Сводка сессий* и *Подсчёт сроков жизни*, затем *Загрузка N строк на GPU* на один кадр, чтобы долгую отправку никогда не приняли за зависание.

### Как это работает {#how-it-works}

Загрузка выполняется в Web Worker ([`ingestWorker.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestWorker.ts)). Когда файлов несколько и потоков разбора больше одного ([потоки разбора](memory-and-budgets.md#parser-threads)), до этого числа файлов разбираются **одновременно**, каждый в собственном рабочем потоке разбора ([`parseWorker.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/parseWorker.ts)), насколько хватает бюджета ОЗУ. Объединяются они всё равно по одному, в порядке выбора, так что набор данных такой же, как при загрузке по одному. Пока в работе несколько файлов, строка прогресса называет файл, который последним сообщил о себе, а полоса и число строк суммируют все файлы в работе. При одном потоке или одном файле файлы разбираются друг за другом в самом рабочем потоке загрузки. Читаются только столбцы, которые называет сопоставление: несопоставленный столбец файла Parquet ничего не стоит; CSV сканируется побайтно, но декодируются только сопоставленные поля.

## Несколько файлов становятся одним набором {#several-files-become-one-dataset}

Когда загружено больше одного файла ([`ingestFiles.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestFiles.ts), [`builder.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/builder.ts)):

- **Один список.** Персоны, группы, сессии и значения категорий — это словари, общие для всех файлов, поэтому один и тот же игрок в двух экспортах — это один человек с одним треком.
- **Одно начало времени.** Времена хранятся как 64-битные секунды при объединении и пересчитываются от самого раннего времени *всего* выбора, а затем хранятся как 32-битные секунды от этого начала. Четыре экспорта с четырёх вечеров ставятся в свой настоящий порядок, а не укладываются друг на друга.
- **Один порядок времени.** Строки из всех файлов сортируются по времени поразрядной сортировкой (см. [предел сортировки](memory-and-budgets.md#the-sort-ceiling)).
- **Столбец `Source file`.** Каждая строка помнит, из какого файла она пришла, — как столбец категории с именем `Source file`. Он появляется в [Фильтрах](filters.md) и как *Source file - сравнить две загрузки* в [разбиении разности](difference.md). Загрузка одного файла его не получает: постоянный столбец стоил бы 4 байта на строку, чтобы ничего не сказать.
- **Отсутствующие столбцы.** Файл, в котором нет одного из столбцов *фильтра*, просто не даёт значений для него. Файл, в котором нет сопоставленного столбца *роли* (X, время, человек, ...), падает с ошибкой *в файле нет столбца "name"*; при загрузке нескольких файлов такой файл пропускается, а остальные загружаются, и пропущенные файлы перечисляются в наборе данных. Загрузка одного файла, которая падает, сообщает об ошибке.
- **Предупреждение о недоборе.** Когда загруженных строк меньше 95% строк, посчитанных заранее, набор данных несёт предупреждение с долей недостающих — из-за нечитаемых файлов или строк без пригодной позиции, которые отбрасываются при входе.

## После загрузки {#after-loading}

Новый набор данных заменяет предыдущий. При каждой загрузке ([`setDataset`](https://github.com/Holdi601/3DHeat/blob/main/src/state/store.ts)):

- все фильтры и видимость групп сбрасываются;
- разбиение разности по группам сбрасывается: первая половина групп (округлённо вверх) положительная, остальные отрицательные;
- радиус спрайта задаётся как горизонтальный размах / 120, насыщение — аналитической оценкой; размер куба, длина луча взгляда, скорость полёта и ближняя и дальняя плоскости задаются по размаху (см. [Сессии, персоны и группы](sessions-persons-groups.md#entity-size));
- сессия box replay задаётся как сессия с наибольшим числом строк;
- маршруты линейного тепла угадываются заново ([Линейное тепло](line-heat.md));
- режим вида откатывается к **Тепло**, если текущий режим не поддерживается новыми данными; временная шкала откатывается к **Все** без столбца времени, а история — к **Накопительно** без сроков жизни;
- ползунок воспроизведения ставится в начало, воспроизведение останавливается;
- камера охватывает весь набор данных с направления по умолчанию (взгляд вдоль -Z, наклон вниз около 36°).

Панель **Набор данных** затем показывает имя набора (выбор, число строк и файлов, а также шаг, если он использовался), `N команд · N персон · N с охвата` и каждое предупреждение, которое выдала загрузка, янтарным цветом, пока набор загружен. **Выгрузить** на этой панели удаляет набор данных.
