# Путь камеры и видео

Снимите фильм по своим данным: вы ставите камеру в нескольких местах, просмотрщик летает между ними и сохраняет видео. Каждый кадр очень чистый, без зерна. Камера и ползунок воспроизведения движутся вместе, поэтому та же панель делает таймлапс ([`PathPanel.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/panels/PathPanel.tsx), [`campath.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/campath.ts), [`record.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/record.ts)).

## Снять пролёт {#make-a-flythrough}

1. Долетите до места, где начинается фильм, и нажмите **Добавить ключевой кадр здесь** в разделе **Путь камеры и рендер**.
2. Долетите до следующего места и нажмите ту же кнопку. Повторите для каждой остановки.
3. Отметьте **Предпросмотр по пути** и тяните **Положение на пути**, чтобы проверить движение.
4. Задайте **Длительность** (как долго будет видео). Если движение правильное, но слишком быстрое, достаточно увеличить длительность.
5. Нажмите **Рендер видео**. Дождитесь строки прогресса; файл скачается, когда рендер закончится.

![Панель «Путь камеры и рендер» с тремя ключевыми кадрами, плавной интерполяцией, 12 с, 30 fps и 16 Мбит/с](../assets/img/en/camera-path-panel.webp)

## Ключевые кадры {#keyframes}

| Элемент | Действие |
|---|---|
| **Добавить ключевой кадр здесь** | Добавляет текущую позицию камеры, рыскание, тангаж и угол обзора как ключевой кадр. |
| **Очистить** | Удаляет все ключевые кадры. |
| Список ключевых кадров | Одна строка на ключ: его номер (щелчок — перелететь камерой туда, заодно задав угол обзора), позиция, `рыскание° / тангаж°` и **×**, чтобы его удалить. |

Ключи расставляются **равномерно** по нормированной оси пути от 0 до 1 каждый раз, когда добавляется или удаляется ключ. Длительность вывода растягивает весь путь, поэтому кадр, который правильный, но слишком быстрый, нуждается только в большей длительности. Рыскание разворачивается между ключами, поэтому камера поворачивает по короткой дуге.

Без ключевых кадров рендер держит текущую камеру неподвижной на всём клипе. Это вполне хороший таймлапс.

## Настройки пути {#path-settings}

| Элемент | По умолчанию | Диапазон (прокрутка) | Значение |
|---|---|---|---|
| **Интерполяция** (2 и больше ключей) | *Плавная* | *Плавная* / *Прямая* | *Плавная*: кубическая кривая Эрмита через ключи с касательными от соседних ключей, поэтому скорость совпадает на каждом ключе и нет толчка там, где сходятся отрезки. *Прямая*: прямые между ключами, предсказуемо, с видимым углом на каждом ключе. Угол обзора всегда интерполируется линейно. |
| Линия пути (2 и больше ключей) | | | `N единиц пути — M в секунду при этой длительности` или примечание, что все ключи в одном месте. |
| **Предпросмотр по пути** (1 и больше ключей) | выключено | | Ведёт камеру окна просмотра по пути и двигает ползунок воспроизведения вместе с ней, как это делает рендер. Так движение можно оценить до рендера. |
| **Положение на пути** (во время предпросмотра) | 0% | 0–100% | Где на пути показывать предпросмотр. |
| **Длительность** | 12 с | 1–120 с (3600) | Длина видео. |
| **Частота кадров** | 30 fps | 6–60 (240) | |
| **Битрейт** | 16 Мбит/с | 1–60 Мбит/с, логарифмически (400) | Тепловые градиенты при низком битрейте сильно полосятся: кодеку почти негде спрятать ошибку. |
| **Предел ожидания сходимости** | 240 кадров | 2–600 (10 000) | Самое долгое ожидание, за которое один выходной кадр становится точным. Кадры, на которые предел подействовал, всё равно записываются и учитываются. |
| Сводка | | | `N кадров · окно: накопление/фиксированное/время жизни`, а если временная шкала в режиме «Все»: *(рендер переключит «Все» на «Пуск», чтобы ползунок имел смысл)*. |
| **Рендер видео** / **Отмена** | | | Запускает рендер. Пока он идёт, показывает `кадр i / n · ожидание w · X МБ` и сколько кадров не были точными. Нужен набор данных. |

## Советы {#tips}

- Размер выходного видео — это размер холста в физических пикселях (коэффициент пикселей дисплея, но не больше 2). Чтобы его изменить, меняйте размер окна браузера.
- Накопленная история наращивает тепло по всему клипу; история по окну или по времени жизни показывает движущийся срез времени.
- Позиции ключевых кадров задаются в координатах экрана: при [инвертированной оси мира](camera.md#invert-world-axis) ключи, сделанные до переключения, после него указывают в другое место.

## Для разработчиков {#for-developers}

### Что делает рендер {#what-a-render-does}

1. Делает пробный снимок кадра, чтобы узнать точный размер вывода в физических пикселях.
2. Выбирает кодек через WebCodecs: **VP9** (`vp09.00.10.08`), иначе **VP8**, при выбранном битрейте и частоте кадров. Без `VideoEncoder` рендер останавливается с сообщением *В этом браузере нет VideoEncoder — для записи видео нужен WebCodecs*; если нет ни одного из кодеков, — с сообщением *Нет поддерживаемого видеокодека (пробовали VP9, VP8)*.
3. Забирает настройки, которые нужны рендеру: ставит воспроизведение на паузу, выключает **адаптивный бюджет**, включает **прогрессивное уточнение** и ставит бюджет спрайтов 64 млн на кадр. (Адаптивный бюджет защищает частоту кадров, а это здесь не та цель: он принял бы каждый медленный сходящийся кадр за повод рисовать меньше строк, а тогда для сходимости нужно больше кадров.) Переключает временную шкалу из **Все** в **Пуск**. Настройка истории (накопление, окно, время жизни) не меняется: рендер должен показать именно то, что вы смотрели, и запечатлеть это от начала до конца.
4. Для каждого выходного кадра *f* из *n*, при *u* = f / (n - 1):
   - ставит камеру в позицию пути при *u* (если есть ключи);
   - перематывает ползунок воспроизведения на ту же долю *u* диапазона временной шкалы (в повторе фигур — на длительность выбранной сессии);
   - принудительно запускает новую оценку, даже если камера не двигалась: унаследованное накопление оставило бы призрак предыдущего окна;
   - ждёт кадр за кадром, пока картинка не станет точной (все строки-кандидаты нарисованы за один кадр или накопление завершено), но не дольше предела ожидания;
   - снимает собранный кадр и кодирует его, с ключевым кадром каждые 2 секунды вывода, чтобы по файлу можно было перематывать.
5. Упаковывает кадры в файл WebM ([`webm.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/webm.ts)) с метками времени, выбранными по частоте кадров. Реальное время, которое занял каждый кадр, не важно.
6. Возвращает бюджет, угол обзора, режим временной шкалы, ползунок и то, шло ли воспроизведение.
7. Скачивает видео как `3dheat-<width>x<height>-<frames>f.webm` и сообщает `N кадров, W×H, X МБ — каждый кадр точный`, либо сколько кадров упёрлось в предел ожидания.

**Отмена** останавливает рендер после текущего кадра (*Рендер отменён.*) и возвращает настройки.
