# Панель производительности и статистика

Окошко в правом верхнем углу области просмотра показывает, как сильно работает просмотрщик: сколько кадров в секунду, сколько точек он рисует и уточняет ли ещё картинку. Панель **Производительность** позволяет обменять качество картинки на скорость.

## Оверлей статистики {#the-stats-overlay}

Окошко в правом верхнем углу области просмотра на вкладках «Тепловая карта» и «Матч» ([`StatsOverlay.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/StatsOverlay.tsx)). Оно читает текущие показания движка на каждом кадре анимации.

![Оверлей статистики на сцене «Много матчей», с номерами пояснений: 1 Бэкенд, 2 FPS, 3 Кадр, 4 Строк в окне, 5 Спрайтов / кадр, 6 Бюджет, 7 Разрешение тепла, 8 Покрытие](../assets/img/en/performance-stats-overlay.webp)

| Строка | Значение |
|---|---|
| **Бэкенд** | *WebGPU* или *WebGL2*. Наведите курсор, чтобы увидеть причину, по которой WebGPU не использовался, если он не использовался. См. [Два бэкенда](backends.md). |
| **FPS** | Кадры в секунду, усреднённые не менее чем за 0,4 с. |
| **Кадр** | Время кадра в мс, сглаженное (90% прежнего значения, 10% нового). Это время между кадрами, а не время GPU: время каждого прохода GPU не измеряется. |
| **Строк в окне** | Кандидаты: строки текущего окна времени до фильтрации по строкам в шейдере. |
| **Спрайтов / кадр** | Спрайты, которые план последнего кадра отправил на рисование (на простаивающих кадрах, которые ничего не рисуют, остаётся запланированное значение). |
| **Бюджет** | Бюджет спрайтов, по которому спланирован этот кадр: значение адаптивного контроллера, поднятое до всех кандидатов, когда рисуются все строки. |
| **Разрешение тепла** | Разрешение буфера тепла как доля холста: настройка *Разрешение тепла*, умноженная на адаптивный масштаб второго этапа. |
| **Покрытие** | Насколько накопление по прогрессу дошло до использования всех строк: процент, пока идёт сходимость (янтарный цвет), и *точно*, когда готово. Шумный кадр никогда не принимается за готовую картинку. |
| **Кубы** | Коробки, нарисованные в [наложении фигур](box-replay.md). |
| **Не в памяти** | Показывается, только когда строки не поместились в бюджет GPU: сколько их. См. [Пребывание в памяти GPU](gpu-memory.md). |

## Индикатор скорости {#the-speed-display}

В правом нижнем углу области просмотра, только в перспективе: скорость полёта и время пересечения данных на этой скорости. Перетащите его, чтобы изменить скорость. См. [Камера](camera.md#fly-speed).

## Если просмотрщик медленный {#if-the-viewer-is-slow}

Посмотрите на оверлей статистики, затем:

1. **Строк в окне заметно больше, чем Спрайтов / кадр, Покрытие ниже 100%** — кадр не может нарисовать всё; при неподвижном виде он сходится за несколько кадров. Сузьте окно, включите фильтр или отсечение, чтобы уменьшить число кандидатов, или примите выборку.
2. **Спрайтов / кадр равно Строк в окне, кадр всё равно медленный** — стоимость идёт за каждый спрайт на экране: уменьшите *Максимальный радиус в пикселях* ([Форма спрайта](sprite-shape.md#pixel-clamps)) или *Разрешение тепла*.
3. **Медленно при малом числе строк** — вероятно, дело в уровне: много конструкций при включённых рёбрах, наземные треугольники, глубина резкости. См. [Внешний вид уровня](level-appearance.md).
4. **Всё медленно и красный баннер** — программный рендеринг ([Определение программного рендеринга](software-rendering.md)).

## Панель производительности {#the-performance-panel}

| Элемент | По умолчанию | Действие |
|---|---|---|
| Подсказка | | Каждый кадр разбрасывает стратифицированную случайную выборку видимых строк с весом, масштабированным для компенсации, поэтому ожидаемое тепло точно при любом бюджете; если вид неподвижен, кадры продолжают сливаться, пока каждая строка не внесёт вклад. |
| **Рисовать каждую строку в каждом кадре** | включено | Каждый кадр, который начинает новую оценку, рисует каждую строку-кандидата (до примерно 268 млн); бюджет ниже становится минимумом. [Выборка и бюджеты](sampling-and-budgets.md#draw-every-row-each-frame) |
| **Адаптивный бюджет** | включено | Подстраивать спрайты за кадр, затем разрешение тепла, чтобы удерживать целевую частоту кадров, и прекращать уменьшение, когда оно не помогает. [Выборка и бюджеты](sampling-and-budgets.md#the-adaptive-budget) |
| **Целевой FPS** | 60 | 20–240 (1000 с ручкой). Значения ниже 15 принимаются как 15. |
| **Начальное число спрайтов / кадр** / **Спрайтов / кадр** | 4,00 млн | 65 536–268 435 456, логарифмически. Называется *Начальное*, пока адаптивный режим включён, потому что контроллер его двигает. |
| **Разрешение тепла** | 100% | 25–100%. Стоимость фрагментов растёт с квадратом: 50% уменьшает работу смешивания вчетверо, а поле тепла достаточно гладкое, поэтому это почти незаметно. |
| **Прогрессивное уточнение** | включено | Накапливать по кадрам, пока вид неподвижен. Если выключено, каждый кадр показывает оценку одного кадра. [Накопление](accumulation.md) |
| **Бюджеты ресурсов** | определены | Бюджеты ОЗУ, GPU и потока разбора. [Память и бюджеты](memory-and-budgets.md#resource-budgets) |

Ничего из этого не сохраняется: после перезагрузки восстанавливаются значения по умолчанию.
