# Геймпад и HOTAS

Камеру можно вести контроллером в стиле Xbox вместо клавиатуры. Используйте его, когда хотите откинуться назад и осмотреть большую сцену. Ввод с геймпада **добавляется** к вводу с клавиатуры, так что можно использовать оба сразу.

## Подключить контроллер {#connect-a-controller}

1. Подключите контроллер (или соедините его по Bluetooth).
2. Щёлкните по области просмотра и нажмите любую кнопку на контроллере. Браузеры показывают контроллер только после его первого ввода.
3. Откройте **Камера и сцена → Геймпад**. В списке устройств он будет отмечен `●`.
4. Толкайте левый стик, чтобы лететь, правый — чтобы смотреть. Если камера дрейфует при стиках в центре, увеличьте **Мёртвую зону**.

Любое устройство, которое браузер сопоставляет со стандартной раскладкой геймпада, работает. Джойстик или дроссель (HOTAS) по умолчанию игнорируются; см. ниже.

## Назначение кнопок {#mapping}

| Элемент управления | Действие |
|---|---|
| Левый стик | Движение: вперёд/назад и боком |
| Правый стик | Обзор: поворот и наклон, со скоростью *Скорость обзора* градусов в секунду при полном отклонении |
| `RT` / `LT` (аналоговые) | Вверх / вниз; в параллельной проекции — приблизить / отдалить |
| `RB` (удержание) | В 6 раз быстрее |
| `LB` (удержание) | 15% скорости |
| `A` (удержание) | Рывок в 3 раза (сочетается с RB/LB) |
| `Y` (нажатие) | Показать все данные в кадре |

Номера кнопок идут по стандартной раскладке: A 0, Y 3, LB 4, RB 5, LT 6, RT 7; стики — на осях 0–1 (левый) и 2–3 (правый).

## Настройки геймпада {#the-gamepad-settings}

В **Камера и сцена → Геймпад**. **Настройки** / **Скрыть** открывают или закрывают элементы подстройки.

| Элемент | По умолчанию | Диапазон (прокрутка) | Значение |
|---|---|---|---|
| **Включено** | включено | | |
| Состояние устройств | | | Все подключённые устройства: `●`, когда за ними следят, `○`, когда нет, и *— не XInput-геймпад, игнорируется* или *— не XInput-геймпад, всё равно используется* для нестандартных устройств. Если их нет: *Геймпад не найден. Браузеры показывают контроллер только после его первого ввода — нажмите на нём любую кнопку.* |
| **Устройство** | *Только геймпады XInput (рекомендуется)* | | Показывается, когда подключено нестандартное устройство. Выберите устройство по имени, чтобы следить за ним. |
| **Скорость обзора** | 150°/с | 20–540 (5000) | Скорость поворота при полном отклонении правого стика. |
| **Мёртвая зона** | 12% | 0–50% (95%) | Радиальная: диагональное движение никогда не попадает только в одну ось. Увеличьте, если камера дрейфует при стиках в центре. |
| **Кривая стика** | x² | от линейной (1) до x⁴ (16) | Показатель отклика после мёртвой зоны: точнее управление возле центра, но полная скорость по краю. |
| **Инвертировать Y стика** | выключено | | |
| **Поменять стики местами** | выключено | | Движение на правом стике, обзор на левом. |

Формирование стика: при отклонении *m* (длина вектора стика) и мёртвой зоне *d* выход = ((m - d) / (1 - d)) ^ кривая вдоль направления стика, а внутри мёртвой зоны 0.

## Почему по умолчанию только стандартные геймпады {#why-only-standard-pads-by-default}

API геймпадов сообщает **о каждом** HID-устройстве с осями — джойстиках, дросселях, педалях, рулях, — а они не возвращаются в центр: ось поворота или рычаг дросселя стоят на полном отклонении, когда их никто не трогает. Прочитанное как стик, это постоянный ввод на полной скорости, который никакая мёртвая зона не подавит: камера крутится сама с момента загрузки страницы (и все режимы тепла тоже выглядят сломанными, потому что движущаяся камера каждый кадр заново запускает накопление).

Поэтому за устройством следят, только когда браузер сообщает `mapping: "standard"` — то есть «контроллер в стиле XInput с осями там, где вы их ждёте». Другие устройства перечисляются и помечаются как игнорируемые, а **Устройство** явно подключает одно из них — например, чтобы управлять камерой с HOTAS. Когда за геймпадом уже следят, камера остаётся за ним, поэтому два контроллера не спорят за камеру в зависимости от порядка перечисления.

**HOTAS:** читаются только оси 0–3 (два стика) и стандартные кнопки. Дроссель или педали на других осях ничего не делают, а стику или дросселю, чьи оси не возвращаются в центр, может понадобиться большая **Мёртвая зона**.

Браузеры скрывают контроллер, пока он не отправит первый ввод, поэтому подключённый, но не тронутый геймпад для страницы пока не существует.
