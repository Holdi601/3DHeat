# Довідник форматів даних

Ця сторінка перелічує кожен тип файлу, який 3DHeat може відкрити, і те, яким має бути таблиця всередині нього. Таблиця — це рядки і стовпці, як у таблиці-електронці: кожен рядок каже, де щось було, а якщо ви це маєте, то коли і хто.

Що читає вкладка Теплова карта, колонка за колонкою, і підказки, які може містити файл Parquet. (Вкладка Аналіз заїздів читає файли кіл, а вкладка Матч читає підсумки матчів. Див. [Аналіз заїздів](race-analysis.md) і [Аналіз матчів](match-analysis.md).)

## Файли {#files}

Це єдиний повний список файлів, які можна завантажити. Панель **Джерело** (**Файли…**, **Тека…** або перетягування) приймає саме їх:

| Розширення | Що це | Хто читає |
|---|---|---|
| `.parquet`, `.pq` | таблиця Parquet | читач Parquet (нижче) |
| `.csv`, `.tsv`, `.txt` | текст із роздільниками | читач тексту (нижче) |
| `.3dheat` | один матч в одному файлі (ZIP, що тримає таблицю і її додатки) | завантажується як таблиця, яку він містить. [Один файл на матч](container.md) |
| `.acmi` (також `.txt.acmi`, `.zip.acmi`) | запис польоту Tacview | власний читач. [Записи Tacview](tacview-acmi.md) |
| `.json`, `.json.gz` | запис OCAP (у стилі Arma) | власний читач |
| `.gpx`, `.kml`, `.kmz`, `.nmea`, `.nma`, `.igc`, `.fit` | GPS-треки: GPX, KML/KMZ, журнали NMEA, журнали планерів IGC, спортивні файли FIT | власний читач; позиції беруться з широти і довготи |

Як позиції не завантажуються: малі файли JSON, які лежать поруч із таблицею і її описують (імена, що закінчуються на `.match.json`, `.course.json`, `.level.json`, `.meta.json`, `.summary.json`, `.session.json`, `.hints.json`), і додаткові таблиці конвертера (`<match>.events.parquet` тощо, див. [Конвертери](converters.md)), якщо їх не вибрано окремо. Усе інше пропускається з причиною. Як фільтрується вибір, пояснено в [Завантаження файлів](loading-files.md#which-files-are-kept).

Порожні файли пропускаються. У виборі, де є файли `movement*.<ext>`, завантажуються лише вони ([Завантаження файлів](loading-files.md#which-files-are-kept)).

Дані — це **один рядок на вибірку**: позиція в певний момент, за бажанням з тим, хто це, яка група, яка сесія, куди дивилися, і будь-які інші колонки. Рядки подій (вбивство, закладка, постріл) можуть стояти в тій самій таблиці, що й рядки позицій. Їх розрізняє колонка подій.

## Текст із роздільниками (CSV, TSV, TXT) {#delimited-text-csv-tsv-txt}

Найменший корисний файл, три рядки:

```
x,y,z,t,player,team
10.5,2.0,-30.2,0.00,Blue 1,Blue
11.0,2.0,-29.8,0.25,Blue 1,Blue
-4.2,1.5,18.9,0.00,Red 3,Red
```

Колонки зіставляються самі ([Зіставлення колонок](column-mapping.md)).

Розбирається сканером на рівні байтів, який декодує лише зіставлені колонки ([`csv.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/csv.ts)).

| Аспект | Правило |
|---|---|
| Заголовок | Перший непорожній рядок містить назви колонок. Порожня назва стає `column_N`. |
| Роздільник | Визначається з перших 20 непорожніх рядків перших 1 МіБ серед коми, крапки з комою, табуляції і вертикальної риски за **послідовністю**: переможе роздільник, що дає однакову кількість полів у кожному вибраному рядку. Далі той, що дає більше полів. Пробіл ніколи не визначається автоматично, але його можна вибрати. Будь-який один символ можна ввести вручну ([Зіставлення колонок](column-mapping.md#the-fields)). |
| Лапки | RFC 4180: поля можуть бути в подвійних лапках. `""` всередині лапок — це буквальна лапка. |
| Пробіли | Початкові й кінцеві пробіли, табуляції та лапки обрізаються з кожного поля. |
| Полів у рядку | Не більше 4096. Більше — помилка (*чи правильний роздільник?*). |
| Числа | Необов'язковий знак, цифри, необов'язкова `.` і десяткові, необов'язковий порядок (`1.5e-3`). Десяткова кома (`1,5`), роздільники тисяч або одиниці після числа (`12 m`) не розбираються і вважаються відсутніми. Якщо ваш файл використовує десяткові коми, замініть їх на крапки перед завантаженням (пошук і заміна в текстовому редакторі це вміє). |
| Числова колонка | Колонка пропонується як числова, коли понад 90% непорожніх значень у перших 50 рядках розбираються як числа. |
| Кількість рядків | Оцінюється до завантаження за середньою довжиною рядка перших 1 МіБ. |
| Кодування тексту | UTF-8. |

## Parquet {#parquet}

Читається за допомогою [hyparquet](https://github.com/hyparam/hyparquet), блок колонок за блоком у типізовані масиви, запитуючи лише зіставлені колонки ([`parquet.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/parquet.ts), [`ingestParquet.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestParquet.ts)).

| Аспект | Правило |
|---|---|
| Кількість рядків | Точна, з футера, до завантаження. |
| Попередній перегляд | Перші 50 рядків, декодовані як об'єкти. Їхні значення вирішують, які колонки виглядають числовими. |
| Цілі числа | `INT32` і `INT64` (декодується як BigInt) стають числами. |
| Дійсні числа | `FLOAT`, `DOUBLE`. |
| Логічні | 1 і 0. |
| Рядки | Використовуються для колонок особи, групи, сесії і категорії. Рядок, що виглядає як число, приймається для числових ролей. |
| Логічні типи `TIMESTAMP`, `DATE` | Декодуються в моменти (мілісекунди від 1970 року). Як вісь часу налаштування одиниць ігнорується. |
| Вкладені колонки | Колонки struct і list не призначені для жодної ролі (у попередньому перегляді показуються як текст JSON). Не перевірено. |
| Метадані футера | Ключ `heat3d` читається як підказки зіставлення (нижче). |

Колонка позиції, часу або погляду, яка містить щось інше, ніж число, декодується як відсутня.

## Ролі колонок і типи {#column-roles-and-types}

| Роль | Тип у файлі | Обов'язкова | Зберігається як | Обмеження |
|---|---|---|---|---|
| X, Y, Z | число | дві з трьох | 32-бітне дійсне, після [зіставлення осей](axes-units-and-time.md) | Рядок без придатної позиції відкидається. |
| Час | число в одній з [одиниць часу](axes-units-and-time.md#time-units), мітка часу Parquet або текст ISO-8601 | ні | 32-бітні дійсні секунди від найранішого рядка | Сортування відмовляє понад 400 000 000 рядків ([чому](memory-and-budgets.md#the-sort-ceiling)). |
| Особа | будь-що; із словником | ні | 32-бітний ідентифікатор | |
| Сесія | будь-що; із словником | ні | 32-бітний ідентифікатор | Підписи перелічуються до 100 000 сесій. |
| Група | будь-що; із словником | ні | 16-бітний ідентифікатор | До 4096 груп, інакше групування відкидається. |
| Рискання, тангаж | число, градуси або радіани | ні | 32-бітні дійсні радіани | |
| Напрямок X, Y, Z | число | ні (усі три разом) | переводиться в рискання і тангаж | |
| Колонка фільтра, *діапазон* | число | ні | 32-бітне дійсне | До 4 фільтрів одночасно. |
| Колонка фільтра, *категорія* | будь-що; із словником | ні | 32-бітний ідентифікатор | До 4096 значень, інакше колонка не зберігається. |

Колонка `TIMESTAMP` Parquet, що збережена як колонка фільтра, — це *діапазон* мілісекунд епохи. Це повзунок, а не список.

## Підказки `heat3d` {#the-heat3d-hints}

Файл Parquet може містити власні інструкції для читання в метаданих ключ-значення свого футера, під ключем **`heat3d`**, як об'єкт JSON ([`MappingHints`](https://github.com/Holdi601/3DHeat/blob/main/src/data/automap.ts)). Переглядач застосовує їх поверх власних припущень, коли файл є першим у виборі. Кожен запис необов'язковий, і кожен результат однаково показується й редагується на панелі [Зіставлення колонок](column-mapping.md#the-heat3d-hints-in-a-parquet-footer). Усе, що не розбирається як об'єкт JSON, ігнорується.

### Схема {#schema}

```
{
  "columns": {
    "x": string, "y": string, "z": string,          column names for the position
    "time": string,                                  the time column
    "timeUnit": "seconds" | "milliseconds" | "microseconds" | "nanoseconds"
              | "unix_seconds" | "unix_milliseconds" | "iso8601",
    "personId": string, "teamId": string, "sessionId": string,
    "lookMode": "none" | "yawPitch" | "vector",
    "yaw": string, "pitch": string,
    "dirX": string, "dirY": string, "dirZ": string,
    "angleUnit": "degrees" | "radians",
    "extra": [string, ...]                           filter columns to keep, most useful first
  },
  "axes": {
    "up": "y" | "z",
    "flipX": boolean, "flipY": boolean, "flipZ": boolean,
    "scale": number                                  must be > 0
  },
  "entity": {
    "size": number                                   size of one tracked thing in file units, > 0
  }
}
```

| Запис | Застосовується, коли | Ефект |
|---|---|---|
| `columns.x` … `columns.dirZ`, `time`, `personId`, `teamId`, `sessionId` | названа колонка є у файлі | Задає цю роль. |
| `columns.timeUnit` | це одна з семи одиниць | Задає одиницю часу. |
| `columns.angleUnit` | `"degrees"` або `"radians"` | Задає одиницю кута. |
| `columns.lookMode` | `"vector"`, коли dirX, dirY і dirZ задано всі; `"yawPitch"`, коли задано yaw; `"none"` | Задає режим погляду. |
| `columns.extra` | це масив | Замінює автоматичний список фільтрів. Залишає лише колонки, що існують і не використані жодною роллю. Кожна стає *діапазоном*, коли виглядала числовою в попередньому перегляді, інакше *категорією*. Без нього автоматичний список лишається без колонок, які підказка призначила ролі. |
| `axes.up` | `"y"` або `"z"` | Вертикальна вісь. |
| `axes.flipX/Y/Z` | логічне | Перевертання. |
| `axes.scale` | число > 0 | Масштаб одиниць. |
| `entity.size` | число > 0 | [Розмір об'єкта](sessions-persons-groups.md#entity-size) (множиться на масштаб одиниць під час завантаження). Це єдиний спосіб його задати. |

### Приклад {#example}

Вигаданий експорт шутера: вісь Z вгору, сантиметри, світ з лівою системою координат, гравці близько 72 см завширшки.

```json
{
  "columns": {
    "x": "pos_x", "y": "pos_y", "z": "pos_z",
    "time": "t", "timeUnit": "seconds",
    "personId": "player", "teamId": "side", "sessionId": "round_id",
    "lookMode": "yawPitch", "yaw": "view_yaw", "pitch": "view_pitch", "angleUnit": "degrees",
    "extra": ["event", "weapon", "map"]
  },
  "axes": { "up": "z", "flipY": true, "scale": 0.01 },
  "entity": { "size": 72 }
}
```

### Як записати {#writing-it}

З pyarrow власні метадані схеми записуються в метадані ключ-значення файлу:

```python
import json
import pyarrow as pa
import pyarrow.parquet as pq

table = pa.table({...})
hints = {"columns": {"x": "pos_x", "y": "pos_y", "z": "pos_z", "time": "t"}, "axes": {"up": "z"}}
meta = dict(table.schema.metadata or {})
meta[b"heat3d"] = json.dumps(hints).encode("utf-8")
pq.write_table(table.replace_schema_metadata(meta), "movement.parquet")
```

`npm run inspect -- file.parquet` виводить схему файлу. Це швидкий спосіб перевірити назви колонок, на які посилаються підказки.

## Що записує вкладка Теплова карта {#what-the-heatmap-tab-writes}

Нічого не записується назад у дані. Результати такі:

- відео у форматі WebM (VP9 або VP8). Див. [Шлях камери і відео](camera-path-and-video.md);
- положення камери, скопійоване в буфер обміну як текст. Див. [Камера](camera.md#pose);
- рівні, збережені в браузері у [бібліотеці рівнів](level-library.md).
