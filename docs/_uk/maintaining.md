# Супровід документації

Ця сторінка для того, хто доглядає за переглядачем і цим сайтом. Тут перелічено кроки, щоб після змін сторінки, зображення і переклади лишалися правильними.

Цей сайт перевіряють знову з **кожним релізом** і щоразу, коли щось сильно змінюється: клавіші, шлях через інтерфейс, налаштування, формати файлів. Контрольний список:

1. **Перегенеруйте довідкові сторінки**: `node tools/docs-refs.mjs` (і `--lang <lang>` для кожної мови). `node tools/docs-refs.mjs --check` завершується помилкою, коли сторінка застаріла.
2. **Перегенеруйте знімки екрана** з [демо-даних](demo-data.md). Використовуйте комп'ютер або контейнер, де регіон en-US, тож числа мають вигляд `0.35`, а не `0,35` (поля для чисел слідують за регіоном браузера, доки їх не змінено). Створіть демо-дані командою `node tools/demo-data.mjs`, запустіть сервер розробки на порту 5321 **без** локального пакета фігур: `HEAT3D_FIGURE_PACK=none npx vite --port 5321 --strictPort --host 127.0.0.1`, а потім виконайте `node tools/docs-shots.mjs --lang <lang>`. Перегляньте кожне зображення: мають бути лише демо-назви (*Demo Valley*, *Blue 1*, *Red 3* ...), без справжніх карт, гравців чи записів.
3. **Перелічіть, що змінилося** від останнього тегу релізу: `git log --oneline <last tag>..HEAD` і розділ **Docs** у `CHANGELOG.md`, який пов'язує кожну функцію з її сторінкою. Кожна нова функція потребує сторінки або розділу, а також зображення, якщо вона видна на екрані.
4. **Незалежний огляд** англійських сторінок людиною, яка їх не писала, для трьох читачів: початківця, восьмирічної дитини і експерта. Чи повні кроки і чи у правильному порядку, чи слова ті самі, що в інтерфейсі, чи актуальні зображення, чи правильні підписи на схемах?
5. **Виправте те, що знайшов огляд.**
6. **Перекладіть змінені сторінки знову** за їхнім хешем джерела, потім проведіть огляд для кожної мови. Див. `tools/docs-translate.md`.
7. **Перевірте змінені файли на конфіденційні терміни** і переконайтеся, що жодне зображення не показує нічого, крім демо-даних.
8. **Публікуйте** лише тоді, коли реліз схвалено.

Та сама перевірка охоплює сайти документації пов'язаних репозиторіїв (див. сторінку [Головна](index.md#related-repositories)).

## Інструменти в exporters/ {#the-tools-under-exporters}

Інструменти навколо переглядача — це окремі публічні проєкти. Кожен має власну ліцензію MIT, релізи, вікі та перевірку оновлень. У цьому репозиторії їх закріплено як git-підмодулі:

| Тека | Репозиторій |
|---|---|
| `exporters/gamefiles/` | [3DHeat-GameFiles](https://github.com/Holdi601/3DHeat-GameFiles) — траси і рівні з власних архівів ігор |
| `exporters/gamecapture/` | [3DHeat-GameCapture](https://github.com/Holdi601/3DHeat-GameCapture) — записувачі телеметрії кіл; рівні з відео ігрового процесу |
| `exporters/unreal/` | [3DHeat-UnrealExporter](https://github.com/Holdi601/3DHeat-UnrealExporter) — плагін для Unreal Editor |
| `exporters/cs2/` | [3DHeat-CS2](https://github.com/Holdi601/3DHeat-CS2) — демо і карти CS2 |
| `exporters/watcher/` | [3DHeat-Watcher](https://github.com/Holdi601/3DHeat-Watcher) — записує гру у фоновому режимі |

**Закріплено** означає, що цей репозиторій записує один точний коміт кожного інструмента. Копія переглядача отримує ці коміти:

```bash
git clone --recursive https://github.com/Holdi601/3DHeat
# or, after a plain clone:
git submodule update --init
```

Обидва шляхи оновлення вище виконують `git submodule update --init` після pull. Тож інструменти слідують за переглядачем до комітів, які закріплює його найновіша версія, а не за найновішими комітами самих інструментів. Новий реліз інструмента доходить до переглядача, коли тут переміщують закріплення: зміни інструмента спершу фіксуються і публікуються в його власній теці (власному репозиторії), а потім тут фіксують нове закріплення. Кожен інструмент також перевіряє власні новіші релізи. Це описано в його власному репозиторії.
