# Шлях камери й відео

Зніміть фільм із ваших даних: ви ставите камеру в кількох місцях, переглядач летить між ними і зберігає відео. Кожен кадр дуже чистий, без зерна. Камера і позиція відтворення рухаються разом, тож та сама панель робить і прискорене відео ([`PathPanel.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/panels/PathPanel.tsx), [`campath.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/campath.ts), [`record.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/record.ts)).

## Зробити політ-проліт {#make-a-flythrough}

1. Долетіть туди, де починається фільм, і натисніть **Додати ключовий кадр тут** у **Шлях камери й рендер**.
2. Долетіть до наступного місця і натисніть знову. Повторіть для кожної зупинки.
3. Позначте **Попередній перегляд шляхом** і перетягніть **Положення на шляху**, щоб перевірити рух.
4. Задайте **Тривалість** (скільки триватиме відео). Рух, який правильний, але занадто швидкий, потребує лише довшої тривалості.
5. Натисніть **Рендер відео**. Почекайте на рядок прогресу; файл завантажиться, коли він завершиться.

![Панель Шлях камери й рендер із трьома ключовими кадрами, плавною інтерполяцією, 12 с, 30 fps і 16 Мбіт/с](../assets/img/en/camera-path-panel.webp)

## Ключові кадри {#keyframes}

| Елемент керування | Дія |
|---|---|
| **Додати ключовий кадр тут** | Додає поточну позицію камери, рискання, тангаж і поле зору як ключовий кадр. |
| **Очистити** | Видаляє всі ключові кадри. |
| Список ключових кадрів | Один рядок на ключ: його номер (клацніть, щоб перенести камеру туди, разом із полем зору), позиція, `рискання° / тангаж°`, і **×**, щоб його видалити. |

Ключі розставляються **рівномірно** вздовж нормалізованої осі шляху від 0 до 1, щойно один додано або видалено; вихідна тривалість потім розтягує весь рух, тож кадр, який правильний, але занадто швидкий, потребує лише довшої тривалості. Рискання розгортається між ключами, тож камера повертається коротшим шляхом.

Без ключових кадрів рендер тримає поточну камеру нерухомо протягом усього кліпу - цілком добре прискорене відео.

## Налаштування шляху {#path-settings}

| Елемент керування | За замовчуванням | Діапазон (повзунок) | Значення |
|---|---|---|---|
| **Інтерполяція** (2+ ключі) | *Плавна* | *Плавна* / *Пряма* | *Плавна*: кубічна крива Ерміта через ключі з дотичними від сусідніх ключів, тож швидкість збігається на кожному ключі і немає ривка там, де з’єднуються відрізки. *Пряма*: прямі відрізки між ключами, передбачувані, з видимим кутом на кожному ключі. Поле зору завжди інтерполюється лінійно. |
| Лінія ходу (2+ ключі) | | | `N одиниць ходу - M за секунду при цій тривалості`, або примітка, що всі ключі в одному місці. |
| **Попередній перегляд шляхом** (1+ ключ) | вимк. | | Веде камеру в'юпорту по шляху і рухає з нею позицію відтворення, як це робить рендер, щоб рух можна було оцінити до рендеру. |
| **Положення на шляху** (під час перегляду) | 0% | 0-100% | Де на шляху показувати перегляд. |
| **Тривалість** | 12 с | 1-120 с (3600) | Довжина відео. |
| **Частота кадрів** | 30 fps | 6-60 (240) | |
| **Бітрейт** | 16 Мбіт/с | 1-60 Мбіт/с, логарифмічна (400) | Градієнти тепла погано смугуються на низькому бітрейті: кодеку мало деталей, за якими можна сховати похибку. |
| **Ліміт очікування збіжності** | 240 кадрів | 2-600 (10 000) | Найдовше, що один вихідний кадр може чекати, щоб стати точним. Кадри, що його досягли, все одно записуються і враховуються. |
| Підсумок | | | `N кадрів · вікно: накопичувальне/фіксоване/час життя`, а коли шкала часу в режимі Усі: *(рендер перемикає Усі на Пуск, щоб позиція відтворення мала зміст)*. |
| **Рендер відео** / **Скасувати** | | | Запускає рендер; поки він іде, показує `кадр i / n · очікування w · X МБ` і скільки кадрів не були точними. Потрібні дані. |

## Поради {#tips}

- Розмір вихідного відео - це розмір полотна в пікселях пристрою (коефіцієнт пікселів дисплея, але не більше 2). Щоб його змінити, змініть розмір вікна браузера.
- Накопичувальна історія нагромаджує тепло протягом кліпу; історія вікна або часу життя показує рухомий шматок часу.
- Позиції ключових кадрів - це координати відображення: з [інвертованою віссю світу](camera.md#invert-world-axis) ключі, зроблені до перемикання, після нього вказують кудись інакше.

## Для розробників {#for-developers}

### Що робить рендер {#what-a-render-does}

1. Робить пробний знімок кадру, щоб дізнатися точний розмір вихідного кадру в пікселях пристрою.
2. Обирає кодек через WebCodecs: **VP9** (`vp09.00.10.08`), інакше **VP8**, з вибраним бітрейтом і частотою кадрів. Без `VideoEncoder` він зупиняється з повідомленням *This browser has no VideoEncoder - WebCodecs is required to write a video*; без жодного з кодеків - *No supported video codec (tried VP9, VP8)*.
3. Перебирає налаштування, яких потребує рендер: призупиняє відтворення, **вимикає адаптивний бюджет**, **вмикає прогресивне уточнення** і ставить бюджет спрайтів на 64 млн на кадр (адаптивний бюджет береже частоту кадрів, а це тут не та мета: він сприйняв би кожен повільний кадр, що збігається, як причину малювати менше рядків, а це потребує більше кадрів для збіжності), і перемикає шкалу часу з **Усі** на **Пуск**. Налаштування історії (накопичувальна, вікно, час життя) лишається як є: рендер має відтворити та записати саме те, на що ви дивилися.
4. Для кожного вихідного кадру *f* з *n*, при *u* = f / (n - 1):
   - ставить камеру в позицію шляху при *u* (якщо є ключі);
   - переміщує позицію відтворення на ту саму частку *u* діапазону шкали часу (проміжок вибраної сесії в повторі коробками);
   - примусово робить нову оцінку, навіть коли камера не рухалася, бо успадкування накопичення попереднього кадру залишило б привид попереднього вікна;
   - чекає покадрово, доки картинка не стане точною (усі рядки-кандидати намальовано в одному кадрі, або накопичення завершено), до ліміту очікування;
   - захоплює скомпонований кадр і кодує його, з ключовим кадром кожні 2 секунди вихідного відео, щоб файл можна було перемотувати.
5. Збирає кадри у файл WebM ([`webm.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/webm.ts)) з мітками часу, обраними з частоти кадрів - настінний час, який займав кожен кадр, не має значення.
6. Відновлює бюджет, поле зору, режим шкали часу, позицію відтворення і те, чи йшло відтворення.
7. Завантажує відео як `3dheat-<ширина>x<висота>-<кадри>f.webm` і повідомляє `N кадрів на W×H, X МБ - кожен кадр точний`, або скільки кадрів досягли ліміту очікування.

**Скасувати** зупиняє рендер після поточного кадру (*Рендер скасовано.*) і відновлює налаштування.
