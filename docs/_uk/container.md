# Один файл на матч: `.3dheat`

Файл `.3dheat` - це один цілий матч в одному файлі, щоб його копіювати, зберігати або ділитися ним. Щоб відкрити такий файл, просто перетягніть його на панель Джерело.

```
match.3dheat   (a ZIP file)
  manifest      what the match is, and the list of everything inside
  table         the positions (Parquet)
  match.json    the match document
  sidecars      what the converter kept whole (events, messages, ...)
```

Раніше сконвертований матч був кількома файлами поруч: таблиця `<match>.parquet`, документ матчу `<match>.match.json` і супровідні файли `<match>.<what>.parquet` ([Конвертери зберігають усе](converters.md)). Файл `.3dheat` містить усе це в одному: один повтор, один файл, який можна копіювати, зберігати або надсилати.

Його зроблено так, щоб завантаження тисячі таких файлів було таким самим швидким, як завантаження окремих таблиць. А пізніші конвертери могли вкласти в нього значно більше без нового формату.

## Як завантажити один {#loading-one}

Там, де завантажується файл або тека, завантажується й `.3dheat`. Тека може містити і контейнери, і окремі файли:

| Де | Що читається з контейнера |
|---|---|
| Панель Джерело **Теплової карти** (файли, тека, перетягування) | його таблиці, так ніби це окремий `<match>.parquet` |
| **Теплова карта → Багато матчів одразу** (Файли, Тека, Додати теку) | його таблиці, читаються на місці воркерами завантажувача |
| Вкладка **Матч** (Завантажити або перетягнути на вигляд) | документ матчу |
| Дошка **Тактика**, телеметрія | його таблиці |

Відкриття контейнера читає два невеликі шматки: його каталог у кінці та маніфест на початку. Нічого з таблиці не читається, поки завантажувач її не прочитає. Супровідні файли і документ матчу читаються лише тоді, коли щось їх запитує. Якщо в теці той самий матч двічі, окремо і запакований, він завантажується один раз.

## Пакування і розпакування {#packing-and-unpacking}

Нові конвертації пишуть контейнери за замовчуванням: конвертер War Thunder (`heat3d-wt-replay`), конвертер CS2 (`heat3d_cs2 demos`) і інструмент Tacview (`node tools/acmi-to-parquet.mjs`). Параметр `--loose` зберігає окремі файли.

Матчі, сконвертовані раніше або іншими інструментами, пакуються так:

```
node tools/3dheat-pack.mjs <folder>... [--delete-loose] [--jobs N] [--settle MIN]
node tools/3dheat-pack.mjs unpack <folder|file.3dheat>... [--delete-container]
node tools/3dheat-pack.mjs verify <folder|file.3dheat>...
node tools/3dheat-pack.mjs update <file.3dheat> [--add <role>[:<name>]=<file>]... [--remove <name>]...
node tools/3dheat-pack.mjs repack <folder|file.3dheat>...
```

- **pack** знаходить у теках кожну таблицю `<match>.parquet` з файлами, що до неї належать, і пише `<match>.3dheat` поруч із ними. Матч, який уже запаковано, пропускається. Кожен контейнер перечитується повністю (sha256, розмір, CRC і футер Parquet кожного елемента) до того, як відбувається щось інше. Окремі файли видаляються лише з `--delete-loose`. Для матчу, запакованого раніше, - лише тоді, коли вони побайтно такі самі, як у контейнері. Матч, у якому файл змінювався за останні `--settle` хвилин (типово 10), не чіпають: конвертер може ще його писати.
- **unpack** записує елементи назад як окремі файли поруч з контейнером.
- **update** додає або замінює елементи, не переписуючи таблиці, які вже є в контейнері (нижче).
- **repack** переписує контейнер цілком і прибирає те, що лишили оновлення.

## Формат {#the-format}

Файл `.3dheat` - це архів ZIP (його відкриває будь-який інструмент для ZIP) з такими правилами:

1. **`manifest.json` - перший елемент**, коли контейнер записано. Він завжди є. Його знаходять через центральний каталог ZIP, тож після `update` він може лежати далі в файлі.
2. **Елементи, які читаються за діапазоном байтів або вже стиснуті, зберігаються** (метод ZIP 0): Parquet, Arrow, зображення, моделі, аудіо, відео, непрозорі блоби. Збережений елемент - це один суцільний діапазон байтів у контейнері. Тому читач бере футер таблиці і її фрагменти стовпців на місці, через `File.slice` у браузері або запит HTTP range, точно так, як читав би окремий файл.
3. **Текст стискається** (метод 8): JSON, CSV, звичайний текст. Вони малі і читаються цілком.
4. Імена в UTF-8 (прапорець біта 11), відносні, з роздільником `/`, без `..`. Вони можуть містити теки (`analysis/heat.json`). Окремий файл, запакований у контейнер, зберігає власне ім'я, тож розпакування повертає ті самі файли.
5. Елементи понад 4 ГіБ або контейнери з понад 65 535 елементами використовують ZIP64, як звично. Записувачі не ставлять дескрипторів даних після елементів.

Елементи, які конвертери пишуть сьогодні, у такому порядку:

| Роль | Елемент | Зберігається |
|---|---|---|
| `table` | `<match>.parquet` | так |
| `match` | `<match>.match.json` | ні (стиснуто) |
| `messages`, `flight`, `events`, `effects`, `objectives`, `packets`, `props`, `strings`, ... | `<match>.<role>.parquet` | так |
| `summary` | `<match>.summary.json`, підсумок індексу мас ([Масовий аналіз](mass-analysis.md)), додається `tools/3dheat-summarize.mjs` | ні (стиснуто) |

Таблиця йде одразу за маніфестом. Тому перше читання початку файлу охоплює і маніфест, і локальний заголовок таблиці.

### Маніфест {#the-manifest}

```json
{
 "format": "3dheat",
 "format_version": "1.0",
 "game": "warthunder",
 "source": "client replay",
 "converter": { "name": "heat3d-wt-replay", "version": "0.2.0" },
 "match": "<map>_RB_<date>_<session>",
 "map": "<map>",
 "mode": "RB ground",
 "started": "2026-01-01T12:00:00+00:00",
 "created": "2026-01-01T13:00:00.000Z",
 "roles": { "table": "<match>.parquet", "match": "<match>.match.json", "flight": "<match>.flight.parquet" },
 "members": [
  {
   "name": "<match>.parquet",
   "role": "table",
   "media_type": "application/vnd.apache.parquet",
   "compression": "stored",
   "bytes": 1738575,
   "rows": 38105,
   "sha256": "<64 hex digits>",
   "schema": { "id": "heat3d-table", "version": "1" }
  }
 ]
}
```

| Поле | Значення |
|---|---|
| `format` | завжди `3dheat` |
| `format_version` | `major.minor` (нижче) |
| `game`, `source`, `converter`, `match`, `map`, `mode`, `started` | що це за матч і що його створило; `null`, де невідомо |
| `created`, `updated` | коли записано, коли востаннє оновлено (`updated` з'являється лише після оновлення) |
| `roles` | кожна роль до імені її першого елемента: швидкий покажчик |
| `members` | кожен елемент, крім маніфесту: повний список, і йому довіряє читач |
| `matches` | необов'язково: матчі контейнера, який містить кілька (нижче) |
| `references` | необов'язково: файли, які контейнеру потрібні, але яких він не містить |
| `extensions` | необов'язково: власні метадані конвертера |

Кожен елемент:

| Поле | Значення |
|---|---|
| `name` | його шлях у контейнері |
| `role` | для чого він (нижче) |
| `media_type` | `application/vnd.apache.parquet`, `application/json`, `image/png`, `model/gltf-binary`, `audio/ogg`, `application/octet-stream`, ... |
| `compression` | `stored` або `deflate` |
| `bytes` | його розмір, без стиснення |
| `sha256` | від його байтів, без стиснення |
| `rows` | кількість рядків таблиці |
| `schema` | конвенція, якої він дотримується, `{ "id", "version" }`: власні `format` і `version` документа (`heat3d-wt-replay-match` 2), `heat3d-table` для таблиці, яку переглядач читає за її футером `heat3d`, `heat3d-acmi-table` для таблиць інструмента Tacview |
| `match` | у контейнері з кількох матчів - `matches[].id`, якому він належить |

### Створено для росту {#made-to-grow}

Формат має нести значно багатші повтори, ніж сьогодні, і не ламати те, що його читає зараз:

- **Версії.** `format_version` - це `major.minor`. Читач читає кожну minor-версію свого major і ігнорує кожне поле, яке не знає. Minor зростає, коли щось додано. Major - лише тоді, коли макет змінюється так, що старіший читач прочитав би його неправильно (елемент більше не зберігається, маніфест винесено з архіву). Конвенція кожного елемента має власну версію в `schema`. Тому нова структура таблиці або нова версія документа не потребують нової версії контейнера. Перші записані контейнери мали `"version": 1` замість цього. Читачі сприймають це як 1.0.
- **Ролі відкриті.** Роль - це будь-який рядок. Читачі використовують ролі, які знають, і лишають решту. Невідома роль перелічується, але ніколи не відхиляється. `update` і `repack` переносять її без змін. Роль може мати багато елементів: кілька таблиць (треки по одиницях, телеметрія з іншими частотами), події, голос, синхронізацію відео, посилання на рівні, перевизначення фігур, результати аналізу. Назви можуть містити теки.
- **Будь-які медіа.** Елемент може бути чим завгодно, що має тип медіа: Parquet, JSON, Arrow, мініатюри PNG або JPEG, моделі glTF, аудіо, сирі блоби.
- **Кілька матчів.** Сесія або турнір можуть піти в один контейнер. `matches` перелічує їх (`{ "id", "map", "mode", "started", ... }`), а кожен елемент називає свій `match`. Переглядач завантажує кожен елемент ролі `table`.
- **Посилання.** Файли, які контейнеру потрібні, але яких він не містить, наприклад рівень для одного з матчів, перелічуються в `references` за назвою і sha256 (`{ "kind": "level", "name": "...", "sha256": "..." }`). Тож потрібний файл знаходиться і перевіряється, і його не копіюють в кожен матч.
- **Розширення.** `extensions` містить власні метадані конвертера під його власним ключем `"<vendor>/<name>": { ... }`. Тож два конвертери ніколи не зіштовхуються, і спільних полів нічого не треба додавати.
- **Оновлення на місці.** `update` додає або замінює елементи, не переписуючи великі збережені таблиці. Нові елементи і новий маніфест дописуються після кінця контейнера, а за ними - новий центральний каталог. Замінене лишається як непосилані байти, доки не буде `repack`. Кожен елемент і кожне поле маніфесту, відомі чи ні, зберігаються. Оновлення, що не вдалося, відкочується до контейнера у вихідному стані.

Тести переглядача перевіряють це так: контейнер формату 1.7 з невідомою роллю, полем елемента, розширенням і аудіоелементом у теці завантажується і переживає оновлення та repack зі всім цим цілим. Контейнер major 2 відхиляється.

## Записувачі {#writers}

- Node: [`tools/container.mjs`](https://github.com/Holdi601/3DHeat/blob/main/tools/container.mjs) (запис, читання, перевірка, оновлення, repack), його використовують інструмент пакування і інструмент Tacview.
- Python: `container.py`, близько 140 рядків на стандартному `zipfile`. Той самий файл у кожному конвертері (`heat3d_ext_warthunder/container.py`, `heat3d_cs2/container.py`), тож жоден конвертер не залежить від іншого. Новий конвертер копіює його.
- Переглядач читає через [`src/data/container.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/container.ts).
