# Геймпад і HOTAS

Камеру можна вести контролером у стилі Xbox замість клавіатури. Це зручно, коли хочете відкинутися назад і оглянути велику сцену. Його входи **додаються** до входів клавіатури, тож можна користуватися обома одночасно.

## Підключення контролера {#connect-a-controller}

1. Підключіть контролер (або сполучіть його).
2. Клацніть на вид і натисніть будь-яку кнопку на контролері. Браузери показують контролер лише після його першого входу.
3. Відкрийте **Камера і сцена → Геймпад**. Список пристроїв покаже його з позначкою `●`.
4. Натисніть лівий стік, щоб летіти, правий, щоб дивитися. Якщо камера дрейфує, коли стіки в центрі, підніміть **Мертву зону**.

Будь-який пристрій, який браузер зіставляє зі стандартною розкладкою геймпада, працює. Джойстик або важіль газу (HOTAS) за замовчуванням ігнорується; див. нижче.

## Призначення {#mapping}

| Елемент | Дія |
|---|---|
| Лівий стік | Рух: вперед і назад та боком |
| Правий стік | Огляд: рискання і тангаж, зі швидкістю *Швидкість огляду* градусів за секунду при повному відхиленні |
| `RT` / `LT` (аналогові) | Вгору / вниз; у паралельній проєкції — наближення / віддалення |
| `RB` (утримувати) | У 6 разів швидше |
| `LB` (утримувати) | 15% швидкості |
| `A` (утримувати) | Ривок у 3 рази (поєднується з RB/LB) |
| `Y` (натиснути) | Вмістити дані в кадр |

Номери кнопок за стандартною розкладкою: A 0, Y 3, LB 4, RB 5, LT 6, RT 7; стіки на осях 0-1 (лівий) і 2-3 (правий).

## Налаштування геймпада {#the-gamepad-settings}

У **Камера і сцена → Геймпад**. **Налаштування** / **Сховати** відкриває елементи керування налаштуванням.

| Елемент | За замовчуванням | Діапазон (повзунок) | Значення |
|---|---|---|---|
| **Увімкнено** | увімкнено | | |
| Стан пристрою | | | Кожен підключений пристрій: `●`, коли він відстежується, `○`, коли ні. Для нестандартних пристроїв: *- not an XInput pad, ignored* або *- not an XInput pad, used anyway*. Якщо пристроїв немає: *No pad detected. Browsers only reveal a controller after it sends its first input - press a button on it.* |
| **Пристрій** | *XInput pads only (recommended)* | | Показується, коли підключено нестандартний пристрій. Оберіть пристрій за назвою, щоб відстежувати його натомість. |
| **Швидкість огляду** | 150°/с | 20-540 (5000) | Швидкість повороту при повному відхиленні правого стіка. |
| **Мертва зона** | 12% | 0-50% (95%) | Радіальна: діагональний натиск ніколи не просочується в одну вісь. Підніміть її, якщо камера дрейфує, коли стіки в центрі. |
| **Крива стіка** | x² | лінійна (1) до x⁴ (16) | Показник відгуку після мертвої зони: точніше керування поблизу центру, повна швидкість на краю. |
| **Інвертувати Y стіка** | вимкнено | | |
| **Поміняти стіки місцями** | вимкнено | | Рух на правому стіку, огляд на лівому. |

Форма стіка: при відхиленні *m* (довжина вектора стіка) і мертвій зоні *d* вихід = ((m - d) / (1 - d)) ^ крива вздовж напрямку стіка, а всередині мертвої зони — 0.

## Чому за замовчуванням лише стандартні геймпади {#why-only-standard-pads-by-default}

API геймпадів повідомляє **кожен** HID-пристрій з осями: джойстики, важелі газу, педалі, керма. Такі осі не лежать у центрі. Вісь скручування або важіль газу стоять на повному відхиленні, коли до них ніхто не торкається. Якщо прочитати це як стік, виходить постійний вхід на повній швидкості, який жодна мертва зона не придушить. Камера крутилася б сама від моменту завантаження сторінки, і всі режими тепла теж виглядали б зламаними, бо рухома камера щокадру перезапускає накопичення.

Тому пристрій відстежується лише тоді, коли браузер повідомляє `mapping: "standard"`, тобто "геймпад у стилі XInput з осями там, де ви їх очікуєте". Інші пристрої перелічуються і позначаються як ігноровані. **Пристрій** вмикає один з них явно, наприклад для керування камерою через HOTAS. Щойно геймпад відстежується, камера лишається з ним, тож два контролери не сперечаються за камеру залежно від порядку перелічення.

**HOTAS:** читаються лише осі 0-3 (два стіки) і стандартні кнопки. Важіль газу або педалі на інших осях нічого не роблять. Джойстик або важіль, чиї осі не лежать у центрі, може потребувати більшої **Мертвої зони**.

Браузери приховують контролер, доки він не надішле перший вхід. Тож підключений, але не чіпаний геймпад для сторінки поки не існує.
