# Адзін файл на матч: `.3dheat`

Файл `.3dheat` - гэта ўвесь матч у адным файле, каб скапіяваць, захаваць або перадаць. Каб адкрыць яго, проста перацягніце файл на панэль Крыніца.

```
match.3dheat   (ZIP-файл)
  manifest      што гэта за матч і спіс усяго, што ўнутры
  table         пазіцыі (Parquet)
  match.json    дакумент матча
  sidecars      тое, што канвэртар захаваў цалкам (падзеі, паведамленні, ...)
```

Канвэртаваны матч раней быў некалькімі файламі побач: табліца `<match>.parquet`, дакумент матча `<match>.match.json` і дапаможныя файлы `<match>.<what>.parquet` ([Канвэртары захоўваюць усё](converters.md)). Файл `.3dheat` трымае ўсе іх разам: адзін паўтор, адзін файл, які можна скапіяваць, захаваць або перадаць.

Ён зроблены так, каб загрузка тысячы такіх файлаў была такой жа хуткай, як загрузка асобных табліц, і каб пазнейшыя канвэртары маглі змясціць у яго нашмат больш без новага фармату.

## Загрузка аднаго {#loading-one}

Там, дзе загружаецца файл або тэчка, загружаецца і `.3dheat`, а тэчка можа змешваць кантэйнеры і асобныя файлы:

| Дзе | Што чытаецца з кантэйнера |
|---|---|
| Панэль крыніцы ў **Цеплыня** (файлы, тэчка, перацягванне) | яго табліцы, так быццам гэта асобны `<match>.parquet` |
| **Цеплыня → Многа матчаў адразу** (Файлы, Тэчка, Дадаць тэчку) | яго табліцы, чытаюцца на месцы працэсамі загрузчыка |
| укладка **Матч** (Загрузіць або перацягнуць на выгляд) | дакумент матча |
| тэлеметрыя дошкі **Тактыка** | яго табліцы |

Адкрыццё кантэйнера чытае дзве невялікія часткі: яго каталог у канцы і яго маніфест на пачатку; нічога з табліцы не чытаецца, пакуль загрузчык яе не чытае. Дапаможныя файлы і дакумент матча чытаюцца толькі тады, калі нешта іх запытае. Тэчка, у якой той самы матч ёсць двойчы - асобна і ўпакаваны, - загружае яго адзін раз.

## Упакоўка і распакоўка {#packing-and-unpacking}

Новыя канвэртацыі па змаўчанні пішуць кантэйнеры: канвэртар War Thunder (`heat3d-wt-replay`), канвэртар CS2 (`heat3d_cs2 demos`) і інструмент Tacview (`node tools/acmi-to-parquet.mjs`). `--loose` захоўвае асобныя файлы.

Матчы, канвэртаваныя раней або іншымі інструментамі, упакоўваюцца так:

```
node tools/3dheat-pack.mjs <folder>... [--delete-loose] [--jobs N] [--settle MIN]
node tools/3dheat-pack.mjs unpack <folder|file.3dheat>... [--delete-container]
node tools/3dheat-pack.mjs verify <folder|file.3dheat>...
node tools/3dheat-pack.mjs update <file.3dheat> [--add <role>[:<name>]=<file>]... [--remove <name>]...
node tools/3dheat-pack.mjs repack <folder|file.3dheat>...
```

- **pack** знаходзіць у тэчках кожную табліцу `<match>.parquet` разам з файламі, якія да яе належаць, і пішэ `<match>.3dheat` побач з імі. Матч, які ўжо ўпакаваны, прапускаецца. Кожны кантэйнер перачытваецца цалкам (sha256, памер, CRC і футэр Parquet кожнага ўдзельніка) перш чым адбудзецца што-небудзь яшчэ; асобныя файлы выдаляюцца толькі з `--delete-loose`, а для матча, упакаванага раней, - толькі тады, калі яны байт у байт тое, што ёсць у кантэйнеры. Матч, у якім файл змяніўся за апошнія `--settle` хвілін (стандартна 10), не чапаецца: канвэртар можа яго яшчэ пісаць.
- **unpack** запісвае ўдзельнікаў назад як асобныя файлы побач з кантэйнерам.
- **update** дадае або замяняе ўдзельнікаў, не перапісваючы табліцы, якія ўжо ёсць у кантэйнеры (ніжэй).
- **repack** перапісвае кантэйнер цалкам, адкідаючы тое, што засталося пасля абнаўленняў.

## Фармат {#the-format}

Файл `.3dheat` - гэта архіў ZIP (любы інструмент ZIP яго адкрые), з такімі правіламі:

1. **`manifest.json` - першы ўдзельнік**, калі кантэйнер пішацца, і ён заўсёды ёсць. Ён знаходзіцца праз цэнтральны каталог ZIP, таму пасля `update` ён можа апынуцца далей у файле.
2. **Удзельнікі, якія чытаюцца па дыяпазоне байтаў або ўжо сціснутыя, захоўваюцца** (метад ZIP 0): Parquet, Arrow, выявы, мадэлі, аўдыё, відэа, непразрыстыя большыя. Захаваны ўдзельнік - гэта адзін суцэльны дыяпазон байтаў кантэйнера, таму чытач чытае футэр табліцы і яе фрагменты слупкоў на месцы, праз `File.slice` у браўзеры або запыт HTTP-дыяпазону, - гэтак жа, як чытаў бы асобны файл.
3. **Тэкст сціскаецца** (метад 8): JSON, CSV, звычайны тэкст. Гэта малыя файлы, і яны чытаюцца цалкам.
4. Назвы - UTF-8 (біт 11 сцяжка), адносныя, з `/` як раздзяляльнікам, без `..`; яны могуць утрымліваць тэчкі (`analysis/heat.json`). Асобны файл пры ўпакоўцы захоўвае сваю назву, таму распакоўка вяртае тыя самыя файлы.
5. Удзельнікі большыя за 4 ГіБ або кантэйнеры з больш чым 65 535 удзельнікамі выкарыстоўваюць ZIP64, як звычайна. Пішучыя не ставяць апісальнікаў даных пасля ўдзельнікаў.

Удзельнікі, якія канвэртары пішуць сёння, у такім парадку:

| Роля | Удзельнік | Захаваны |
|---|---|---|
| `table` | `<match>.parquet` | так |
| `match` | `<match>.match.json` | не (сціснуты) |
| `messages`, `flight`, `events`, `effects`, `objectives`, `packets`, `props`, `strings`, ... | `<match>.<role>.parquet` | так |
| `summary` | `<match>.summary.json`, падсумаванне індэкса масы ([Масавы аналіз](mass-analysis.md)), дададзенае `tools/3dheat-summarize.mjs` | не (сціснуты) |

Табліца ідзе адразу пасля маніфеста, таму першае чытанне пачатку файла ахоплівае і маніфест, і лакальны загаловак табліцы.

### Маніфест {#the-manifest}

```json
{
 "format": "3dheat",
 "format_version": "1.0",
 "game": "warthunder",
 "source": "client replay",
 "converter": { "name": "heat3d-wt-replay", "version": "0.2.0" },
 "match": "<map>_RB_<date>_<session>",
 "map": "<map>",
 "mode": "RB ground",
 "started": "2026-01-01T12:00:00+00:00",
 "created": "2026-01-01T13:00:00.000Z",
 "roles": { "table": "<match>.parquet", "match": "<match>.match.json", "flight": "<match>.flight.parquet" },
 "members": [
  {
   "name": "<match>.parquet",
   "role": "table",
   "media_type": "application/vnd.apache.parquet",
   "compression": "stored",
   "bytes": 1738575,
   "rows": 38105,
   "sha256": "<64 hex digits>",
   "schema": { "id": "heat3d-table", "version": "1" }
  }
 ]
}
```

| Поле | Значэнне |
|---|---|
| `format` | заўсёды `3dheat` |
| `format_version` | `major.minor` (ніжэй) |
| `game`, `source`, `converter`, `match`, `map`, `mode`, `started` | што гэта за матч і што яго стварыла; `null`, дзе невядома |
| `created`, `updated` | калі напісана, калі апошні раз абноўлена (`updated` з'яўляецца толькі пасля абнаўлення) |
| `roles` | кожная роля да назвы першага ўдзельніка: хуткі індэкс |
| `members` | кожны ўдзельнік, апроч маніфеста: поўны спіс, і той, якому чытач верыць |
| `matches` | неабавязкова: матчы кантэйнера, які трымае некалькі (ніжэй) |
| `references` | неабавязкова: файлы, якія кантэйнеру патрэбны, але якіх ён не трымае |
| `extensions` | неабавязкова: уласныя метаданыя канвэртара |

Кожны ўдзельнік:

| Поле | Значэнне |
|---|---|
| `name` | яго шлях у кантэйнеры |
| `role` | для чаго ён (ніжэй) |
| `media_type` | `application/vnd.apache.parquet`, `application/json`, `image/png`, `model/gltf-binary`, `audio/ogg`, `application/octet-stream`, ... |
| `compression` | `stored` або `deflate` |
| `bytes` | яго памер, без сціскання |
| `sha256` | яго байтаў, без сціскання |
| `rows` | колькасць радкоў табліцы |
| `schema` | канвенцыя, якой ён адпавядае, `{ "id", "version" }`: уласныя `format` і `version` дакумента (`heat3d-wt-replay-match` 2), `heat3d-table` для табліцы, якую глядзельнік чытае па яе footer `heat3d`, `heat3d-acmi-table` для табліц інструмента Tacview |
| `match` | у кантэйнеры некалькіх матчаў - `matches[].id`, да якога ён належыць |

### Створана для росту {#made-to-grow}

Фармат задуманы, каб несці значна багацейшыя паўторы, чым сёння, і пры гэтым не ламаць тое, што чытае яго цяпер:

- **Версіі.** `format_version` - гэта `major.minor`. Чытач чытае кожную малодшую версію свайго major і ігнаруе кожнае поле, якое не ведае. Minor павялічваецца, калі нешта дадаецца; major - толькі калі макет мяняецца так, што стары чытач прачытаў бы яго няправільна (удзельнік больш не захоўваецца, маніфест вынесены з архіва). Канвенцыя кожнага ўдзельніка версіруецца асобна, у яго `schema`, таму новы макет табліцы або новая версія дакумента не патрабуюць новай версіі кантэйнера. Першыя кантэйнеры пісалі `"version": 1`; чытачы бяруць гэта як 1.0.
- **Ролі адкрытыя.** Роля - любы радок. Чытачы выкарыстоўваюць ролі, якія ведаюць, і захоўваюць астатнія: невядомая роля пералічваецца, але ніколі не адхіляецца, а `update` і `repack` яе не чапаюць. Роля можа мець многа ўдзельнікаў: некалькі табліц (трэкі па адзінках, тэлеметрыя з іншым крокам), падзеі, голас, сінхранізацыя відэа, даведнікі ўзроўняў, перавызначэнні фігур, вынікі аналізу. Назвы могуць утрымліваць тэчкі.
- **Любы медыя.** Удзельнікам можа быць усё, што мае тып медыя: Parquet, JSON, Arrow, мініяцюры PNG або JPEG, мадэлі glTF, аўдыё, сырыя двайковыя дадзеныя.
- **Некалькі матчаў.** Сесія або турнір могуць трапіць у адзін кантэйнер: `matches` пералічвае іх (`{ "id", "map", "mode", "started", ... }`), і кожны ўдзельнік называе свой `match`. Глядзельнік загружае кожнага ўдзельніка з роляй `table`.
- **Даведнікі.** Файлы, якія кантэйнеру патрэбны, але якіх ён не трымае, напрыклад узровень для аднаго з іх, пералічаны ў `references` па назве і sha256 (`{ "kind": "level", "name": "...", "sha256": "..." }`), таму патрэбны файл знаходзіцца і правяраецца, без капіравання ў кожны матч.
- **Пашырэнні.** `extensions` трымае ўласныя метаданыя канвэртара пад уласным ключом, `"<vendor>/<name>": { ... }`, таму два канвэртары ніколі не сутыкаюцца і нічога не трэба дадаваць у агульныя палі.
- **Абнаўленне на месцы.** `update` дадае або замяняе ўдзельнікаў, не перапісваючы вялікія захаваныя табліцы: новыя ўдзельнікі і новы маніфест дапісваюцца пасля канца кантэйнера, а потым ідзе новы цэнтральны каталог. Тое, што было замененае, застаецца як нявыкарыстаныя байты да `repack`. Кожны ўдзельнік і кожнае поле маніфеста, вядомае ці невядомае, захоўваецца. Абнаўленне, якое не ўдалося, адразаецца назад да кантэйнера ў тым выглядзе, у якім ён быў.

Тэсты глядзельніка трымаюць яго да гэтага: кантэйнер фармату 1.7 з невядомай роляй, палем удзельніка, пашырэннем і аўдыя-ўдзельнікам у тэчцы загружаецца і перажывае абнаўленне і repack з усім гэтым цэлым; кантэйнер major 2 адхіляецца.

## Пісцы {#writers}

- Node: [`tools/container.mjs`](https://github.com/Holdi601/3DHeat/blob/main/tools/container.mjs)
  (запіс, чытанне, праверка, абнаўленне, repack), які выкарыстоўваюць інструмент упакоўкі і інструмент Tacview.
- Python: `container.py`, каля 140 радкоў на стандартным `zipfile`, той самы файл у кожным канвэртары (`heat3d_ext_warthunder/container.py`, `heat3d_cs2/container.py`), таму ніводзін канвэртар не залежыць ад другога. Новы канвэртар проста капіруе яго.
- Глядзельнік чытае з
  [`src/data/container.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/container.ts).
