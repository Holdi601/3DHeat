# Падтрымка дакументацыі

Гэтая старонка для таго, хто падтрымлівае праглядальнік і гэты сайт. Яна пералічвае крокі, каб захаваць старонкі, малюнкі і пераклады правільнымі пасля змены.

Гэты сайт правяраецца зноў пры **кожным выпуску** і калі нешта моцна мяняецца: клавішы, шлях праз інтэрфейс, налады, фарматы файлаў. Кантрольны спіс:

1. **Перагенерыраваць даведачныя старонкі**: `node tools/docs-refs.mjs` (і `--lang <lang>` для кожнай мовы). `node tools/docs-refs.mjs --check` падае, калі старонка састарэла.
2. **Перагенерыраваць скрыншоты** з [дэма-даных](demo-data.md). Выкарыстоўвайце камп'ютар або кантэйнер з рэгіёнам en-US, каб лікі чыталіся як `0.35`, а не `0,35` (полі лікаў ідуць за рэгіёнам браўзера, пакуль яго не змянілі). Стварыце дэма-даныя камандай `node tools/demo-data.mjs`, запусціце дэв-сервер на порце 5321 **без** лакальнага пакета фігур: `HEAT3D_FIGURE_PACK=none npx vite --port 5321 --strictPort --host 127.0.0.1`, потым запусціце `node tools/docs-shots.mjs --lang <lang>`. Праглядзіце кожны малюнак: толькі дэма-назвы (*Demo Valley*, *Blue 1*, *Red 3* ...), ніякіх сапраўдных карт, гульцоў або запісаў.
3. **Спісаць, што змянілася** пасля апошняга тэга выпуску: `git log --oneline <last tag>..HEAD` і раздзел **Docs** у `CHANGELOG.md`, які звязвае кожную функцыю з яе старонкай. Кожная новая функцыя патрабуе старонкі або раздзела, з малюнкам, калі яна відаць на экране.
4. **Незалежны агляд** англійскіх старонак кімсьці, хто іх не пісаў, для трох чытачоў: пачаткоўца, васьмігадовага і эксперта. Ці поўныя і ў правільным парадку крокі, ці словы — тыя, што ў інтэрфейсе, ці малюнкі актуальныя, ці правільныя подпісы на схемах?
5. **Выправіць тое, што знайшоў агляд.**
6. **Перапісаць змененыя старонкі** па іх хэшы крыніцы, потым зрабіць агляд па мовах. Гл. `tools/docs-translate.md`.
7. **Прасканаваць на канфідэнцыйныя тэрміны** змененыя файлы і праверыць, што на малюнках нічога, акрамя дэма-даных.
8. **Публікаваць** толькі тады, калі выпуск зацверджаны.

Тая ж праверка ахоплівае сайты дакументацыі звязаных рэпазіторыяў (гл. старонку [Галоўная](index.md#related-repositories)).

## Інструменты ў exporters/ {#the-tools-under-exporters}

Інструменты вакол праглядальніка — асобныя публічныя праекты, кожны са сваёй ліцэнзіяй MIT, выпускамі, вікі і праверкай абнаўленняў, замацаваныя ў гэтым рэпазіторы як git-субмодулі:

| Папка | Рэпазітор |
|---|---|
| `exporters/gamefiles/` | [3DHeat-GameFiles](https://github.com/Holdi601/3DHeat-GameFiles) — курсы і ўзроўні з уласных архіваў гульняў |
| `exporters/gamecapture/` | [3DHeat-GameCapture](https://github.com/Holdi601/3DHeat-GameCapture) — запісвалкі тэлеметрыі кругоў; ўзроўні з відэа гульні |
| `exporters/unreal/` | [3DHeat-UnrealExporter](https://github.com/Holdi601/3DHeat-UnrealExporter) — плагін Unreal Editor |
| `exporters/cs2/` | [3DHeat-CS2](https://github.com/Holdi601/3DHeat-CS2) — дэма CS2 і карты |
| `exporters/watcher/` | [3DHeat-Watcher](https://github.com/Holdi601/3DHeat-Watcher) — запісвае гульню ў фоне |

**Замацаваны** азначае, што гэты рэпазітор запісвае адзін дакладны камміт кожнага інструмента. Копія праглядальніка атрымлівае гэтыя камміты:

```bash
git clone --recursive https://github.com/Holdi601/3DHeat
# or, after a plain clone:
git submodule update --init
```

Абодва шляхі абнаўлення вышэй запускаюць `git submodule update --init` пасля загрузкі, таму інструменты ідуць за праглядальнікам да камітаў, якія замацоўвае яго найноўшая версія, — а не да найноўшых камітаў саміх інструментаў. Новы выпуск інструмента трапляе ў праглядальнік, калі тут перамяшчаецца замацаванне: змены ў інструменце спачатку фіксуюцца і адпраўляюцца ў яго ўласнай папцы (ва ўласным рэпазіторы), потым новае замацаванне фіксуецца тут. Кожны інструмент таксама правярае свае новыя выпускі; гэта задакументавана ў яго ўласным рэпазіторы.
