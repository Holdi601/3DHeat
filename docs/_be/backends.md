# Два бэкэнды

Браўзер можа дазволіць старонцы выкарыстоўваць відэакарту двума спосабамі: WebGPU (навейшы) і WebGL2. Праглядальнік можа выкарыстоўваць абодва і сам выбірае лепшы, таму звычайна вам нічога рабіць не трэба. Каб даведацца, які з іх працуе, глядзіце радок **Бэкенд** у накладцы статыстыкі (уверсе справа ў выгляду).

![Накладка статыстыкі: Бэкенд, FPS, Кадр, Радкоў у акне, Спрайтаў / кадр, Бюджэт, Разрозн. цяпла, Пакрыццё](../assets/img/en/performance-stats-overlay.webp)

Праглядальнік мае два поўныя рэндэрары за адным інтэрфейсам ([`types.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/types.ts)): **WebGPU** ([`webgpu/`](https://github.com/Holdi601/3DHeat/tree/main/src/render/webgpu)) і **WebGL2** ([`webgl2/`](https://github.com/Holdi601/3DHeat/tree/main/src/render/webgl2)). Абодва малююць адну і тую ж карціну з тымі ж алгарытмамі; шэйдары існуюць у WGSL і GLSL ES 3.00 побач. Першы радок накладкі статыстыкі, **Бэкенд**, паказвае, які працуе; калі навесці на яго курсор, відаць, чаму WebGPU не выкарыстоўваўся, калі ён не выкарыстоўваўся.

## Для распрацоўшчыкаў {#for-developers}

### Як выбіраецца адзін {#how-one-is-chosen}

Палатно можа мець толькі адзін від кантэксту, таму выбар робіцца адзін раз, перш за любое маляванне ([`createRenderer.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/createRenderer.ts)):

1. Калі WebGL2 не выбраны прымусова: калі `navigator.gpu` існуе, запытаць адаптар з `powerPreference: 'high-performance'` і прыладу, і стварыць рэндэрар WebGPU. Любая няўдача запамінаецца як прычына.
2. Калі WebGPU быў выбраны прымусова і не ўдаўся, спыніцца: у выглядзе паказваецца *Cannot initialise the renderer.* з прычынай.
3. Інакш стварыць рэндэрар WebGL2 (таксама з запытам адаптара высокай прадукцыйнасці). Калі WebGL2 недаступны або не можа маляваць у float-тэкстуры (`EXT_color_buffer_float`), у выглядзе паказваецца памылка.

`powerPreference: 'high-performance'` не дае ноўтбуку з пераключальнай графікай аддаць старонцы ўбудаваны GPU. Больш старонка ўплываць не можа: апаратнае паскарэнне — гэта налада браўзера.

### Перамыкачы ў адрасе {#url-switches}

Дапішыце да адраса старонкі, напрыклад, `http://127.0.0.1:5273/?backend=webgl2`.

| Параметр | Эфект |
|---|---|
| `?backend=webgpu` | Выкарыстоўваць WebGPU або памылка. |
| `?backend=webgl2` | Выкарыстоўваць WebGL2, нават калі WebGPU даступны, — аддзяляе «тут малюецца няправільна» ад «тут малюецца няправільна на WebGPU». |
| `?heat=f16` | Прымусова ўключыць 16-бітны шлях накаплення цеплыні на любым бэкэндзе ([Накапленне ў half-float](half-float-accumulation.md)). |
| `?glcheck` | WebGL2: счытваць памылкі GL падчас кадра і паказваць іх у `renderer.heatDebug`. Па змаўчанні выключана, бо `getError` спыняе канвеер. |
| `?occdebug=<n>` | Дапаможнік распрацоўшчыка для WebGL2: замяняе цеплыню значэннямі адладкі закрыцця. Не для звычайнага выкарыстання. |

### Адрозненні, якія важныя {#differences-that-matter}

| | WebGPU | WebGL2 |
|---|---|---|
| Захаванне радкоў | Буферы захоўвання: індэкс радка — гэта індэкс масіва. Запытвае найбольшую прывязку буфера захоўвання адаптара і памеры буфераў. | Цэлалікавыя тэкстуры (8 192 тэксэлі ў шырыню), адрасуюцца з `gl_VertexID` праз тэкстуру індэксаў блокаў для кожнага кадра. |
| 32-бітнае накапленне цеплыні | Калі адаптар дае і `float32-blendable`, і `float32-filterable` | Калі ёсць `EXT_float_blend` |
| Інакш | 16-бітнае (`r16float`) | 16-бітнае (`R16F`) |
| Дыяпазон глыбіні | [0, 1]; рухавік папярэдне памнажае перамапаванне матрыц three.js з [-1, 1]. Без гэтага паралельная праекцыя, глыбіня якой лінейная, амаль цалкам трапляе ніжэй за 0 і без папярэджання адсякаецца. | [-1, 1], выкарыстоўваецца як ёсць |
| Uniform-значэнні | Кальцо слотаў па 256 байт з выраўноўваннем, па аднаму на кожнае малаванне, прывязаных праз зрушэнне. `queue.writeBuffer` упарадкаваны ў чарзе, таму, калі адзін буфер перазапісваць для кожнага малавання, кожнае малаванне счытае апошні запіс. Блок uniform-значэнняў праходу цеплыні — роўна адзін слот у 256 байт. | Звычайныя uniform-значэнні |
| Цеплавая мэта ніжэй за разрозненне палатна | Атрымлівае ўласную тэкстуру глыбіні (кожнае далучэнне ў праходзе павінна быць аднаго памеру) | |
| Захоп кадра | `captureFrame()` рэндэрыць кампазіт другі раз у вонкавую мэту і счытвае назад (headless Chromium рэндэрыць WebGPU, але ніколі не кампануе сваё палатно) | Счытвае стандартны буфер кадра назад на наступным адрэндарэным кадры |
| Счытванне назад | Буферы для счытвання захоўваюцца і выкарыстоўваюцца паўторна; адзін чытач у палёце адначасова | `readPixels`, які пытаецца ў драйвера, якая пара фармат/тып дапушчальная |

Абодва бэкэнды загружаюць табліцу крывых спрайтаў як half-float; `queue.writeTexture` у WebGPU капіруе сырыя байты, таму дадзеныя спачатку кадуюцца ў binary16 ([`half.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/half.ts)).

#### Абмежаванні тэкстур {#texture-limits}

`texStorage2D` за межамі `MAX_TEXTURE_SIZE` не кідае выключэнне: выдзяленне адкідаецца, наступныя загрузкі не ўдаюцца, і выбарка вяртае нуль. Дапаможнік WebGL2 [`createTexture`](https://github.com/Holdi601/3DHeat/blob/main/src/render/webgl2/glutil.ts) правярае абодва памеры супраць абмежавання і кідае выключэнне з памерам; тэкстура індэксаў блокаў дзвюхмерная (4 096 у шырыню), таму не можа перарасці абмежаванне; а `src/render/limits.test.ts` замацоўвае кожны памер тэкстуры супраць абмежаванняў, якія варта падтрымліваць. Рэндэрар WebGL2 таксама адмаўляецца ад прылады, максімальны памер тэкстуры якой меншы за шырыню 8 192 тэксэлі тэкстуры радкоў.

### Праверка абодвух {#testing-both}

`npm run smoke` запускае рэальны дадатак у headless Chromium на WebGL2 (па змаўчанні `http://127.0.0.1:5273/`); для WebGPU перадайце `"http://127.0.0.1:5273/?backend=webgpu"` у `node tools/smoke.mjs`, а для шляху half-float — `npm run smoke:f16`. `tools/probe-webgpu.mjs` і `tools/probe-present.mjs` (пералічаныя ў інструментах распрацоўшчыка ў [Інструменты каманднага радка](ref-tools.md)) дыягнастуюць даступнасць адаптара і вываду ў headless-браўзерах.
