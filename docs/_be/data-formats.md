# Даведнік па фарматах даных

Гэта старонка пералічвае кожны від файлаў, якія 3DHeat можа адкрыць, і тое, якім павінна быць табліца ўнутры іх. Табліца - гэта радкі і слупкі, як у электроннай табліцы: кожны радок кажа, дзе нешта было, а калі вы гэта маеце, - калі і хто.

Што ўкладка «Цеплавая карта» чытае, слупок за слупком, і падказкі, якія можа несці файл Parquet. (Укладка «Аналіз заездаў» чытае файлы кругоў, а ўкладка «Матч» - зводкі матчаў; гл. [Аналіз заездаў](race-analysis.md) і [Аналіз матчу](match-analysis.md).)

## Файлы {#files}

Гэта адзіны поўны спіс файлаў, якія можна загрузіць. Панэль **Крыніца** (**Файлы…**, **Папка…** або перацягванне) прымае толькі іх:

| Пашырэнне | Што гэта | Чытае |
|---|---|---|
| `.parquet`, `.pq` | табліца Parquet | чытач Parquet (ніжэй) |
| `.csv`, `.tsv`, `.txt` | тэкст з раздзяляльнікамі | чытач тэксту (ніжэй) |
| `.3dheat` | адзін матч у адным файле (ZIP, які ўтрымлівае табліцу і яе дадаткі) | загружаецца як табліца, якую ўтрымлівае - [Адзін файл на матч](container.md) |
| `.acmi` (таксама `.txt.acmi`, `.zip.acmi`) | запіс палёту Tacview | уласны чытач - [Запісы Tacview](tacview-acmi.md) |
| `.json`, `.json.gz` | запіс OCAP (як у Arma) | уласны чытач |
| `.gpx`, `.kml`, `.kmz`, `.nmea`, `.nma`, `.igc`, `.fit` | GPS-трэкі: GPX, KML/KMZ, журналы NMEA, журналы планёрыстаў IGC, спартыўныя файлы FIT | уласны чытач; пазіцыі бяруцца з шыраты і даўгаты |

Не загружаюцца як пазіцыі: маленькія JSON-файлы, што стаяць побач з табліцай і апісваюць яе (імёны, якія заканчваюцца на `.match.json`, `.course.json`, `.level.json`, `.meta.json`, `.summary.json`, `.session.json`, `.hints.json`), і дадатковыя табліцы канвертара (`<match>.events.parquet` і падобныя, гл. [Канвертары](converters.md)), калі вы іх не выбралі асобна. Усё астатняе прапускаецца з прычынай. Як фільтруецца выбар, растлумачана ў [Загрузка файлаў](loading-files.md#which-files-are-kept).

Пустыя файлы прапускаюцца. У выбары, які змяшчае файлы `movement*.<ext>`, загружаюцца толькі яны ([Загрузка файлаў](loading-files.md#which-files-are-kept)).

Даныя - **адзін радок на пробу**: пазіцыя ў момант, па жаданні з тым, хто, якая група, якая сесія, куды глядзеў, і любыя далейшыя слупкі. Радкі падзей (забойства, закладка, стрэл) могуць стаяць у той самай табліцы, што і радкі пазіцый, і адрозніваюцца па слупку падзеі.

## Тэкст з раздзяляльнікамі (CSV, TSV, TXT) {#delimited-text-csv-tsv-txt}

Найменшы карысны файл, тры радкі:

```
x,y,z,t,player,team
10.5,2.0,-30.2,0.00,Blue 1,Blue
11.0,2.0,-29.8,0.25,Blue 1,Blue
-4.2,1.5,18.9,0.00,Red 3,Red
```

Слупкі размяшчаюцца самі ([Супастаўленне слупкоў](column-mapping.md)).

Разбіраецца сканерам на ўзроўні байтаў, які дэкадуе толькі супастаўленыя слупкі ([`csv.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/csv.ts)).

| Аспект | Правіла |
|---|---|
| Загаловак | Першы непусты радок змяшчае назвы слупкоў. Пустая назва становіцца `column_N`. |
| Раздзяляльнік | Вызначаецца па першых 20 непустых радках першага 1 МіБ, сярод коска, кропка з коскай, табуляцыя і вертыкальная рыска, па **узгодненасці**: выйгрывае той раздзяляльнік, які дае аднолькавую колькасць палёў у кожным узятым радку, потым той, які дае больш палёў. Прабел ніколі не вызначаецца, але можа быць абраны; любы адзіны знак можна ўвесці ([Супастаўленне слупкоў](column-mapping.md#the-fields)). |
| Цытаванне | RFC 4180: палі могуць быць загорнутыя ў двукоссі, `""` унутры цытаты - літаральная двукоссе. |
| Прабелы | Пачатковыя і канцавыя прабелы, табуляцыі і двукоссі абразаюцца з кожнага поля. |
| Палі ў радку | Не больш за 4 096; больш - памылка (*раздзяляльнік правільны?*). |
| Лічбы | Неабавязковы знак, лічбы, неабавязковая `.` і дзесятковыя, неабавязковы паказчык (`1.5e-3`). Дзесятковая коска (`1,5`), падзельнікі тысяч або адзінкі ў канцы (`12 m`) не разбіраюцца і лічацца адсутнымі. Калі ў вашым файле дзесятковыя коскі, замяніце іх кропкамі перад загрузкай (пошук і замена ў тэкставым рэдактары працуе). |
| Лікавы слупок | Слупок прапануецца як лікавы, калі больш за 90% непустых значэнняў у першых 50 радках разбіраюцца як лічбы. |
| Колькасць радкоў | Ацэньваецца перад загрузкай па сярэдняй даўжыні радка першага 1 МіБ. |
| Кадыроўка тэксту | UTF-8. |

## Parquet {#parquet}

Чытаецца з дапамогай [hyparquet](https://github.com/hyparam/hyparquet), кавалак слупка за кавалкам у тыпізаваныя масівы, запытваючы толькі супастаўленыя слупкі ([`parquet.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/parquet.ts), [`ingestParquet.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestParquet.ts)).

| Аспект | Правіла |
|---|---|
| Колькасць радкоў | Дакладная, з футэра, перад загрузкай. |
| Перадпрагляд | Першыя 50 радкоў, дэкадаваных як аб'екты; іх значэнні вызначаюць, якія слупкі выглядаюць лікавымі. |
| Цэлыя лікі | `INT32` і `INT64` (дэкадуюцца як BigInt) становяцца лікамі. |
| Дробавыя | `FLOAT`, `DOUBLE`. |
| Булевы | 1 і 0. |
| Радкі | Выкарыстоўваюцца для слупкоў асобы, групы, сесіі і катэгорыі; радок, які выглядае як лік, прымаецца для лікавых роляў. |
| Лагічныя тыпы `TIMESTAMP`, `DATE` | Дэкадуюцца ў моманты (мілісекунды ад 1970); як вось часу выкарыстоўваюцца, а налада адзінак ігнаруецца. |
| Укладзеныя слупкі | Слупкі struct і list не прызначаны ні для якой ролі (паказваюцца як тэкст JSON); не правяраліся. |
| Метададзеныя футэра | Ключ `heat3d` чытаецца як падказкі супастаўлення (ніжэй). |

Слупок пазіцыі, часу або погляду, які змяшчае нешта іншае, чым лік, дэкадуецца як адсутны.
## Ролі слупкоў і тыпы {#column-roles-and-types}

| Роля | Тып у файле | Патрэбна | Захоўваецца як | Абмежаванні |
|---|---|---|---|---|
| X, Y, Z | лік | два з трох | 32-бітавае дробавае, пасля [адлюстравання восяў](axes-units-and-time.md) | Радок без прыдатнай пазіцыі адкідаецца. |
| Час | лік у адной з [адзінак часу](axes-units-and-time.md#time-units), метка часу Parquet або тэкст ISO-8601 | не | 32-бітавыя дробавыя секунды ад самага ранняга радка | Сартаванне адмаўляецца вышэй за 400 000 000 радкоў ([чаму](memory-and-budgets.md#the-sort-ceiling)). |
| Асоба | любы; слоўнікавае кадаванне | не | 32-бітавы ідэнтыфікатар | |
| Сесія | любы; слоўнікавае кадаванне | не | 32-бітавы ідэнтыфікатар | Падпісы пералічаны да 100 000 сесій. |
| Група | любы; слоўнікавае кадаванне | не | 16-бітавы ідэнтыфікатар | Да 4 096 груп, інакш групаванне адкідаецца. |
| Рысканне, нахіл | лік, градусы або радыяны | не | 32-бітавыя дробавыя радыяны | |
| Напрамак X, Y, Z | лік | не (усе тры разам) | пераўтвараецца ў рысканне і нахіл | |
| Слупок фільтра, *дыяпазон* | лік | не | 32-бітавыя дробавыя | Да 4 фільтраў адначасова. |
| Слупок фільтра, *катэгорыя* | любы; слоўнікавае кадаванне | не | 32-бітавы ідэнтыфікатар | Да 4 096 значэнняў, інакш слупок не захоўваецца. |

Слупок `TIMESTAMP` Parquet, які захоўваецца як слупок фільтра, - гэта *дыяпазон* мілісекунд эпохі: паўзунок, а не спіс.

## Падказкі `heat3d` {#the-heat3d-hints}

Файл Parquet можа несці ўласныя інструкцыі чытання ў метададзеных ключ-значэнне свайго футэра, пад ключом **`heat3d`**, як аб'ект JSON ([`MappingHints`](https://github.com/Holdi601/3DHeat/blob/main/src/data/automap.ts)). Праграма ўжывае іх паверх сваіх здагадак, калі файл першы ў выбары; кожны запіс неабавязковы, і кожны вынік усё роўна паказваецца і рэдагуецца на панэлі [Супастаўленне слупкоў](column-mapping.md#the-heat3d-hints-in-a-parquet-footer). Усё, што не разбіраецца як аб'ект JSON, ігнаруецца.

### Схема {#schema}

```
{
  "columns": {
    "x": string, "y": string, "z": string,          назвы слупкоў для пазіцыі
    "time": string,                                  слупок часу
    "timeUnit": "seconds" | "milliseconds" | "microseconds" | "nanoseconds"
              | "unix_seconds" | "unix_milliseconds" | "iso8601",
    "personId": string, "teamId": string, "sessionId": string,
    "lookMode": "none" | "yawPitch" | "vector",
    "yaw": string, "pitch": string,
    "dirX": string, "dirY": string, "dirZ": string,
    "angleUnit": "degrees" | "radians",
    "extra": [string, ...]                           слупкі фільтраў, якія трымаць, найкарысныя першыя
  },
  "axes": {
    "up": "y" | "z",
    "flipX": boolean, "flipY": boolean, "flipZ": boolean,
    "scale": number                                  павінна быць > 0
  },
  "entity": {
    "size": number                                   памер аднаго адсочванага аб'екта ў адзінках файла, > 0
  }
}
```

| Запіс | Ужываецца, калі | Эфект |
|---|---|---|
| `columns.x` … `columns.dirZ`, `time`, `personId`, `teamId`, `sessionId` | названы слупок ёсць у файле | Задае гэтую ролю. |
| `columns.timeUnit` | гэта адна з сямі адзінак | Задае адзінку часу. |
| `columns.angleUnit` | `"degrees"` або `"radians"` | Задае адзінку вугла. |
| `columns.lookMode` | `"vector"`, калі заданыя dirX, dirY і dirZ; `"yawPitch"`, калі задан yaw; `"none"` | Задае рэжым погляду. |
| `columns.extra` | гэта масіў | Замяняе аўтаматычны спіс фільтраў, захоўваючы толькі існуючыя слупкі, не занятыя роляй; кожны *дыяпазон*, калі ў перадпрагляду выглядаў лікавым, інакш *катэгорыя*. Без яго аўтаматычны спіс захоўваецца, мінус любы слупок, якому падказка назначыла ролю. |
| `axes.up` | `"y"` або `"z"` | Вось уверх. |
| `axes.flipX/Y/Z` | булеў | Пераварочванні. |
| `axes.scale` | лік > 0 | Маштаб адзінак. |
| `entity.size` | лік > 0 | [Памер аб'екта](sessions-persons-groups.md#entity-size) (памнажаецца на маштаб адзінак пры загрузцы). Адзіны спосаб яго задаць. |

### Прыклад {#example}

Выдуманы экспарт стралялкі: Z уверх, сантыметры, левы свет, гульцы каля 72 см шырынёй.

```json
{
  "columns": {
    "x": "pos_x", "y": "pos_y", "z": "pos_z",
    "time": "t", "timeUnit": "seconds",
    "personId": "player", "teamId": "side", "sessionId": "round_id",
    "lookMode": "yawPitch", "yaw": "view_yaw", "pitch": "view_pitch", "angleUnit": "degrees",
    "extra": ["event", "weapon", "map"]
  },
  "axes": { "up": "z", "flipY": true, "scale": 0.01 },
  "entity": { "size": 72 }
}
```

### Як запісаць {#writing-it}

З pyarrow уласныя метададзеныя схемы запісваюцца ў метададзеныя ключ-значэнне файла:

```python
import json
import pyarrow as pa
import pyarrow.parquet as pq

table = pa.table({...})
hints = {"columns": {"x": "pos_x", "y": "pos_y", "z": "pos_z", "time": "t"}, "axes": {"up": "z"}}
meta = dict(table.schema.metadata or {})
meta[b"heat3d"] = json.dumps(hints).encode("utf-8")
pq.write_table(table.replace_schema_metadata(meta), "movement.parquet")
```

`npm run inspect -- file.parquet` выводзіць схему файла - хуткі спосаб праверыць назвы слупкоў, на якія спасылаюцца падказкі.

## Што пішэ ўкладка «Цеплавая карта» {#what-the-heatmap-tab-writes}

Нічога не запісваецца назад у даныя. Вынікі такія:

- відэа ў фармаце WebM (VP9 або VP8) - [Шлях камеры і відэа](camera-path-and-video.md);
- пазіцыя камеры, скапіраваная ў буфер абмену як тэкст - [Камера](camera.md#pose);
- узроўні, захаваныя ў [бібліятэцы ўзроўняў](level-library.md) браўзера.
