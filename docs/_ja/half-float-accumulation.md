# 半精度浮動小数点の累積

一部のグラフィックカードは、ヒートを小さな 16 ビットの数でしか保てません。そのため、最も熱い場所が切り捨てられたり丸められたりすることがあります。ビューアーは数を調整して、これが見えないようにしています。あなたが何かをする必要はありません。このページは開発者向けです。

## 開発者向け {#for-developers}

32 ビットの浮動小数点のテクスチャにブレンドできない機器（WebGPU では `float32-blendable` と `float32-filterable` がない、WebGL2 では `EXT_float_blend` がない）は、**16 ビットの浮動小数点**（`r16float`）のヒートのターゲットを使います。最大値は 65,504、仮数部は 11 ビットです。密度の高い場では数十万に達するため、16 ビットのターゲットは**切り詰め**も**丸め**も起こします。丸めの誤差は値とともに大きくなります。そのため、非常に特徴的な見え方になります。密度の最も高い場所は実際より大幅に低く表示され、まばらな場所は正しく見えます。2 つの仕組みで対処しています。両方が働いて初めて、絵は正しくなります。

### 範囲: すべてのスプラットにゲインを掛ける {#range-a-gain-on-every-splat}

すべてのスプラットに**ゲイン**を掛け、合成のときにそれを割り戻します。そのため、場は半精度浮動小数点がうまく扱える大きさの範囲に置かれます（[`heatGain`](https://github.com/Holdi601/3DHeat/blob/main/src/render/engine.ts)）。

```
estimate = analytic saturation estimate for this dataset, radius and centre intensity
gain     = 2 ^ round(log2(2048 / estimate)),  exponent clamped to -20..20
```

2048 にすると、65,504 に達するまでに、ランプの上端より約 32 倍の余裕があります。ゲインは **2 のべき乗**なので、推定値がわずかに動いても、ゲインと累積されたバッファーは変わりません。また、ゲインは[ジオメトリのシグネチャー](accumulation.md#what-restarts-it)の一部なので、変わると累積がやり直されます。

ゲインは解析的な推定値に固定されていて、意図的に**飽和点には結びつけていません**。飽和は、合成の時点で適用されます。そのため、スライダーを動かしても収束がやり直されることはありません。もしゲインが飽和点と一緒に動くと、バッファーは古いゲインで書かれた値をまだ持っているのに、合成は新しいゲインで割ることになります。2 つの誤差が正確に打ち消し合い、スライダーが何もしないように見えてしまいます。

32 ビットのターゲットでは、ゲインは常に 1 です。

### 精度: 部分的なフレームをゼロから {#precision-partial-frames-from-zero}

重み 1/n で累積に統合されるフレームは、直接 1/n の重みで累積にスプラットされるのではなく、まず**作業用のターゲット**にゼロからスプラットされ、それからブレンドされます（[累積](accumulation.md#why-each)）。直接スプラットすると、各スプライトの寄与は、足される累積の合計の 1/n の大きさになります。半精度浮動小数点はそれを丸めて消してしまいます。その傾向は、ピクセルの密度が高いほど強くなります。ゼロから始めると、すべての加算値は、それが加わる合計と同じくらいの大きさになります。これは、1 フレームで既に行っている計算と同じです。

### 測定された効果 {#measured-effect}

密度の高い合成のシーンで、同じ単位にそろえて場を読むと次のとおりです。

| | p50 | p90 | p99 | max |
|---|---|---|---|---|
| 32 ビット（基準） | 6051 | 60742 | 121199 | 232744 |
| 16 ビット、修正前 | 1372 | 6972 | 7840 | 7840 |
| 16 ビット、修正後 | 5996 | 59666 | 118824 | 210357 |

ピークは、30 倍低い値から 0.90 倍になりました。合成されたフレームは、平均の輝度の 0.1% 以内で 32 ビットのフレームと一致します。

### テスト {#testing-it}

`?heat=f16` を使うと、どちらのバックエンドでもこの経路を強制できます。切り替えがなければ、弱い GPU だけが実行する計算は、それを動かす人たちによってしか試されないことになります。`npm run smoke:f16` は、この設定でブラウザのテストすべてを実行します。

読み戻しでは、ゲインを元に戻します。自動露出は、読み取った場をゲインで割り、`engine.readHeatProbe()` はそれを描画エンジンに渡します。[定規の、ライブのヒートの読み取り](measure.md#notes)も、同じ方法で読まれます。
