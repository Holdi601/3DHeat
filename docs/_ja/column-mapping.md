# 列マッピング

ファイルは表であり、3DHeat は、どの列が東西の位置を持ち、どの列が時刻を持ち、どの列がプレイヤーの名前を持つかなどを知っておかなければなりません。このパネルは、3DHeat が何を推測したかを示し、間違った推測を直す場所です。

![Parquet ファイルを読み込んだ後の列マッピングパネル: すべての欄がすでに埋まっている - 1 X、2 Y、3 Z、4 時刻、5 人物 ID、6 セッション/マッチ、7 チーム/グループ](../assets/img/en/column-mapping-panel.webp)

*ファイルが自分の列に名前を付けていたので、すべての欄がすでに埋まっています。*

たとえば、ヘッダーが `x,y,z,t,player,team` の CSV は、自分でマッピングされます。x、y、z が位置に、`t` が時刻に、`player` が [人物](glossary.md)、`team` が [グループ](glossary.md) になります。

ファイルを選ぶと、**列マッピング** パネルがソースパネルの下に開きます。どの列がどの役割を果たすかを示します。自動で埋められ、**読み込む** を押す前ならどの欄も変えられます。マッピングは読み込みの時点で読まれるので、後で変えたら、もう一度読み込む必要があります。

## 欄 {#the-fields}

すべての列のメニューには、最初のファイルのすべての列と、*- なし -* が並びます。

| 欄 | 役割 | 注 |
|---|---|---|
| **区切り文字** | CSV だけ: 欄の区切り。 | メニュー: *カンマ ,*、*セミコロン ;*、*タブ*、*パイプ \|*、*スペース*。または *または 1 文字を入力* に任意の 1 文字を入力。自動で検出されます (下を参照)。変えると自動マッピングが走り直すので、それ以前の編集は失われます。 |
| **X**、**Y**、**Z** | 位置。 | 少なくとも 2 つが必要です。マップされていない 3 つ目の軸は 0 になります (データは平面上にある)。2 つの軸に同じ列があるとエラーです。 |
| **ソースの上方向の軸** | ソースのどの軸が上を向くか。 | *Z が上 (ほとんどのゲームエンジン)* または *Y が上 (グラフィックスの慣例)*。[軸、単位、時間](axes-units-and-time.md) を参照してください。 |
| **単位スケール** | すべての位置に掛ける。 | ボタン *1 (m)* と *0.01 (cm→m)*、または値を入力。 |
| **X を反転 / Y を反転 / Z を反転** | ソースの軸を反転する。 | 位置と視線の向きのベクトルに適用されます。 |
| **時刻** | 時間の軸。 | 任意。なければタイムラインはありません。 |
| **時間単位** | 時刻の列をどう読むか。 | 7 つの単位。[軸、単位、時間](axes-units-and-time.md#time) を参照してください。Parquet の `TIMESTAMP`/`DATE` 列には効きません。パネルがそう伝えます。 |
| **人物 ID** | 行が属する人またはもの。 | 任意。軌跡、生存期間、ボックスリプレイ、ラインヒートを可能にします。 |
| **セッション/マッチ** | 行がどの試合、襲撃、ラウンド、走行、ラップに属するか。 | 任意。セッションの切り替わりをまたいで、位置が補間されたり、航跡になったり、ルートにつながったりすることは決してありません。[セッション、人物、グループ](sessions-persons-groups.md) を参照してください。 |
| **チーム/グループ** | 値の種類が少ない任意の列。 | 任意。グループの色、チームのヒート、グループごとの差分の分割を動かします。 |
| **視線の向き** | *なし*、*ヨー / ピッチの列* または *方向ベクトルの列*。 | ヨー/ピッチの場合: **ヨー**、**ピッチ**、**角度の単位** (*度* / *ラジアン*)。ベクトルの場合: **Dir X**、**Dir Y**、**Dir Z**。[ボックスリプレイ](box-replay.md) の視線の線に使われます。 |
| **フィルター用に保持** | メモリに残す追加の列。 | 列ごとのチェックボックス。チェックされたものごとに *範囲* (数値) または *カテゴリ* を選びます。どれも行あたり 4 バイトと、読み込み時の復号の一巡を費やします。残された列だけが [フィルター](filters.md) をかけられ、[差分の分割](difference.md) に使われ、または [ラインヒート](line-heat.md) のイベントの列になれます。 |
| **サンプル行を表示** | 最初の 12 のサンプル行の表、すべての列。 | 推測を確かめるため。 |

明示的に設定されていない、チェックされたフィルター列は *範囲* として読まれます。数値に見える ID の列は、*カテゴリ* として使うほうがしばしば役立ちます。同時に有効にできるフィルターは 4 つだけです ([フィルター](filters.md))。

## 自動マッピングの推測 {#how-the-auto-mapping-guesses}

推測は [`src/data/automap.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/automap.ts) にあります。列の名前、サンプルの行でどの列が数値か (空でない値の 90% 超が数値として読める)、サンプルで各列がとる別々の値の数、そして Parquet の論理型を見ます。名前のパターンは、大文字と小文字を区別せず、順番に試されます。空いている列に一致した最初のパターンが勝ちます。

### 位置 {#position}

| 軸 | 名前のパターン、順番どおり (数値の列だけ) |
|---|---|
| X | `x`、`…_x` / `… x`、`pos…x`、`x…pos`、`loc…x`、`lon…`、`longitude` |
| Y | `y`、`…_y`、`pos…y`、`y…pos`、`loc…y`、`lat…`、`latitude` |
| Z | `z`、`…_z`、`pos…z`、`z…pos`、`loc…z`、`…alt…`、`…height…`、`…elev…` |

軸がまだ空の場合は、最初に空いている数値の列 (`filename`、`level`、`year`、`month`、`day`、`hour`、`location` は無視) が、順番にそれを埋めます。間違った推測は画面で見ればすぐわかります。空のままだと、表示領域が空になってしまいます。

### 時刻 {#time}

- **まず Parquet のタイムスタンプの列。** 論理型が `TIMESTAMP` または `DATE` の列の中から、点数で最良のものが選ばれます。名前が時刻のパターンに一致すれば +10,000、ただの `DATE` なら -5,000、そしてサンプルにある別々の値の数が加わります。1 日の日付や、一定のセッションの開始は、別々の値がほとんどないので、イベントの瞬間が勝ちます。単位は *Unix タイムスタンプ (ms)* になります。
- **そうでなければ名前で:** `time`、`timestamp`、`ts`、`…event…time…`、`…time…stamp…`、`t`、`…date…time…`、`when`、`tick`、`…frame…`、その後に経過時間の名前 (`gdur`、`g_duration`、`…duration…`、`…elapsed…`、`…match time…`、`…round time…`、`…game time…`、`…minute from start…`、`…since start…`、`age`)。単位は、値から推測されます。値が `YYYY-MM-DDT…` または `YYYY-MM-DD …` のように見えれば ISO-8601。そうでなければ最大の大きさで: 10^17 ナノ秒より大きければナノ秒、10^14 マイクロ秒より大きければマイクロ秒、10^11 Unix ミリ秒より大きければ Unix ミリ秒、10^8 Unix 秒より大きければ Unix 秒、10^6 ミリ秒より大きければミリ秒、それ以外は秒。

経過時間の列が選ばれると、パネルは、すべてのセッションがそれぞれの開始に合わせられることを注記します。試合を重ねて比べるには良いですが、実際の順序で見るには向きません。

### セッション、人物、グループ {#session-person-group}

セッションは、時間の軸の **後** で、人物とグループの **前** に取られます。セッションの列は、しばしばタイムスタンプだからです (試合の開始時刻が、その試合のすべての行にある)。

| 役割 | 名前のパターン、順番どおり |
|---|---|
| セッション | `session` / `session_id`、`match…`、`round…`、`raid…`、`game…`、`run…`、`replay…`、`instance…`、`lap…`、`stint…` (それぞれ完全一致、任意で `_id`) |
| 人物 | `name`、`…player…id/name…`、`…user…`、`…account…`、`persona…`、`…character…`、`victim`、`actor`、`…puuid…`、`…steam id…`、`subject…`、その後に `driver` / `driver_id` / `driver_name`、`car` / `car_id` / `car_name` (レースのデータ: 動くのは車) |
| グループ | `spawn_team`、`real_team`、`team` / `team_id` / `team_name`、`squad…`、`side`、`…faction…`、`clan…`、`party…`、`alliance…`、`car_class` |
| グループ、予備 | `…victim_ai…`、`…killer_ai…`、`…is_ai/bot/npc…`、`target_type`、`survived`、`outcome`、`result` |

サンプルの行の大半で別々の値をとるグループ候補 (max(48, サンプルの 60%) を超える) は、グループではなく ID です。人物の列が見つかっていなければ人物の列になり、グループとしては使われません。グループの列がまったく見つからなければ、2 から 12 の別々の値を持つ、数値でない列のうち、値の種類が最も少ないものが使われます。

### 視線の向き {#look-direction}

`yaw`、`…rot…yaw…`、`…heading…`、`azimuth…`、`…view…yaw…`、または `rot_z` / `rotation_z` という名前の数値の列は、視線の向きをヨー/ピッチに切り替えます。ピッチは、`pitch`、`…rot…pitch…`、`…elevation…angle…`、`…view…pitch…` として探されます。サンプルのヨーの大きさが 7 を超えれば度、そうでなければラジアンと見なされます。方向ベクトルは、決して推測されません。下のヒント、またはあなたから来ます。

### フィルターの列 {#filter-columns}

最大 **6** 列が、順位をつけて自動的に残されます。

1. `region`、`sessionMode`、`actor` - フィルターをかけるために存在する列 (点数 1200)。
2. サンプルで変化するカテゴリの列。別々の値の少ないものが先 (1000 から数を引いたもの)。
3. サンプルで一定の列。ただし、複数のファイルが読み込まれているときだけ。ファイルごとに違うかもしれない、地域やテスト実行の ID のようなものです (600)。
4. 数値の列 (500)。

すでに役割を持つ列、上の雑音の名前、1 つのファイルの読み込みで一定の列、そして自由記述の列 (max(16, サンプルの半分) を超える別々の値) は、自動では候補になりません。どの列も、手でチェックすれば残せます。

### 上方向の軸 {#up-axis}

3 つの軸すべてがマップされているとき、サンプルで Y と Z のうち広がりが小さいほうの軸が上と見なされます (マップは高さより幅のほうがずっと広いからです)。そうでなければ Z が上と見なされます。

## Parquet のフッターにある `heat3d` のヒント {#the-heat3d-hints-in-a-parquet-footer}

Parquet ファイルは、どう読むべきかを言えます。ファイルのフッターのキーと値のメタデータに **`heat3d`** というキーの項目があると、その値は JSON として解析され、推測の上に重ねられます ([`applyHints`](https://github.com/Holdi601/3DHeat/blob/main/src/data/automap.ts))。CS2 のデモのコンバーターはそのような項目を書くので、その表は、人物としてのプレイヤー、グループとしての陣営、セッションとしての各ラウンド、視線の向きがオンで、世界が正しい向きに、開かれます。

ヒントのために読まれるのは、選択の **最初の** ファイルだけです。どの項目も任意で、ヒントのある値はどれもパネルに表示され、変えられます。スキーマの完全な説明は、例とその書き方とともに、[データの形式のリファレンス](data-formats.md#the-heat3d-hints) にあります。

規則を簡単に言うと、次のとおりです。

- ヒントが指定した列は、ファイルがその列を持つときだけ適用されます。
- `lookMode: "vector"` は、`dirX`、`dirY`、`dirZ` がすべて設定されているときだけ効きます。`"yawPitch"` は、`yaw` が設定されているときだけ効きます。
- `extra` があると、自動のフィルターの一覧を置き換えます (知らない名前と、すでに役割を持つ列は捨てられます)。各列の範囲/カテゴリの種類は、それが数値に見えたかどうかに従います。なければ、自動の一覧が、ヒントが役割を与えた列を除いて残されます。
- `axes.up` は `"y"` か `"z"` でなければなりません。反転は真偽値でなければなりません。`scale` は正でなければなりません。
- `entity.size` は、正のとき、ファイルの単位での追跡される 1 つのものの大きさです ([実体の大きさ](sessions-persons-groups.md#entity-size))。これが設定する唯一の方法です。

## 既知の問題: CSV の区切り文字を上書きする {#known-issue-overriding-the-csv-separator}

検出されたものと違う区切り文字に変えても、列の一覧とサンプルの行は変わりません (プレビューは、今も検出された区切り文字で分けます)。選んだ区切り文字は、読み込みそのものには使われます。検出された区切り文字が間違っている場合は、次のようにしてください。

1. ファイルをテキストエディターで開きます。
2. すべての場所で、区切り文字をカンマに置き換えます (小数点のカンマはドットに)。
3. 保存してから、ファイルをもう一度読み込みます。

原因は [`previewSource`](https://github.com/Holdi601/3DHeat/blob/main/src/data/sourcePreview.ts) にあります。
