# フィルター

**フィルター** は、気にしない行を隠します。たとえば、1つの車両クラスや、1つのイベントの種類です。絵はすぐに更新されます。パネルには、読み込み時に *フィルター用に保持* の下で保持された列（[列マッピング](column-mapping.md)）と、複数のファイルを読み込んだ場合は *元ファイル* が並びます。

## 試す {#try-it}

1. データセットを読み込み、サイドバーで **フィルター** を開きます。
2. **車両クラス** の下で *Tank* のチェックを外します。絵はすぐに変わります。
3. **すべてのフィルターをクリア** を押すと元に戻ります。

![フィルターパネル：ビューア自身の列（イベント種別、車両クラス）が先、その後にファイルの列](../assets/img/en/filters.webp)

最初の行は、ビューア自身の列です（下を参照）。その後の行は、ファイルから来ます。

## ビューアが追加する列 {#columns-the-viewer-adds}

読み込み時に、ビューアは独自の4つの列を計算し、それを**最初に**並べます。名前と値はあなたの言語で表示されるので、同じフィルターがどのゲームやデータの元でも使えます：

| 列 | 値 | 計算の元 |
|---|---|---|
| **イベント種別** | 23 種類：位置、射撃、発射（ミサイル、ロケット、爆弾）、命中、外れ（武器が標的の近くで終わらなかった）、爆発、ダメージ、撃墜、死亡、撃破、墜落、脱出 / 離脱、出現、消滅、離陸、着陸、地面との接触、地上で停止、再武装 / 給油、占領 / 目標、デコイ、メッセージ、その他 | `event`、`events`、`event_type`、`event_name` という名前の列。各ゲームの独自の言葉（`shot`、`burst`、`fired`、`struck`、`flare`、`plant` など）がこれらの種類に対応づけられます。全表：[イベントの種類とクラス](ref-event-types.md)。 |
| **プレイヤーか AI** | プレイヤー、AI | `ai`、`is_ai`、`bot`、`actor` という列。なければ `is_player` / `human`。なければアカウント ID（`user_id`、`steam_id`。空または 0 は AI）。Tacview の記録では、そのオブジェクトにパイロットがいるかどうか。 |
| **車両クラス** | 17 種類：戦闘機、攻撃機、爆撃機、その他の航空機、ヘリコプター、戦車、装甲車両、防空、砲兵、トラック / 車、艦船、潜水艦、歩兵、兵装、デコイ、構造物、その他 | 車両またはユニットの名前（[フィギュアのカタログ](figures.md)と照合）と、種類の列 |
| **目標クラス** | 車両クラスと同じ | 相手側の車両（`other_vehicle`、`target_vehicle`、`victim_type` など） |

実際に現れる種類だけが一覧に出ます。値の列（`cost_*`、`earn_*`、`net_*` と *コストの元*。[価値の重み付け](value-weighting.md)を参照）は、どの数値の列とも同じように絞り込めます。たとえば、*コストの元* の下で *estimate* のチェックを外すと、価格のついた行だけが残ります。

12 を超える値を持つカテゴリーの一覧には、検索の欄（*n 個の値を検索*）と、一致する値だけを正確に許可する **これのみ** ボタンが付きます。

どの列を絞り込めるかは、読み込み時に決まります。読み込みの時点で読まれる必要があるからです。保持された列がない場合、パネルはそう表示し、*フィルター用に保持* を指し示します。

## 数値の列（範囲） {#numeric-columns-range}

![両端をドラッグした範囲フィルター（失った金額）](../assets/img/en/filters-numeric.webp)

| 部分 | 意味 |
|---|---|
| 名前と `最小 ... 最大` | 列と、現在の範囲（フィルターが設定されていない間は、列の全範囲）。 |
| 1行目：数値の欄とスライダー | 下限。スライダーを上限より上にドラッグすると、上限もいっしょに動きます。 |
| 2行目：数値の欄とスライダー | 上限。下限より下にドラッグすると、下限もいっしょに動きます。 |
| **列をリセット** | このフィルターを取り除きます。 |

スライダーは列の最小から最大を 1,000 段階で覆います。数値の欄は任意の値を受け付けます。大きな値は指数表記で表示されます（`1.23e6`）。行は、その値が範囲に入るとき（両端を含む）に通ります。

## カテゴリーの列 {#category-columns}

| 部分 | 意味 |
|---|---|
| 名前と `許可数/総数` | 列と、許可されている値の数。 |
| 値の一覧 | 値ごとのチェックボックス。空の値は *(空)* と表示されます。 |
| **すべて** / **なし** | すべての値を許可 / どの値も許可しない。 |

すべての値を許可すると、フィルターは取り除かれます。

## ルール {#rules}

- **同時に4つのフィルター。** ヘッダーには `active/4` と表示されます。5つ目のフィルターは適用されず、パネルがそう表示します。[エンティティ](entities.md)での選択（または マッチタブのプレイヤーの焦点）も、この4つのうち1つを使います。列全体を覆うフィルターは、どれも使いません。
- **カテゴリーの列は最大 4,096 個の値を持てます。** それより広い列は、読み込み時に保持されません。
- **フィルターは AND で組み合わさり**、チームの表示、差分の分割、時間の窓、距離によるカリング、[スライス](slice.md)とも組み合わさります。
- **フィルターを変えると、累積は最初からやり直し**、数フレーム後に露出を測り直します。フィルターは密度を大きく変えうるからです（[色と露出](colour-and-exposure.md#auto-exposure)）。
- **すべてのフィルターをクリア** は、列のフィルターをすべて取り除きます。チームの表示と、ほかの場所で設定したプレイヤーの選択は残ります。
- 列のフィルターはヒートモードを変えますが、[フィギュアのリプレイ](box-replay.md)のフィギュアは変えません。フィギュアはチームの表示とエンティティの選択に従います。エンティティの選択は両方を変えます。
- [線のヒート](line-heat.md)では、フィルターは各線分が**終わる**行で判定されます。
- 新しいデータセットを読み込むたびに、すべてのフィルターは消去されます。

## 開発者向け {#for-developers}

**スロット。** 有効な各フィルターは、GPU のスロットを 1 つ使います（[`MAX_FILTER_SLOTS`](https://github.com/Holdi601/3DHeat/blob/main/src/render/types.ts)）。行 1 つにつき 4 バイトのテクスチャです。スロットは、最後に変更された順にフィルターへ割り当てられます（[`filterSlots`](https://github.com/Holdi601/3DHeat/blob/main/src/render/filterTables.ts)。シェーダーと両方のパネルで共有）。4 つを超えると、*適用されるのは最初の4個のフィルターだけです。どれかをクリアしてください — 残りは黙って組み合わされるのではなく、無視されています。* という表示が出て、余分なフィルターの名前は *列（未適用）* と表示されます。フィルターは頂点シェーダーで行ごとに動くので、しきい値を変えても再解析も再アップロードも不要です。

**パネルに表示されないフィルター。** アプリケーションの状態には、さらに2種類のフィルターがあります（[`FilterSpec`](https://github.com/Holdi601/3DHeat/blob/main/src/state/types.ts)）：

- **グループ** フィルター。マッチタブが一方の側に焦点を当てたときに設定されます。ほかのグループを、すべてのモードで隠します。列で分割した[差分](difference.md)も含みます。
- **人物** フィルター。[エンティティ](entities.md)パネルと、マッチタブが1人のプレイヤーに焦点を当てたときに設定されます。フィギュアのリプレイとヒートモードを制限します。ヒートでは、人物 ID に対するカテゴリーのフィルターで、4 つのスロットの1つを使います。そのマスクは 65,536 個の ID を保持します（[`FILTER_MASK_CAPACITY`](https://github.com/Holdi601/3DHeat/blob/main/src/render/types.ts)）。それを超える人物は、有効な間はヒートには描かれません。選ばれていても同じです。フィギュアのリプレイには、まだ表示されます。
