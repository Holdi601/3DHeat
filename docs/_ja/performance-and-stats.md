# パフォーマンスパネルと統計オーバーレイ

ビューの右上の箱は、ビューアーがどれだけ働いているかを示します。1秒あたりのフレーム数、描いている点の数、絵をまだ精細にしているかどうかです。**パフォーマンス** パネルでは、絵の品質と速さを交換できます。

## 統計オーバーレイ {#the-stats-overlay}

ヒートのタブとマッチのタブのビューの右上にある箱です（[`StatsOverlay.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/StatsOverlay.tsx)）。アニメーションのフレームごとに、エンジンの現在の値を読みます。

![多数のマッチのシーンにある統計オーバーレイ。番号付きの注記：1 バックエンド、2 FPS、3 フレーム、4 ウィンドウ内の行、5 スプライト/フレーム、6 予算、7 ヒート解像度、8 カバー率](../assets/img/en/performance-stats-overlay.webp)

| 行 | 意味 |
|---|---|
| **バックエンド** | *WebGPU* または *WebGL2*。WebGPU を使わなかった場合は、その理由をマウスを載せて確認できます。[2つのバックエンド](backends.md)を参照してください。 |
| **FPS** | 1秒あたりのフレーム数。少なくとも 0.4 秒にわたって平均します。 |
| **フレーム** | フレームの時間（ミリ秒）。前の値 90%、新しい値 10% で平滑化します。これは描画と描画の間の時間で、GPU の時間ではありません。パスごとの GPU の時間は測定していません。 |
| **ウィンドウ内の行** | 候補の行。現在の時間のウィンドウにある行で、シェーダーで行ごとのフィルターをかける前の数です。 |
| **スプライト/フレーム** | 前のフレームの計画で描画に回されたスプライト数（何も描かないアイドルのフレームでは、計画の値のまま表示されます）。 |
| **予算** | このフレームの計画に使われたスプライト予算。適応制御の値で、すべての行を描くときは候補すべてまで引き上げられます。 |
| **ヒート解像度** | ヒートのバッファーの解像度を、キャンバスに対する割合で示したもの。*ヒート解像度* の設定に、適応の第二段階の倍率を掛けた値です。 |
| **カバー率** | 段階的な累積が、すべての行を使うところまでどれだけ進んだか。収束中はパーセント（琥珀色）で、終わると *正確* と表示されます。ノイズのあるフレームを、完成した絵と間違えることはありません。 |
| **キューブ** | [ボックス再生](box-replay.md)で描かれた箱の数。 |
| **非常駐** | GPU 予算に行が収まらなかったときだけ表示されます。その数です。[GPU メモリの常駐](gpu-memory.md)を参照してください。 |

## 速度の表示 {#the-speed-display}

ビューの右下にあり、遠近法のときだけ表示されます。飛行の速さと、その速さでデータを端から端まで横切る時間です。ドラッグすると速さを変えられます。[カメラ](camera.md#fly-speed)を参照してください。

## ビューアーが遅いとき {#if-the-viewer-is-slow}

まず統計オーバーレイを見て、次のとおり確認します。

1. **ウィンドウ内の行がスプライト/フレームよりずっと多く、カバー率が 100% 未満** - フレームですべてを描くことはできません。静止すると、数フレームかけて収束します。ウィンドウを狭める、フィルターをかける、またはカリングで候補を減らします。サンプリングを受け入れることもできます。
2. **スプライト/フレームがウィンドウ内の行と同じで、それでもフレームが遅い** - 負荷は画面上のスプライトの数に比例しています。*最大ピクセル半径*（[スプライトの形](sprite-shape.md#pixel-clamps)）または *ヒート解像度* を下げてください。
3. **行が少ないのに遅い** - おそらくレベルが原因です。構造物の数が多く、輪郭が有効、地面の三角形、被写界深度などです。[レベルの見た目](level-appearance.md)を参照してください。
4. **すべてが遅く、赤いバナーが出ている** - ソフトウェア描画です（[ソフトウェア描画の検出](software-rendering.md)）。

## パフォーマンスパネル {#the-performance-panel}

| 操作 | 既定値 | 効果 |
|---|---|---|
| ヒント | | 各フレームは、表示されている行のうち層化ランダムに選んだ一部を散布します。重みは補正されているので、予算がどの値でも、期待されるヒートは正確です。絵を静止させておくと、すべての行が寄与するまでフレームの統合を続けます。 |
| **毎フレームすべての行を描画** | オン | 新しい推定を始めるフレームでは、候補のすべての行を描きます（約 2 億 6,800 万まで）。下の予算は下限になります。[サンプリングと予算](sampling-and-budgets.md#draw-every-row-each-frame) |
| **自動予算** | オン | フレームあたりのスプライトを調整し、次にヒートの解像度を調整して、目標のフレームレートを保ちます。切り下げても効果がないときは、それ以上は下げません。[サンプリングと予算](sampling-and-budgets.md#the-adaptive-budget) |
| **目標FPS** | 60 | 20-240（ハンドルを使うと 1000）。15 未満の値は 15 として扱われます。 |
| **初期スプライト/フレーム** / **スプライト/フレーム** | 4.00M | 65,536-268,435,456、対数目盛り。自動予算がオンの間は、制御が値を動かすため *初期* と表示されます。 |
| **ヒート解像度** | 100% | 25-100%。フラグメントの負荷は二乗で変わります。50% にすると、ブレンドの作業量は 4 分の 1 になります。ヒートの場は十分になめらかなので、ほとんど目立ちません。 |
| **プログレッシブ描画** | オン | 表示が静止している間、フレームをまたいで累積します。オフにすると、毎フレーム、1フレームの推定値を表示します。[累積](accumulation.md) |
| **リソース予算** | 検出済み | RAM、GPU、パーサースレッドの予算。[メモリと予算](memory-and-budgets.md#resource-budgets) |

これらの設定はどれも保存されません。ページを再読み込みすると、既定値に戻ります。
