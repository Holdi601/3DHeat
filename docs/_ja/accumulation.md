# 累積

ビューアーが1フレームで1つ1つの点をすべて描けないとき、その一部を描き、次に別の一部を描き、あなたが静止している間、絵を足し合わせます。写真が現像されるように、絵は鮮明になっていきます。カメラを動かすと、最初からやり直しです。統計のオーバーレイの **カバー率** の行には、どこまで進んだかが表示されます。

![統計のオーバーレイ: 絵が現像されている間はカバー率が割合で表示され、完了すると *正確* と表示される](../assets/img/en/performance-stats-overlay.webp)

## 開発者向け {#for-developers}

1フレームですべての行を描けないとき、標本を描いて重みを付けます。そのため、絵は偏りのない、しかしノイズのある推定値になります。**累積**は連続するフレームを合成するため、何も変わらない間に、推定値が正確な答えに収束します。各フレームは5つのモードのうち1つを選びます（[`engine.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/engine.ts)）。最後に使われたものは `engine.live.accumMode` にあります。

| モード | いつ | アキュムレーターに起きること |
|---|---|---|
| **reset** | カメラが動いた、フィールドを変える何かが変わった、段階的な精緻化がオフ、成長する窓が始まった（再生の最初のフレーム、シークの後）、または再生されるラインヒートが動いた | このフレームの推定値に置き換えられる。 |
| **extend** | 前のフレームから大きくなっただけの**累積**の窓 | このフレームは、ちょうど見えるようになった行だけを、全重みで描き、足し合わせる。何も減衰しない。 |
| **ema** | 移動する窓（**窓**、**ライフタイム**）が動いた | `acc = acc × (1 - 0.34) + frame × 0.34`。約3フレーム分の指数移動平均。 |
| **mean** | 何も変わらず、推定値が完全ではない | n 番目のフレームで `acc = acc × (1 - 1/n) + frame × 1/n`。実行中の平均。 |
| **skip**（待機） | 収束し、何も変わらない | 何も描かない。フレームは合成し直すだけ。 |

### それぞれの理由 {#why-each}

- **合計ではなく実行中の平均。** バッファーを 1 - 1/n 倍し、新しいフレームの 1/n を足すことは、代数的には、最後に合計して *n* で割ることと同じです。しかし、バッファーは常に1つのフィールド分の値を保ちます。合計では、フィールドの *n* 倍になり、16ビットの対象では 65,504 で飽和します。割る数が増え続けると、静止したビューは長く止まっているほどフェードしてしまいます。一方、カメラが動くときはフレームごとにリセットされるため、完全に正しく見えます。スモークテストは、16 フレームを合成したものが、1フレームの 1.00 倍を保つことを確認しています。
- **再生の累積には extend。** すでに累積された行はまだ見えているため、フレームはちょうど届いた数分の1秒だけが必要です。それは1フレームに収まるので、そのまま正確に入ります。代わりに再推定すると、フレームごとに別のランダムな部分集合が光ってフェードし、塊がぱっと現れて消えるように見えます。一時停止したフレームは、塗り足され続けてしまいます。テストは、再生中に合計が単調に増え、一時停止した 2.5 秒の間は 0.02% 以内に保たれることを確認しています。
- **移動する窓には移動平均。** これらは本当にフレームごとに変わります。固定のブレンドの重みは、動いている窓を追いかけます（再生が始まってからの全フレームの平均は、再生ヘッドより遅れてしまいます）。そして、最初からやり直すよりずっと静かです。
- **再生されるラインには reset。** ラインヒートの先頭は毎フレーム動きます。移動平均だと、それぞれが筋に滲んでしまうため、各フレームは全体で描かれ、尾のフェードは絵そのものが持つものになります。
- **部分的なフレームは作業用の対象を通る。** 全重みの一部で合成されたフレームは、ゼロから別の対象に描かれ、その後アキュムレーターにブレンドされます。1/n の重みで直接描くのではありません。直接描くと、各スプライトは、加わる合計の 1/n の大きさで足されてしまいます。半精度浮動小数点の対象は、それを丸めて消してしまいます。最も密なところで最悪になります（[half-float 累積](half-float-accumulation.md)）。

### 収束 {#convergence}

各フレームの計画は、候補の行がいくつあるか、そしていくつ送信するかを知っています。そのため、すべての行を覆うために必要なフレーム数は ⌈候補 / 送信数⌉ です。その数のフレームが合成されると、ビューは**収束**します。統計のオーバーレイの *カバー率* の行は、割合から *正確* に変わり、それ以降のフレームは待機します。**毎フレームすべての行を描画**がオン（既定）の場合、1フレームで通常すべてを覆うため、収束はすぐに起きます。段階的な仕組みが必要になるのは、窓が1つの描画計画で扱える量（約 6,700 万）を超える行を持つときだけです。

### 再開させるもの {#what-restarts-it}

設定は3つのグループに分かれます。変わった後も、累積されたバッファーが何を意味するかによります。

| グループ | 変わるもの | 効果 |
|---|---|---|
| **形状**（どの行が寄与し、どれだけか） | ビューのモード。ラインの経路。スプライトの半径、中心と縁の強度、減衰、スムーズランプ、カーブ、ピクセルの制限、平坦化。距離カリングの近方、遠方、平面。遮蔽と地形の裏を隠す。スライス。キャンバスのサイズ。ヒート解像度。グループの表示と符号。差分の分割。すべて / 再生。履歴。列のフィルターとエンティティの選択。半精度の利得 | リセット。 |
| **窓**（時間範囲） | 再生ヘッドの移動。ライフタイムのフォールバックとフェード | 拡張（累積）または移動平均（移動する窓）。 |
| **合成**（色付けだけ） | 彩度、密度の応答、最小ヒート、カラーランプ。レベルのカット。グリッドと軸。ボックスリプレイの設定とセッション。被写界深度 | ヒートに触れずに描き直す。 |

カメラの移動は、必ずリセットされます。そのため、彩度やランプをドラッグしても費用はかかりませんが、スプライトの半径をドラッグすると、一歩ごとに収束がやり直されます。
