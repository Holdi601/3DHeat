# ファイルの読み込み

このページでは、3DHeat にファイルを渡す方法と、3DHeat がそれをどう扱うかを説明します。フォルダーをドロップすると、3DHeat は位置を含むファイルを選び、それらを 1 つの画像にまとめます。

1. ヒートマップのサイドバーの上にある **ソース** を開きます。
2. ファイルかフォルダーをドロップゾーンにドロップするか、**ファイル…** または **フォルダー…** を押します。
3. 選択の行と **メモリの見積もり** を読みます (下の図を参照)。
4. **読み込む** を押します。

![10 個の試合のフォルダーをドロップした後のソースパネル: 1 は選択の行、2 は fits と表示されたメモリの見積もり、3 は 10 個のファイルを読み込む](../assets/img/en/loading-files-source.webp)

*フォルダーをドロップすると、3DHeat は見つけたものと、それが収まるかどうかを伝えます。*

ファイルは、ヒートマップタブのサイドバーの上にある **ソース** パネルで読み込みます。一度に選んだものはすべて **1 つの** データセットになります。

## ファイルの選び方 {#choosing-files}

| 操作 | 働き |
|---|---|
| **ファイルかフォルダーをここにドロップ** (ドロップゾーン) | ファイルとフォルダーを任意に混ぜてドロップできます。フォルダーは再帰的にたどられます。ドロップゾーンをクリックすると、**ファイル…** と同じ選択画面が開きます。 |
| **ファイル1つ…** | 1 つのファイルを選ぶ選択画面です。 |
| **ファイル…** | 複数のファイルを選べる選択画面です。 |
| **フォルダー…** | フォルダーを選ぶ選択画面です (ブラウザの `webkitdirectory` の選択画面)。フォルダーツリー内のすべてのファイルが候補になります。 |

選択画面は、[読み込めるファイルの一覧](data-formats.md#files) にあるファイル形式を受け付けます。要約すると、`.parquet`/`.pq` は Parquet として、`.csv`/`.tsv`/`.txt` は区切り文字のテキストとして読まれます。`.acmi` (Tacview)、OCAP の `.json`/`.json.gz`、GPS 形式 (GPX、KML、KMZ、NMEA、IGC、FIT) は、それぞれ専用の読み込み機能を通ります。`.3dheat` の試合コンテナは、中に入っている表として読み込まれます ([試合ごとに1ファイル (.3dheat)](container.md))。読めないコンテナは *csv/parquet ファイルではない* としてスキップされます。

ドロップされたフォルダーは、深さ 12 階層まで、最大 20,000 ファイルまでたどられます。これは、シンボリックリンクの循環や、際限なく広がるツリーを防ぐためです。

## 残すファイル {#which-files-are-kept}

何かを読む前に、選択は絞り込まれます ([`filterDataFiles`](https://github.com/Holdi601/3DHeat/blob/main/src/data/filePick.ts))。

- 別の拡張子のファイルはスキップされます: *csv/parquet ファイルではない*。
- 0 バイトのファイルはスキップされます: *空 (0 バイト)*。
- **コンバーターの付属ファイル** は、試合の表の隣にコンバーターが残す生データです。`<試合>.messages.parquet`、`.events.parquet`、`.raw.parquet` などがあり、[コンバーターはすべて残す](converters.md) に一覧があります。これらはスキップされます: *コンバーターの付属ファイル*。1 つ開くには、それだけを選ぶかドロップしてください (または付属ファイルだけを選ぶ)。付属ファイルだけの選択は、ほかの表と同じように読み込まれます。表の隣にある JSON (`.match.json`、`.course.json`、`.level.json`、`.meta.json`、`.summary.json`、`.session.json`、`.hints.json`) は、位置の候補にはなりません。
- **移動ファイルの規則。** 選択の中のどれかのファイルが `movement*.parquet`、`movement*.csv` (ほかの拡張子も同様) という名前 (`movement.parquet`、`movement_1.parquet` など) なら、ほかのデータファイルはすべてスキップされます: *移動ファイルではなく、このフォルダーには移動ファイルがある*。テレメトリのエクスポートは、位置のない数十の表の隣に、位置の表が 1 つだけある場合がよくあります。描けるのは位置の表だけです。移動ファイルのないフォルダーは、すべてのデータファイルを読み込みます。例: `movement_1.parquet`、`kills.parquet`、`shop.parquet` のあるフォルダーは、`movement_1.parquet` を読み込みます。残りの 2 つはスキップとして一覧に出ます。例: `movement_1.parquet`、`kills.parquet`、`shop.parquet` のあるフォルダーは、`movement_1.parquet` を読み込みます。残りの 2 つはスキップとして一覧に出ます。
- 残ったファイルは、選択の中のパスで並べられます。そのため、同じフォルダーからは、いつも同じデータセットと同じ色が作られます。

パネルには、その後、選択内容 (1 つのファイルの名前、または最も長い共通フォルダーを使った `フォルダー (N ファイル)`)、ファイル数、合計サイズ、合計の行数が表示されます。行数は、すべてが Parquet なら正確な数になり、CSV が 1 つでもあれば `≈` が付きます。スキップされたファイルは、その理由とともに一覧になります。最初の 4 つは名前で示されます。

## スキーマを読む {#reading-the-schema}

選択の **最初の** ファイルは、スキーマを説明するために開かれます (「スキーマを読んでいます」)。その列名、最初の 50 のデータ行、数値に見える列、そして Parquet の場合は各列の論理型と `heat3d` のフッターの項目を読みます。1 つの表のエクスポートのフォルダーは、1 つのスキーマを共有するので、1 つのファイルがすべてを代表します。その後、すべてのファイルが測られます (「行を数えています」)。Parquet のフッターは、小さな読み込み 1 回で正確な数を与えます。CSV の数は、最初の 1 MB の 1 行あたりの平均の長さから推定されます。

[列のマッピング](column-mapping.md) パネルは、自動でマッピングされた推測とともに開き、[メモリの見積もり](memory-and-budgets.md) は **読み込む** ボタンの上に出ます。

## 読み込む前のメッセージ {#messages-before-loading}

選択の下に、パネルは [`validateMapping`](https://github.com/Holdi601/3DHeat/blob/main/src/data/validate.ts) から次のものを一覧にします。

- **エラー** (赤) - 読み込みを始められません。位置の軸が 2 つ未満、2 つの軸に同じ列、ファイルにないマップされた列、数値に見えない位置の列、単位は数値なのにサンプルの値が文字列の時刻の列 (すべての行が NaN になり、時刻 0 に入ります)、サンプルのどの値も日付として読めない ISO-8601 の時刻の列、単位の倍率が 0 の場合です。
- **警告** (琥珀色) - 読み込まれますが、意図どおりにはならない可能性が高いもの: サンプルの大半で別々の値をとるグループの列 (グループではなく ID です)、`DATE` の時刻の列 (1 日の全行が同じ瞬間を共有します)、視線の向きが列なしで設定されている場合です。
- **メモ** - マッピングが意味すること: 軸が 1 つマップされていない場合は平面上の描画、時刻の列がなければタイムラインなし、人物の列がなければ軌跡なし、グループの列がなければ全体が 1 色で、差分はフィルター用に残した列でしか分けられないことです。

## 読み込み {#loading}

**読み込む** ボタンには、*ファイルを読み込む*、*N 個のファイルを読み込む*、または [間引きの間隔](memory-and-budgets.md#decimation) が設定されている場合は *N 個のファイルを読み込む (1 / K)* と表示されます。[収まるかの確認](memory-and-budgets.md#the-fit-check) が、読み込みが収まらないと言う場合は *大きすぎます - 減らすか間引いてください* と表示され、無効になります。マッピングにエラーがあるとき、または別の読み込みが実行中のときも無効です。

読み込み中、パネルには現在の手順 (ファイルが複数あるときは先頭に `[ファイル/ファイル数]`)、これまでに読んだ行数、進行バー、**キャンセル** が表示されます。キャンセルすると、取り込みワーカーが止まり、それが始めたパーサーのワーカーもすべて止まります。

読み込み中もページは描画を続けます。作業は背景で行われるからです。現在の手順、読んだ行数、進行バー、**キャンセル** が見えます。最後のファイルの後、パネルには手順が表示されます: *行を時刻順に並べています*、*列を並べ替えています (n / m)*、*範囲を測っています*、*名簿を作っています*、*セッションをまとめています*、*生存期間を計算しています*。その後、1 フレームの間 *N 行を GPU にアップロードしています* と表示されます。長いアップロードが、フリーズと間違えられることがないようにするためです。

### 仕組み {#how-it-works}

読み込みは Web Worker ([`ingestWorker.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestWorker.ts)) で行われます。ファイルが複数あり、[パーサースレッド](memory-and-budgets.md#parser-threads) が 2 つ以上あるとき、RAM の予算が許す範囲で、そのスレッド数まで **同時に** 解析されます。それぞれ自分のパーサーワーカー ([`parseWorker.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/parseWorker.ts)) で解析されます。それでも、選択の順番どおりに 1 つずつ統合されるので、データセットは 1 つずつ読み込んだ場合と同じになります。複数が処理中のとき、進行の行には最後に報告したファイルの名前が出て、バーと行数は処理中のすべてのファイルを合計します。スレッドが 1 つのとき、またはファイルが 1 つのときは、ファイルは取り込みワーカー自身の中で、1 つずつ順に解析されます。読まれるのはマッピングが指定した列だけです。マップされていない Parquet の列はコストがかかりません。CSV はバイト単位で走査されますが、マップされたフィールドだけが復号されます。

## 複数のファイルが 1 つのデータセットになる {#several-files-become-one-dataset}

ファイルが 2 つ以上読み込まれるとき ([`ingestFiles.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestFiles.ts)、[`builder.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/builder.ts))。

- **名簿は 1 つ。** 人物、グループ、セッション、カテゴリの値は、すべてのファイルで共有される辞書です。そのため、2 つのエクスポートに出てくる同じプレイヤーは、1 人の人物で、軌跡も 1 つです。
- **時刻の起点は 1 つ。** 統合の間、時刻は 64 ビットの秒として保たれ、選択 *全体* の最も早い時刻を基準に振り直されます。その後、その起点からの 32 ビットの秒として保存されます。4 日分の 4 つのエクスポートは、重ねられるのではなく、実際の順序で並びます。
- **時刻の順序は 1 つ。** すべてのファイルの行は、基数ソート ([ソートの上限](memory-and-budgets.md#the-sort-ceiling)) で時刻順に並べられます。
- **`Source file` 列。** すべての行は、どのファイルから来たかを覚えています。これは `Source file` という名前のカテゴリ列です。[フィルター](filters.md) に出てきますし、[差分の分割](difference.md) では *Source file - 2 つの読み込みを比較* として出ます。1 ファイルの読み込みでは付きません。値が変わらない列は、1 行あたり 4 バイトを使って何も伝えないことになるからです。
- **欠けている列。** フィルター用の列が 1 つないファイルは、その列には値を出しません。マップされた *役割* の列 (X、時刻、人物など) がないファイルは、*ファイルに列 "名前" がありません* で失敗します。複数ファイルの読み込みでは、そのファイルはスキップされ、ほかのファイルは読み込まれます。スキップされたファイルは、データセットの上に一覧になります。1 ファイルの読み込みが失敗すると、エラーが報告されます。
- **不足の警告。** 読み込んだ行数が、事前に数えた行数の 95% 未満のとき、データセットには不足の割合とともに警告が付きます。読めないファイルや、使える位置のない行 (途中で捨てられる) が原因です。

## 読み込んだ後 {#after-loading}

新しいデータセットは、以前のものを置き換えます。読み込むたびに ([`setDataset`](https://github.com/Holdi601/3DHeat/blob/main/src/state/store.ts))、次のことが行われます。

- すべてのフィルターとグループの表示がクリアされます。
- グループごとの差分の分割がリセットされます。グループの前半 (切り上げ) が正、残りが負になります。
- スプライトの半径は、水平方向の範囲 / 120 に設定され、飽和度は解析的な推定値に設定されます。キューブの大きさ、視線の長さ、飛行速度、近い面と遠い面は、範囲から設定されます ([セッション、人物、グループ](sessions-persons-groups.md#entity-size) を参照)。
- ボックスリプレイのセッションは、行数が最も多いセッションに設定されます。
- ラインヒートのルートは、改めて推測されます ([ラインヒート](line-heat.md))。
- 表示モードが新しいデータでサポートされていない場合、表示モードは **ヒート** に戻ります。タイムラインは時刻の列がなければ **すべて** に、生存期間がなければ履歴は **累積** に戻ります。
- 再生ヘッドは先頭に置かれ、再生は止まります。
- カメラは、既定の向きから、データセット全体を収めます (-Z 方向を見て、約 36° 下を向きます)。

その後、**データセット** パネルには、データセットの名前 (選択、行数とファイル数、使った場合は間隔)、`N チーム · N 人 · N 秒の範囲`、そして読み込みが出したすべての警告が琥珀色で表示されます。データセットが読み込まれている間は、ずっと表示されます。そのパネルの **アンロード** で、データセットを取り除けます。
