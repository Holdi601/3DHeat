3Dレベルは、データが置かれている場所（丘、道路、建物）のモデルです。熱がどの階、どの丘、どの屋根にあるかを見られます。ビューアーはこれを、地面（不透明）、構造物（透けて見えるので内側を見られる）、水に分けます。

## 3Dレベルを読み込む {#load-a-3d-level}

1. 先にデータを読み込みます（[データの取り込み](getting-data-in.md)）。モデルは、データと同じワールド空間と単位を使い、Y が上である必要があります。
2. **背景/レベル**で**簡略化の目標**を選びます。モデルがとても大きい場合を除き、*Full - no simplification*（簡略化なし）のままにします。
3. **3Dモデル…**を押し、`.glb`、`.gltf`、`.obj`、`.stl`、`.ply` のファイルを選びます。
4. 進行状況の行が出るまで待ちます。**キャンセル**で止められます。
5. ビューで **F** を押します。地面は不透明、構造物は透けた殻、水は平らになります。
6. [レベルの見た目](level-appearance.md)で見た目を調整します。結果を残すには、**ライブラリに保存**を押します（[レベルのライブラリ](level-library.md)）。

![読み込んだ3Dレベル：等高線のある不透明な地面、透けた建物、平らな水](../assets/img/en/model-levels-loaded.webp)

**3Dモデル…**はレベルのメッシュを読み込みます。バックグラウンドのワーカー（[`modelWorker.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/modelWorker.ts)）で、解析、分類、簡略化を行います。進行状況の行と**キャンセル**があり、表示は *Reading model*（モデルを読み込み中）、*Parsing file*（ファイルを解析中）、*Packing N textures*（N 個のテクスチャをまとめ中）、*Classifying N parts*（N 個のパーツを分類中）、*Simplifying ground (N tris)*（地面を簡略化中、N 個の三角形）、*Simplifying structures (N tris)*（構造物を簡略化中、N 個の三角形）、*Building wireframe*（ワイヤーフレームを作成中）です。

## 形式 {#formats}

| 形式 | 読み取る内容 | 制限 |
|---|---|---|
| `.glb` | `mode` が 4（三角形）か、モードなしのメッシュの各プリミティブ。各ノードのワールド変換を適用。`POSITION`。頂点色としての `COLOR_0`（vec3 または vec4）。マテリアルの `baseColorTexture` と、その `TEXCOORD_n` によるテクスチャ。ノードとメッシュの名前はパーツの名前になります。 | 線と点は飛ばします。 |
| `.gltf` | 同じ。 | 埋め込みのバッファがある場合のみ。外部の `.bin` を参照する glTF は *Export as a single .glb so the geometry is embedded.*（形状が埋め込まれるよう、1つの .glb として書き出してください）と表示され、拒否されます。 |
| `.obj` | 面。`o` と `g` のブロックはパーツになります。 | 形状のみ（マテリアルなし）。 |
| `.stl` | バイナリと ASCII（`solid …`）。 | 1つのパーツ。 |
| `.ply` | ASCII のみ。 | バイナリの PLY は *Convert to .glb or binary .stl.*（.glb またはバイナリの .stl に変換してください）と表示され、拒否されます。 |

形状のみを読みます。位置、法線、三角形を、1つのバッファにまとめます（同じ点はつなげます）。存在する場合は、色とテクスチャ座標も含みます（[`modelParse.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/modelParse.ts)）。三角形がないモデルは拒否されます。モデルは、データと同じワールド空間と単位（Y が上）である必要があります。合わせるための変換は一切行いません。

## 地面、構造物、水 {#ground-structures-and-water}

取り込み時にレベルは3つの種類に分けられます。扱いが正反対だからです（[`classify.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/classify.ts)）。

- **地面**：不透明に描き、傾き、等高線、標高の段階色などの起伏の手がかりで陰影を付けます。そのため、位置を地面に対して読み取れます。
- **構造物**：建物や小物は、カメラと、その中にある熱の間に立つため、**透明な殻**として描きます（うっすらした面と明るい縁、そして重複をなくした辺）。テクスチャがある場合は、そのテクスチャのまま不透明に描きます。
- **水**：起伏の手がかりなしで平らに描きます。湖の上に等高線が引かれるのは不自然だからです。

各パーツ（glTF のノード、OBJ のオブジェクト、またはグループ）は、それぞれ単独で、最初に当てはまる次のルールで分類されます。

1. **書き出し元のラベル**。`ground:`、`structure:`、`water:` で始まる名前（または `:` の代わりに `|`）は、そのまま採用されます。このプロジェクトの書き出しツールは、すべてのパーツをこの形で名付けます。
2. **水の名前**。単語としての `water`（*water tower*、*-tank*、*-mill*、*-front*、*-fall*、*-pump*、*-pipe* は除く）、`ocean`、`sea`、`lake`、`pond`、`lagoon`、`river`。
3. **地面の名前**。`terrain`、`landscape`、`ground…`、`…_ground`、`heightmap`、`floor…`、`map` / `map_…`、`base` / `base_…`、`road`、`street`、`pavement`、`sidewalk`。
4. **構造物の名前**。`house`、`building`、`bldg`、`wall`、`roof`、`door`、`window`、`stair`、`prop`、`asset`、`clutter`、`debris`、`crate`、`barrel`、`fence`、`tree`、`rock`、`bush`、`vehicle`、`car`、`truck`、`tank`、`bridge`、`tower`、`silo`、`hangar`、`bunker`。
5. **形状**。レベルの X-Z 面積の25%を超えて広がり、面積で重み付けした三角形の60%を超える面が上を向いているパーツは地面です。上を向いている割合が45%未満のパーツ、またはレベルの高さの15%より高く、かつ面積の10%未満しか覆わないパーツは構造物です。上向きの割合は面積で重み付けするので、屋根があるだけの家が平らと判定されることはありません。
6. **それ以外は地面**。判定が曖昧なパーツは地面になります。ほぼ見えない殻を既定にすると、レベルが描画の失敗のように見えてしまうからです。

パーツが1つだけで、それが構造物と分類されたモデルは、代わりに地面になります（*single unnamed mesh - treated as ground*（名前のない単一のメッシュ。地面として扱います））。

### ナビゲーションメッシュ {#navigation-meshes}

`nav:…` という名前のパーツ（レベルの書き出し元の `nav:walkable` など）はナビゲーションメッシュで、兵士が立てる場所を表します。地面として一覧に入ります（*navigation mesh - not drawn, as it lies on the ground; clicks still find it*（ナビゲーションメッシュ。地面の上にあるため描画しません。クリックでは引き続き見つかります））。ただし、**描画はしません**。元になった地面の上に、数センチの誤差で同じ平面に重なっています。描いてしまうと、2つの面がすべてのピクセルで取り合いになります。焼き込まれた地面のテクスチャがあるレベルでは、遊べる範囲全体が、ナビ三角形ごとに1枚ずつ、灰色とベージュの角張った斑点として見えてしまいました。簡略化せずに残すので、[クリックで選ぶ](camera.md#click-to-pick)で、その場所を歩けるかどうかを示せます。ライブラリの項目には残りません。

パネルの**パーツの分類を表示 (N)**（パーツが2つ以上あるモデルで表示）は、すべてのパーツを、その分類と理由とともに一覧にします。理由は *labelled by the exporter*（書き出し元が名付けた）、*name matches pattern*（名前がパターンに合う）、*covers X% of the map, Y% up-facing*（マップの X% を覆い、Y% が上向き）、*Y% up-facing, Z% of level height*（Y% が上向き、レベルの高さの Z%）、*ambiguous - defaulted to ground*（曖昧なので地面にしました）です。分類を変えるには、元のモデルでパーツの名前を変えて、もう一度取り込みます。分割は索引バッファに焼き込まれるためです。

## 簡略化 {#simplification}

**簡略化の目標**は、次の取り込みに使う三角形の予算を決めます（[`simplify.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/simplify.ts)）。

| 設定 | 三角形の数 |
|---|---|
| *Full - no simplification*（簡略化なし。既定） | すべて |
| *High - 8M triangles* | 8,000,000 |
| *Medium - 3M triangles* | 3,000,000 |
| *Low - 800k triangles* | 800,000 |
| *Silhouette - 100k triangles* | 100,000 |

予算は**構造物に60%、地面に40%**で分け、それぞれ別々に簡略化します。構造物は間引きで形が最も早く崩れるためです。水は簡略化しません。簡略化は、二次誤差による辺の縮約（[meshoptimizer](https://github.com/zeux/meshoptimizer)、WebAssembly 経由）です。その前に、同じ位置の頂点をつなげるので、輪郭と硬い辺が残ります。取り込みの注記には `source → now triangles, deviation X%`（元 → 現在の三角形数、ずれ X%）、パーツ全体での地面・構造物・水の内訳が表示されます。800万三角形を超えるモデルで *Full* を使った場合は、*High*（最大3,000万）または *Medium*（それ以上）を提案します。WebAssembly がない場合は簡略化は使えず、取り込みでそう表示されます。

このプロジェクトの書き出しツールが作ったレベルは、すでに予算が決まっています。目標は、予算のない生のアートのためにあります。

## テクスチャ {#textures}

ベースカラーのテクスチャを持つパーツがある `.glb` は、そのテクスチャで描かれます。たとえばレースコースの書き出しには、地形のタイルごとに1枚、配置したモデルごとに1枚が含まれます。

地面のテクスチャは、あれば既定で表示されます。テクスチャを持つ構造物は、**自分のテクスチャのまま不透明**で始まります（縁石、ガードレール、タイヤの壁、標識は、中を見るべき建物ではなく、道路の縁だからです）。ワイヤーフレームと平面シェーディングはオフです。[レベルの見た目](level-appearance.md)を参照してください。

## 大きなレベル {#large-levels}

- 構造物の三角形が**300,000**を超えると、構造物の辺は最初からオフになり、面の不透明度は35%になります。どのピクセルにも辺があると、街区が白一色に見えてしまうからです。
- カメラの遠方の面は、レベルに合わせて広がります（[レベル](levels.md#what-a-level-does-for-the-heat)）。

## 開発者向け {#for-developers}

### テクスチャのアトラス {#texture-atlas}

すべてのテクスチャは、取り込みのワーカーで**1枚のアトラス**にまとめられます（[`atlas.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/atlas.ts)）。これにより、レベルは両方のバックエンドで、1回の描画、1つのサンプラー、1つのテクスチャ座標の属性のままになります。

- 各画像の元のサイズのまま、棚状に詰めます。セットが、どちらの方向でも **8192 px**（WebGPU の既定のテクスチャサイズの上限）に収まらない場合にだけ縮めます。
- 各画像の周りに **16ピクセルの余白**を取り、その余白が守る5つのミップレベルだけを使います。こうすると、遠くの標識が隣のテクスチャを読むことはありません。
- **繰り返すテクスチャ**は繰り返しのままです。glTF のサンプラーが繰り返す（glTF の既定）画像で、テクスチャ座標が 0〜1 の外に出るもの（UV が 0 から 40 まで走るレンガの壁など）は、*タイル*になります。頂点は自分の座標と、16ビットのタイル番号を持ちます。シェーダーが、ピクセルごとに座標をタイルの矩形の中に折り返し、ミップレベルは折り返す前の座標から取るので、継ぎ目は見えません。タイルの余白には、反対側の端が入ります。クランプするサンプラーの軸はクランプされたままです。座標が 0〜1 に収まる画像は、これまでどおり描かれます。タイルのあるレベルは、頂点ごとに4バイト増えます。

### 書き出しの約束 {#the-exporter-contract}

何が作ったレベルであっても、ビューアーがレベルに求めるもの：

- 1つの完結した `.glb`。
- float32 の `POSITION`、三角形のプリミティブ。
- ノードの名前は `ground:*`、`structure:*`、`water:*`（それ以外は上のルールで分類されます）。ナビゲーションメッシュは `nav:*`。残しますが描画はしません。
- ワールド空間の座標、**Y が上**、テレメトリと同じ単位。これにより、配置の手順なしでデータがそのままレベルの上に乗ります。
