# カメラの経路と動画

データの映画を作ります。カメラをいくつかの場所に置くと、ビューアーがその間を飛び、動画を保存します。どのフレームもとてもきれいで、粒状感はありません。カメラと再生ヘッドが一緒に動くため、同じパネルでタイムラプスも作れます（[`PathPanel.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/panels/PathPanel.tsx)、[`campath.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/campath.ts)、[`record.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/record.ts)）。

## 飛行の映像を作る {#make-a-flythrough}

1. 映画の開始地点まで飛び、**カメラパスとレンダリング**の **ここにキーフレームを追加** を押します。
2. 次の地点まで飛び、もう一度押します。停止地点ごとに繰り返します。
3. **パスに沿ってプレビュー**をオンにし、**パス上の位置**をドラッグして動きを確認します。
4. **長さ**（動画の長さ）を設定します。動きは正しいが速すぎる場合は、長さを長くするだけで済みます。
5. **動画をレンダリング**を押します。進行状況の行を待ちます。完了するとファイルがダウンロードされます。

![3つのキーフレーム、スムーズな補間、12 秒、30 fps、16 Mbps を表示したカメラパスとレンダリングのパネル](../assets/img/en/camera-path-panel.webp)

## キーフレーム {#keyframes}

| 設定 | 効果 |
|---|---|
| **ここにキーフレームを追加** | 現在のカメラの位置、ヨー、ピッチ、視野をキーフレームとして末尾に追加します。 |
| **クリア** | すべてのキーフレームを削除します。 |
| キーフレームの一覧 | キーごとに1行: 番号（クリックするとカメラがそこへ飛び、視野も設定される）、位置、`yaw° / pitch°`、削除する **×**。 |

キーは、追加または削除されるたびに、0 から 1 までの正規化されたパスの軸に沿って**等間隔**に並べられます。出力の長さは、移動全体を伸縮させます。そのため、正しいが速すぎる映像は、長さを長くするだけで済みます。ヨーはキーの間で巻き戻されるため、カメラは短い方向に回ります。

キーフレームがない場合、レンダリングは現在のカメラを、クリップ全体で静止させます。これは完全に使えるタイムラプスです。

## パスの設定 {#path-settings}

| 設定 | 既定値 | 範囲（ジョグ） | 意味 |
|---|---|---|---|
| **補間**（2つ以上のキー） | *スムーズ* | *スムーズ* / *直線* | *スムーズ*: キーを通る三次エルミート曲線です。接線は隣のキーから取られるため、各キーで速度が揃い、区間が合流するところで急に揺れません。*直線*: キーの間の直線です。予測しやすいですが、キーごとに角が見えます。視野は常に線形に補間されます。 |
| 移動線（2つ以上のキー） | | | `N 単位の移動 - この長さで毎秒 M`。または、キーがすべて1か所にあるという注記。 |
| **パスに沿ってプレビュー**（1つ以上のキー） | オフ | | ビューポートのカメラをパスで動かし、レンダリングと同じように再生ヘッドも動かします。そのため、レンダリングの前に動きを判断できます。 |
| **パス上の位置**（プレビュー中） | 0% | 0〜100% | プレビューするパス上の位置。 |
| **長さ** | 12 s | 1〜120 s（3600） | 動画の長さ。 |
| **フレームレート** | 30 fps | 6〜60（240） | |
| **ビットレート** | 16 Mbps | 1〜60 Mbps、対数（400） | ヒートのグラデーションは、ビットレートが低いと帯状になりやすくなります。コーデックが誤差を隠せる細部が少ないためです。 |
| **収束待機の上限** | 240 フレーム | 2〜600（10,000） | 1つの出力フレームが正確になるまでに待てる最長の時間。上限に達したフレームも書き出され、数えられます。 |
| 要約 | | | `N フレーム · 窓: 累積/固定/ライフタイム`。タイムラインが「すべて」モードのときは、*（再生ヘッドに意味を持たせるため、レンダリング中は「すべて」を「再生」に切り替えます）*。 |
| **動画をレンダリング** / **キャンセル** | | | レンダリングを開始します。実行中は `フレーム i / n · 待機 w · X MB` と、正確でなかったフレーム数を表示します。データセットが必要です。 |

## ヒント {#tips}

- 出力サイズは、デバイスピクセルでのキャンバスのサイズです（ディスプレイのピクセル比、上限 2）。ブラウザーのウィンドウのサイズを変えると変わります。
- 累積の履歴は、クリップの間にヒートを積み上げます。窓またはライフタイムの履歴は、動いている時間の断片を示します。
- キーフレームの位置は表示座標です。[反転したワールドの軸](camera.md#invert-world-axis)を使うと、切り替える前に作ったキーは、切り替えた後に別の場所を指します。

## 開発者向け {#for-developers}

### レンダリングの処理 {#what-a-render-does}

1. フレームのテスト撮影を行い、デバイスピクセルでの正確な出力サイズを調べます。
2. WebCodecs でコーデックを選びます: **VP9**（`vp09.00.10.08`）、なければ **VP8**。選んだビットレートとフレームレートを使います。`VideoEncoder` がなければ *このブラウザーには VideoEncoder がありません - 動画の書き出しには WebCodecs が必要です* で止まります。どちらのコーデックもなければ、*対応する動画コーデックがありません（VP9、VP8 を試しました）* です。
3. レンダリングに必要な設定を引き継ぎます。再生を一時停止し、**自動予算をオフ**、**段階的な精緻化をオン**にし、スプライト予算をフレームあたり 6,400万に設定します。自動予算はフレームレートを守るものですが、ここでは誤った目標です。収束が遅いフレームを、より少ない行を散布する理由と読んでしまい、収束にさらに多くのフレームが必要になるためです。そして、タイムラインを「すべて」から「再生」に切り替えます。履歴の設定（累積、窓、ライフタイム）はそのままにします。レンダリングは、今見ていたものを、再生して書き残すことを目的としているからです。
4. *n* 個の出力フレームのそれぞれ *f* について、*u* = f / (n - 1) で:
   - カメラを、*u* でのパスの姿勢に置きます（キーがある場合）;
   - 再生ヘッドを、タイムラインの範囲の同じ割合 *u* に移動します（ボックスリプレイでは選択したセッションの範囲）;
   - カメラが動いていなくても、新しい推定値を強制します。前のフレームの累積を引き継ぐと、前の窓の残像が残るためです;
   - 絵が正確になるまで（すべての候補行が1フレームで描かれるか、累積が完了するまで）、フレームごとに待ちます。上限は待機の上限です;
   - 合成されたフレームを取り込み、符号化します。出力の2秒ごとにキーフレームを入れるため、ファイルはシークできます。
5. フレームを WebM ファイルに多重化します（[`webm.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/webm.ts)）。タイムスタンプはフレームレートから選ばれます。各フレームにかかった壁時計の時間は関係ありません。
6. 予算、視野、タイムラインのモード、再生ヘッド、再生中かどうかを元に戻します。
7. 動画を `3dheat-<width>x<height>-<frames>f.webm` としてダウンロードし、`N フレーム、W×H、X MB - すべてのフレームが正確` と、または上限に達したフレーム数を報告します。

**キャンセル**は、現在のフレームの後で止まり（*レンダリングをキャンセルしました。*）、設定を元に戻します。
