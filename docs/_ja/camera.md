シーンは鳥のように飛び回れます。**W A S D** で動き、マウスをドラッグして見回します。このページでは、飛び方、真上や真横からのビューへの移動、カメラの正確な位置の読み方を説明します。

## 4つの手順で飛ぶ {#fly-in-4-steps}

1. ビューを一度クリックして、キーボードの入力を受け取れるようにします。
2. **W** を押し続けると前へ、**S** で後ろへ、**A** と **D** で横へ、**Space** で上へ、**Q** で下へ飛びます。
3. 左か右のマウスボタンを押したままドラッグして見回します。
4. **F** を押して、すべてのデータを再び収めます。

カメラは、透視と平行の投影、プリセットのビュー、入力したポーズ、被写界深度を持つ自由移動カメラです。その設定は、サイドバーの下部にある**カメラとシーン**パネルにあります（レース分析とマッチのタブにも表示されます）。実装は [`camera.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/camera.ts) です。

## 飛ぶ {#flying}

| 入力 | 効果 |
|---|---|
| `W` `A` `S` `D` または矢印キー | 前（ビューの向きに沿って、ピッチを含む）、左、後ろ、右 |
| `Space` または `E` | 上（ワールドの上） |
| `Q` または左 `Ctrl` | 下 |
| `Shift`（押したまま） | 6倍速く |
| 左 `Alt`（押したまま） | 15%の速さ |
| 左か右のマウスボタンでドラッグ | 見回す。ドラッグ中はポインターを固定します。 |
| マウスホイール | 1段で移動速度 ×1.5（透視）。ズーム（平行） |
| `F` | データを収める |
| クリック（ドラッグせずに） | ポインターの下にあるものを表示（[ビューを調べる](#inspecting-the-view)） |
| `C` | カメラの位置、ヨー、ピッチをコピー |
| `G` | 入力した点へ移動 |
| `Esc` | 選択カードを閉じる（ユニットの追従も止める） |

### ユニットを追従している間 {#while-following-a-unit}

リプレイでカメラがユニットを追従しているとき（[試合のリプレイ](match-replay.md)）、飛行のキーは別の働きをします。

| 入力 | 効果 |
|---|---|
| ホイール、`W` / `S` | ユニットに近づく / 離れる（衛星ビューでは上 / 下） |
| `A` / `D`、`Q` / `E` | ユニットの周りを回る（チェイスとオービットのビュー） |
| ドラッグ | ユニットの周りを見回す（コックピットでは内側を見回す） |
| `V` / `Shift+V` | 次 / 前のカメラビュー |
| `Esc` | まず2つ目のユニットを見るのを止め、次に追従を止める |

移動のキーは、[ゲームパッド](gamepad.md)の入力と加算されます。それ以外のすべては[キーボードのリファレンス](keyboard-reference.md)を参照してください。テキストボックスやドロップダウンにフォーカスがある間は、キーは無視されます。ピッチは、真上と真下のすぐ手前で止まります。

## カメラとシーンのパネル {#camera--scene-panel}

![カメラとシーンのパネル：投影、プリセットビュー、視野角のボタン、移動速度、ポーズ](../assets/img/en/camera-panel.webp)

### 投影 {#projection}

**投影**：*透視*（既定）または*平行*。

*平行*（正射影）は遠近法の縮みをなくすので、密度が同じ2つのホットスポットは、フレームのどこにあっても同じ大きさに見えます。これは、マップのヒートマップが比較のために存在する理由であり、アイソメトリックのビューをアイソメトリックにしているものです。平行モードでは、マウスホイールがズームします（スケールを変える前進はありません）。また、[速度の表示](#fly-speed)は隠れます。

**切り替えても、対象の大きさは同じに保たれます。** 平行投影には視野角がないため、その錐台の高さはカメラの距離と無関係です。そのまま切り替えると、大きくズームされるか、何も見えなくなります。平行に切り替えると、錐台の高さは、焦点距離で透視カメラが映す範囲に設定されます（2 × 距離 × tan(視野角 / 2)。焦点距離は、最後に収めたときの距離です）。透視に戻すと、平行ビューがさまよった先ではなく、離れたときの透視のポーズに、同じ見かけの大きさで戻ります。

### プリセットビュー {#preset-views}

| グループ | ボタン | 向き |
|---|---|---|
| **アイソメトリック** | **NE**、**NW**、**SE**、**SW** | 平行。ピッチ -35.264°（= atan(1/√2)。3つの軸がすべて同じ長さに投影される角度）、ヨー -45°、45°、-135°、135°。1つだけでは、どれか1つの手前にあるもので地図の半分が常に隠れてしまうため、4つの角があります。 |
| **立面図** | **上**、**下**、**前**、**後**、**左**、**右** | 平行。上はまっすぐ下を見る（ピッチ -89.9°）、下はまっすぐ上を見る、前は -Z に沿う（ヨー 0°）、後ろは +Z に沿う（180°）、左は -X に沿う（-90°）、右は +X に沿う（90°）。 |
| | **透視に戻す** | 離れた透視のポーズに戻ります。透視のときは無効です。 |
| | **斜め上からの表示** | 透視、ヨー -35°、ピッチ -28°。 |

どのプリセットも投影そのものを切り替えます。透視では「真上からのビュー」もまだ消失点に向かって収束するため、同じ面積が同じに見えなくなります。そして、その向きからデータを収めます。

### 視野角 {#field-of-view}

**視野角**は縦の角度です。既定は 65°、トラックでは 10〜140°（ハンドルを使うと 179°）。ボタンとして **Flat 20°**、**Long 35°**、**Normal 50°**、**Wide 65°**、**Very wide 90°** があります。狭くすると遠近法が平らになり、平行投影に近く見えます。広くすると奥行きが誇張され、距離が判断しにくくなります。平行モードでも有効なままで、そのモードでは、切り替えで求める縮尺と、**フレーム**が使う距離を決めます。

### 移動速度 {#fly-speed}

**移動速度**は、全開のときの1秒あたりのワールド単位（メートル）です。既定は 120。読み込むたびに、データの水平方向の広がり / 12 になります。対数で、0.02〜20,000 です（ハンドルを使うと 200,000。ハンドルは量ではなく比率で変えます）。マウスホイールは、0.02〜200,000 の範囲で1段ごとに 1.5 倍または 1/1.5 倍します。

同じ値がビューの右下にも表示されます（透視のみ）。m/s または km/s での速度と、その速度でデータ（3Dレベルを読み込んでいる場合はレベル）を横切るのにかかる時間です。上下にドラッグすると、速度を変えられます。

### 近方と遠方 {#near-and-far}

**近方**（既定 0.5）と**遠方**（既定 40,000）は、クリップの距離です。どちらも読み込むたびにデータから再計算され（近方 = max(0.05, 広がり / 20,000)、遠方 = 広がり × 12）、より大きな3Dレベルがあれば、狭めることはなく広げられます（[レベル](levels.md#what-a-level-does-for-the-heat)）。その比率が、遮蔽が頼る奥行きの精度を決めます。そのため、近方が極端に小さく遠方が極端に大きいと、[遮蔽](depth-and-culling.md)が弱くなります。シーンの外から、またはその地面の高いところから見るとき、実際に使われる近方の面は、その距離の 2% まで外へ移ります。そのため、遠くの高い位置から見た地図でも、水と岸がちらつかないだけの奥行きの精度が保たれます。ボックスには、設定された値がそのまま表示されます。

### ポーズ {#pose}

5つの数値の欄 **X**、**Y**、**Z** と **yaw °**、**pitch °**。どれにもフォーカスがない間は、カメラに従って値が変わります。値を入力して `Enter` を押す（または欄から離れる）と、カメラがそこへ動きます。**コピー**は `pos X Y Z · yaw A · pitch B` をクリップボードに入れます（その規約を選んでいれば、後ろに `(game yaw)` が付きます）。飛んで探すのが探索の方法で、座標はビューを再現する方法です。これらは、[カメラの読み出し](#camera-readout)と同じ数値です。データ自身の座標で、軸を反転している場合も同じです。ヨーは、選んだ[規約](#yaw-conventions)によります。

### ワールド軸を反転 {#invert-world-axis}

**ワールド軸を反転 X / Y / Z** は、その軸を逆にしてワールドを描きます。左手系のワールドを保つゲームは、この右手系のビューアーでは鏡像になります（右に曲がるコーナーが左に曲がるものとして描かれる）。X または Z を反転すると元に戻ります。**変わるのは描き方だけ**です。データ、分析、ツールが表示するすべての座標（ポーズ、定規、断面）は、ゲーム自身のままです。ビューはその場で反転し、同じ場所を見続けられます。この設定はブラウザに記憶されます（`localStorage` のキー `heat3d.mirror`）。読み込み時の[反転](axes-units-and-time.md#flips)と比べてください。反転はデータを変えます。

## ビューを調べる {#inspecting-the-view}

カメラがどこにあるか、ポインターの下に何があるか、点へ移動すること。カメラとシーンのパネルの**調査**のブロックと、ビューの左上の2つのオーバーレイです。コードは [`pose.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/pose.ts)、[`pick.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/pick.ts)、[`inspector.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/inspector.ts) にあります。

| 操作 | 既定 | 意味 |
|---|---|---|
| **ビュー上にカメラ位置を表示** | オン | 下のカメラの読み出し。**×** でも閉じられます。 |
| **クリックでその場所を表示** | オン | 下のクリックで選ぶ機能。 |
| **ヨーの規約** | ビューア | 読み出し、ポーズの欄、移動のボックスが、どのヨーを表示し、読むか。 |

この3つは、ブラウザに記憶されます（`localStorage` のキー `heat3d.inspect`）。

### カメラの読み出し {#camera-readout}

ビューの左上にあります。カメラの **x**、**y**、**z**、**yaw**、**pitch** をリアルタイムで表示し、ヨーの規約を示すタグが付きます。[ポーズ](#pose)の欄と同じ数値です。飛んでいる間もコストはかかりません（パネルを描き直さず、フレームの時計に合わせてページに書き込みます）。

- **コピー**（または、テキストボックスの外で `C`）は `x X y Y z Z yaw A pitch B (viewer yaw)` をクリップボードに入れます。言語にかかわらず小数点は `.` です。移動のボックスや、どのスクリプトでも読み戻せる行です。
- **移動**（または `G`）は、その下にボックスを開きます。点を貼り付けて `Enter` を押すと、その点を見られます。コピーしたポーズ全体を貼り付けると、そのビューに立てます。`Esc` でボックスを閉じます。

### 座標：データ自身の座標系 {#coordinates-the-datas-own-frame}

調査のツールが表示または受け取るすべての座標は、**読み込んだデータ自身の座標系**にあります。読み込みの[軸の対応](axes-units-and-time.md)（上の軸、反転、縮尺）は元に戻されます。ビューから読み取った位置は、ソースの表が持つ数値になり、表からの数値を移動のボックスに入力すると、その場所に着きます。対応が何も変えない場合（Y が上で、縮尺のない読み込み。キャプチャツールとレベルの書き出し元が書く形式）は、単にワールドです。それ以外の場合は、読み出しに**データ座標系**のタグが付きます。データセットがなければ、座標はワールドの座標です。ヨーとピッチは常に、ビューアーのワールド（Y が上）を基準にします。

### ヨーの規約 {#yaw-conventions}

| 規約 | ヨー 0° が向く方向 | 増える方向 | 使われる場所 |
|---|---|---|---|
| **ビューア** | -Z | -X | 飛行カメラ、[プリセットビュー](#preset-views) |
| **ゲーム / キャプチャツール** | +X | -Z | キャプチャツールの `yaw` 列とポーズ。ビューアーの座標系で書き出したレベルでは、そのゲーム自身のヨー |

ピッチは両方で同じです。水平から上向きです。2つの違いは直角1回転分だけです。

> ビューアーのヨー = ゲームのヨー - 90°

方向 `d` は、ゲームの規約では `(cos p · cos y, sin p, -cos p · sin y)`、ビューアーの規約では `(-sin y · cos p, sin p, -cos y · cos p)` です。キャプチャの表からヨーをそのまま入力したい場合や、読み出しと比べたい場合は、**ゲーム / キャプチャツール**を選びます。

### 点へ移動 {#going-to-a-point}

調査のブロックの**点へ移動**（および読み出しの**移動**のボックス）：

- テキストボックスは `x, y, z` または `x y z`（または `x; y; z`）を受け取ります。小数点でも小数点のカンマでも構いません。`-321.6, 137.8, -59.9` と `-321,6 137,8 -59,9` は同じ点です。5つの数値なら、ヨーとピッチも加わります。読み出しやポーズの欄からコピーしたポーズは、ラベルと規約を含めて全体が読まれます。
- **ヨー °** と **ピッチ °**（任意）は、選んだ規約でカメラを回します。
- **見る**は向きを保ちます（水平に見ていた場合は、少なくとも 20° 下を見るように傾けます）。その向きに沿って、現在の距離まで下がります。距離は、シーンの幅の 0.3%〜3% の間に保たれます（2 km のレベルでは 6〜60 m）。焦点距離、平行ビューの高さ、移動速度もそれに従うので、ビューがすぐ使える状態で着きます。
- **ここに立つ**は、カメラをその点に置き、指定したヨーとピッチ（または今の向き）に向けます。

貼り付けたポーズが自分のヨーとピッチを持つ場合は、常にそのビューに立ちます。

### クリックで選ぶ {#click-to-pick}

ビューをクリックすると（押して離す。4ピクセルを超えてドラッグしない。ドラッグは見回しになります）、左上にカードが表示され、ポインターの下にあるものが示されます。[定規](measure.md)が有効な間は、クリックは定規に送られます。

**描かれたデータの点が優先されます。** クリックから8ピクセル以内で、実際に描かれているものの中で最も近いサンプル。時間の窓と寿命の中にある行、[フィルター](filters.md)を通る行、表示しているグループ、差分の分割の中にある行、距離のカリングの内側、熱をクリップする断面の内側の行です。ボックスのリプレイでは、ポインターの下にあるボックス（その上のどこでも）。カードには、その行が持つすべての列が、ソースの列名のまま表示されます。時刻（壁時計の時刻、またはファイル自身の秒を `m:ss.ss` で）、人、グループ、セッション、保持されている各列、位置、見ている方向です。カメラからの距離も表示されます。メモリにあるのは、読み込みで残した列だけです。[フィルターの列](column-mapping.md)に選ばれなかった列は表示されません。

**それ以外の場合は、レベルの面**：クリックの光線がレベルの実際の三角形に交わる点（定規の基準面ではありません）。その点が属する**パーツ**（書き出し元の名前、`structure:props`、`ground:terrain …`）、その**種類**（地面、構造物、水、地図画像）、座標、距離を表示します。断面や距離のカリングで隠れている形状は、通り抜けます。レベルに[ナビゲーションメッシュ](model-levels.md#navigation-meshes)がある場合は、その名前を示し、その場所がその上にあるかどうか（✓）を示します。`≈` で始まるパーツの名前は、パーツのバウンディングボックスから推定したものです。読み込み時にそのレベルの部分が簡略化されたためです。

カードは、閉じる（**×**、`Esc`）か、別のクリックで別のものが選ばれるか、何もない場所をクリックするまで残ります。シーン上の点には水色の十字が、その上の画面には輪が描かれます。ボタンは **コピー**（すべての値と、座標 `x, y, z`）、**見る**、**ここに立つ**です。（データの点の場合は、見ている方向の情報がある行なら、その行が見ていた向きに。面の場合は、その上 1.7 m に。）

レベルは、最初にピッキングが必要になったクリックのときに索引化されます。フットプリントの上の列のグリッドで、フレームの合間に数ミリ秒ずつ作られるので、ビューが止まることはありません（数百万の三角形のレベルで約1秒の作業）。レベルが変わるまで保持されます。それまでは、カードは割合付きで *Preparing the level for picking*（ピッキングのためにレベルを準備中）と表示し、準備ができたらそのクリックに答えます。400万行を超える描画されたデータの点の検索も、同じようにフレームに分けて行われます。

## 被写界深度 {#depth-of-field}

カメラとシーンの中の折りたたみセクションで、有効な間は *Depth of field - on*（被写界深度 - オン）と表示されます。既定ではオフです。これは見せ方の効果であり、既定のビューは解釈ではなくデータを見せるべきだからです。

| 操作 | 既定 | 範囲（ダイヤル） | 意味 |
|---|---|---|---|
| **有効** | オフ | | |
| **フレームしたものに合焦** | オン | | 最後の収め方で使った距離に焦点を合わせます（*Focused at N m.*（N m に合焦））。 |
| **合焦距離** | 1000 | 1〜200,000、対数（10,000,000） | 焦点が手動のとき表示されます。 |
| **絞り** | ±35% | ±2%〜±200%、対数（±3200%） | 焦点距離の割合として、鮮明に保たれる奥行き。シーンは部屋から 8 km の地図まであるので、f 値ではなく相対値です。 |
| **最大ぼかし** | 12 px | 1〜48（256） | ぼかし半径の最大値。コストはこれに比例します。 |

ぼかされるのは**レベル、グリッド、ボックス**で、**熱はぼかされません**。ピクセルの熱は、多くの奥行きのスプライトの合計なので、ピントが合わなくなる単一の奥行きがありません。その後ろにある形状でぼかすと、熱がどこに浮いていても、前にある場合は誤りになります。鮮明なデータを、ぼやけた背景の上に載せるほうが、どちらにとっても有用でもあります。ぼかしは、合成パスの24タップのゴールデンアングルの集め方です。鮮明な前景が、その後ろのぼやけた背景によって外に広がらないよう重み付けされています。変えると、熱の累積を再開せずに描き直します。

## キャンバスの解像度 {#canvas-resolution}

キャンバスは、ディスプレイのピクセル比で描かれ、上限は 2 です。熱のバッファは、それより低い解像度で描かれることがあります（[熱の解像度](performance-and-stats.md)）。
