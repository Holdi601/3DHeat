# セッション、人物、グループ

**人物** は、動く 1 つのもの (プレイヤー、車) です。**チーム/グループ** は、それが属する陣営です。**セッション** は、1 つの試合またはラップです。[用語集](glossary.md) を参照してください。

ファイルの 1 行は、この 3 つすべてを指定できます。

| x | y | 時刻 | プレイヤー | チーム | 試合 |
|---|---|---|---|---|---|
| 10.5 | -30.2 | 12.0 | Blue 1 | Blue | Match 01 |

`player` が人物、`team` がグループ、`match` がセッションです。

任意の列が 3 つあり、それぞれの行が *誰* のものか、そして物語の *どの場面* のものかを説明します。読み込みのとき、それぞれは辞書エンコードされます。文字の値は、行ごとの小さな整数の ID と、読み込みのすべてのファイルで共有されるラベルの一覧 1 つになります。

## 人物 {#person}

**人物 ID** 列は、行が属する動くものの名前を指定します。プレイヤー、ボット、車などです。行ごとに 32 ビットの ID として保存されます。

人物と時刻の列があると、読み込みは各行の **生存期間** を計算します。同じ人物の、**同じセッション内** での次のサンプルまでの時間です。次のサンプルがないとき (人物が死亡した、離脱した、ログが終わった) は、「なし」(番兵の -1) になります。生存期間は、[タイムライン](timeline.md) の **ライフタイム** の履歴、[ボックスリプレイ](box-replay.md) の補間と古さ、[ラインヒート](line-heat.md) のルートの切れ目に使われます。後続のない行をどう扱うかは、表示の設定 (*予備の寿命*) であり、データに焼き込まれてはいません。

各人物には、時刻順で **最初の** 行のグループが与えられます。その割り当てが、ボックスリプレイでのボックスの色を決め、どのグループの表示切り替えでその人物が隠れるかを決めます。ヒートモードは、代わりに各行自身のグループを使います。

### 同時に複数のものが使う名前 {#names-worn-by-several-things-at-once}

名前が、いつも 1 つの実体とは限りません。エクスポートによっては、どの試合のどのボットも、同じ 1 つの名前で記録されます。そのような「人物」の 2 つのサンプルを (補間、航跡、ルートでつなぐと)、地図の上で別々の 2 つの生き物を結ぶ線が描かれてしまいます。

読み込み ([`computeLifetimes`](https://github.com/Holdi601/3DHeat/blob/main/src/data/builder.ts)) で、名前は **共有** と印を付けられます。その名前の 2 つの記録が次のすべてを満たすときです。

- 同じセッションにある。
- 同じ時刻である。
- 同じ種類である (残されているカテゴリ列がすべて同じ値)。
- データの範囲の対角線の 1% より離れている。

共有された名前は、1 つ 1 つのサンプルとして描かれます。補間も、航跡も、ラインヒートのルートもありません。ヒート (その熱) など、ほかの点は影響を受けません。データセットのパネルには、印の付いた名前の数が、3 つまでの例とともに一覧されます。ボックスリプレイのパネルも、その数を繰り返します。

## セッション {#session}

**セッション/試合** 列は、行がどの試合、襲撃、ラウンド、走行、ラップに属するかを示します。これが、人物のサンプルを 1 本の連続した軌跡にします。実際のテレメトリでは、同時に行われる試合がしばしば混ざります。そして、再生ヘッドの直前の人物のサンプルと、直後のものが、何百メートルも離れた別の試合から来ている場合があります。セッション列があると、次のようになります。

- 補間、航跡、ラインヒートのルートが、セッションの切り替わりをまたぐことは決してありません。
- 行の生存期間は、そのセッションの終わりで終わります。
- **セッション** の選択が、サイドバーの上端、表示モードの下に出ます。

セッション列は、**タイムスタンプ** であることが非常によくあります。その試合の開始時刻が、その試合のすべての行に繰り返されているのです。そのため、自動マッパーは、人物とグループより先にセッションの名前を探します ([列のマッピング](column-mapping.md#session-person-group) を参照)。レースのラップやスティントもセッションです。同じ車による 2 つのラップを 1 本の軌跡にまとめてはいけません。

### セッションの選択 {#the-session-picker}

![10 個の試合があるファイルで開いたセッションの選択: すべてのセッション (10)、Match 01、Match 02 など](../assets/img/en/sessions-persons-groups-picker.webp)

*1 つのファイルに 10 個の試合があります。1 つを選ぶか、すべてを見ます。*

データセットにセッションの一覧があるとき表示されます (下の上限を参照)。

| 部分 | 意味 |
|---|---|
| 右側のラベル | 選んだセッションの行数、または *すべて一度に*。 |
| メニュー | *すべてのセッション (N)*、その後にすべてのセッションを、最も忙しいものから、`ラベル - N 行、範囲` の形で。範囲は、90 秒未満なら秒、90 分未満なら分、それより長ければ時間です。 |
| 琥珀色のヒント | *すべてのセッション* のとき表示されます。位置は、やはりセッションをまたいでつながることはありません。ただし、同時に行われる試合では、無関係なプレイヤーが地図上に一緒に出ます。 |
| ヒント | 1 つのセッションが選ばれているヒートモードで表示されます。選択は再生ヘッドを動かすだけです。 |

読み込み時には、最も忙しいセッションが選ばれます。セッションを選ぶと、再生ヘッドがそのセッションの開始へ移動します。

選択で変わるもの:

- **[ボックスリプレイ](box-replay.md)** では、どのセッションを再生するかが決まります。そのセッションのボックスと航跡だけが描かれ、タイムラインの範囲はそのセッション自身の範囲になります。
- **ヒートモード** では、ヒートは制限されません。選択肢の下のヒントがそれを伝えます: *ヒートモードでは、これはセッションの開始へ再生ヘッドを動かすだけです。ヒートはすべてのセッションを数え続けます。ボックスリプレイは、選んだセッションだけを再生します。* ヒートを 1 つのセッションに制限するには、セッション列をフィルター用の列としても残し (*フィルター用に残す*)、それでフィルターをかけます。1 つの列が、セッションの列であり、同時にフィルターの列でもあっても構いません。読み込みは、チェックされたフィルター列を、それがほかにどんな役割を持っていても、それぞれ単独で読みます。

### セッションが多すぎる場合 {#too-many-sessions}

セッションは最大 **100,000** まで一覧されます。それを超えると、その列は実際には ID です (数行ずつのセッションが何百万もあるフォルダーなど)。それだけのラベルをワーカーからページへ送ると、タブのメモリが尽きてしまいます。そこで読み込みは、セッションの **ID** を残します。そのため、境界は今も至るところで守られます。ただし、ラベルとセレクターは捨てられ、データセットのパネルがそれを伝えます。

## グループ {#group}

**チーム/グループ** 列は、どんな種類の少ない値の列でも構いません。チーム、陣営、分隊、勢力、プレイヤーか AI かのフラグ、車のクラスなどです。行ごとに 16 ビットの ID として保存され、次のものを動かします。

- [チーム一覧](teams-list.md) (グループごとの表示、+ / − の陣営)。
- [チームのヒート](team-heat.md) (グループごとの色相)。
- グループごとに分割する [差分](difference.md)。
- [ボックスリプレイ](box-replay.md) のボックスの色 (グループごとの色相のファミリー、メンバーごとの濃さ)。

### 上限 {#limits}

異なるグループは、最大 **4,096** まで。グループ ID は、GPU 上の各行の位置テクセルの 4 番目のチャンネルに乗ります。そして、各グループは、シェーダーが *隠す*、*加える*、*引く* を決めるために読む、4,096 幅の符号テーブルに 1 つのテクセルを必要とします。異なる値がそれより多い列は、グループではなく ID です。**読み込みは、すべての行を残し、グループ分けだけを捨てます**。データセットには、代わりに人物の列としてマップするか、フィルター用の列として残すよう提案する警告が付きます。

同じ 4,096 の上限は、残されたカテゴリのフィルター列にも適用されます。それより広いものは残されず、データセットがそれを伝えます。数値の列 (たとえば時刻) には、*範囲* のフィルターとしてはそのような上限はありません。

グループの値 `0`、空の値、`none`、`unknown`、`null`、`-1` (大文字と小文字は区別しません) は、[チームのヒート](team-heat.md) では「グループなし」を意味します。自信のある色ではなく、中立の灰色で描かれます。

## 実体の大きさ {#entity-size}

追跡される 1 つのもの (プレイヤーの衝突ボックス、車) がどれくらい大きいかで、[ボックスリプレイ](box-replay.md) のボックスと視線の線の大きさが決まります。パネルにそのための欄はありません。ファイルの [`heat3d` のヒント](data-formats.md#the-heat3d-hints) から来ます (`entity.size`。ファイル自身の単位で、CS2 のコンバーターは 32 を書きます)。読み込みは、それに単位の倍率を掛けます。

読み込みのたびに ([`calibrate`](https://github.com/Holdi601/3DHeat/blob/main/src/data/calibrate.ts))、*範囲* はデータの X と Z の広がりのうち大きいほうです。

| 設定 | 実体の大きさがあるとき | ないとき |
|---|---|---|
| キューブの大きさ | 実体の大きさ | 範囲 / 500 |
| 視線の線の長さ | 実体の大きさ × 4 | 範囲 / 200 |
| スプライトの半径 | 範囲 / 120 | 範囲 / 120 |
| 飽和点 | 解析的な推定値 (その後、測られる) | 同じ |
| 飛行速度 | 範囲 / 12 | 同じ |
| 遠い面 | 範囲 × 12 | 同じ |
| 近い面 | max(0.05, 範囲 / 20,000) | 同じ |

## データセットのパネル {#the-dataset-panel}

ソースパネルの下にあります。データセットが読み込まれていると、次のものが表示されます。

- データセットの **名前** - 選択、行数、ファイル数、使われた場合は間隔。
- **`N チーム · N 人 · N 秒の範囲`**。
- 読み込みが出したすべての **警告**。データセットが読み込まれている間は、琥珀色で表示されます。値が多すぎて外されたグループやフィルター列、一覧されていないセッション、共有された名前、欠けた行、スキップされたファイルなどです。
- [合成ジェネレーター](synthetic-generator.md)。
- **アンロード**。データセットを取り除きます。

行数は、パネルのヘッダーに表示されます。
