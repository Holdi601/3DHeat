# 機動: 集団がどう動くか

**インサイト → 機動** は、各陣営のユニットが *集団として* どう動くかを追い、集団が行った機動に名前を付けます。側面攻撃、挟撃、突破、待ち伏せ、撤退、ミサイル防御、T 字の横切りなどです。各機動には、どれくらい確かか、その根拠の数字、成功したかどうか、教範や歴史上の似た例が付きます。**マスアナリシス → 機動** は、これを何千もの試合にわたって数えます。マップ、モード、陣営ごとに、どれくらい多く行われ、どれくらい成功したかを示します。

すべてブラウザの中で、専用のワーカー (`src/insights/maneuver`) が計算します。数百ユニットの試合なら 10〜500 ミリ秒、数千のオブジェクトがある 2 時間の航空戦でも約 1 秒です。

## 使い方 {#using-it}

- **インサイト** を開き、タブ **機動** を選びます。開いたときに数えます。フィルタを変えたら **もう一度検索** を押します。
- **確実 / 可能性が高い / 可能性あり** で、表示する確からしさを決めます (初期値は可能性が高い)。
- **タイムライン** には陣営ごとのレーンと、機動ごとのバーがあります。その下の **リスト** は同じものを時間順に並べます。クリックすると、その開始点のリプレイに切り替わり、カメラがそこへ飛び、機動を 3D で描きます。各集団の動きは矢印で、挟撃の 2 本の腕はその弧で描かれます。重要な瞬間の集団の輪郭も出ます (敵は自陣営の色)。敵の前線は白い線です。**すべてを 3D で描画** を押すと、同じ試合の他の機動も薄く加わります。線は選択が変わったときに一度だけグラフィックカードへ送られ、毎フレーム送られることはありません。再生中に 480 の機動を描いても、実機の GPU (WebGL2 と WebGPU) では、フレーム時間は描かない場合と同じです (p99 18.0〜18.5 ms、最大 19.5〜20.8 ms)。
- 開いた機動には、その結果 (機動を行ったユニットが、実行中とその直後に撃破した数と失った数。試合全体での陣営自身のやり取りと比べたもの)、その根拠、そして知識ベースの関連項目が出ます。関連項目は教範と歴史上の似た例です (挟撃ならカンナエ、突破なら 1940 年のセダン、T 字の横切りなら対馬沖海戦、おとりならボロ作戦など)。
- 最後にある小さな表は、種類と陣営ごとに、行われた数と成功した数を示します。

## 集団の見つけ方 {#how-groups-are-found}

すべてのユニットは共通の時間軸に置かれます (歩兵なら 1 秒刻み、それ以外は 2 秒刻み、非常に大きなファイルではさらに長い刻み)。死亡したユニットは、その場に留めておきます。そうすると、リスポーンが地図を横切る線を描くことはありません。各時点で、同じ陣営かつ同じ種類 (航空機、車両、艦船、歩兵) のユニットは、近いときに結ばれます。距離は歩兵で 18 m、車両で 170 m、艦船で 3 km、航空機で 5 km です。さらに、速度が似ている必要があります (速いほうの速度の半分以内、または両方とも静止)。クラスタは、メンバーの多くがいた集団の ID を引き継ぎます。種類のないユニットは、その速度によって歩兵、車両、航空機のどれかに入れられます。

集団の **形** は、進行方向に対して読まれます。前後と左右の広がりで縦隊か横隊かを決め、中央が先頭に立てばくさび形、メンバーが片側へ段違いに下がれば梯形、四隅を守れば箱形です。

すべては試合自身の規模で判断されます。**交戦距離** `R` は、撃破者と被撃破者の距離の 75 パーセンタイルです (そのゲームの領域の範囲に収まるよう制限されます)。機動の時間は、ユニットの種類に応じて伸び縮みします (歩兵は地上の 3 分の 1)。

## 見つけるもの {#what-it-finds}

| 機動 | 見つかる条件 |
|---|---|
| 編成 | 集団が 30 秒間、移動中のステップの 60% で同じ形を保つ |
| 正面攻撃 | 集団が射程外から接触まで、¾ R 以上の距離を詰める。敵の向きの 35° 以内から |
| 側面攻撃 | 同じだが、50〜130° の方向から (背後は 130° より先)。確実なのは、そこで敵と交戦している味方の *固定部隊* がいる場合だけ (どちらの場合も撃破がある) |
| 挟撃 | 同じ陣営の 2 つの側面攻撃が、同じ敵の本体に、反対側から (100° 以上離れて)、90 秒以内に行われる。両方の腕が交戦していれば確実 |
| 包囲 | 敵の密集した集団を、相手側の、それ以上の数のユニットが 1.5 R 以内で囲む。2 つ以上の集団からなり、100° を超える隙間がなく、1 分間続き、自陣営から切り離されている。環が ½ R まで狭まり、そのポケットと交戦すると確実 |
| 突破 | 集団が、保持された線を越える (30 秒間、その左右に敵が立っていて、その陣営の中央がその線の向こう側)。½ R 向こうに達し、20 秒そこに留まって交戦すると確実。さらに R 向こうに達すると突破 |
| 支援射撃付きの前進 | 小さな集団で、一部が動き、残りが止まっている。役割が 4 回以上入れ替わり、止まっている部分が援護射撃をする |
| 集中 / 分散 | 陣営の、最も密集した点の近くにいる割合が 35% から 60% に上がる (ユニットが 1.5 R 以上の距離から集まり、その後接触する)。または、陣営が広がって下がる |
| おとり | 接触中の小さな部隊が、他所から 2 つ以上の敵を引きつける。その後、より大きな集団が、4 射程離れた、敵の少ない所を攻める |
| 撤退 / 追撃 | 接触中の集団が向きを変え、交戦した場所から R 離れる。その場所の敵が、ちょうど集団の 1 機を撃破していて、集団がその撃破者から 2 R 離れたら確実 (徒歩では決してない。下を参照)。同じ方向に動く敵が付いてくれば追撃 |
| 縦深防御 | 敵の進路を横切る 2 つ以上の帯に、止まったユニットがいる。帯は R の深さがあり、敵が近づき、帯から射撃する |
| 逆斜面 | 丘を越えてきた被撃破者を、止まっていたユニットが近距離で 3 件以上撃破する |
| 待ち伏せ | 移動中の集団が、45 秒間止まっていた敵と出会う。敵が先に撃ち、移動側は 2 機、または集団の半分を失う |
| 先行警戒 | 3 以上のまとまりの前を、1 つか 2 つのユニットが先行し、最初に敵と接触する |
| 内線 | 陣営の集団が、相手の集団の間で互いに近くまとまり、そのユニットが集団の間を移る |
| テンポ | 接触への対応 (旋回、速度の変更、最初の射撃) が 1.5 倍速い。Mann-Whitney の p が 0.05 未満 |
| クランク、ノッチ、ドラッグ、ポンプ | ミサイル発射の目標が、発射側を 35〜70°、75〜105°、140° 超へ旋回させる。または引きずって、旋回し直させる |
| 空中の挟撃、壁、先導と追従、すり潰し | 2 機が 1 つの敵へ分かれて向かう。3 機が横一線に敵へ向かう。ある要素が別の要素の 5〜20 km 後ろにいる。2 機が 1 点の周りを、1 点の距離で旋回する |
| 戦闘空中哨戒 | 3 分間、ある拠点の周りを旋回する |
| エネルギーの戦い / 角度の戦い | 近距離の戦闘で、針路が 30° 離れ、各機が交互に相手を正面に捉える。またはその間で撃破がある。高度を使って上昇する、または水平で急旋回しながら減速する。一方が他方を撃破したら確実 |
| 攻撃パッケージ、SEAD | 役割の混ざった航空集団で、そのうち何機かが地上を攻撃する。防空の撃破は、ほかの地上撃破の多くより前に起きる |
| 戦列、T 字の横切り | 縦隊の 3 隻の艦。敵の縦隊の先頭を、正方形に並んで横切る |

各機動は、知識ベースのどの **パターン** を示すかを示し (`patterns-maneuver.ts`: 編成、正面攻撃、二重包囲、包囲、突破、射撃と機動、おとり、撤退、追撃、縦深防御、スクリーニング、分散、ミサイル防御、角度の戦い、戦闘空中哨戒、攻撃パッケージ、戦列、T 字の横切り)、最初に読むべき項目を示します。古い項目は、新しいパターンを `knowledge/maneuver-tags.ts` を通して引き継ぎます。[知識レンズ](knowledge.md) を参照してください。

**成功** は、ユニットが機動の間 (と 1 分後まで) に行ったやり取りを、試合全体での陣営のやり取りと比べます。撤退は、旋回後に失った数が旋回前より少なければ成功です。ミサイル防御は、航空機が 1 分間生き残れば成功です。包囲は、ポケットの損失が半分になれば成功です。

## 多くの試合にわたって {#over-many-matches}

各試合の要約 (`src/mass/summarize.ts`。[マスアナリシス](mass-analysis.md) を参照) には、小さな `maneuvers` の節があります。種類と陣営ごとに、行われた数 (可能性が高い以上のもの)、成功した数、成功しなかった数、撃破、損失が入ります。**マスアナリシス → 機動** は、フィルタが残す試合にわたってこれを合計します。マップとモードごと、または全体です。成功率には Wilson 信頼区間が付きます。行をクリックすると、その機動が行われた試合を読み込みます。この節の前に書かれた要約にはこれがありません。その場合は `node tools/3dheat-summarize.mjs <フォルダ> --force` で追加してください。

## どれくらい確かか {#how-sure-it-is}

機動を仕込んだ合成試合 (`synth.ts`。`maneuver.test.ts` が実行) では、仕込んだ 28 種類すべてが可能性が高い以上で見つかります。報告された 50 件の機動のうち、31 件は仕込んだ種類で、残りの 19 件も実際にそこにあります (移動する集団の編成、突破する縦隊の正面接近など)。誤りはありません。帰無試合 30 件 (ランダムウォークを離して混ぜたもの、ランダムに立つユニット、直線飛行の航空機、群衆がうろつく場面) では、可能性が高い以上で何も報告されません。

実データ (数十の地上戦、数件の長い航空戦ミッション、十数の射撃試合) では、戦車戦では正面攻撃、側面、突破、包囲が、航空戦では編成と近距離の戦闘が、航空戦ミッションではミサイル防御、戦闘空中哨戒、先導と追従の組が、射撃試合では正面の処刑、縦隊、待ち伏せの数件と、挟み撃ちの組が見つかりました。しきい値は、ゲームの規模に合わせた教範の形です。1 件の発見は、その根拠と一緒に読んでください。表の割合は、その信頼区間と一緒に読んでください。

### 同じ試合の帰無モデルとの比較 {#against-null-models-of-the-same-matches}

検出器は、地形と群衆に惑わされることがあります。乱戦では、どの集団にも周りじゅうに敵がいるからです。そこで、各種類は、同じ試合から作った **帰無モデル** でも走らされます (`nulls.ts`)。帰無モデルでは、両陣営が実際のように出会わなくなります。一方の陣営のタイムラインを、試合の 3 分の 1 から 3 分の 2 の間の時点で回転させる (*shift*)。またはその航跡を、マップの中心の周りに回転させる (*rotate*)。さらに、チームのラベルを混ぜる (*teams*。これは構造上、実際の戦いのおよそ半分を残します)。戦闘は、撃破と、その被撃破者とを組にしたものだけを数えます。撃破者は 2 R 以内、被撃破者はその位置にいる必要があります。帰無モデルはこの組を壊します。実際と帰無モデルで、可能性が高い以上で見つかった件数です (戦車戦 30 件、射撃試合 12 件):

| 種類 | 戦車戦: 実際 / shift / rotate | 射撃試合: 実際 / shift / rotate |
|---|---|---|
| 包囲 | 0 / 0 / 0 (以前は 1.3 / 1.2 / 0.8) | 0 / 0 / 0 |
| 突破 | 0.03 / 0.02 / 0.05 (以前は 1.6 / 1.8 / 1.4) | 0 / 0 / 0 |
| 側面 | 0.33 / 0.07 / 0.10 | 1.0 / 0.08 / 0.21 |
| 正面攻撃 | 0.87 / 0.47 / 0.12 | 14.4 / 6.5 / 4.3 |
| 撤退 | 0.03 / 0 / 0.02 | 0.08 / 0.08 / 0.5 (そのため、徒歩では確実にならない) |
| 待ち伏せ | - | 0.17 / 0.04 / 0.04 |
| エネルギーの戦い | 1.2 / 0.1 / 0.85 | - |
| 角度の戦い | 0.6 / 0.07 / 0.3 | - |

戦場の中心付近で行われる近距離の空中戦は、その中心の周りの旋回に耐えます。そのため rotate の列は、地上の種類よりも空中戦を割り引きません。1 つの陣営の中で完結する種類 (編成、戦闘空中哨戒、すり潰し、攻撃パッケージ、SEAD、支援射撃付きの前進、先行警戒) は、もう一方の陣営に依存しないので、この方法では試しません。`maneuver.test.ts` は、帰無モデルが、合成試合に仕込んだ側面、挟撃、包囲、突破、待ち伏せ、撤退を取り除くことを確かめます。

## 限界 {#limits}

- 集団は、時間にわたる位置を必要とします。イベントのファイルしかない場合は位置がありません。
- 向きはデータから読めません。敵の前線は、固定部隊が敵と交戦している場所、なければ敵が動いている方向、それもなければ攻撃側が来た方向とします。
- 地形は、ユニット自身の高さから読みます (逆斜面)。見通し線の判定はありません。
- 非常に大きなファイルは、より長い刻みでサンプリングされます。その中の短い航空機の機動は、それでも 2〜4 秒の刻みから読まれます。
