# 描画の内部

ビューアーは何百万もの点を、光る円のかたまりとして描き、それを足し合わせます。このセクションでは、それを速く保つ工夫と、統計オーバーレイの数値の意味を説明します。ビューアーが遅く感じるとき、または描画部分に手を入れたいときに読んでください。

```
data -> time window -> GPU filters -> sampling plan -> splat -> accumulate -> colour -> screen
```

お使いのコンピューターの状態は、ビューの右上にある統計の箱で確認できます: [パフォーマンスパネルと統計オーバーレイ](performance-and-stats.md)。新しい言葉（GPU、行、スプライト、ヒートマップ）は[用語集](glossary.md)にあります。

## 中心となる問題 {#the-core-problem}

半径 *r* の放射状のなだらかな濃淡を重ね合わせた和は、1フレームあたり *N* × π*r*² 個のブレンドされたフラグメントを必要とします。半径 8 px のスプライトが 1 億個あれば、2 × 10¹⁰ フラグメントです。高性能な GPU でおよそ 1 秒の作業量です。毎フレーム力ずくで計算することはできないため、ビューアーは次の仕組みを組み合わせています。

- **時間順に並べた行** - 時間軸のウィンドウは、2回の二分探索で決まります。再生にかかる負荷は、データセット全体ではなく、ウィンドウ内の行に比例します。
- **フレームごとに CPU で行を処理しないこと** - 行は量子化されて GPU メモリに置かれます。フィルター、グループの符号、寿命の判定、ウィンドウ、カリング、スライスは、すべて頂点シェーダーで計算します。
- **層化サンプリング**（フレームですべての行を描けないとき、補正の重みを付けます）と、**段階的な累積**（表示が静止している間、すべての行を使った正確な答えに近づけます）（[サンプリングと予算](sampling-and-budgets.md)、[累積](accumulation.md)）。
- **二段階のスロットル**。まずフレームあたりのスプライト数を減らし、次にヒートの解像度を下げて、フレームレートを保ちます（[サンプリングと予算](sampling-and-budgets.md#the-adaptive-budget)）。
- **強制されるメモリ予算**。データセットが収まらない場合は、クラッシュせずに、切り捨てられたことが画面にはっきり示されます（[GPU メモリの常駐](gpu-memory.md)）。

## 1フレーム {#one-frame}

フレームのループは [`Engine.frame`](https://github.com/Holdi601/3DHeat/blob/main/src/render/engine.ts) です。フレームごとに変わるもの（カメラ、再生位置、予算）は、すべてエンジンの中にあり、アプリケーションの状態にはありません。そのため、1フレームで React の処理は発生しません。状態は1フレームに1回読まれ、低頻度の表示値だけが書き戻されます。

1. **新しいデータはあるか?** 新しいデータセットは、1フレーム目に通知されます（*N 行を GPU にアップロード中*）。アップロードは次のフレームで行われます。そのため、作業でスレッドが止まる前に、メッセージが描画されます。新しいレベルは描画エンジンに渡されます。ライン・ヒートの経路は、作られるか解放されます。
2. **再生位置** が進みます（1フレームあたり実時間 0.1 秒まで）。ループするか、止まります。
3. **カメラ**は、キーボード、マウス、ゲームパッドを読みます。軸の反転はビューの行列に組み込まれます。WebGPU では、深度の範囲を補正する行列で、three.js の OpenGL 形式の深度の範囲を WebGPU の範囲に変換します。
4. **何が見えるか**: タイムラインと履歴から決まる時間の範囲。列によるグループ分けのときのグループの符号表（表示のみ）。最大 4 つのフィルター（列のフィルターとエンティティの選択）。差分の分割。
5. **色と曲線のテーブル** は、設定が変わっていれば作り直されます。
6. **予算**: 適応制御が、このフレームのスプライト予算とヒートの解像度を決めます。*毎フレームすべての行を描画* を選んでいる場合、予算は候補のすべての行を含むまで引き上げられます。
7. **シグネチャー**は、累積バッファーが何を意味するかを決めます。どの行がどう寄与するかを変えるもの（*ジオメトリ*）、時間のウィンドウ、または結果の色だけを変えるもの（*合成*）が変わると、累積は作り直されます。[累積](accumulation.md#what-restarts-it)を参照してください。
8. **サンプリング計画**: 描画する行のブロック（[サンプリングと予算](sampling-and-budgets.md)）。
9. **累積モード**: リセット、延長、移動平均、running mean、または停止。
10. **ボックス再生のジオメトリ**（立方体、軌跡）を CPU で作ります。これはそのモードのときで、停止していないときだけです。
11. **描画**: バックエンドがシーン（レベル、グリッド、軸、ボックス、軌跡、定規）を描き、ヒートをヒートのターゲットに散布し、アキュムレーターに統合し、ヒートをシーンに重ねてキャンバスに合成します。
12. **自動露出**は、カウントダウンが 0 になったときに動きます。定規のヒートの測定は、最大で 120 ミリ秒に 1 ピクセルだけ読み取ります。表示値は公開されます。

静止したフレーム（収束していて、何も変わっていない）では、シーンとヒートの描画は省かれますが、**再合成**は行われます。`preserveDrawingBuffer` を指定せずに作られた WebGL のキャンバスは、合成のあとに内容が未定義になります。そのため、前のフレームを表示し続けると信用することはできません。シーンとヒートのターゲットは、ビューアー自身のフレームバッファーで、内容を保持します。そのため、静止したフレームのコストは全画面パス1回分だけです。
