**マッチ**タブは、記録を図として再生します。Counter-Strike 2 の試合では、スコアボードも表示します。各ラウンドを誰が勝ったか、どのように勝ったか、誰がキルしたかがわかります。試合をラウンドごとに振り返り、そのあとヒートマップの同じ瞬間へ飛ぶのに使います。

マッチタブは、**リプレイ内のマッチ**に一覧される任意の記録を図として再生します。War Thunder や Tacview の記録、CS2 のデモが対象です（[試合のリプレイ](match-replay.md)）。CS2 の `.match.json` ファイルを加えると、このページで説明するスコアボードが表示されます。

## CS2 の試合を振り返る {#review-a-cs2-match}

1. デモを変換します（[下](#where-the-data-comes-from)）。`.parquet` と `.match.json` ファイルができます。
2. **ヒートマップ**タブで、**ソース**の下の `.parquet` ファイルを読み込みます。
3. **マッチ**タブを開き、**マッチファイルを読み込む…**を押すか、`.match.json` ファイルをビューにドロップします。
4. **マッチ概要**の試合をクリックし、次にラウンドの帯のセルをクリックして、そのラウンドを開きます。
5. **ラウンドを表示**を押すと、そのラウンドをヒートマップで見られます。**ラウンドを再生**を押すと、図として再生して見られます。

![マッチタブ：ラウンドの帯で1ラウンドを開いた状態。キルフィードとスコアボード](../assets/img/en/match-analysis-round.webp)

KAST、ADR、エコ、フォースバイ、トレードなどの用語は[用語集](glossary.md#counter-strike-words)にあります。

## データの出どころ {#where-the-data-comes-from}

[3DHeat CS2](https://github.com/Holdi601/3DHeat-CS2) のデモ変換ツールは、デモを、マップごとのフォルダーの中で、試合ごとに2つのファイルに変換します。

```bash
python -m heat3d_cs2 demos <demo files or folders> -o out
```

| ファイル | 読み込む場所 | 持つもの |
|---|---|---|
| `<match>.parquet` | **ヒートマップ**タブ（ソースのパネル。ほかの Parquet と同じく、1つ、複数、またはフォルダー全体） | すべてのプレイヤーの位置を毎秒8回。そして、起きたすべてのイベント：キル、デス、ダメージ、発射、投擲、スモーク、フラッシュ、HE、モロトフ、デコイ、ブラインド、設置、解除、爆発。`match`、`round`、`roundId`、`event`、`player`、`side`、`team`、見ている方向、`weapon`、`place`、`opening`、`traded` などを含む |
| `<match>.match.json` | **マッチ**タブ | チーム、スコア、すべてのラウンド（勝者、勝ち方、経済、設置、順番どおりのすべてのキル、クラッチ、生存者）、すべてのプレイヤーのスコアボードの行 |

Parquet ファイルのフッターには読み方の指示（キー `heat3d`）があるので、何も設定せずに開けます。プレイヤーは人として、側はグループとして、各ラウンド（`roundId`、「<match> #NN」）はセッションとして扱われます。見ている方向も加わり、ワールドは正しい向きになります（CS2 のワールドは右手系で Z が上です。既定の Z 上の対応で読むと、鏡像になってしまいます）。[列の対応](column-mapping.md)と[ファイルの読み込み](loading-files.md)を参照してください。`python -m heat3d_cs2 map <map>` は、マップの形状を同じ座標系で書き出し、**レベル**で読み込みます。

数字の背後にある規約は、変換ツールのもの（その README に書かれ、各要約に含まれています）です。デスは、キラーが、被害者のチームメイトのひとりに **5 秒**以内に倒されたとき**トレード**されたとします。**KAST** は、キル、アシスト（フラッシュのアシストも含む）、生存、またはトレードされたデスのあるラウンドの割合です。**ダメージ**は、実際に失った体力で、敵へのものだけです。**クラッチ**は、敵が立っている状態で、自分の側の最後の生存者であることです。そのチームが勝つと成功になります。**購入**は、フリーズタイム終了時の平均装備価値から、側ごとに決めます。各半分の最初のラウンドは、ピストルラウンド（延長戦はなし）。その後、$1,500 未満はエコ、$4,000 未満はフォースバイ、それ以上はフルバイです。

## タブ {#the-tab}

マッチタブのサイドバーには、上にヒートマップのモード切り替えとセッションの選択があり、その下に試合のセクション、さらにヒートマップの**フィルター**、**レベル**、**カメラ**のパネルがあります。ビューは、ヒートマップタブに読み込まれた Parquet のヒートマップです。

### マッチ概要 {#match-summaries}

| 操作 | 内容 |
|---|---|
| **マッチファイルを読み込む…** | `.json` ファイルを選びます（一度に複数可）。`.match.json` の要約です。 |
| ビューにドロップ | マッチタブが開いている間にビューにドロップされた JSON ファイルは、同じように読み込まれます（ほかのファイルは無視されます）。 |
| **クリア** | すべての試合を削除します。 |
| **すべての試合**（2つ以上あるとき） | 「N 試合、M ラウンド」。すべてにわたる統計です。 |
| 試合の行 | 「TeamA 13 対 TeamB 9」、マップ · N ラウンド。その試合を開きます。 |

ファイルは、`"format": "heat3d-cs2-match"` を持つ JSON で、配列 `rounds`、`players`、`teams` があるものだけ受け付けます。エラーはボタンの下に一覧されます。「<file>：JSON ではありません」、「<file>：CS2 の試合の要約ではありません（heat3d-cs2-match）」、「<file>：rounds、players、teams のいずれかがありません」。同じ試合（同じ `match` 名）をもう一度読み込むと、前のものを置き換えます。試合はマップ、次に名前の順に並びます。ちょうど1試合だけ読み込まれている場合は、それが開きます。そうでなければ、選択はそのままです（既定ではすべての試合）。

何も読み込まれていないときは、このセクションが説明します。`python -m heat3d_cs2 demos` で変換し、ここに `.match.json` ファイルを、ヒートマップタブに `.parquet` ファイルを読み込みます。

### マッチ（1試合を開いた状態） {#match-one-match-open}

**ヘッダー**：両チームとそのスコア、マップ、前半と後半。「前半 7-5、後半 6-6」。ラウンド1〜12 と 13〜24 です（プレミアとコンペティティブのプレイは MR12。要約が半分の長さを示していればそれを使うので、MR15 では 1〜15 と 16〜30）。試合が延長戦に入った場合は、その延長だけのスコアも表示されます（「延長 4-2」。両半分の後のラウンドです）。引き分けのラウンドは、どちらのチームにも数えません。要約が不完全なラウンドを列挙している場合は、「デモの中で N ラウンドが途切れている」とも表示されます。

**ラウンドの帯**：ラウンドごとに1つのセルで、勝った側の色が付きます。番号と、どう終わったかの印も付きます。引き分けのラウンド（勝者なし）は、印 `=` の中立のグレーのセルで、どちらかの側の色にはなりません。ツールチップには「ラウンド 30：引き分け。どちらの側も勝っていない」と表示されます。

| 印 | 終わり方 |
|---|---|
| B | 爆弾が爆発 |
| D | 爆弾が解除 |
| K | 全滅 |
| T | 時間切れ |
| S | 降伏 |
| = | 引き分け |
| ? | その他 |

仕切りが、後半の始まり（ラウンド 13、または要約の半分の長さの後のラウンド）と、各3ラウンドの延長戦の半分（ラウンド 25、28、31 など）の始まりを示します。セルにカーソルを合わせると、「ラウンド 7：TeamA（T）- 爆弾が爆発、A に設置」（要約にサイトがない場合は「…、設置、サイト不明」）と、両側の購入と装備価値が表示されます。クリックするとラウンドが開きます。もう一度クリックすると閉じます（「キル、経済、リプレイのためにラウンドをクリック」）。

**ラウンド**：

- 「ラウンド 7：<チーム> の勝ち - <勝ち方>」（引き分けの場合は「ラウンド 30：引き分け。どちらの側も勝っていない」）と、ラウンドが続いた時間（フリーズ終了から決着まで、m:ss）。
- 経済：各側のチーム、購入（ピストル、エコ、フォースバイ、フルバイ）、装備価値（「$4,350」）。
- 設置：サイト、プレイヤー、ラウンド開始からの時間（どちらの要約のバージョンからでも）。サイトがわからない場合は「<player> が 1:05 に設置、サイト不明」。
- **キルフィード**（順番どおり）：ラウンド開始からの時間、アタッカー（側の色で。アタッカーがいない場合は「world」）、武器、そしてフラグ。**HS** はヘッドショット、**WB** は壁越し、**SM** はスモーク越し。**open** はラウンド最初のキル、**trade** は5秒以内にチームメイトの仇を討った、**traded** はキラーが5秒以内に倒された、**team** はチームキル（自殺は含まない）。ラウンドが決まった後のキルは薄く表示されます。
- クラッチ：「<player>（T）が 3 人を相手に一人：クラッチ成功」／「失敗」。
- 各側で、最後まで生き残っていた者（「なし」）。
- **ラウンドを表示**：このラウンドのすべてを、ヒートマップで。
- **ラウンドを再生**：ラウンドを、その開始から箱として再生します（下）。

この試合、または開いているラウンドについての**ヒートマップで表示**ボタン（[下](#show-in-the-heatmap)を参照）。

### スコアボード {#scoreboard}

チームごとに表があり、プレイヤーごとに行があります。

| 列 | 内容 |
|---|---|
| K、D | キル、デス |
| A | アシスト（フラッシュのアシストを含む） |
| ± | キル - デス（0 より上は緑、下は赤） |
| ADR | ラウンドあたりのダメージ。実際に失った体力 |
| KAST | キル、アシスト、生存、またはトレードされたデスのあるラウンドの割合 |
| HS | ヘッドショットでのキルの割合 |
| Open | 先制デュエルの勝ち-負け |
| Cl | クラッチの勝ち / 挑戦 |

プレイヤーにカーソルを合わせると、トレードのキル、トレードされた回数、フラッシュのアシスト、フラッシュした敵、ユーティリティのダメージ、マルチキルのラウンド（「2×3k」）が表示されます。**プレイヤーをクリック**すると、この試合でのそのプレイヤーのキルとデスがヒートマップに表示されます。

### 試合をまたいで（すべての試合） {#across-matches-all-matches}

読み込まれたすべての試合について：

- 「N 試合・M ラウンド・<マップ>」。引き分けがあれば「N ラウンドは引き分け。どちらの側も勝っていない」。
- **勝ったラウンド**は、側ごとに：全体、**ピストル**ラウンド（要約のピストルラウンド）、**エコ**、**フォース**、**フル**の購入（それぞれ、プレイしたラウンド数つきの割合。カーソルを合わせると「プレイした数のうち勝った数」）。引き分けのラウンドは、両側がプレイし、どちらも勝っていないものとして数えます。
- **爆弾**：サイトごとの設置と、T 側がそのラウンドを勝ち続けた頻度（「A での設置 12 回（T が 67% 勝利）」）。要約がサイトを単独では知らない設置（「不明なサイトでの設置 2 回（T が 50% 勝利）」）、または「一度も設置されず」。ラウンドの終わり方は、多い順。
- 「先制キルを取った側が、それらのラウンドの N% を勝った。」（自殺は先制キルではありません。引き分けのラウンドは先制を成功に変えません）。
- **先制デュエルの場所**：先制キルが最も多い10の場所（被害者がいた場所による。ゲームの場所の名前を読みやすくしたもの。「TopofMid」→「Top of Mid」）。デュエルと、T 側が勝った割合。
- **プレイヤー**：キル - デスで上位15人。すべての試合を合計（Steam ID で照合）。試合数、K-D、ラウンド数で重み付けした ADR と KAST、キル数で重み付けした HS%、先制デュエル。**プレイヤーをクリック**すると、すべての試合でのそのプレイヤーのキルとデスがヒートマップに表示されます。

すべての読み込まれた試合の「ヒートマップで表示」ボタンが、その下にあります。

## ヒートマップで表示 {#show-in-the-heatmap}

どのリンクも、ヒートマップ自身の**フィルター**を設定します。そのため、表示されているものはフィルターのパネルで見られ、編集もできます。**すべて表示**でそれらをクリアします。これらは、ヒートマップタブに読み込まれたヒートマップのテーブルで動きます。マッチタブがそれを自分で読み込むことはありません。

| ボタン | 表示されるイベント |
|---|---|
| **位置** | `position`：プレイヤーがいた場所を毎秒8回 |
| **キル** | `kill`：キラーがいた場所 |
| **デス** | `death`：被害者が倒れた場所 |
| **先制** | `kill` と `death` で `opening` = 1。各ラウンドの最初のキル。両者がいた場所（テーブルに `opening` 列がある場合のみ提供） |
| **スモーク** | `smoke`：スモークが着弾した場所 |
| **フラッシュ** | `flash`：フラッシュが炸裂した場所 |
| **モロトフ** | `molotov`：モロトフとインセンディアリーが燃えた場所 |
| **HE** | `he`：HE 手榴弾が爆発した場所 |
| **設置** | `plant`：爆弾が設置された場所 |
| **発射** | `shot`：発射された場所 |

ボタンのある場所で範囲が決まります。読み込まれたすべての試合、この試合、またはこのラウンド（「ヒートマップで表示 - ラウンド 7」）。

適用できないものは、ボタンの下で説明されます。黙ってフィルターで何も残さないことはしません。「一致する試合の列が保持されていない。試合は適用されません」、「試合：X は読み込まれたデータにない」、ラウンドとイベントについても同じ、「プレイヤー X は読み込まれたデータにない」、「側 X は読み込まれたデータにない」、「ヒートマップのデータが読み込まれていない。ヒートマップタブで試合の .parquet ファイルを読み込んでください」。データが読み込まれていない場合、リンクは「マップで見るには、ヒートマップタブで試合の .parquet ファイルを読み込んでください。」とも表示します。

**ラウンドを再生**は、さらにヒートマップを**ボックスのリプレイ**に切り替え、タイムラインを、ウィンドウを*寿命*に設定した*再生*モードにし、ラウンドのセッションの開始へ移動して再生します。ラウンドが読み込まれたデータのセッションでない場合は、「このラウンドは読み込まれたデータのセッションではない。再生するものがない」と表示されます。

### 要約のバージョン {#summary-versions}

このタブは、バージョン 1 とバージョン 2 の要約（ファイルの `"version"`）を並べて読み、同じように扱います。

| | バージョン 2 | バージョン 1 |
|---|---|---|
| 設置の時刻 | キルと同じく、ラウンド内の秒 | 試合の秒。タブがラウンド開始を引く |
| 設置のサイト | `A` または `B`。デモがそう言わない場合は空 | `A`、`B`、またはエンティティ番号。不明なサイトとして読む |
| 半分の長さ | `halfLength`（側が最初に入れ替わる場所から）。null の場合は 12 | 12（MR12） |
| ピストルラウンド | `pistolRounds`（ラウンド 1 と、後半の最初のラウンド） | 購入が `pistol` のラウンド |
| 引き分けのラウンド | `winner` と `winnerTeam` が空 | - |
| 自殺 | キル上の `suicide`。チームキルにはならない | アタッカーとヴィクティムが同じプレイヤーであることで判定 |

キルの `noscope` と `attackerBlind`（バージョン 2）は、マッチタブには表示されません。また、マッチタブはヒートマップのテーブルから場所も表示しません。そのため、そこでの手榴弾の行の空の `place` は、ここでは何も変えません。

フォーカスがフィルターになる方法（`focusFilters`）：

- **試合** → `match` 列のカテゴリーフィルター。
- **ラウンド** → 数値の `round` 列に対する範囲フィルター `round` = N（カテゴリーの列では、カテゴリーフィルター）。そして、そのラウンドのセッション（`<match> #NN`）がセッションの選択で選ばれます。
- **イベント** → `event` 列のカテゴリーフィルター。
- **プレイヤー** → そのプレイヤーの人フィルター。
- **側** → グループフィルター。
