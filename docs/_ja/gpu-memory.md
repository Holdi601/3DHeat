# GPU メモリの常駐

グラフィックカードのメモリには限りがあります。データが収まらない場合、ビューアーは収まったものを表示し、そのことを伝えます。統計オーバーレイに、琥珀色の **非常駐** の行が出て、除かれた行の数が示されます。一部だけを残したデータセットが完全に見えるのは、分析ツールが犯しうる最悪の間違いです。そのため、この行が隠されることはありません。

![琥珀色の非常駐の行がある統計オーバーレイ](../assets/img/en/gpu-memory-not-resident.webp)

より多く収めるには、**リソース予算** で GPU の予算を上げて、読み込み直します（[メモリと予算](memory-and-budgets.md#raising-the-gpu-budget)）。または、先にデータを絞ります。あるいは、メモリの多いカードを使います。

## 開発者向け {#for-developers}

### GPU に行を保存する方法 {#how-rows-are-stored-on-the-gpu}

行は、データセットが届いたときに一度だけアップロードされます。アップロードは **チャンク** 単位で、1チャンクは 8,388,608 行（2²³）です（[`CHUNK_ROWS`](https://github.com/Holdi601/3DHeat/blob/main/src/render/types.ts)）。各チャンクは、それ自身のバウンディングボックスと時間の範囲に対して量子化されます。

| データ | 形式 | 行あたりのバイト数 |
|---|---|---|
| 位置の X、Y、Z とグループ ID | 16 ビット符号なし整数 4 つ（WebGL2 では RGBA16UI）。X、Y、Z はチャンクのバウンディングボックス内 | 8 |
| 時間と寿命（データセットに時間と人物の両方がある場合） | 16 ビット符号なし整数 2 つ（RG16UI）。時間はチャンクの時間の範囲内。寿命は、65,535 のとき「次のサンプルなし」を意味します。 | 4 |

チャンクごとのバウンディングボックスがあるので、16 ビットで十分です。チャンクは通常、地図のごく一部しか覆わないため、量子化の刻みは、数キロメートル四方の地図でも 1 センチメートルをはるかに下回ります。これは実際のテレメトリのノイズよりずっと小さい値です。4 番目のチャンネルに乗せたグループ ID は追加のコストがありません。そのため、グループは最大 4,096 個までです（[グループ](sessions-persons-groups.md#limits)）。

WebGL2 では、各チャンクは幅 8,192 テクセルのテクスチャで、テクスチャの行の単位に満たない分は詰め物がされます。行には、フレームごとのブロック番号テクスチャを通じて、`gl_VertexID` からアクセスします。WebGPU では、ストレージバッファーを使います。

使用時に割り当てられる、行ごとのそのほかの GPU メモリ:

- 有効な列の[フィルター](filters.md): 行あたり 4 バイト（32 ビット浮動小数点の値またはカテゴリー ID）。フィルターを初めて使ったとき、チャンクごとにアップロードされます。
- [ライン・ヒート](line-heat.md): 行あたり 8 バイト（各セグメントの始点を、データのバウンディングボックス内で量子化した値と、フラグ）。ライン・モードがオンの間です。

さらに、描画のターゲットがあります。シーンの色と深度、ヒートのターゲットとその作業用の複製（[チームヒート](team-heat.md)では 4 チャンネル）、[遮蔽](depth-and-culling.md)のための深度の剥離の層、そしてレベルのジオメトリです。

### アップロード時に予算を強制する {#the-budget-is-enforced-at-upload}

WebGL は、対応できない割り当てを受け付けてしまいます。その後、コンテキストを失うか、とても高くつくシステムメモリにフォールバックします。そのため、GPU の予算はデータセットのアップロード時に強制されます（[`setDataset`](https://github.com/Holdi601/3DHeat/blob/main/src/render/webgl2/renderer.ts)）。

- チャンクは順番に（つまり時間の順に）、収まる限りアップロードされます。
- 収まらない最初のチャンクは、まったくアップロードされないのではなく、**一部だけ** アップロードされます。残りの予算に入るだけの、テクスチャの行の単位で、数の行がアップロードされます。そのため、チャンク全体を入れられない予算でも、できる限り表示されます。行は時間順なので、表示される部分は、つながった時間の範囲になります。
- そのあとのものはすべて **非常駐** です。

不足は隠されません。統計オーバーレイには、ゼロより大きいときはいつも、収まらなかった行の数を示す琥珀色の **非常駐** の行が出ます。完全に見えるのに切り詰められたデータセットは、分析ツールが持ちうる最悪の失敗です。読み込む前の[収まりの確認](memory-and-budgets.md#the-fit-check)は、この事態を防ぐためのものです。

描画が使う予算は、**リソース予算** の GPU の予算です。収まりの確認で使われるのと同じ値です。検出された値より上にも、スライダーの上限まで設定できます（[GPU の予算を上げる](memory-and-budgets.md#raising-the-gpu-budget)を参照）。データセットのアップロード時に適用されます。あとから変更しても、次の読み込みで反映されます。
