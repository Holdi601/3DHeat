# マップ画像

マップ画像は平面の絵です。ミニマップ、航空写真、間取り図などを、データの下に敷いて、ヒートがどこにあるかを見られるようにします。絵の上の2点を、ワールドの2つの場所に留めることで（「アンカー」）、その絵がどこにあるべきかをビューアーに伝えます。

## マップ画像を読み込んで配置する {#load-and-place-a-map-image}

1. まずデータを読み込みます（[データの取り込み](getting-data-in.md)）。
2. **背景/レベル**で **マップ画像…** を押し、絵を選びます。データの範囲に引き伸ばされます。
3. 絵が動いてしまった場合は **データの範囲に合わせる** を押します。アンカー 1 は絵の左上の隅に、アンカー 2 は右下の隅に、データの端で置かれます。
4. ヒートが絵と揃わない場合は、互いに遠く離れた2つのランドマークを選びます（例: 建物の対角の2つの隅や、2つの交差点）。それぞれの絵の上のピクセルと、ワールドの位置を読み取ります（[定規](measure.md)でポイントして **X** と **Z** を読み取ります）。
5. それらを **配置** に入力します。**アンカー 1** にはランドマークの **px**、**py**、**ワールド X**、**ワールド Z**。**アンカー 2** も同様です。
6. 確認します。道路の上にあると分かっている軌跡やホットスポットが、今その道路の上に来ているはずです。そうなるまで数字を調整します。

![2つのアンカーと、マップの絵に描かれたヒートを示す配置のセクション](../assets/img/en/map-images-placement.webp)

2つのランドマークは、ピクセルの列とピクセルの行の両方が異なっていなければなりません。そうでないと、パネルは *2つのアンカーがピクセルの同じ行または列にあります* と表示します。

## 読み込み {#loading}

ブラウザーが読み込める画像形式なら何でも構いません。長い方の辺が **8192 px** を超える画像は、8192 に縮小されます（GPU が保持を求められる最大の辺です）。パネルには *W×H から w×h に縮小しました* と表示されます。

読み込むと、画像はデータの X-Z の範囲に（データがなければ ±1000 の単位で）、北を上にして、データの最も低い Y に引き伸ばされます。既定値は **不透明度** 100%、**明るさ** 0.7、**彩度を下げる** 100%、**南北を反転** オンです。背景の役目はヒートの場所を見つけやすくすることであり、ヒートと競うことではないため、彩度を下げて暗くします。

## 設定 {#controls}

| 設定 | 既定値 | 範囲 | 意味 |
|---|---|---|---|
| **不透明度** | 100% | 0〜100% | |
| **明るさ** | 0.7 | 0〜2（ジョグ 64） | |
| **彩度を下げる** | 100% | 0〜100% | 背景を灰色にし、ヒートは鮮やかに保ちます。マップの色がデータの色と競ってしまうのを防ぎます。 |
| **南北を反転** | オン | | 画像のどの行が、ワールドの最大 Z になるかを決めます。データを読み込んでいるときに切り替えると、アンカーもデータの範囲に合わせ直されます。 |
| **配置**: アンカー 1、アンカー 2 | データの範囲上の画像の隅 | | 各アンカーは、絵の上のピクセルです。**px**（左から、0 から幅まで）と **py**（上から、0 から高さまで）と、そこに置かれるワールドの座標 **ワールド X** と **ワールド Z** です。尺度とずれは、この2点から決まります。 |
| **データの範囲に合わせる** | | | アンカー 1 を絵の左上の隅に、アンカー 2 を右下の隅に、データの X-Z の範囲で置きます。正確な配置の出発点になります。データが必要です。 |
| **高さ** | データの最も低い Y | データの最小 Y − 500 から最大 Y + 500（ジョグは最大 Y + 100,000） | マップの平面の高さ。データのすぐ下に置くと、何も隠されません。 |

名前の行には `幅×高さ px · x × z m/px` が表示されます。これは、各軸に沿った 1 ピクセルのワールドでの大きさです。

## シーンの中 {#in-the-scene}

画像は、その高さに置かれた1枚のテクスチャ付きの四角形です。不透明度が 100% のときは深度を書き込むため、地面として[遮蔽](depth-and-culling.md)に加わります。100% 未満では混ぜられ、深度を書き込まないため、何も遮蔽しません。[定規](measure.md)は、その平面上で計測します。[レベルライブラリ](level-library.md)は、画像のレベルをアンカーとともに保存します。

## Dota 2 のマップ {#dota-2-map}

**マップ画像…** の横の **Dota 2 マップ** は、[OpenDota](https://www.opendota.com) がその試合のページに表示している、現在の Dota 2 マップの図を取得し、[Watcher](https://github.com/Holdi601/3DHeat-Watcher) が Dota 2 のリプレイから書き出す表の下に配置します（[`dotaMap.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/tactics/dotaMap.ts)）。画像は、ボタンを押したときに opendota.com から取得されます。3DHeat の一部ではありません。最新のパッチの図は OpenDota 自身の一覧から取られ、一覧を読めないときは 7.40 の図を使います。

| | |
|---|---|
| 出典 | `opendota.com/assets/images/dota2/map/detailed_<patch>.webp`、900×900 px |
| 配置 | OpenDota の校正: 画像は両軸で Dota のワールド単位 -8192〜8064 にまたがります（128 単位のセルは 64〜191）。北が上です。リプレイの表の軸（Z が上、Y は反転）では、ワールド X は -8192〜8064、ワールド Z は -8064〜8192 になります。1 ピクセルあたり約 18 単位です。 |
| 高さ | 0。ヒーローは 0 から約 600 の間に立ちます。 |
| 見た目 | 明るさ 0.8、彩度を下げる 50%。 |

パッチ 7.40 の公開された試合のリプレイで確認しました。すべてのヒーローの軌跡が、描かれたレーンに沿っており、リプレイが配置するタワー、バラック、アンシェントは、描かれた拠点の上に来ます。**上**の表示は、画面の下に北を置いてマップを表示します。Y を反転させた Z が上の表はどれでも、そう表示します。

この図は OpenDota のもので、Valve のマップに基づいています。Valve は 3DHeat を推奨していません。

### 3D マップ {#the-3d-map}

Dota 2 がインストールされていれば、別のツールである [3DHeat Dota](https://holdi601.github.io/3DHeat-Ext-Dota/)（`heat3d-dota-maps level -o dota.glb`。Watcher の [`dota-map`](https://holdi601.github.io/3DHeat-Watcher/dota-map.html) コマンドもこれを実行します）がゲーム自身のファイルからマップを 3D で作ります。地面、崖、水、木、建物を、リプレイのテーブルと同じ単位と軸で作成します。このファイルを **3Dモデル…** で一度読み込むと、ビューアーはそのパーツ（`ground:terrain`, `structure:tower`, `structure:ancient`, `structure:tree`。`dotaMap.ts` の `isDotaLevel`）で Dota のマップと見分け、すぐに[レベルライブラリ](level-library.md)へ入れ（古いものは置き換えます）、そのことを表示します。以後、**Dota 2 マップ** は図をダウンロードする代わりに、ライブラリからこの 3D マップを読み込みます。ライブラリにない場合は図をダウンロードし、3D マップの作り方を表示します。このファイルはご自身のインストールから作られ、お使いのマシンに留まります。

## 開発者向け {#for-developers}

### アンカーが画像を配置する方法 {#how-the-anchors-place-the-image}

アンカー *a* と *b* を使う [`mapQuadFromAnchors`](https://github.com/Holdi601/3DHeat/blob/main/src/render/level.ts) より:

```
scaleX = (b.worldX - a.worldX) / (b.px - a.px)
scaleZ = (b.worldZ - a.worldZ) / (b.py - a.py)
pixel (0, 0) sits at  (a.worldX - a.px × scaleX,  a.worldZ - a.py × scaleZ)
```

2つのアンカーは、各軸の尺度とずれを独立に決めます。そのため、マップは X と Z で異なる比率に引き伸ばせますが、回転はできません。アンカーは、**両方**のピクセル座標で異なっていなければなりません。行または列を共有すると、尺度を導けず、マップは描かれず、パネルは *2つのアンカーがピクセルの同じ行または列にあります* と表示します。
