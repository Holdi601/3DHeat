# Референца формата података

Ова страница наводи сваку врсту датотеке коју 3DHeat може да отвори и какву табелу унутар ње мора да има. Табела су редови и колоне, као у табличном прорачуну: сваки ред каже где је нешто било и, ако то имате, када и ко.

Шта картица **Топлотна мапа** чита, колону по колону, и савете које Parquet датотека може да носи. (Картица **Анализа трке** чита датотеке кругова, а картица **Анализа меча** сажетке мечева; видите [Анализа трке](race-analysis.md) и [Анализа меча (CS2)](match-analysis.md).)

## Датотеке {#files}

Ово је једини потпун списак датотека које се могу учитати. Панел **Извор** (**Датотеке…**, **Фасцикла…** или превлачење) прихвата тачно ове:

| Екстензија | Шта је | Чита га |
|---|---|---|
| `.parquet`, `.pq` | Parquet табела | Parquet читач (испод) |
| `.csv`, `.tsv`, `.txt` | Текст са раздвајачима | читач текста (испод) |
| `.3dheat` | Један меч у једној датотеци (ZIP са табелом и њеним додацима) | учитава се као табела коју садржи - [Једна датотека по мечу](container.md) |
| `.acmi` (такође `.txt.acmi`, `.zip.acmi`) | Tacview снимак лета | сопствени читач - [Tacview снимци (ACMI)](tacview-acmi.md) |
| `.json`, `.json.gz` | OCAP снимак (у стилу Arma) | сопствени читач |
| `.gpx`, `.kml`, `.kmz`, `.nmea`, `.nma`, `.igc`, `.fit` | GPS трагови: GPX, KML/KMZ, NMEA записници, IGC записници једриличарства, FIT спортске датотеке | сопствени читач; положаји долазе из географске ширине и дужине |

Не учитавају се као положаји: мали JSON фајлови који стоје уз табелу и описују је (имена која се завршавају на `.match.json`, `.course.json`, `.level.json`, `.meta.json`, `.summary.json`, `.session.json`, `.hints.json`), као и додатне табеле конвертора (`<match>.events.parquet` и слične, видите [Конвертори задржавају све](converters.md)), осим ако их сами изаберете. Све остало се прескаче уз наведен разлог. Како се избор филтрира, објашњено је у [Учитавање датотека](loading-files.md#which-files-are-kept).

Празне датотеке се прескачу. У избору који садржи `movement*.<ext>` датотеке учитавају се само оне ([Учитавање датотека](loading-files.md#which-files-are-kept)).

Подаци су **један ред по узорку**: положај у једном тренутку, по потреби са тим ко је, која група, која сесија, куда је гледао и све друге колоне. Редови догађаја (убиство, постављање, пуцањ) могу стајати у истој табели као редови положаја, а разликују се по колони догађаја.

## Текст са раздвајачима (CSV, TSV, TXT) {#delimited-text-csv-tsv-txt}

Најмања корисна датотека, три реда:

```
x,y,z,t,player,team
10.5,2.0,-30.2,0.00,Blue 1,Blue
11.0,2.0,-29.8,0.25,Blue 1,Blue
-4.2,1.5,18.9,0.00,Red 3,Red
```

Колоне се саме мапирају ([Мапирање колона](column-mapping.md)).

Чита га скенер на нивоу бајтова који декодира само мапиране колоне ([`csv.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/csv.ts)).

| Особина | Правило |
|---|---|
| Заглавље | Први непразан ред садржи имена колона. Празно име постаје `column_N`. |
| Раздвајач | Препознаје се из првих 20 непразних редова у првих 1 MiB, међу зарезом, тачком са зарезом, табулатором и усправном цртом, по **доследности**: побеђује раздвајач који даје исти број поља у сваком узетом реду, па онај који даје више поља. Размак се никад не препознаје, али може да се изабере; може да се унесе било који појединачни знак ([Мапирање колона](column-mapping.md#the-fields)). |
| Наводници | RFC 4180: поља могу бити у двоструким наводницима, а `""` унутар наводника је дословни наводник. |
| Размаци | Размаци, табулатори и наводници на почетку и крају сваког поља се уклањају. |
| Поља по реду | Највише 4.096; више је грешка (*да ли је раздвајач исправан?*). |
| Бројеви | Опционални знак, цифре, опционална `.` и децимале, опционални експонент (`1.5e-3`). Децимални зарез (`1,5`), раздвајачи хиљада или ознаке јединица (`12 m`) не могу да се прочитају и броје се као недостајуће. Ако ваша датотека има децимални зарез, замените га тачкама пре учитавања (пронађи и замени у уређивачу текста ради). |
| Бројчана колона | Колона се нуди као бројчана када се више од 90% непразних вредности у првих 50 редова може прочитати као број. |
| Број редова | Процењује се пре учитавања из просечне дужине реда у првих 1 MiB. |
| Кодирање текста | UTF-8. |

## Parquet {#parquet}

Чита се помоћу [hyparquet](https://github.com/hyparam/hyparquet), део по део колоне, у типизоване низове, тражећи само мапиране колоне ([`parquet.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/parquet.ts), [`ingestParquet.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestParquet.ts)).

| Особина | Правило |
|---|---|
| Број редова | Тачан, из подножја датотеке, пре учитавања. |
| Преглед | Првих 50 редова, декодованих као објекти; њихове вредности одлучују које колоне изгледају бројчано. |
| Цели бројеви | `INT32` и `INT64` (декодован као BigInt) постају бројеви. |
| Децимални бројеви | `FLOAT`, `DOUBLE`. |
| Логичке вредности | 1 и 0. |
| Ниске | Користе се за колоне особе, групе, сесије и категорије; ниска која изгледа као број прихвата се за бројчане улоге. |
| Логички типови `TIMESTAMP`, `DATE` | Декодују се у тренутке (милисекунде од 1970); кад се користе као временска оса, подешавање јединице се занемарује. |
| Угнежђене колоне | Колоне структура и листа нису намењене ниједној улози (у прегледу се приказују као JSON текст); није тестирано. |
| Метаподаци подножја | Кључ `heat3d` се чита као савети за мапирање (испод). |

Колона која садржи нешто друго осим броја, а служи за положај, време или поглед, декодује се као недостајућа.

## Улоге и типови колона {#column-roles-and-types}

| Улога | Тип у датотеци | Обавезна | Чува се као | Ограничења |
|---|---|---|---|---|
| X, Y, Z | број | две од три | 32-битни децимални број, после [мапирања оса](axes-units-and-time.md) | Ред без употребљивог положаја се одбацује. |
| Време | број у једној од [јединица времена](axes-units-and-time.md#time-units), Parquet временски печат или ISO-8601 текст | не | 32-битни децимални број, у секундама од најранијег реда | Сортирање се одбија преко 400.000.000 редова ([зашто](memory-and-budgets.md#the-sort-ceiling)). |
| Особа | било шта; кодирано речником | не | 32-битни ид | |
| Сесија | било шта; кодирано речником | не | 32-битни ид | Ознаке се наводе до 100.000 сесија. |
| Група | било шта; кодирано речником | не | 16-битни ид | До 4.096 група, иначе се груписање одбацује. |
| Скретање, нагиб | број, у степенима или радијанима | не | 32-битни децимални број у радијанима | |
| Смер X, Y, Z | број | не (сва три заједно) | претвара се у скретање и нагиб | |
| Колона филтера, *опсег* | број | не | 32-битни децимални број | До 4 филтера активна истовремено. |
| Колона филтера, *категорија* | било шта; кодирано речником | не | 32-битни ид | До 4.096 вредности, иначе колона није задржана. |

Колона `TIMESTAMP` из Parquet-а, задржана као колона филтера, је *опсег* епох милисекунди - клизач, а не листа.

## Савети `heat3d` {#the-heat3d-hints}

Parquet датотека може да носи сопствена упутства за читање у метаподацима кључ/вредност свог подножја, под кључем **`heat3d`**, као JSON објекат ([`MappingHints`](https://github.com/Holdi601/3DHeat/blob/main/src/data/automap.ts)). Приказ их примењује преко својих претпоставки када је датотека прва у избору. Сваки унос је необавезан, а сваки резултат се и даље приказује и може да се мења у панелу [Мапирање колона](column-mapping.md#the-heat3d-hints-in-a-parquet-footer). Све што није исправан JSON објекат се занемарује.

### Шема {#schema}

```
{
  "columns": {
    "x": string, "y": string, "z": string,          назив колоне за положај
    "time": string,                                  колона времена
    "timeUnit": "seconds" | "milliseconds" | "microseconds" | "nanoseconds"
              | "unix_seconds" | "unix_milliseconds" | "iso8601",
    "personId": string, "teamId": string, "sessionId": string,
    "lookMode": "none" | "yawPitch" | "vector",
    "yaw": string, "pitch": string,
    "dirX": string, "dirY": string, "dirZ": string,
    "angleUnit": "degrees" | "radians",
    "extra": [string, ...]                           колоне филтера за задржавање, најкориснија прва
  },
  "axes": {
    "up": "y" | "z",
    "flipX": boolean, "flipY": boolean, "flipZ": boolean,
    "scale": number                                  мора бити > 0
  },
  "entity": {
    "size": number                                   величина једне праћене ствари у јединицама датотеке, > 0
  }
}
```

| Унос | Примењује се кад | Дејство |
|---|---|---|
| `columns.x` … `columns.dirZ`, `time`, `personId`, `teamId`, `sessionId` | названа колона постоји у датотеци | Поставља ту улогу. |
| `columns.timeUnit` | је једна од седам јединица | Поставља јединицу времена. |
| `columns.angleUnit` | `"degrees"` или `"radians"` | Поставља јединицу угла. |
| `columns.lookMode` | `"vector"` кад су dirX, dirY и dirZ сви постављени; `"yawPitch"` кад је yaw постављен; `"none"` | Поставља режим погледа. |
| `columns.extra` | је низ | Замењује аутоматски списак филтера: задржава само постојеће колоне које није узела нека улога. Свака је *опсег* ако је у прегледу изгледала бројчано, иначе *категорија*. Без овог уноса аутоматски списак се задржава, минус свака колона коју савет додељује некој улози. |
| `axes.up` | `"y"` или `"z"` | Усправна оса. |
| `axes.flipX/Y/Z` | логичка вредност | Окретање. |
| `axes.scale` | број > 0 | Размера јединица. |
| `entity.size` | број > 0 | [Величина ентитета](sessions-persons-groups.md#entity-size) (множи се размером јединица при учитавању). Једини начин да се постави. |

### Пример {#example}

Измишљен извоз пуцачке игре: Z је усправно, јединице су центиметри, свет је леворук, а играчи су широки око 72 cm.

```json
{
  "columns": {
    "x": "pos_x", "y": "pos_y", "z": "pos_z",
    "time": "t", "timeUnit": "seconds",
    "personId": "player", "teamId": "side", "sessionId": "round_id",
    "lookMode": "yawPitch", "yaw": "view_yaw", "pitch": "view_pitch", "angleUnit": "degrees",
    "extra": ["event", "weapon", "map"]
  },
  "axes": { "up": "z", "flipY": true, "scale": 0.01 },
  "entity": { "size": 72 }
}
```

### Писање {#writing-it}

Уз pyarrow, прилагођени метаподаци шеме се записују у кључ/вредност метаподатке датотеке:

```python
import json
import pyarrow as pa
import pyarrow.parquet as pq

table = pa.table({...})
hints = {"columns": {"x": "pos_x", "y": "pos_y", "z": "pos_z", "time": "t"}, "axes": {"up": "z"}}
meta = dict(table.schema.metadata or {})
meta[b"heat3d"] = json.dumps(hints).encode("utf-8")
pq.write_table(table.replace_schema_metadata(meta), "movement.parquet")
```

`npm run inspect -- file.parquet` исписује шему датотеке, што је брз начин да проверите називе колона на које се савети односе.
