# 篩選

**篩選**會隱藏你不關心的列，例如某一種載具類別或某一種事件，而畫面會立即更新。面板會列出載入時在**保留以供篩選**下保留的欄位（[欄位對應](column-mapping.md)），若載入了多個檔案，還會列出*來源檔案*。

## 試用 {#try-it}

1. 載入一個資料集，然後在側邊欄中開啟**篩選**。
2. 在**載具類別**下，取消勾選*Tank*。畫面會立即改變。
3. 按**清除所有篩選**即可復原。

![篩選面板：先顯示檢視器自己的欄位（事件類型、載具類別），然後才是你檔案中的欄位](../assets/img/en/filters.webp)

前幾列是檢視器自己的欄位（見下文）。之後的列則來自你的檔案。

## 檢視器新增的欄位 {#columns-the-viewer-adds}

載入時，檢視器會自行推導出四個欄位，並**優先**列出，名稱與值都以你的語言顯示，因此同一種篩選適用於每一款遊戲與每一種資料來源：

| 欄位 | 值 | 推導依據 |
|---|---|---|
| **事件類型** | 23 種：位置、射擊、發射（飛彈、火箭、炸彈）、命中、未命中（武器結束時附近沒有目標）、爆炸、傷害、擊殺、死亡、摧毀、墜毀、彈射／跳傘、出生、消失、起飛、降落、接觸地面、在地面停止、重新裝填／補充燃料、佔領／目標、誘餌、訊息、其他 | 名為 `event`、`events`、`event_type` 或 `event_name` 的欄位；各遊戲自己的用詞（`shot`、`burst`、`fired`、`struck`、`flare`、`plant` 等）會對應到這些種類。完整表格：[事件類型與類別](ref-event-types.md)。 |
| **玩家或AI** | 玩家、AI | 名為 `ai`、`is_ai`、`bot` 或 `actor` 的欄位；否則為 `is_player` / `human`；否則為帳號 id（`user_id`、`steam_id`；空白或 0 即為 AI）；對於 Tacview 錄影，則看該物件是否有駕駛員 |
| **載具類別** | 17 種類別：戰鬥機、攻擊機、轟炸機、其他飛機、直升機、戰車、裝甲車、防空、火砲、卡車／汽車、艦艇、潛艇、步兵、武器、誘餌、結構物、其他 | 載具或單位名稱（與[模型目錄](figures.md)比對）以及類型欄位 |
| **目標類別** | 同上的類別 | 另一方的載具（`other_vehicle`、`target_vehicle`、`victim_type` 等） |

只會列出實際出現的種類。數值欄位（`cost_*`、`earn_*`、`net_*` 與*成本來源*，見[數值加權](value-weighting.md)）與任何數字欄位一樣可以篩選：例如，在*成本來源*下取消勾選*估計*，即可只保留有定價的列。

類別清單超過 12 個值時，會出現搜尋方塊（*搜尋 n 個值*）與**僅這些**按鈕，後者只允許符合條件的值。

哪些欄位可以篩選，是在載入時決定的，因為必須在那時讀取它們。若沒有任何保留的欄位，面板會說明此情況，並指向*保留以供篩選*。

## 數值欄位（範圍） {#numeric-columns-range}

![範圍篩選（損失的金錢），兩端都已拖動](../assets/img/en/filters-numeric.webp)

| 部分 | 意義 |
|---|---|
| 名稱與 `最小值 ... 最大值` | 欄位，以及目前的範圍（未設定篩選時為欄位的完整範圍）。 |
| 第一列：數字方框與滑桿 | 下限。把滑桿拖過上限時，會連同上限一起推動。 |
| 第二列：數字方框與滑桿 | 上限。拖到下限之下時，也會一起推動。 |
| **重設 *欄位*** | 移除此篩選。 |

滑桿以 1,000 個步進涵蓋欄位的最小值到最大值；數字方框可接受任何值。列的值只要落在範圍內（兩端都包含）即可通過。較大的值會以指數形式顯示（`1.23e6`）。

## 類別欄位 {#category-columns}

| 部分 | 意義 |
|---|---|
| 名稱與 `允許數/總數` | 欄位，以及允許的值數量。 |
| 值清單 | 每個值一個核取方塊；空白值顯示為 *（空白）*。 |
| **全部** / **無** | 允許每個值／不允許任何值。 |

允許所有值即會移除此篩選。

## 規則 {#rules}

- **同時最多四個篩選。** 標題會顯示 `已啟用數/4`。第五個篩選不會套用，面板也會說明。在[實體](entities.md)中的選取（或對戰頁籤的玩家焦點）同樣會佔用其中一個名額。涵蓋整個欄位的篩選不佔用名額。
- **類別欄位最多 4,096 個值**；超過的欄位在載入時不會被保留。
- **篩選以 AND 組合**，並與隊伍可見性、差異分割、時間視窗、距離剔除與[切片](slice.md)組合。
- **變更篩選會重新開始累積**，並在幾個影格後重新測量曝光，因為篩選可能大幅改變密度（[色彩與曝光](colour-and-exposure.md#auto-exposure)）。
- **清除所有篩選**會移除每一個欄位篩選。隊伍可見性與其他地方設定的玩家選取會保留。
- 欄位篩選會改變熱度模式。它們不會改變[模型重播](box-replay.md)中的模型，後者依隊伍可見性與實體選取。實體選取則會同時改變兩者。
- 在[線條熱度](line-heat.md)中，篩選是以每一段*結束*時所在的那一列來測試。
- 每次載入新的資料集時，所有篩選都會被清除。

## 給開發者 {#for-developers}

**名額。** 每個啟用中的篩選佔用四個 GPU 名額之一（[`MAX_FILTER_SLOTS`](https://github.com/Holdi601/3DHeat/blob/main/src/render/types.ts)），是每列 4 位元組的紋理。名額依篩選最後一次變更的順序分配（[`filterSlots`](https://github.com/Holdi601/3DHeat/blob/main/src/render/filterTables.ts)，由著色器與兩個面板共用）。超過四個時，會出現錯誤訊息：*只套用前 4 個篩選。請清除一個 - 其餘篩選被忽略，而不是靜默地組合。*，多出的篩選名稱會顯示為 *欄位（未套用）*。篩選會在頂點著色器中逐列執行，因此變更門檻不需要重新解析，也不需要重新上傳。

**面板不顯示的篩選。** 應用程式狀態中還有兩種篩選（[`FilterSpec`](https://github.com/Holdi601/3DHeat/blob/main/src/state/types.ts)）：

- **群組**篩選，由對戰頁籤在焦點集中於某一方時設定。它會在所有模式中隱藏其他群組，包括依欄位分割的[差異](difference.md)。
- **人員**篩選，由[實體](entities.md)面板與對戰頁籤在焦點集中於某一位玩家時設定。它會限制模型重播與熱度模式。在熱度中，它是對人員 id 的類別篩選，並佔用四個名額之一。其遮罩可容納 65,536 個 id（[`FILTER_MASK_CAPACITY`](https://github.com/Holdi601/3DHeat/blob/main/src/render/types.ts)）；超過此數的人員在啟用期間，即使被選取，也不會在熱度中繪製。模型重播仍會顯示他們。
