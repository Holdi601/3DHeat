# 重播與 3D 場景

把你的單圈一起重播，就像比賽一樣，看哪一台車領先。**賽車分析**分頁 3D 視圖中看到的一切都在這裡說明：行駛走線、畫在賽道上的顏色、車輛與標籤。

![原因地圖：車輛在彎道前 40 m 排齊，賽道上有顏色，並有兩台車與旗桿](../assets/img/en/race-replay-lined-up.webp)

## 重播時鐘 {#the-replay-clock}

一個時鐘驅動每一圈：以**參考圈**的秒數計算。播放時，引擎會在每一幀推進它（依幀時間乘以重播速度）；播完時，若開啟了**循環**，就會回到 0，否則停止。這個時鐘刻意不放在狀態儲存中，這樣側邊欄就不會每一幀都重新繪製；HUD 與圖表會訂閱它，每一幀最多更新一次。

**重播的長度**是時鐘上任何一圈跑得最久的時間：每一圈的圈速（減去它在*排齊*中的偏移），或是在*並排*中參考圈的圈速。

## 控制列 {#the-transport-bar}

在視圖下方，由左到右：

| 控制項 | 功能 |
|---|---|
| ⏮ | 回到開頭（也可用 **Home**） |
| ▶ / ❚❚ | 播放／暫停（也可用 **K**） |
| 速度 | 0.25×、0.5×、1×、2×、4× |
| 拖曳滑桿 | 直接設定時鐘，以 0.01 s 為單位 |
| 時鐘 | `時間 / 長度 · 公尺數`：以圈速表示的時鐘、重播的長度，以及參考車在參考圈上已經走了多遠 |
| *從起跑線* / *排齊* / *並排* | 重播模式（見下文） |
| **在此排齊** | 把每台車放到參考車目前所在的位置，並從那裡繼續 |
| **循環** | 播完後從頭再開始（預設開啟） |
| **隱藏圖表** / **顯示圖表** | 控制列下方的距離圖表 |

載入單圈之前，這些按鈕都是停用的（一圈就能重播；比較則需要兩圈）。

## 重播模式 {#replay-modes}

每一圈自己的時間，如何從時鐘推算出來：

| 模式 | 每一圈的時間 | 顯示什麼 |
|---|---|---|
| **從起跑線**（`start`） | 時鐘本身 | 每一圈都從它自己的起點開始：它們之間的競賽，差距會像在賽道上那樣逐漸拉開 |
| **排齊**（`anchor`） | 時鐘加上該圈的偏移 | 每台車在同一時刻、同一地點排齊，然後同時放開——從那一點開始發生的事，而不是從單圈開始發生的事 |
| **並排**（`locked`） | 該圈到達參考圈目前距離的時間 | 每台車整圈都保持在參考圈的距離上：逐公尺比較速度與操作 |

使用時機：

- **從起跑線**：你想看誰領先，以及差距如何拉開。
- **排齊**：你想知道某一個彎道或某一段直線上發生了什麼，所有人在那裡起點相同。
- **並排**：你想比較駕駛在賽道上同一個地點，踩踏板與轉方向盤的方式。

**排齊的偏移：**若錨點位於參考圈上 `s` 公尺處，每一圈的偏移就是它在 `s` 的時間，減去參考圈在 `s` 的時間，兩者都取自已對齊的單圈（見[一條距離軸](race-corner-analysis.md#one-distance-axis)）。沒有涵蓋 `s` 的單圈，偏移保持為 0。從模式按鈕選擇*排齊*時，錨點會設在參考圈目前的距離上。

在*排齊*模式中，一面插著旗子的白色旗桿（高 14 m）會標示錨點。

### 排齊 {#lining-up}

| 動作 | 錨點 | 時鐘 |
|---|---|---|
| **在此排齊** | 參考車目前所在的位置 | 不變 |
| 在圖表上 Shift+點擊 | 點擊的那一公尺 | 在參考車到達之前 1.5 s |
| *可改進之處*中的一項發現、賽道上的編號徽章、*逐彎分析*中有發現的一列 | 發現原因開始處之前 40 m | 該點之前 1.5 s；然後播放 |
| 車輛控制事件、撞擊的標籤 | 事件之前 40 m | 之前 1.5 s；然後播放 |
| 賽道統計中的一圈 | 同其發現或事件 | 同上，並將該圈設為焦點 |

查看一項發現時，攝影機也會把它框起來——以發現範圍的中點為中心的一個球體，半徑取 40 m，與其長度的一半加 30 m 中較大者（事件則為 60 m）——除非攝影機正在追逐某台車。

### 追逐攝影機 {#chase-camera}

單圈列表中的 ⌖ 會讓攝影機跟隨那台車：位於它後方 2.5 + 4 × 車輛大小（公尺）處、上方 0.9 + 1.1 × 車輛大小（公尺）處，沿著它的行進方向看去，並向下俯向車輛，並會逐幀緩和（每一幀前進 20%），因此不會隨著每一次晃動而抖動。再按一次 ⌖ 則解除追逐。被追逐的車會畫得稍微淡一點，地面上有白色圓環，而它的卡片會被突出顯示。

| 控制項 | 預設 | 功能 |

| 圖例 | - | 時間地圖為*領先 ↔ 落後*，原因地圖為原因顏色，失誤地圖為*少數圈 ↔ 多數圈* |
| **行駛走線** | 開 | 每台可見單圈的走線，以其顏色繪製 |
| **車輛** | 開 | 車輛，以及 HUD 卡片的來源 |
| **輪胎與懸吊** | 開 | 輪胎溫度、滑移環、懸吊推桿，以及其他每個輪胎的圖示，還有車頂燈 |
| **標籤** | 開 | 彎道名稱、編號徽章、撞擊標籤，以及失誤地圖上的彎道標籤 |
| **依單圈生成賽道** | 開 | 沒有擷取賽道模型的遊戲，會畫出路面（載入**關卡**中的賽道模型時隱藏） |

| **車輛大小** | 1× | 1× 到 10×，以 0.5 為單位；1× 為車輛的真實大小，與遊戲中一樣長、一樣寬。只有這個滑桿會改變它 |

## 行駛走線 {#driven-lines}

每台可見單圈沿著自己的樣本行駛的路徑，以其顏色繪製，位於記錄位置下方 0.12 m 處（車輛的記錄位置是它的參考點，在擷取的 Forza 賽道上，它比路面高 0.28 到 0.47 m）。每 1.5 m 保留一個點；可見的單圈超過 10 圈時，未被查看的單圈每 6 m 保留一個點（每個頂點每一幀都會傳送到 GPU）。

## 地圖 {#the-maps}

三者都是沿著**參考圈**路徑的色帶，位於記錄位置下方 0.2 m，每 2 m 格網一個四邊形。

### 時間地圖（`where`） {#time-map-where}

針對焦點單圈：在該點上，與它所比較的那一圈（同等級中最快的，或對參考圈而言，是各區段中最快的其他圈）相比，每公尺領先或落後的秒數。它由對齊差值每格網的變化量計算，並以前後 ±10 m 平滑。落後時為紅色，領先時為綠色，中間為灰色；色階以絕對值的第 95 百分位為準，因此尖峰會被截斷，整圈大多數都落在範圍內。寬 6 m。

### 原因地圖（`why`） {#cause-map-why}

針對焦點單圈：每一項損失都畫在它的**原因**所在的範圍上（而不是時間顯示的位置），依原因的群組上色；若兩項重疊，則以代價較高的那項為準。寬度為 `3 + 9·√(代價 / 最大代價)` 公尺；若沒有任何損失的地方，則畫一條 2 m 的灰色帶。在*可改進之處*中被選取的發現，會以白色繪製。

| 群組 | 顏色 | 發現 |
|---|---|---|
| 煞車 | 橘色 | 煞車階段的駕駛損失 |
| 入彎 | 洋紅色 | 入彎與中段的駕駛損失 |
| 出彎 | 藍色 | 出彎的駕駛損失 |
| 直線 | 黃色 | 直線上的駕駛損失 |
| 車輛 | 灰色 | 車輛所解釋的部分 |
| 情境 | 深灰色 | 情境（例如比賽起跑對上飛躍圈） |

### 失誤地圖 {#mistake-map}

在每一公尺上，所有單圈（在賽道統計中所選等級的圈）中，有多少圈犯了失誤——任何類型的失誤，或只計算統計中所選的那一種。每一圈在每一公尺只計一次；每個失誤的範圍會向兩側各加寬 6 m，讓很短的失誤也看得見。寬度為 `3 + 10·(圈數 / 最多的圈數)` 公尺，顏色由暗棕色到亮橘色；沒有任何單圈犯錯的地方，為 2 m 的灰色帶。見[賽道統計](race-course-statistics.md#the-mistake-map)。

## 依單圈生成賽道 {#track-from-the-laps}

對於尚未擷取賽道的遊戲，會在走線下方畫出一條路面：寬度為單圈在參考圈上的分布範圍（側向偏移在 25 m 以內的算入），加上兩側各 2 m，且兩側至少各為參考線外側 4 m，以前後 ±8 個格點（±16 m）平滑處理，為柏油灰色並帶有淺色邊線，位於記錄位置下方 0.3 m。若在**關卡**中載入了賽道模型，則隱藏。

## 賽道上的撞擊與碰撞 {#hits-and-crashes-on-the-track}

每台可見單圈的撞擊與碰撞（見[車輛控制事件](race-control-events.md#hits-and-crashes)），只要畫出走線或車輛，都會標示在它們發生的地方：一顆帶尖刺的星星——撞車為紅色，撞擊為琥珀色——立在一根柱子上，柱腳有該圈顏色的圓環，大小隨車輛大小變化（撞車較大）。當車輛經過撞擊的那一刻時，會從那裡擴散出一圈衝擊波，持續 0.8 秒。

## 說明模式 {#help-mode}

語言選擇器旁的 **?**，或 **?** 或 **F1** 鍵，會開啟視圖中每一種顏色的圖例，適用於三個分頁（[`HelpPanel.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/help/HelpPanel.tsx)、[`RaceHelp.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/race/RaceHelp.tsx)）。這個選擇會保留在此瀏覽器中。

- 視圖角落的**圖例**，會列出目前分頁與模式所使用的顏色。每一個色階都來自視圖取得它的地方，因此你編輯過的熱度色階會顯示為編輯後的內容。在賽車分頁中，只列出已載入單圈所包含的內容。
- **每台車的卡片**會增加一張表格，依名稱列出畫在它車輪上的內容，並以每個車輪的數值與其繪製顏色對照。
- **焦點車輛**會在每個車輪旁邊加上一個標籤，說明同樣的內容，並放在彎角外側。若車輛在畫面上太小，裝不下這些標籤，就會隱藏。

## 車輛 {#the-cars}

**每台車都以其自己的外形呈現**，使用它的單圈顏色，並為其真實大小。這些外形來自一個車輛檔，由遊戲所在的電腦上製作一次：

```
python -m heat3d_gamefiles cars -o forza.h3dcars
```

沒有車輛檔時，每台車都會以**檢視器自己的車**來呈現，依其種類與年代：轎車、跑車、掀背車、旅行車、跑車、超級跑車、肌肉車、越野車、皮卡、廂型車或微型車，每一種又分為經典款（1980 年以前）、80 與 90 年代款，或現代款（[`carBodies.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/race/carBodies.ts)）。這些車是依一般比例在此建立的：沒有商標、沒有車型名稱，也不使用任何遊戲的檔案，因此隨檢視器一起發佈。車輛的種類來自其名稱，年代來自名稱中的年份；名稱中兩者都沒有的車，則依其等級推斷。約一百個真實世代的車輛，可依其公布的長、寬、高與軸距取得尺寸（[`carSpecs.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/race/carSpecs.ts)；每款一行，已四捨五入），因此 1990 年代的 3 系列會得到該車的大小與姿態，但仍是沒有徽章或水箱護罩的純外形。

車輛檔是在你自己的電腦上，用你自己的遊戲副本製作的。它包含每台車的低細節模型，約 900 個三角形，並包含它的輪胎位置（見[擷取工具的 `cars` 指令](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/docs/commands.md#cars)）。在檢視設定中按 **載入車輛檔案…**，或把檔案拖放到賽車分頁上，即可載入；它會留在此瀏覽器中。它包含遊戲的外形，因此不應該拿去分享，檢視器本身也不附帶任何車輛檔。

每次都會依目前已載入的內容，即時決定哪台車代表某一圈的車，而且不會儲存下來，因此今天沒有對應車型的車，只要有較新的檔案包含它，就會立即顯示它自己的外形（[`carMatch.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/race/carMatch.ts)）：

| 單圈的車 | 顯示為 |
|---|---|
| 其編號出現在同一遊戲的檔案中 | 就是那台車 |
| 同一廠牌，且名稱中含有該車型的一個字 | 該車型，年份最接近的那一款 |
| 同一廠牌、同一世代 | 該廠牌中年份最接近的那台車 |
| 其他情況，且有車輛檔 | 若有同廠牌，取最接近的那台；否則取同類車身中年份最接近的 |
| 單座賽車（依其名稱判斷） | 下方的單座賽車 |
| 前兩者都不符，且檢視器認得這台車的大小 | 以該真實車輛的大小呈現的檢視器自己的車，有無檔案皆然 |
| 其他且沒有檔案 | 該種類與年代的檢視器自己的車 |

因此，另一個遊戲中 1990 年的 BMW 3 系列單圈，會顯示為該年代左右的 BMW；比檔案還新的車，則會顯示它最接近的親戚，直到檔案重新製作為止。單圈的提示，以及焦點單圈在車輛大小下方的那一行，會說明它被繪製成什麼，以及它與實際車輛有多接近。

檢視器自己的車有深色車窗。車輛檔中的模型是整台車單一顏色，因為檔案中沒有塗裝或玻璃可以參考。下方的車輪、尾燈、燈具與遙測圖示，都依單座賽車的方式繪製；推桿會沿著車輪外側向上延伸，以便看見，而下擺臂則省略不畫。

**單座賽車**是以單圈顏色繪製的開放式賽車，因此從任何角度都能一眼看出車頭，而且沒有任何東西遮住車輪：車身、引擎蓋、側箱、駕駛艙（含頭盔）、保護環、底板、前後翼；四個圓形車輪，前輪會隨方向盤轉動（滿舵時最多 0.5 rad），每個車輪都由兩根下擺臂支撐，並有立柱、前方的橫拉桿或後方的傳動軸，以及一根推桿。模型會從記錄位置下降 0.3 m，讓車輪落在路面上，並由**車輛大小**縮放。

**車身隨著彈簧移動**：當單圈包含四個懸吊行程時，每個角落會依其行程下降（從完全伸張到完全壓縮，會誇大到 0.12 m，讓追逐攝影機也看得見），車身則會沿著四點所在的平面下沉、俯仰與側傾。

**由遙測繪製的內容**（開啟**輪胎與懸吊**時）依[通道表](race-charts-and-hud.md#the-channel-table)：

| 圖示 | 來源 | 繪製方式 |
|---|---|---|
| 輪胎顏色 | `tireTemp` | 輪胎本身：在 40-130 °C 之間，由藍色（冷）→ 青色 → 綠色（正常工作）→ 黃色 → 紅色（過熱） |
| 滑移環 | `slipRatio`、`slipAngle`、`combinedSlip`、`slipIndex`（取最大值） | 車輪下方地面上的一個環：仍有抓地力時為綠色，0.66 時為琥珀色，1 時為紅色（遊戲回報的抓地力邊緣）；低於 0.3 時幾乎看不見 |
| 懸吊桿 | `suspension`（0..1） | 依行程上色的推桿：伸張為藍色，中段為白色，壓縮為紅色 |
| 煞車發光 | `brakeTemp`（100-900 °C） | 車輪外側面的一個煞車碟，由暗色到橘色 |
| 磨損帶 | `tireWear`（0..1） | 胎面邊緣的一圈色帶：全新為白色，磨損為紅色 |
| 負荷條 | `wheelLoad`（0-12 000 N） | 車輪旁邊的一根柱子，高度與負荷成正比 |

煞車燈（雨燈與翼板端板）會隨煞車踏板亮起。每個 `lamp` 通道若為開啟（超過其範圍的一半），就會以其顏色點亮進氣箱上方的一盞燈：ABS 作動、循跡控制作動、DRS、維修站限速器、手煞車，以及騰空。

**人群中**（可見車輛超過 10 台時），沒有被查看的車只以簡單的方式繪製：車身、翼、車輪與煞車燈。

## 標籤 {#labels}

釘在賽道上，每一幀依攝影機的投影放置（在畫面外或攝影機後方則隱藏）。開啟**標籤**時：

| 標籤 | 位置 | 點擊 |
|---|---|---|
| 彎道名稱（`T1`、`T2` ……） | 參考圈上每個彎道的頂點上方 | - |
| 編號徽章 1-5 | 焦點單圈的五個最大駕駛損失，位於每個原因範圍的中點，以原因顏色為外框；滑鼠移上去可看標題與代價 | 排齊並重播該發現 |
| 撞擊／碰撞標籤 | 焦點單圈中每一次爆發的上方："撞車 −45 km/h" / "撞擊 −12 km/h"；滑鼠移上去可看完整說明與建議 | 排齊並重播該次撞擊 |
| 失誤地圖的彎道標籤（地圖為失誤地圖時，取代彎道名稱與徽章） | 每個彎道的頂點："T3 · 5/40 提早煞車"（最常見的失誤，犯錯的圈數／跑過該彎的圈數）；選取了一種時為"T3 · 5/40"；都沒有時為"T3 · 乾淨"；滑鼠移上去可看該彎道的損失，以及其最常見的五種失誤 | 在賽道統計中開啟或關閉該彎道 |

## 鏡像的世界 {#mirrored-worlds}

檢視器的世界是右手座標系，Y 軸朝上：從上方看，行進方向 `atan2(dx, dz)` 增加的車，是在左轉。使用左手座標系的遊戲（Forza 就是其中之一）會呈現鏡像，每一個右彎都會畫成左彎，賽道與單圈皆然。

單圈會自己說明這一點（[`handedness.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/race/handedness.ts)）：每一圈每次沿著走 3 m，將其路徑的轉向，與外側懸吊的壓縮量（`suspension.FR` 減 `suspension.FL`）比較；若沒有懸吊資料，則與方向盤比較（在每個轉接器中，正向都是朝右）。總轉向角小於 π 的單圈不作判斷；證據超過轉向量的 2% 才會計入。單圈投票決定；若平手，則為「無法判斷」。

當單圈的判斷與目前的軸向反轉不一致時（**攝影機與場景 → 反轉世界軸**中，被反轉的軸數為奇數），**單圈**區段會在列表下方提示：

- 遊戲是鏡像，且沒有任何反轉：「這些單圈在賽道繪製為左彎的地方向右轉……」，並附上**反轉 X**；
- 軸已反轉，但單圈並非鏡像：「被反轉的軸，把這些單圈畫成了鏡像……」，並附上**重設座標軸**。

改變的只有繪製——在視圖矩陣中摺疊一個鏡射；資料、分析，以及工具顯示的每一個座標，都仍然是遊戲原本的。這個反轉會保留在瀏覽器中。分析也會用同樣的量測方式，判斷彎道是向左還是向右（未知的世界視為鏡像，與 Forza 相同）。

### 某一刻車輛的狀態 {#what-a-car-is-at-a-moment}

`stateAt` 會在單圈時間前後的兩個樣本之間，對每個通道做內插。會階梯式變化的通道（檔位、旗標），取最近的樣本。已跑完的單圈會停在終點線上。

**航向。** 行進方向取自相隔數公尺的位置（每一側至少 2 m，因此晃動不會讓車子轉向）。車身的航向只有在遊戲的橫擺角與行進方向擬合之後，才會採用——正負號與偏移量，以超過 10 m/s 的樣本（至少 20 個）取圓形平均值求得——而且只有在它與行進方向一致時才採用（圓形變異數低於 0.05，約 18° 的散佈）；否則車身就沿著行進方向。這樣既能看見側滑（車身與行進方向分開），又不必信任遊戲的角度慣例。

**方向盤與左右。** 正向的轉向會使車子向哪一邊轉，以及遊戲的右側輪胎屬於哪一邊，都是從單圈量測得來的：方向盤與路徑轉向的比較，以及在彎道外側是哪一邊的懸吊被壓縮（若沒有懸吊資料，則 Forza 遊戲視為鏡像）。
