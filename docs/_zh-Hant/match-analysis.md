# 對戰分析（Counter-Strike 2）

**對戰**分頁會以圖形重播一段錄影；對於 Counter-Strike 2 的對戰，它還會顯示計分板：每個回合誰贏、如何贏，以及誰拿到擊殺。用它來逐回合檢視一場對戰，然後跳到熱圖中的同一時刻。

對戰分頁能以圖形重播任何錄影：War Thunder 或 Tacview 錄影，或 CS2 示範，這些都列在**重播中的對戰**之下（[對戰重播](match-replay.md)）。CS2 的 `.match.json` 檔案會加上本頁所述的計分板。

## 檢視一場 CS2 對戰 {#review-a-cs2-match}

1. 將示範轉換為 `.parquet` 與 `.match.json` 檔案（[見下文](#where-the-data-comes-from)）。
2. 在**熱圖**分頁中，於**來源**下載入 `.parquet` 檔案。
3. 開啟**對戰**分頁，並點按**載入對戰檔案…**，或將 `.match.json` 檔案拖放到檢視上。
4. 點按**對戰摘要**中的一場對戰，然後點按回合列中的一個格子以開啟該回合。
5. 點按**顯示回合**，即可在熱圖中看到該回合；或點按**重播回合**，以圖形觀看它。

![對戰分頁：回合列（已開啟一個回合）、擊殺紀錄與計分板](../assets/img/en/match-analysis-round.webp)

像 KAST、ADR、eco、強起與補槍這類詞彙，見[詞彙表](glossary.md#counter-strike-words)。

## 資料從哪裡來 {#where-the-data-comes-from}

[3DHeat CS2](https://github.com/Holdi601/3DHeat-CS2) 的示範轉換器會把示範轉成每場對戰兩個檔案，並依地圖分資料夾存放：

```bash
python -m heat3d_cs2 demos <demo files or folders> -o out
```

| 檔案 | 載入於 | 內容 |
|---|---|---|
| `<match>.parquet` | **熱圖**分頁（來源面板，與任何 Parquet 相同——一個、數個或整個資料夾） | 每位玩家每秒八次的位置，以及每個事件發生的地點：擊殺、死亡、受傷、射擊、投擲、煙霧彈、閃光彈、HE、燃燒彈、誘餌、致盲、下包、拆包、爆炸；欄位包括 `match`、`round`、`roundId`、`event`、`player`、`side`、`team`、觀看方向、`weapon`、`place`、`opening`、`traded` …… |
| `<match>.match.json` | **對戰**分頁 | 隊伍、比分、每個回合（勝者、方式、經濟、下包、依序的每次擊殺、殘局、倖存者），以及每位玩家的計分板列 |

Parquet 檔案的結尾含有讀取說明（鍵 `heat3d`），因此開啟時不需要任何設定：玩家即為人員，陣營即為群組，每個回合（`roundId`，「<match> #NN」）即為一個工作階段，觀看方向會開啟，世界的方向也會正確（CS2 的世界為右手座標系，Z 軸向上；若以預設的 Z 軸向上對應讀取，會呈現鏡像）。見[欄位對應](column-mapping.md)與[載入檔案](loading-files.md)。`python -m heat3d_cs2 map <map>` 會以相同座標系匯出地圖幾何，可在**關卡**中載入。

這些數字背後的約定由轉換器決定（寫在其 README 中，並保存在每份摘要裡）：當被擊殺者的擊殺者在 **5 秒**內被受害者的隊友擊殺時，該死亡即為**被補**；**KAST** 是有擊殺、助攻（包括閃光助攻）、存活或被補死亡的回合占比；**傷害**是實際損失的血量，只計敵方；**殘局**是在敵方仍站立時，己方唯一存活的人，並在己方獲勝時算贏；**購買類型**依凍結時間結束時的平均裝備價值，依陣營判定——每半場正規賽的第一回合為手槍局（延長賽中沒有），之後低於 $1,500 為 eco，低於 $4,000 為強起，更多則為全亮。

## 分頁 {#the-tab}

對戰分頁的側邊欄頂部是熱圖的模式切換與工作階段選擇器，下方是對戰的各區段，再下方是熱圖的**篩選器**、**關卡**與**攝影機**面板——檢視顯示的是熱圖分頁中已載入的任何 Parquet 的熱圖。

### 對戰摘要 {#match-summaries}

| 控制項 | 作用 |
|---|---|
| **載入對戰檔案…** | 選取 `.json` 檔案（可一次多個）：即 `.match.json` 摘要 |
| 拖放到檢視上 | 在對戰分頁開啟時，拖放到檢視上的 JSON 檔案以相同方式載入（其他檔案會被忽略） |
| **清除** | 移除所有對戰 |
| **所有對戰**（有兩場或以上時） | 「N 場對戰 · M 個回合」：所有對戰的統計 |
| 一列對戰 | 「TeamA 13 對 TeamB 9」，地圖 · N 個回合：開啟該場對戰 |

檔案只有在它是 JSON、含有 `"format": "heat3d-cs2-match"`，且具有陣列 `rounds`、`players` 與 `teams` 時才會被接受。錯誤會列在按鈕下方：「<file>：不是 JSON」、「<file>：不是 CS2 對戰摘要（heat3d-cs2-match）」、「<file>：缺少 rounds、players 或 teams」。若重新載入同一場對戰（相同的 `match` 名稱），會取代先前的那一場。對戰會依地圖排序，再依名稱排序。若只載入一場對戰，會直接開啟；否則選取保持不變（預設為所有對戰）。

沒有載入任何東西時，此區段會說明：用 `python -m heat3d_cs2 demos` 轉換，在此載入 `.match.json` 檔案，並在熱圖分頁中載入 `.parquet` 檔案。

### 對戰（已開啟一場對戰） {#match-one-match-open}

**標題列：**兩隊與其比分、地圖、半場——「半場 7-5、6-6」：第 1–12 回合與第 13–24 回合（競技與競爭模式採 MR12；若摘要明確說明半場長度，則依其數值，例如 MR15 為第 1–15 與第 16–30 回合）——然後，若對戰進入延長賽，則單獨顯示其比分：「延長賽 4-2」，即兩個半場之後的回合。平手的回合不計入任何一隊。若摘要列出不完整的回合，則顯示「示範中截斷了 N 個回合」。

**回合列：**每個回合一格，依獲勝的陣營上色，格中有其編號與一個表示結束方式的標記。平手的回合（沒有勝者）是一個中性灰色的格子，標記為 `=`，絕不使用任何陣營的顏色；其工具提示寫著「第 30 回合：平手——雙方皆未贏下」。

| 標記 | 結束方式 |
|---|---|
| B | 炸彈爆炸 |
| D | 炸彈拆除 |
| K | 全部擊倒 |
| T | 時間用完 |
| S | 投降 |
| = | 平手 |
| ? | 其他 |

分隔線標示第二半場的開始（第 13 回合，或摘要半場長度之後的那一回合），以及每個三回合延長賽半場的開始（第 25、28、31……回合）。將指標移到格子上會顯示：「第 7 回合：TeamA（T）——炸彈爆炸，已下包於 A」（若摘要沒有包點資訊，則為「……，已下包，包點未知」），以及雙方的購買類型與裝備價值。點按即可開啟該回合；再點按則關閉（「點按一個回合，即可查看其擊殺、經濟與重播。」）。

**回合：**

- 「第 7 回合：<team> 獲勝——<how>」（若為平手，則為「第 30 回合：平手——雙方皆未贏下」），以及該回合持續的時間（從凍結結束到定勝負，m:ss）；
- 經濟：每個陣營的隊伍、購買類型（手槍、eco、強起、全亮）與裝備價值（「$4,350」）；
- 下包：包點、玩家，以及進入回合後的時間（兩種摘要版本皆可）；若包點未知，則顯示「由 <player> 於 1:05 下包，包點未知」；
- **擊殺紀錄**，依序：進入回合後的時間、攻擊者（以其陣營顏色顯示；沒有攻擊者則為「world」）、武器，以及標記——**HS** 爆頭、**WB** 穿牆、**SM** 穿煙；**open** 為該回合的第一次擊殺，**trade**（在 5 秒內為隊友報仇），**traded**（擊殺者在 5 秒內被擊殺），**team** 誤殺（自殺不算）。在回合已定勝負之後發生的擊殺會變暗；
- 殘局：「<player>（T）一人對 3：殘局獲勝」／「殘局落敗」；
- 各陣營在結束時仍存活的人（「沒有人」）；
- **顯示回合**：此回合的一切，在熱圖中顯示；
- **重播回合**：從回合開始，以方框重播該回合（見下文）。

本場對戰或已開啟的回合，會在其下方有**在熱圖中顯示**按鈕（見[下文](#show-in-the-heatmap)）。

### 計分板 {#scoreboard}

每隊一個表格，每位玩家一列：

| 欄位 | 意義 |
|---|---|
| K、D | 擊殺、死亡 |
| A | 助攻，包括閃光助攻 |
| ± | 擊殺減死亡（大於 0 為綠色，小於 0 為紅色） |
| ADR | 每回合傷害，即實際損失的血量 |
| KAST | 有擊殺、助攻、存活或死亡被補的回合百分比 |
| HS | 爆頭擊殺的百分比 |
| Open | 首殺對決的勝－負 |
| Cl | 殘局的勝／總數 |

將指標移到某位玩家上：會顯示補槍擊殺、被補次數、閃光助攻、閃到的敵人數、道具傷害，以及多殺回合（「2×3k」）。**點按玩家**即可在熱圖中查看其（本場對戰的）擊殺與死亡。

### 跨對戰（所有對戰） {#across-matches-all-matches}

對所有已載入的對戰：

- 「N 場對戰 · M 個回合 · <maps>」，若有平手，另有「N 個回合平手，雙方皆未贏下」；
- 每個陣營的**贏得回合**：整體、**手槍局**（摘要中的手槍局），以及 **eco**、**強起**與**全亮**購買（各以百分比加上所打回合數顯示；將指標移上去可見「贏的場次／打的場次」）。平手的回合由雙方都打了，但雙方都沒贏；
- **炸彈**：每個包點的下包數，以及 T 方在這些回合中後來贏了多少次（「在 A 下包 12 次（T 贏 67%）」）、摘要本身不知道包點的下包（「在未知包點下包 2 次（T 贏 50%）」），或「從未下包」；回合如何結束，依最常見者排序；
- 「取得首殺的陣營贏得了其中 N% 的回合。」（自殺不算首殺；平手的回合不會將首殺轉換為勝利）；
- **首殺對決位置**：首殺數最多的十個地點（依受害者所在位置；遊戲的地點名稱已轉為易讀的形式，例如「TopofMid」→「Top of Mid」），對決次數，以及 T 方贏得的比例；
- **玩家**：依擊殺減死亡排名前十五的玩家，合併其所有對戰（依 Steam ID 配對）：場次、K-D、以回合數加權的 ADR 與 KAST、以擊殺數加權的 HS%，以及首殺對決。**點按玩家**即可在熱圖中查看其跨所有對戰的擊殺與死亡。

「在熱圖中顯示」按鈕（針對所有已載入的對戰）位於其下方。

## 在熱圖中顯示 {#show-in-the-heatmap}

每個連結都會設定熱圖本身的**篩選器**，因此顯示的內容會保留在篩選器面板中，可以看到也可以編輯；**全部顯示**會將其清除。它們作用於熱圖分頁中已載入的熱圖表格；對戰分頁本身從不載入它。

| 按鈕 | 顯示的事件 |
|---|---|
| **位置** | `position`——玩家所在的位置，每秒八次 |
| **擊殺** | `kill`——擊殺者所站的位置 |
| **死亡** | `death`——受害者倒下的位置 |
| **首殺** | `kill` 與 `death`，其中 `opening` = 1——每回合的第一次擊殺，雙方所在的位置（僅在表格有 `opening` 欄位時提供） |
| **煙霧彈** | `smoke`——煙霧彈落地的位置 |
| **閃光彈** | `flash`——閃光彈爆開的位置 |
| **燃燒彈** | `molotov`——燃燒彈與燃燒瓶燃燒的位置 |
| **HE** | `he`——HE 手榴彈爆炸的位置 |
| **下包** | `plant`——炸彈下包的位置 |
| **射擊** | `shot`——開槍的位置 |

範圍由按鈕所在的位置決定：所有已載入的對戰、本場對戰，或本回合（「在熱圖中顯示——第 7 回合」）。

無法套用的條件會顯示在按鈕下方，而不會悄悄地篩選成空白：「沒有保留對戰欄位——未套用對戰篩選」、「對戰：X 不在已載入的資料中」、回合與事件也是如此，「玩家 X 不在已載入的資料中」、「陣營 X 不在已載入的資料中」、「未載入熱圖資料：請在熱圖分頁中載入對戰的 .parquet 檔案」。在沒有載入資料時，這些連結也會顯示「請在熱圖分頁中載入對戰的 .parquet 檔案，以在地圖上看到它們。」

**重播回合**另外會將熱圖切換為**箱形重播**，時間軸切換為*播放*模式，其視窗設定為*生命期*，跳到該回合工作階段的開始並開始播放。若該回合不是已載入資料中的工作階段：「此回合不是已載入資料的工作階段：沒有可重播的內容」。

### 摘要版本 {#summary-versions}

此分頁會同時讀取版本 1 與版本 2 的摘要（檔案中的 `"version"`），並將兩者一視同仁：

| | 版本 2 | 版本 1 |
|---|---|---|
| 下包時間 | 回合內的秒數，與擊殺相同 | 對戰秒數；分頁會減去回合的開始時間 |
| 下包包點 | `A` 或 `B`；示範未說明時為空 | `A`、`B`，或實體編號——視為未知包點 |
| 半場長度 | `halfLength`，從雙方第一次交換位置時計算；為 null 時為 12 | 12（MR12） |
| 手槍局 | `pistolRounds`（第 1 回合與半場後的第一回合） | 購買類型為 `pistol` 的回合 |
| 平手回合 | `winner` 與 `winnerTeam` 為空 | - |
| 自殺 | 擊殺上的 `suicide`，絕不是誤殺 | 由攻擊者與受害者為同一玩家判定 |

擊殺上的 `noscope` 與 `attackerBlind`（版本 2）不會在對戰分頁中顯示；對戰分頁也不顯示熱圖表格中的地點，因此該表格中手榴彈列的空白 `place` 在此處不會造成任何影響。

焦點如何轉換為篩選器（`focusFilters`）：

- **對戰** → 對 `match` 欄位的類別篩選；
- **回合** → 對數值型 `round` 欄位的範圍篩選 `round` = N（對類別型欄位則為類別篩選），並在工作階段選擇器中選取該回合的工作階段（`<match> #NN`）；
- **事件** → 對 `event` 欄位的類別篩選；
- **玩家** → 對該玩家的人員篩選；
- **陣營** → 群組篩選。
