# 場次、人物與群組

**人物** 是一個移動中的事物（一位玩家、一輛車）。**隊伍／群組** 是他們所屬的陣營。**場次** 是一場比賽或一圈。請參閱[詞彙表](glossary.md)。

檔案中的一列可以同時指名這三者：

| x | y | time | player | team | match |
|---|---|---|---|---|---|
| 10.5 | -30.2 | 12.0 | Blue 1 | Blue | Match 01 |

`player` 是人物，`team` 是群組，`match` 是場次。

有三個可選欄位描述一列屬於*誰*，以及它屬於故事中的*哪個位置*。每個欄位在載入時都會做字典編碼：文字值變成每列一個小型整數 ID，外加一份標籤清單，並由該次載入的每個檔案共用。

## 人物 {#person}

**人物 ID** 欄位指出一列屬於哪個移動中的事物：一位玩家、一個機器人、一輛車。它以每列 32 位元 ID 的形式保存。

當有人物與時間欄位時，載入會為每一列計算其**存續時間**：到同一人物在*同一場次中*的下一個樣本為止的時間；若沒有下一個樣本——該人物死亡、離開，或紀錄已結束——則為「無」（一個哨兵值 -1）。存續時間為[時間軸](timeline.md)的**存續時間**歷史、[箱形重播](box-replay.md)中的內插與過時判斷，以及[線條熱度](line-heat.md)的路線中斷提供依據。沒有後續樣本的列會如何處理，是一項檢視設定（*備用存續時間*），而不是寫死在資料中。

每位人物會被指派其時間上**第一**列所屬的群組；此指派決定他們在箱形重播中的方框顏色，以及在那裡由哪個群組的可見性開關隱藏。熱度模式則改用每一列自己的群組。

### 同時由多個事物共用的名稱 {#names-worn-by-several-things-at-once}

一個名稱不一定只對應一個實體：在某些匯出中，每場比賽的每個機器人都以同一個名稱記錄。若將這種「人物」的兩個樣本相連（透過內插、拖尾或路線），就會在地圖上畫出一條連接兩個不同生物的線。

載入時（[`computeLifetimes`](https://github.com/Holdi601/3DHeat/blob/main/src/data/builder.ts)），若某個名稱的兩筆紀錄符合以下所有條件，該名稱會被標記為**共用**：

- 位於同一場次；
- 時間相同；
- 種類相同（每個保留下來的類別欄位都具有相同的值）；且
- 彼此的距離大於資料範圍對角線的 1%。

共用名稱會以單一樣本繪製——不做內插、不畫拖尾、也不產生線條熱度路線。它們的其他部分（例如熱度）不受影響。資料集面板會列出被標記的名稱數量，並附上最多三個例子；箱形重播面板也會重複顯示這個數量。

## 場次 {#session}

**場次／對戰** 欄位指出一列屬於哪一場比賽、團隊戰、回合、跑步或圈。它是讓同一人物的樣本成為一條連續軌跡的關鍵：真實的遙測常常會交錯進行中的多場比賽，而播放頭之前的一個樣本與之後的一個樣本，可能分屬相距數百公尺的不同比賽。有場次欄位時：

- 內插、拖尾與線條熱度路線永遠不會跨越場次的變更；
- 一列的存續時間會在其所屬場次結束時終止；
- **場次** 選擇器會出現在側欄頂端、模式列之下。

場次欄位經常是*時間戳*——即比賽的開始瞬間，在該場比賽的每一列上重複出現。自動對應因此會在人物與群組之前先尋找場次名稱（[欄位對應](column-mapping.md#session-person-group)）。賽車的一圈或一段（stint）也是一個場次：同一輛車的兩圈絕不能被串成一條軌跡。

### 場次選擇器 {#the-session-picker}

![打開的場次選擇器，位於含十場比賽的檔案上：全部場次（10）、Match 01、Match 02 等](../assets/img/en/sessions-persons-groups-picker.webp)

*同一個檔案中有十場比賽：選一場，或全部檢視。*

當資料集已列出場次時顯示（參閱下方的上限）。

| 部分 | 意義 |
|---|---|
| 右側的標籤 | 所選場次的列數，或*全部同時*。 |
| 選單 | *全部場次（N）*，接著是每個場次，依最忙碌者排前，格式為 `標籤 - N 列, 跨度`（跨度在 90 秒以下以秒計，90 分鐘以下以分鐘計，以上以小時計）。 |
| 琥珀色提示 | 在*全部場次*時顯示：位置仍然絕不會跨場次相連，但同時進行的比賽會把不相干的玩家一起放上地圖。 |
| 提示 | 在熱度模式中選定單一場次時顯示：此選擇只會移動播放頭。 |

載入時會自動選定最忙碌的場次。選定某個場次時，播放頭會跳到該場次的開始處。

此選擇會改變的內容：

- 在 **[箱形重播](box-replay.md)** 中，它決定播放哪一場：只繪製該場次的方框與軌跡，而時間軸的範圍會變成該場次自己的跨度。
- 在 **熱度模式** 中，它不會限制熱度，選擇器下方的提示會說明這一點：*在熱度模式中，此選擇只會把播放頭移到該場次的開始處；熱度仍會計入每一個場次。箱形重播只會播放所選的場次。* 若要把熱度限制在單一場次，請同時將場次欄位保留為篩選欄位（*保留以供篩選*），並以它來篩選。一個欄位可以同時是場次欄位與篩選欄位：載入器會獨立讀取每個勾選的篩選欄位，無論它另外扮演什麼角色。

### 場次過多 {#too-many-sessions}

最多會列出 **100,000** 個場次。超過此數時，該欄位其實就是一個 ID（例如一個資料夾中有數百萬個場次，每個場次只有少數幾列），若將如此多的標籤從工作執行緒送到頁面，就會讓分頁耗盡記憶體。此時載入會保留場次的 **ID**——因此邊界仍然在各處生效——但捨棄標籤與選擇器，資料集面板會說明這一點。

## 群組 {#group}

**隊伍／群組** 欄位可以是任何低基數的欄位：一支隊伍、一個陣營、一個小隊、一個派系、一個玩家對 AI 的旗標，或一個車輛等級。它以每列 16 位元 ID 的形式保存，並驅動：

- [隊伍清單](teams-list.md)（各群組的可見性，以及 + / − 陣營）；
- [隊伍熱度](team-heat.md)（每個群組一個色相）；
- 依群組的[差異](difference.md)分割；
- [箱形重播](box-replay.md)中的方框顏色（每個群組一個色系，每位成員一個色階）。

### 限制 {#limits}

最多 **4,096** 個不同的群組。群組 ID 會搭載在 GPU 上每一列位置紋素的第四個通道中，而每個群組在著色器讀取的 4,096 寬符號表中都需要一個紋素，用來決定*隱藏*、*新增*或*扣除*。若某欄位的不同值更多，它就是一個 ID，而不是群組：**載入會保留每一列，只捨棄分組**，並在資料集上顯示警告，建議改將其對應為人物欄位，或保留為篩選欄位。

同樣的 4,096 限制也適用於保留下來的*類別*篩選欄位；超過此數的欄位不會被保留，資料集會說明這一點。數值欄位（例如時間戳）作為*範圍*篩選時則沒有這個限制。

群組值 `0`、空值、`none`、`unknown`、`null` 與 `-1`（不分大小寫）對[隊伍熱度](team-heat.md)而言表示「沒有群組」，會以中性灰色繪製，而不會賦予明確的顏色。

## 實體大小 {#entity-size}

一個被追蹤事物的大小（玩家的碰撞盒、一輛車）決定了[箱形重播](box-replay.md)中方框與視線射線的繪製大小。面板中沒有針對它的欄位；它來自檔案的 [`heat3d` 提示](data-formats.md#the-heat3d-hints)（`entity.size`，以檔案自身的單位表示；CS2 轉換器寫入 32）。載入時會將它乘以單位比例。

每次載入時（[`calibrate`](https://github.com/Holdi601/3DHeat/blob/main/src/data/calibrate.ts)），*範圍*為資料的 X 與 Z 跨度中較大的那一個：

| 設定 | 有實體大小時 | 沒有實體大小時 |
|---|---|---|
| 立方體大小 | 實體大小 | 範圍 / 500 |
| 視線射線長度 | 實體大小 × 4 | 範圍 / 200 |
| Sprite 半徑 | 範圍 / 120 | 範圍 / 120 |
| 飽和點 | 解析估計（之後再測量） | 相同 |
| 飛行速度 | 範圍 / 12 | 相同 |
| 遠裁剪面 | 範圍 × 12 | 相同 |
| 近裁剪面 | max(0.05, 範圍 / 20,000) | 相同 |

## 資料集面板 {#the-dataset-panel}

位於來源面板之下。載入資料集後，它會顯示：

- 資料集的**名稱**——選取內容、列數、檔案數，以及若有使用抽樣時的步距；
- **`N 支隊伍 · N 位人物 · N 秒跨度`**；
- 載入時產生的每一則**警告**，以琥珀色顯示，只要該資料集仍在載入中就會持續顯示：因為值過多而被捨棄的群組或篩選欄位、未列出的場次、共用名稱、遺失的列、被略過的檔案；
- [合成產生器](synthetic-generator.md)；
- **卸載**，用以移除資料集。

列數顯示在面板的標題列上。
