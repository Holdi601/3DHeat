# 3D 關卡

3D 關卡是你的資料所在場地的模型——山丘、街道、建築物。它讓你看到熱量位於哪一層、哪座山丘或哪個屋頂之上。檢視器會把它分為地面（實心）、結構（半透明，讓你能看進去）與水體。

## 載入 3D 關卡 {#load-a-3d-level}

1. 先載入你的資料（[匯入資料](getting-data-in.md)）。模型必須與資料使用相同的世界空間與單位，且 Y 軸向上。
2. 在**背景／關卡**中，選擇一個**簡化目標**。除非模型非常大，否則保持*完整——不簡化*。
3. 按**3D 模型…**，並選取一個 `.glb`、`.gltf`、`.obj`、`.stl` 或 `.ply` 檔案。
4. 等待進度列。按**取消**即可停止。
5. 在檢視中按 **F**。地面為實心，結構為半透明外殼，水體為平面。
6. 在[關卡外觀](level-appearance.md)中調整外觀。按**儲存至關卡庫**即可保留結果（[關卡庫](level-library.md)）。

![已載入的 3D 關卡：不透明的地面與等高線、半透明的建築物、平坦的水面](../assets/img/en/model-levels-loaded.webp)

**3D 模型…**會載入關卡網格。它會在背景工作執行緒（[`modelWorker.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/modelWorker.ts)）中被剖析、分類並簡化，並顯示進度列與**取消**：*讀取模型*、*剖析檔案*、*打包 N 張貼圖*、*分類 N 個部件*、*簡化地面（N 個三角形）*、*簡化結構（N 個三角形）*、*建立線框*。

## 格式 {#formats}

| 格式 | 讀取內容 | 限制 |
|---|---|---|
| `.glb` | 每個 `mode` 為 4（三角形）或沒有 mode 的網格圖元，並套用每個節點的世界變換；`POSITION`；`COLOR_0`（vec3 或 vec4）作為頂點顏色；材質的 `baseColorTexture` 及其 `TEXCOORD_n` 作為貼圖；節點與網格名稱作為部件名稱。 | 線與點會被略過。 |
| `.gltf` | 相同。 | 僅限內嵌緩衝區：參照外部 `.bin` 的 glTF 會被拒絕，並顯示*匯出為單一 .glb，使幾何資料內嵌。* |
| `.obj` | 面，`o` 與 `g` 區塊作為部件。 | 僅幾何（無材質）。 |
| `.stl` | 二進位與 ASCII（`solid …`）。 | 一個部件。 |
| `.ply` | 僅 ASCII。 | 二進位 PLY 會被拒絕，並顯示*轉換為 .glb 或二進位 .stl。* |

僅幾何：位置、法線與三角形會焊接成一個緩衝區，若存在，另加顏色與貼圖座標（[`modelParse.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/modelParse.ts)）。沒有三角形的模型會被拒絕。模型必須與資料使用相同的世界空間與單位（Y 軸向上）：不會為了配合而做任何變換。

## 地面、結構與水體 {#ground-structures-and-water}

關卡在匯入時會被分為三個類別，因為它們需要相反的處理方式（[`classify.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/classify.ts)）：

- **地面**——以不透明方式繪製，並帶有起伏提示（坡度、等高線、高度漸層），使位置可以對照它來讀取。
- **結構**——建築物與道具位於攝影機與其內部熱量之間，因此以**透明外殼**繪製（淡色的面加上明亮的邊緣，以及去除重複的邊線）——若有貼圖，則以其貼圖呈現實心。
- **水體**——平面，沒有地形提示：橫跨湖面的等高線毫無意義。

每個部件（glTF 節點、OBJ 物件或群組）都會各自分類，依第一個適用的規則：

1. **匯出器的標籤。** 以 `ground:`、`structure:` 或 `water:` 開頭的名稱（或以 `|` 取代 `:`）會被照字面採用。本專案自己的匯出器會以此方式為每個部件加上標籤。
2. **水體名稱。** 以單字形式出現的 `water`（不包括 *water tower*、*-tank*、*-mill*、*-front*、*-fall*、*-pump*、*-pipe*），以及 `ocean`、`sea`、`lake`、`pond`、`lagoon`、`river`。
3. **地面名稱。** `terrain`、`landscape`、`ground…`、`…_ground`、`heightmap`、`floor…`、`map` / `map_…`、`base` / `base_…`、`road`、`street`、`pavement`、`sidewalk`。
4. **結構名稱。** `house`、`building`、`bldg`、`wall`、`roof`、`door`、`window`、`stair`、`prop`、`asset`、`clutter`、`debris`、`crate`、`barrel`、`fence`、`tree`、`rock`、`bush`、`vehicle`、`car`、`truck`、`tank`、`bridge`、`tower`、`silo`、`hangar`、`bunker`。
5. **幾何。** 覆蓋地圖 X-Z 面積超過 25%，且其三角形面積中超過 60% 朝上的部件為地面。朝上比例低於 45%，或高度超過關卡高度 15% 而覆蓋面積不到 10% 的部件，為結構。朝上比例以面積加權，因此房屋不會因為有屋頂就被判定為平坦。
6. **否則為地面**——模糊的部件預設為地面，因為預設為幾乎看不見的外殼，會讓關卡看起來像是渲染失敗。

若模型只有單一個部件被分類為結構，則改為地面（*單一未命名網格——視為地面*）。

### 導航網格 {#navigation-meshes}

名稱為 `nav:…`（關卡匯出器的 `nav:walkable`）的部件，是一個導航網格：士兵可以站立的地方。它被列為地面（*導航網格——不繪製，因為它位於地面上；點按仍可找到它*），但**不會繪製**。它覆蓋在其所從生成的地面之上，與之共面，誤差在公分以內；若把它繪製為地面，兩個表面會在每個像素上爭奪顯示：在一個有烘焙地面貼圖的關卡上，整個可遊玩區域會顯示為硬邊的灰色與米色斑塊，每個導航三角形一塊。它會被保留，且不簡化，以便[點按拾取](camera.md#click-to-pick)能說明某個地點是否可以行走。圖庫項目不會保留它。

面板中的**顯示部件分類（N）**（僅對有多個部件的模型顯示）會列出每個部件及其類別與原因——*由匯出器標示*、*名稱符合模式*、*覆蓋地圖 X%，朝上 Y%*、*朝上 Y%，佔關卡高度 Z%*、*模糊——預設為地面*。若要變更其中一個，請在來源模型中重新命名該部件，然後重新匯入；分類已烘焙在索引緩衝區中。

## 簡化 {#simplification}

**簡化目標**設定下一次匯入的三角形預算（[`simplify.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/simplify.ts)）：

| 設定 | 三角形數 |
|---|---|
| *完整——不簡化*（預設） | 全部 |
| *高——8M 個三角形* | 8,000,000 |
| *中——3M 個三角形* | 3,000,000 |
| *低——800k 個三角形* | 800,000 |
| *輪廓——100k 個三角形* | 100,000 |

預算會以 **60% 分給結構、40% 分給地面**，分別簡化——結構在抽稀時最快失去其形狀。水體不會被簡化。簡化採用二次誤差度量的邊收縮（[meshoptimizer](https://github.com/zeux/meshoptimizer)，透過 WebAssembly），並在焊接重合的頂點之後進行，因此輪廓與硬邊得以保留。匯入說明會回報 `來源 → 現在的三角形數，偏差 X%`、各部件之間的地面／結構／水體比例，並且——當對超過 800 萬個三角形的模型使用*完整*時——建議改用*高*（最多 3,000 萬個）或*中*（更多）。若沒有 WebAssembly，簡化器無法使用，匯入時會說明此事。

專案自己的匯出器所產生的關卡已經有預算；此目標是為了沒有預算的原始美術素材而存在的。

## 貼圖 {#textures}

若 `.glb` 的部件帶有基底顏色貼圖，就會以這些貼圖繪製——例如，賽道的匯出檔每個地形圖塊與每個放置的模型各帶有一張貼圖。

存在貼圖時，預設會顯示地面貼圖；帶有貼圖的結構會以**其自身的貼圖、實心**方式開始（路緣、護欄、輪胎牆與標誌是道路的邊緣，而不是需要看進去的建築物），線框與平面著色皆為關閉。見[關卡外觀](level-appearance.md)。

## 大型關卡 {#large-levels}

- 超過 **300,000** 個結構三角形時，結構邊線會一開始就關閉，面的不透明度設為 35%：若每個像素都有一條邊線，該區域會顯示為平坦的白色。
- 攝影機的遠裁切面會擴大，以容納整個關卡（[關卡](levels.md#what-a-level-does-for-the-heat)）。

## 給開發者 {#for-developers}

### 紋理圖集 {#texture-atlas}

每一張貼圖都會在匯入工作執行緒中被打包進**一個圖集**（[`atlas.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/atlas.ts)），因此在兩種後端上，關卡都維持一次繪製、一個取樣器與一個紋理座標屬性：

- 以各圖像自身的尺寸以層架方式打包，只有在整組無法放入任一方向的 **8192 px**（WebGPU 預設的紋理尺寸上限）時才會縮小；
- 每張圖像周圍有 **16 像素的邊界**，且只保留該邊界所保護的 5 個 mip 層級，因此遠處的標誌永遠不會取樣到其鄰近貼圖；
- **重複貼圖**保持重複。若某圖像的 glTF 取樣器會重複（glTF 預設），且其紋理座標超出 0..1——例如一面沿其方向 UV 從 0 延伸到 40 的磚牆——它就會成為一個*圖塊*：其頂點保留自己的座標與一個 16 位元的圖塊編號，著色器會在每個像素上把座標包回圖塊的矩形內，mip 層級則取自未包裹的座標，因此接縫不會顯現。圖塊的邊界保有其自身相對的邊緣。若某軸的取樣器是夾限的，則維持夾限；座標保持在 0..1 內的圖像，則照舊繪製。含有圖塊的關卡，每個頂點多耗用 4 位元組。

### 匯出器合約 {#the-exporter-contract}

無論製作者是誰，檢視器對關卡的需求如下：

- 一個自成一體的 `.glb`；
- float32 的 `POSITION`，三角形圖元；
- 節點名稱為 `ground:*`、`structure:*` 與 `water:*`（其他名稱依上述規則分類），而 `nav:*` 為導航網格，會被保留但不繪製；
- 世界空間座標，**Y 軸向上**，與遙測資料使用相同的單位，使資料不需要任何放置步驟，即可位於關卡之上。
