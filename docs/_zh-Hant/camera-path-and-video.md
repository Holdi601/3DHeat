# 攝影機路徑與影片

為你的資料拍一部影片：你把攝影機放在幾個位置，檢視器會在它們之間飛行，並儲存成影片。每個影格都非常乾淨，沒有顆粒感。攝影機與播放頭會一起移動，因此同一個面板也能做延時攝影（[`PathPanel.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/panels/PathPanel.tsx)、[`campath.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/campath.ts)、[`record.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/record.ts)）。

## 製作飛越影片 {#make-a-flythrough}

1. 飛到影片開始的位置，然後按下**攝影機路徑與渲染**中的**在此新增關鍵影格**。
2. 飛到下一個位置，再按一次。每一個停靠點都重複這個動作。
3. 勾選**沿路徑預覽**，並拖曳**路徑上的位置**來檢查移動。
4. 設定**長度**（影片的時間長度）。如果移動的方式正確但太快，只要加長長度即可。
5. 按下**渲染影片**。等待進度列；完成時檔案會自動下載。

![攝影機路徑與渲染面板，含三個關鍵影格、平滑內插、12 秒、30 fps 與 16 Mbps](../assets/img/en/camera-path-panel.webp)

## 關鍵影格 {#keyframes}

| 控制項 | 效果 |
|---|---|
| **在此新增關鍵影格** | 將目前的攝影機位置、偏航、俯仰與視野新增為一個關鍵影格。 |
| **清除** | 移除所有關鍵影格。 |
| 關鍵影格清單 | 每個關鍵影格一列：其編號（點擊即可把攝影機飛到該處，並同時設定視野）、位置、`偏航° / 俯仰°`，以及用來移除它的 **×**。 |

每當新增或移除一個關鍵影格時，這些關鍵影格都會沿著從 0 到 1 的標準化路徑軸**均勻**地排列；輸出長度接著會拉伸整段移動，因此移動方式正確但太快的鏡頭，只需要加長長度即可。關鍵影格之間的偏航會被展開，使攝影機以較短的方向轉動。

沒有關鍵影格時，渲染會讓目前的攝影機在整段影片中保持靜止——這本身就是一個很好的延時攝影。

## 路徑設定 {#path-settings}

| 控制項 | 預設值 | 範圍（撥動） | 意義 |
|---|---|---|---|
| **內插**（2 個以上關鍵影格） | *平滑* | *平滑* / *直線* | *平滑*：穿過各關鍵影格的三次 Hermite 曲線，切線取自相鄰的關鍵影格，因此每個關鍵影格兩側的速度相符，線段交接處不會突然顛簸。*直線*：關鍵影格之間為直線，可預測，但每個關鍵影格都會有一個可見的轉角。視野一律以線性方式內插。 |
| 移動線（2 個以上關鍵影格） | | | `N 個單位的移動 - 在此長度下每秒 M 個單位`，或說明所有關鍵影格都在同一個位置。 |
| **沿路徑預覽**（1 個以上關鍵影格） | 關閉 | | 依路徑驅動視埠攝影機，並隨渲染一樣移動播放頭，讓你能在渲染前判斷移動的效果。 |
| **路徑上的位置**（預覽時） | 0% | 0-100% | 要在路徑的哪個位置預覽。 |
| **長度** | 12 s | 1-120 s（3600） | 影片的長度。 |
| **影格速率** | 30 fps | 6-60（240） | |
| **位元速率** | 16 Mbps | 1-60 Mbps，對數刻度（400） | 熱度漸層在低位元速率下會出現明顯的色階斷層：編解碼器能用來隱藏誤差的細節很少。 |
| **收斂等待上限** | 240 個影格 | 2-600（10,000） | 一個輸出影格為了變得精確而可以等待的最長時間。達到上限的影格仍會被寫入，並會計算在內。 |
| 摘要 | | | `N 個影格 · 視窗：累積／固定／存續期`；當時間軸處於*全部*模式時，會顯示：*（渲染會把「全部」切換為「播放」，讓播放頭有意義）*。 |
| **渲染影片**／**取消** | | | 開始渲染；執行期間會顯示 `影格 i / n · 等待 w · X MB`，以及有多少影格不夠精確。需要資料集。 |

## 提示 {#tips}

- 輸出大小為畫布以裝置像素計的尺寸（顯示器的像素比例，上限為 2）。要改變它，請調整瀏覽器視窗的大小。
- 累積歷史會在影片期間逐漸建立熱度；視窗或存續期歷史則會顯示一段移動中的時間切片。
- 關鍵影格的位置是顯示座標：若使用了[反轉的世界軸](camera.md#invert-world-axis)，在切換前建立的關鍵影格，切換後會指向別處。

## 給開發者 {#for-developers}

### 渲染做了什麼 {#what-a-render-does}

1. 先拍攝一張測試擷取畫面，以得知以裝置像素計的精確輸出尺寸。
2. 透過 WebCodecs 選擇編解碼器：**VP9**（`vp09.00.10.08`），否則使用 **VP8**，並採用所選的位元速率與影格速率。若沒有 `VideoEncoder`，會停止並顯示 *This browser has no VideoEncoder - WebCodecs is required to write a video*；若兩種編解碼器都不支援，則顯示 *No supported video codec (tried VP9, VP8)*。
3. 接管渲染所需的設定：暫停播放，將**自適應預算關閉**、**漸進式精緻化開啟**，並把 Sprite 預算設為每個影格 6,400 萬個（自適應預算保護的是影格率，而這裡的目標並非如此：它會把每個緩慢收斂的影格視為應該減少繪製資料列的理由，而這需要更多影格才能收斂），並把時間軸從**全部**切換為**播放**。歷史設定（累積、視窗、存續期）則保持不變：渲染的目的，是把你正在看的內容播放一遍並記錄下來。
4. 對於 *n* 個輸出影格中的每一個 *f*，設 *u* = f / (n - 1)：
   - 將攝影機放在路徑於 *u* 處的姿態（若有關鍵影格）；
   - 將播放頭移到時間軸範圍中相同的比例 *u* 處（在盒子重播中則為所選場次的跨度）；
   - 即使攝影機沒有移動，也會強制進行全新的估計——繼承上一個影格的累積，會在畫面上留下前一個視窗的殘影；
   - 逐影格等待，直到畫面精確為止（所有候選資料列在一個影格內繪製完成，或累積已完成），最多到等待上限；
   - 擷取合成後的影格並編碼，每輸出 2 秒插入一個關鍵影格，使檔案可以定位。
5. 依影格速率決定時間戳，將影格封裝為 WebM 檔案（[`webm.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/webm.ts)）——每個影格實際花費的時鐘時間並不重要。
6. 還原預算、視野、時間軸模式、播放頭，以及原本是否正在播放。
7. 將影片下載為 `3dheat-<width>x<height>-<frames>f.webm`，並回報 `N 個影格，尺寸 W×H，X MB - 每個影格都精確`，或有多少影格達到了等待上限。

**取消**會在目前的影格之後停止（*渲染已取消。*），並還原設定。
