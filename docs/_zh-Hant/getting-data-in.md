# 匯入資料

在 3DHeat 能畫出任何東西之前，它需要一張表格：每一列說明某件事發生在哪裡，若你有記錄，也會說明何時、以及是誰。本節說明一個檔案如何變成一張圖。還沒有資料？試試[示範資料](demo-data.md)。

**現在就這樣做：**

1. 在熱圖側邊欄中開啟**來源**，然後按**多個檔案…**（或把檔案或資料夾拖放到放置區）。
2. 查看**欄位對應**：方框通常已自動填好。
3. 確認**記憶體估計**顯示*可容納*。
4. 按**載入**。

```mermaid
flowchart LR
  A["來源<br/>選取檔案或資料夾"] --> B["預覽<br/>前幾列"]
  B --> C["欄位對應<br/>X、Y、Z、時間、人員、隊伍"]
  C --> D["記憶體估計<br/>可容納、勉強或容不下"]
  D --> E["載入"]
  E --> F["圖像"]
```

熱圖頁籤所顯示的一切，都來自一個**資料集**：一張表格，每列都有位置，並可選擇性地包含時間、人員、群組、場次、視線方向，以及任意數量保留用於篩選的額外欄位。本節說明資料集如何製作。

## 從檔案到圖像的路徑 {#the-path-from-files-to-picture}

1. 在**來源**面板中**選取檔案**：一個、多個、一整個資料夾樹，或直接拖放。可接受 Parquet、CSV、Tacview、GPS 軌跡等；完整清單位於[資料格式](data-formats.md#files)。請參閱[載入檔案](loading-files.md)。
2. **預覽。** 會開啟所選的第一個檔案：顯示其欄位名稱、前 50 列、哪些欄位看起來是數值，以及（Parquet）每個欄位的邏輯型別，還有檔案本身的讀取說明，也就是 `heat3d` 結尾的項目。
3. **自動對應。** 欄位會被指派到各種角色：X、Y、Z、時間、人員、場次、群組、視線方向，另保留少數欄位用於篩選。每項猜測都會顯示在**欄位對應**面板中，且可以更改。請參閱[欄位對應](column-mapping.md)與[座標軸、單位與時間](axes-units-and-time.md)。
4. **統計。** 會讀取每個檔案的列數（Parquet 直接從結尾讀取，正確無誤；CSV 則為估計值），因此面板能在載入前說明需要多少記憶體，以及是否容得下。若容不下，它會建議每 *N* 列載入一列。請參閱[記憶體與預算](memory-and-budgets.md)。
5. **載入。** 背景工作執行緒只解析每個檔案中已對應的欄位，同時處理多個檔案，數量受[解析執行緒](memory-and-budgets.md#parser-threads)預算限制；它會依所選順序，將它們合併為一個資料集：所有檔案共用一份人員、群組與場次字典，共用一個時間原點，所有列依時間排序。請參閱[場次、人員與群組](sessions-persons-groups.md)。
6. **上傳。** 主執行緒會在一個影格中顯示「正在將 N 列上傳至 GPU」，然後在 GPU 預算內將列打包進 GPU 記憶體。請參閱[GPU 記憶體駐留](gpu-memory.md)。
7. **第一張圖。** 攝影機會框住資料，Sprite 半徑與飽和度依資料範圍與列數設定，並在渲染 8 個影格後，依畫面本身量測飽和度（[色彩與曝光](colour-and-exposure.md)）。

## 載入前檢查的需求 {#requirements-checked-before-a-load}

| 需求 | 缺少時會發生什麼 |
|---|---|
| **X / Y / Z 至少兩項** | 拒絕載入。只有兩項時，第三軸為 0，資料會畫成 3D 場景中的平面，這正是俯視地圖熱圖所需要的。 |
| 時間欄位 | 選用。沒有它時，時間軸會停用，檢視會停留在**全部**模式，側邊欄也會說明原因。 |
| 人員欄位 | 選用。[模型疊加](box-replay.md)（每個人一個模型）、[線條熱度](line-heat.md)（每個人走過的路徑）、內插、軌跡與**存續時間**歷史都需要它。 |
| 群組欄位 | 選用。[隊伍熱度](team-heat.md)與[差異](difference.md)模式（至少兩個群組）需要它。 |

已載入的資料無法支援的模式，會在模式列中變成灰色；將滑鼠移到上面，會說明原因。

## 沒有自己的資料時 {#without-your-own-data}

**資料集**面板（位於**來源**下方）中有[合成資料產生器](synthetic-generator.md)，可產生任意大小、形狀類似大逃殺的資料集，適合用來試用檢視器，或測試機器的負荷能力。
