# 地圖影像

地圖影像是一張平面圖片：小地圖、衛星照片或平面圖，鋪在你的資料之下，讓你看見熱度位於何處。你可以把圖片上的兩個點釘到世界中的兩個地點（即「錨點」），以此告訴檢視器這張圖片應該放在哪裡。

## 載入並放置地圖影像 {#load-and-place-a-map-image}

1. 先載入你的資料（[匯入資料](getting-data-in.md)）。
2. 在**背景／關卡**中按下**地圖影像…**，然後選擇圖片。它會被拉伸到資料的範圍上。
3. 如果圖片被移動過，請按下**符合資料範圍**。錨點 1 會放到資料邊緣的圖片左上角，錨點 2 則放到右下角。
4. 如果熱度與圖片對不齊，請選擇兩個距離很遠的地標（例如一棟建築物的兩個對角，或兩個十字路口）。讀取每個地標在圖片上的像素位置，以及它的世界座標（用[量尺](measure.md)把滑鼠移上去即可讀取 **X** 與 **Z**）。
5. 把這些值輸入**定位**：錨點 1 的地標 **px**、**py**、**世界 X**、**世界 Z**；錨點 2 同樣處理。
6. 檢查：你知道位於某條道路上的軌跡或熱點，現在應該會落在那條道路上。調整數字直到如此為止。

![定位區段，含兩個錨點，熱度繪製在地圖圖片上](../assets/img/en/map-images-placement.webp)

兩個地標的像素欄與像素列都必須不同，否則面板會顯示*兩個錨點共用同一像素列或欄*。

## 載入 {#loading}

瀏覽器可解碼的任何圖片格式。長邊超過 **8192 px** 的圖片會被縮小為 8192（GPU 能夠容納的最大邊長），面板會顯示*從 W×H 縮小為 w×h*。

載入時，圖片會以北方朝上的方式拉伸到資料集的 X-Z 範圍上，位於資料集的最低 Y 高度。預設值為**不透明度** 100%、**亮度** 0.7、**降低飽和度** 100%、**南北翻轉**開啟：降低飽和度並調暗，因為背景的工作是讓你找到熱點的位置，而不是與熱點競爭。

## 控制項 {#controls}

| 控制項 | 預設值 | 範圍 | 意義 |
|---|---|---|---|
| **不透明度** | 100% | 0-100% | |
| **亮度** | 0.7 | 0-2（撥動 64） | |
| **降低飽和度** | 100% | 0-100% | 灰色背景，飽和的熱度。地圖中的顏色會與資料中的顏色互相競爭。 |
| **南北翻轉** | 開啟 | | 圖片的哪一列是世界的最大 Z。在已載入資料集時切換它，也會把錨點重新符合到資料範圍。 |
| **定位**：錨點 1、錨點 2 | 位於資料範圍上的圖片角落 | | 每個錨點都是圖片上的一個像素——**px**（由左起，0 到寬度）與 **py**（由上起，0 到高度）——以及它所在的世界座標，**世界 X** 與**世界 Z**。比例與偏移量由這一對點推導而來。 |
| **符合資料範圍** | | | 將錨點 1 放在圖片的左上角，錨點 2 放在右下角，並對齊資料的 X-Z 範圍。這是精確定位的起點。需要資料集。 |
| **高度** | 資料集的最低 Y | 資料最小 Y - 500 到最大 Y + 500（撥動至最大 Y + 100,000） | 地圖平面的高度。把它設在資料略低的位置，使資料不會被它遮住。 |

名稱列會顯示 `寬×高 px · x × z m/px`，即沿每個軸方向一個像素所代表的世界大小。

## 在場景中 {#in-the-scene}

圖片是位於該高度的單一貼圖四邊形。在完全不透明時，它會寫入深度，因此會以地面的身分參與[遮擋](depth-and-culling.md)；不透明度低於 100% 時，它會被混合且不寫入深度，因此不遮擋任何東西。[量尺](measure.md)在其平面上測量。[關卡庫](level-library.md)會把影像關卡連同其錨點一併儲存。

## Dota 2 地圖 {#dota-2-map}

**地圖影像…**旁的 **Dota 2 map** 會取得 [OpenDota](https://www.opendota.com) 在其對戰頁面上顯示的目前 Dota 2 地圖圖稿，並把它放在 [Watcher](https://github.com/Holdi601/3DHeat-Watcher) 從 Dota 2 重播所寫出的表格之下（[`dotaMap.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/tactics/dotaMap.ts)）。按下按鈕時，圖片才會從 opendota.com 取得，它不屬於 3DHeat 的一部分；最新版本的圖稿取自 OpenDota 自己的清單，若無法讀取清單，則使用 7.40 的圖稿。

| | |
|---|---|
| 來源 | `opendota.com/assets/images/dota2/map/detailed_<patch>.webp`，900×900 px |
| 定位 | OpenDota 的校準：圖片在兩個軸上都涵蓋 Dota 世界單位 -8192 到 8064（128 單位的格子為 64 到 191），北方在頂端。使用重播表格的軸（Z 向上，Y 翻轉）時，即世界 X 為 -8192 到 8064，世界 Z 為 -8064 到 8192。約每像素 18 個單位。 |
| 高度 | 0。英雄站立於 0 到約 600 之間。 |
| 外觀 | 亮度 0.8，降低飽和度 50%。 |

已用 7.40 版公開對戰的重播核對：每位英雄的軌跡都沿著圖上繪製的通道行進，重播所放置的防禦塔、兵營與遠古遺跡，也都落在圖上繪製的基地上。**頂視**視角會以北方在螢幕底部的方式顯示地圖，與它顯示任何 Y 翻轉之 Z 向上表格的方式相同。

圖稿屬於 OpenDota，地圖則屬於 Valve；Valve 並未為 3DHeat 背書。Dota 的 3D 地圖需要安裝遊戲：請見 Watcher 關於 Dota 2 重播的說明。

## 給開發者 {#for-developers}

### 錨點如何定位圖片 {#how-the-anchors-place-the-image}

來自 [`mapQuadFromAnchors`](https://github.com/Holdi601/3DHeat/blob/main/src/render/level.ts)，錨點為 *a* 與 *b*：

```
scaleX = (b.worldX - a.worldX) / (b.px - a.px)
scaleZ = (b.worldZ - a.worldZ) / (b.py - a.py)
pixel (0, 0) sits at  (a.worldX - a.px × scaleX,  a.worldZ - a.py × scaleZ)
```

兩個錨點會分別在每個軸上決定比例與偏移，因此地圖可以在 X 與 Z 上以不同方式拉伸，但不能旋轉。錨點必須在**兩個**像素座標上都不同；若它們共用同一列或同一欄，就無法推導出比例，地圖也不會被繪製，面板會顯示*兩個錨點共用同一像素列或欄*。
