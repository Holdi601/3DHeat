# 機動：群組如何移動

**洞察 → 機動** 會追蹤每一方的單位如何*以群組為單位*移動，並命名它們所做的機動：側翼攻擊、鉗形攻勢、突破、伏擊、撤退、飛彈防禦、橫越 T 字（crossing the T）。每一項都會列出其確定程度、所依據的數字、是否奏效，以及在準則與歷史中的對應。**大量分析 → 機動** 則會在數千場比賽中統計它們：每張地圖、每種模式、每一方各做了多少次，以及有多常奏效。

所有計算都在你的瀏覽器中完成，並在獨立的背景執行緒（`src/insights/maneuver`）中進行。一場有數百個單位的比賽需要 10 至 500 毫秒；一場有數千個物件、長達兩小時的空戰約需一秒。

## 使用方式 {#using-it}

- 開啟 **洞察**，分頁 **機動**。開啟時會自動計算；變更篩選後請按 **重新尋找**。
- **確定／較可能／可能** 會設定要列出的信心度（預設為較可能）。
- **時間軸** 每一方有一條軌道，每個機動一個長條；下方的 **列表** 內容相同，但依時間排列。點擊後會切換到該機動開始的重播、把攝影機飛到那裡，並在 3D 中畫出：每個編組的移動路徑為一支箭頭（鉗形攻勢的兩翼即為其弧線）；關鍵時刻各編組的外框（敵方外框以其陣營的顏色顯示）；敵方的前線為一條白線。**全部以 3D 繪製** 會以淡色加入該場比賽的其他機動。線條只會在選取改變時上傳到顯示卡一次，播放時不會每個影格都重新上傳。在真實 GPU 上播放 480 個機動時（WebGL2 與 WebGPU，p99 為 18.0 至 18.5 毫秒，最大值 19.5 至 20.8 毫秒），影格時間與未繪製時相同。
- 點開的機動會顯示：其結果（執行期間及之後不久，該機動單位的擊毀與損失，與該方全場的交換比相比）、其證據，以及知識庫中對應的條目，也就是準則與歷史類比（包圍用坎尼戰役、突破用 1940 年色當戰役、橫越 T 字用對馬海戰、佯攻用博洛行動……）。
- 結尾的小表格：依機動類型與陣營列出做了幾次，以及其中奏效多少次。

## 如何找出編組 {#how-groups-are-found}

每個單位都會放到共同的時間軸上（步長：步行為 1 秒，其他為 2 秒，檔案非常大時更長），並在死亡時保持不動，使復活不會在地圖上畫出一條橫越地圖的線。在每一步，同一方、同一類別（飛機、載具、艦船、步兵）的單位，只要夠靠近且移動方向相近（速度在較快者速度的一半以內，或兩者皆靜止），就會被連結起來。靠近的距離為：步行 18 公尺、載具 170 公尺、艦船 3 公里、飛機 5 公里。一個群集會保留其大多數成員原本所屬編組的編號。沒有類別的單位，會依其速度判定為步行、乘載具或在空中。

編組的**隊形**是以其前進方向為基準來判讀的：沿前進方向與垂直方向的散布，決定它是縱隊還是橫列；中間領先的是楔形；成員依序向一側退後的是梯隊；成員守住四個角落的是方陣。

所有判斷都以比賽本身的尺度進行。**交戰距離** `R` 是殺手與受害者之間距離的第 75 百分位數（限制在該領域的合理範圍內）。機動的時間依單位種類縮放（步兵為地面的三分之一）。

## 它會找出什麼 {#what-it-finds}

| 機動 | 判定條件 |
|---|---|
| 隊形 | 一個編組在 30 秒內，有 60% 的移動步驟保持同一隊形 |
| 正面攻擊 | 一個編組從射程外逼近到接觸，距離達 ¾ R 或以上，且來自敵人面向方向 35° 以內 |
| 側翼攻擊 | 同上，但來自 50 至 130°（背後超過 130° 者更多）；只有在己方*牽制兵力*於該處與敵人交戰時才判定為確定（雙方皆有擊殺） |
| 鉗形攻勢 | 同一方的兩次側翼攻擊，指向同一個敵方主體，來自相反兩側（相距 100° 或以上），且在 90 秒內發生；兩翼都在交戰時為確定 |
| 合圍 | 一個緊密的敵方編組，周圍有至少同等數量的另一方單位在 1.5 R 內包圍，來自兩個或以上編組，缺口不超過 100°，持續一分鐘，且與其本方隔絕；包圍圈在 ½ R 內收攏並與被圍部隊交戰時為確定 |
| 突破 | 一個編組穿過一條被守住的防線（敵方在其左右兩側各站立 30 秒，己方中央位於其後）；推進到 ½ R 之外、停留 20 秒並在那裡交戰時為確定；再深入 R 則為突破成功 |
| 交替掩護躍進 | 在小編組中，一部分移動而其餘靜止，角色互換四次或以上，且靜止的一部分提供掩護火力 |
| 集中／分散 | 一方在其最密集點附近的兵力占比，從 35% 升至 60%（單位以 1.5 R 或更遠的距離集結，然後接觸）；或隨著該方散開而下降 |
| 佯攻 | 一個小單位在接觸中，吸引來自別處的兩個或以上敵人；隨後一個較大的編組在四個射程外、敵人較少之處發動攻擊 |
| 撤退／追擊 | 一個接觸中的編組轉身離開，並在其交戰處拉開 R 的距離；若在那裡有敵人剛擊殺了其一員，且該編組與該殺手拉開 2 R 時為確定（步行時永不判定，見下文）；同向移動並跟上的敵人即為追擊 |
| 縱深防禦 | 站立的單位在敵方軸線上形成兩道或以上的防線，縱深 R，敵人壓上，且防線上有火力 |
| 反斜坡 | 站立的單位在近距離擊殺三次或以上，且受害者是越過山脊而來的 |
| 伏擊 | 移動中的編組遇上曾站立 45 秒的敵人；對方先開火，移動方損失兩個單位或一半的編組 |
| 屏護 | 一或兩個單位在三個以上單位組成的主力前方移動，最先遭遇敵人 |
| 內線 | 一方的編組在另一方的編組之間靠攏，其單位在它們之間轉移 |
| 節奏 | 一方回應接觸（轉向、變速、首先開火）的速度快 1.5 倍，Mann-Whitney p 值低於 0.05 |
| 彎折、凹口、拖曳、泵升 | 飛彈的發射目標使發射者轉向 35 至 70°、75 至 105°、超過 140°，或拖曳後再轉回 |
| 空中鉗形、牆、領航－跟隨、磨耗戰 | 一對飛機分開攻擊同一個敵機；三機並排衝向敵人；一個單位落後另一個 5 至 20 公里；兩個單位繞同一點盤旋、相距一點 |
| 戰鬥空中巡邏 | 圍繞一個據點盤旋三分鐘 |
| 能量戰／角度戰 | 近距離纏鬥中，航向相差 30°，雙方輪流把對方咬在自己的機頭前，或雙方之間有一次擊殺；使用高度並爬升，或平飛並急轉同時減速；若其中一方擊殺了另一方則為確定 |
| 打擊群、壓制防空（SEAD） | 由多種角色混編的空中編組，其中一些對地面發動攻擊；防空擊殺先於大多數其他對地擊殺 |
| 戰列線、橫越 T 字 | 三艘艦船成縱列；一個縱隊橫過敵方縱隊的艦首 |

每項機動都會標示它呈現了知識庫中的哪些**模式**（`patterns-maneuver.ts`：隊形、正面攻擊、雙翼包圍、合圍、突破、火力與機動、佯攻、撤退、追擊、縱深防禦、屏護、分散、飛彈防禦、角度戰、戰鬥空中巡邏、打擊群、戰列線、橫越 T 字），以及應先閱讀的條目。較舊的條目則透過 `knowledge/maneuver-tags.ts` 帶上新的模式。參閱[知識視角](knowledge.md)。

**奏效** 會將機動期間（及之後一分鐘）單位的交換，與其所屬陣營全場的交換相比。撤退在轉向後損失的單位比轉向前少時奏效；飛彈防禦在飛機存活一分鐘時奏效；合圍在包圍圈損失一半時奏效。

## 在許多比賽中 {#over-many-matches}

每場比賽的摘要（`src/mass/summarize.ts`，參閱[大量分析](mass-analysis.md)）包含一個小型的 `maneuvers` 區段：依機動類型與陣營列出做了幾次（信心度為較可能或以上）、奏效、未奏效、擊殺與損失。**大量分析 → 機動** 會把篩選保留的比賽加總，依地圖與模式分列，或合計全部；並附上奏效率的 Wilson 區間。點選一列會載入產生該機動的比賽。在此區段出現之前寫入的摘要沒有這些資料；執行 `node tools/3dheat-summarize.mjs <folder> --force` 即可補上。

## 有多確定 {#how-sure-it-is}

含有植入機動的合成比賽（`synth.ts`，由 `maneuver.test.ts` 執行）：植入的 28 種類型，全部都在較可能或以上被找到。在回報的 50 個機動中，31 個是植入的類型，其餘 19 個也確實存在（移動中編組的隊形、突破縱隊的正面接近）；沒有任何一個是錯的。在 30 場空白比賽中（隨機漫步的分開與混合、單位隨機站立、飛機沿直線飛行、人群四處走動），在較可能或以上沒有任何回報。

在真實資料上（數十場地面戰、數場長時間的空戰任務、十餘場射擊遊戲比賽）：坦克戰中出現正面攻擊、側翼、突破與合圍；空戰中出現隊形與近距離纏鬥；空戰任務中出現飛彈防禦、戰鬥空中巡邏的盤旋與領航－跟隨配對；射擊遊戲中出現正面處決、縱隊，以及少數伏擊與交替掩護配對。門檻是準則形狀在遊戲尺度下的對應。請連同其證據來解讀單一發現，並以其區間來解讀大量統計表中的比率。

### 與同一批比賽的空白模型比較 {#against-null-models-of-the-same-matches}

偵測器可能會被地形與人群騙過：在混戰中，每個編組四周都有敵人。因此每種類型也會在**空白模型**（`nulls.ts`）上執行。這些模型由同一批比賽建立，其中雙方不再如實際般相遇：一方的時間軸被旋轉三分之一到三分之二的比賽時長（*shift*，位移），或其軌跡繞地圖中心旋轉（*rotate*，旋轉）；以及隨機打亂的隊伍標籤（*teams*，隊伍）。依其建構方式，隊伍打亂大約會保留一半真實的交戰。交戰只計算成對的擊殺與死亡：殺手在 2 R 內，受害者在該地點。空白模型會打破這些條件。下表為在較可能或以上找到的機動數，真實資料與空白模型的比較（30 場坦克戰；12 場射擊遊戲比賽）：

| 類型 | 坦克戰：真實 / 位移 / 旋轉 | 射擊遊戲：真實 / 位移 / 旋轉 |
|---|---|---|
| 合圍 | 0 / 0 / 0（原為 1.3 / 1.2 / 0.8） | 0 / 0 / 0 |
| 突破 | 0.03 / 0.02 / 0.05（原為 1.6 / 1.8 / 1.4） | 0 / 0 / 0 |
| 側翼 | 0.33 / 0.07 / 0.10 | 1.0 / 0.08 / 0.21 |
| 正面攻擊 | 0.87 / 0.47 / 0.12 | 14.4 / 6.5 / 4.3 |
| 撤退 | 0.03 / 0 / 0.02 | 0.08 / 0.08 / 0.5（因此步行時從不確定） |
| 伏擊 | - | 0.17 / 0.04 / 0.04 |
| 能量戰 | 1.2 / 0.1 / 0.85 | - |
| 角度戰 | 0.6 / 0.07 / 0.3 | - |

靠近戰場中心的空戰纏鬥，在繞該中心轉向後仍然存在，因此「旋轉」欄對它們的削弱，不如對地面類型那樣大。同一方內的類型（隊形、戰鬥空中巡邏、磨耗戰、打擊群、壓制防空、交替掩護、屏護）不依賴另一方，因此不以此方式測試。`maneuver.test.ts` 會檢查空白模型是否能從合成比賽中移除植入的側翼、鉗形、合圍、突破、伏擊與撤退。

## 限制 {#limits}

- 編組需要隨時間變化的位置資料；只有事件的檔案沒有位置。
- 面向不是從資料中讀取的：敵方的前線是牽制兵力與其交戰之處，否則是其移動之處，再否則是攻擊者來的方向。
- 地形是從單位自身的高度讀取（反斜坡）；沒有視線測試。
- 非常大的檔案會以較長的步長取樣；其中的短時間空中機動，仍以 2 至 4 秒的步長讀取。
