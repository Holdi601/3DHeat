# 載入檔案

本頁說明如何把你的檔案交給 3DHeat，以及它會如何處理這些檔案。拖放一個資料夾，它會挑出含有位置的檔案，並把它們合併成同一張圖。

1. 開啟熱圖側欄最上方的 **來源**。
2. 將檔案或資料夾拖放到拖放區，或按下 **多個檔案…** 或 **資料夾…**。
3. 查看選取說明行與 **記憶體估計**（見下圖）。
4. 按下 **載入**。

![拖放十場比賽的資料夾後的來源面板：1 選取說明行，2 記憶體估計顯示為可容納，3 載入 10 個檔案](../assets/img/en/loading-files-source.webp)

*拖放資料夾後，3DHeat 會告訴你它找到了什麼，以及是否放得下。*

檔案是在熱圖分頁側欄最上方的 **來源** 面板中載入的。一次選取的所有內容，會成為**一個**資料集。

## 選擇檔案 {#choosing-files}

| 控制項 | 作用 |
|---|---|
| **將檔案或資料夾拖放到這裡**（拖放區） | 可拖放任意組合的檔案與資料夾。資料夾會被遞迴走訪。點擊拖放區會開啟與 **多個檔案…** 相同的選擇器。 |
| **單一檔案…** | 用於選取單一檔案的檔案選擇器。 |
| **多個檔案…** | 可選取多個檔案的檔案選擇器。 |
| **資料夾…** | 資料夾選擇器（瀏覽器的 `webkitdirectory` 選擇器）；資料夾樹中的每個檔案都會被提供。 |

選擇器接受[可載入檔案清單](data-formats.md#files)中的檔案類型。簡單來說：`.parquet`／`.pq` 以 Parquet 讀取，`.csv`／`.tsv`／`.txt` 以分隔文字讀取，`.acmi`（Tacview）、OCAP 的 `.json`／`.json.gz`，以及 GPS 格式（GPX、KML、KMZ、NMEA、IGC、FIT）則各自透過其專用讀取器處理，而 `.3dheat` 比賽容器則會以其中所含的表格載入（[每場比賽一個檔案](container.md)）。無法讀取的容器會被略過，原因為*不是 csv／parquet 檔案*。

拖放的資料夾最深會走訪 12 層，最多 20,000 個檔案，以防止符號連結迴圈與失控的目錄樹。

## 保留哪些檔案 {#which-files-are-kept}

在讀取任何內容之前，會先篩選選取的檔案（[`filterDataFiles`](https://github.com/Holdi601/3DHeat/blob/main/src/data/filePick.ts)）：

- 副檔名不同的檔案會被略過：*不是 csv／parquet 檔案*。
- 大小為 0 位元組的檔案會被略過：*空檔案（0 位元組）*。
- **轉換器附屬檔**——轉換器保存在比賽表格旁邊的原始資料，即 `<match>.messages.parquet`、`.events.parquet`、`.raw.parquet`，以及 [轉換器保留所有資料](converters.md)中列出的其他檔案——會被略過：*轉換器的附屬檔*。若要開啟其中一個，請單獨選取或拖放它（或只選取附屬檔）：若選取的全是附屬檔，它們會像任何表格一樣被載入。位於表格旁的 JSON（`.match.json`、`.course.json`、`.level.json`、`.meta.json`、`.summary.json`、`.session.json` 與 `.hints.json`）永遠不會被當成位置資料提供。
- **移動檔規則。** 若選取的任何檔案名稱為 `movement*.parquet`、`movement*.csv`（以及其他副檔名）——例如 `movement.parquet`、`movement_1.parquet` 等——則其他所有資料檔都會被略過：*不是移動檔，且此資料夾有移動檔*。遙測匯出通常會有一張位置表，旁邊還有數十張沒有位置的表，而只有前者能被繪製。沒有任何移動檔的資料夾，會載入其所有資料檔。範例：一個含有 `movement_1.parquet`、`kills.parquet` 與 `shop.parquet` 的資料夾，只會載入 `movement_1.parquet`；另外兩個會列為已略過。
- 保留下來的檔案會依其在選取內的路徑排序，因此同一個資料夾總會產生相同的資料集與相同的顏色。

來源面板隨後會顯示選取內容（單一檔案的名稱，或以最長共同資料夾表示的 `資料夾（N 個檔案）`）、檔案數量、總大小，以及總列數——若所有檔案都是 Parquet，則為精確數字；若其中任何一個是 CSV，則以 `≈` 標示。已略過的檔案會列出其原因，前四個會顯示其名稱。

## 讀取結構描述 {#reading-the-schema}

選取內容中的**第一個**檔案會被開啟，用以描述結構（「正在讀取結構描述」）：其欄位名稱、其前 50 列資料、哪些欄位看起來是數值，以及對於 Parquet，每個欄位的邏輯型別與 `heat3d` 結尾區項目。同一張表的匯出資料夾會共用一個結構，因此一個檔案即可代表全部。接著會測量每個檔案（「正在計算列數」）：Parquet 的結尾區只需一次小型讀取即可得到精確的列數；CSV 的列數則是根據其前一 MB 的平均行長度估算的。

[欄位對應](column-mapping.md)面板會以自動對應的猜測開啟，而[記憶體估計](memory-and-budgets.md)會顯示在 **載入** 按鈕的上方。

## 載入前的訊息 {#messages-before-loading}

在選取內容下方，面板會列出（來自 [`validateMapping`](https://github.com/Holdi601/3DHeat/blob/main/src/data/validate.ts)）：

- **錯誤**（紅色）——載入無法開始：位置軸少於兩個、同一欄位對應到兩個軸、對應的欄位不在檔案中、位置欄位看起來不是數值、時間欄位的取樣值為文字而單位卻是數字（每一列都會讀成 NaN 並落在時間 0）、時間欄位設為 ISO-8601 但取樣值沒有任何一個能解析為日期，或單位比例為 0。
- **警告**（琥珀色）——會載入，但可能不是你原本想要的結果：分組欄位在大多數取樣列中取得不同的值（因此它是 ID，而不是群組）、`DATE` 時間欄位（同一天的每一列都共用同一個瞬間），或設定了視線方向卻沒有對應的欄位。
- **附註**——對應所隱含的事項：當一個軸未對應時會在平面上繪圖、沒有時間欄位就沒有時間軸、沒有人物欄位就沒有軌跡，以及沒有分組欄位時，所有資料都是同一種顏色，而差異只能依保留供篩選的欄位來分割。

## 載入 {#loading}

**載入** 按鈕會顯示*載入檔案*、*載入 N 個檔案*，或在設定了[抽樣步距](memory-and-budgets.md#decimation)時顯示*載入 N 個檔案（每 K 取 1）*。當[容量檢查](memory-and-budgets.md#the-fit-check)判定載入放不下時，它會顯示*太大，請減少或抽樣*並停用；在對應有錯誤或另一個載入正在進行時，它也會停用。

載入期間，面板會顯示目前的步驟（若有多個檔案，前面會加上 `[檔案/檔案數]`）、已讀取的列數、進度條，以及 **取消**。取消會終止匯入工作執行緒，以及它所啟動的任何解析工作執行緒。

由於工作是在背景進行，頁面在載入時仍會持續繪製。你會看到目前的步驟、已讀取的列數、進度條與 **取消**。在最後一個檔案之後，面板會依序顯示步驟：*依時間排序列*、*重新排列欄位（第 n 個，共 m 個）*、*測量範圍*、*建立名單*、*彙整場次*與*計算存續時間*，接著是*將 N 列上傳至 GPU*（畫面上維持一個影格），因此不會把長時間的上傳誤認為凍結。

### 運作方式 {#how-it-works}

載入是在 Web Worker（[`ingestWorker.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestWorker.ts)）中執行的。若有多個檔案且解析執行緒多於一個（[解析執行緒](memory-and-budgets.md#parser-threads)），則在 RAM 預算允許的範圍內，最多會有相同數量的檔案**同時**解析，每個檔案各在自己的解析工作執行緒中（[`parseWorker.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/parseWorker.ts)）；但它們仍會依選取的順序，一次合併一個，因此資料集與逐一載入的結果相同。當多個檔案同時進行時，進度行會顯示最後回報的那個檔案，而進度條與列數則會加總所有進行中的檔案。只有一個執行緒，或只有一個檔案時，檔案會在匯入工作執行緒本身中依序解析。只讀取對應所指定的欄位：Parquet 檔中未對應的欄位不花費任何成本；CSV 會逐位元組掃描，但只解碼已對應的欄位。

## 多個檔案變成一個資料集 {#several-files-become-one-dataset}

當載入的檔案不只一個時（[`ingestFiles.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestFiles.ts)、[`builder.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/builder.ts)）：

- **一份名單。** 人物、群組、場次與類別值，都是所有檔案共用的字典，因此兩份匯出中的同一位玩家，就是一個人物，擁有一條軌跡。
- **一個時間原點。** 合併時時間以 64 位元秒保存，並重新以*整個*選取內容中最早的時間為基準，然後以 32 位元秒從該原點儲存。來自四個下午的四份匯出，會依其真實的先後順序排列，而不是彼此疊在一起。
- **一個時間順序。** 所有檔案的列都以基數排序依時間排序（參閱[排序上限](memory-and-budgets.md#the-sort-ceiling)）。
- **一個 `Source file` 欄位。** 每一列都會記住它來自哪個檔案，以名為 `Source file` 的類別欄位保存。它會出現在[篩選](filters.md)中，也會以*Source file - 比較兩次載入*的形式出現在[差異分割](difference.md)中。單一檔案的載入不會有這個欄位——一個常數欄位每列要花 4 位元組來說明一件無需說明的事。
- **缺少的欄位。** 缺少某個*篩選*欄位的檔案，只是不為該欄位提供任何值。缺少已對應的*角色*欄位（X、時間、人物……）的檔案，會以*檔案沒有欄位「名稱」*失敗；在多檔案載入中，該檔案會被略過，其他檔案仍會載入，而被略過的檔案會列在資料集上。單一檔案的載入若失敗，則會回報錯誤。
- **不足警告。** 當實際載入的列數少於事先計算的列數的 95% 時，資料集會附上一則警告，並註明缺少的比例——原因可能是無法讀取的檔案，或是沒有可用位置的列（這些列會在進入時被捨棄）。

## 載入之後 {#after-loading}

新的資料集會取代先前的資料集。每次載入時（[`setDataset`](https://github.com/Holdi601/3DHeat/blob/main/src/state/store.ts)）：

- 所有篩選與群組可見性都會清除；
- 依群組的差異分割會重設：群組的前半（無條件進位）為正，其餘為負；
- Sprite 半徑設為水平範圍 / 120，飽和度設為解析估計值；立方體大小、視線射線長度、飛行速度與近／遠裁剪面，皆依範圍設定（參閱[場次、人物與群組](sessions-persons-groups.md#entity-size)）；
- 箱形重播的場次設為列數最多的那一場；
- 線條熱度的路線會重新猜測（參閱[線條熱度](line-heat.md)）；
- 若目前的視圖模式不被新資料支援，視圖模式會退回 **熱度**；沒有時間欄位時，時間軸退回 **全部**；沒有存續時間時，歷史退回 **累積**；
- 播放頭停在起點，並停止播放；
- 攝影機從預設方向（沿 -Z 方向望去，俯角約 36°）框住整個資料集。

之後，**資料集** 面板會顯示資料集的名稱（選取內容、列數與檔案數，以及若有使用抽樣時的步距）、`N 支隊伍 · N 位人物 · N 秒跨度`，以及載入時產生的每一則警告（琥珀色），只要該資料集仍在載入中就會持續顯示。該面板中的 **卸載** 會移除資料集。
