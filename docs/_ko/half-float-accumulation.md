# 반정밀도 부동소수점 누적

일부 그래픽 카드는 열을 작은 16비트 수에만 담을 수 있어서, 가장 뜨거운 곳이 잘리거나 반올림될 수 있습니다. 뷰어는 수를 조정해서 이것이 드러나지 않게 합니다. 여러분이 할 일은 없습니다. 이 페이지는 개발자용입니다.

## 개발자용 {#for-developers}

32비트 부동소수점 텍스처에 블렌딩할 수 없는 장치(WebGPU에서 `float32-blendable`과 `float32-filterable`이 없거나, WebGL2에서 `EXT_float_blend`가 없는 장치)는 **16비트 부동소수점** (`r16float`) 히트 타깃을 받습니다. 최댓값은 65,504이고 가수는 11비트입니다. 밀집된 장은 수십만에 이르므로, 16비트 타깃은 **잘리고** **반올림됩니다**. 반올림 오차는 값이 커질수록 커집니다. 그래서 증상이 매우 특징적입니다. 밀집된 곳이 실제보다 훨씬 차갑게 보이고, 희박한 곳은 괜찮아 보입니다. 이를 처리하는 방법은 두 가지이며, 두 가지가 모두 작동해야 그림이 맞습니다.

### 범위: 모든 스플랫에 곱하는 이득 {#range-a-gain-on-every-splat}

모든 스플랫에 **이득(gain)**을 곱하고, 합성 단계에서 그것을 다시 나눕니다. 그래서 장은 반정밀도가 잘 다루는 크기 안에 머뭅니다 ([`heatGain`](https://github.com/Holdi601/3DHeat/blob/main/src/render/engine.ts)):

```
estimate = 이 데이터셋, 반경, 중심 강도에 대한 해석적 포화 추정값
gain     = 2 ^ round(log2(2048 / estimate)),  지수는 -20..20으로 제한
```

2048이면 65,504까지 램프 꼭대기 위로 약 32배의 여유가 남습니다. 이득은 **2의 거듭제곱**이므로, 추정값이 조금 흔들려도 이득과 누적된 버퍼는 바뀌지 않습니다. 또 이득은 [지오메트리 서명](accumulation.md#what-restarts-it)의 일부이므로, 바뀌면 누적이 다시 시작됩니다.

이득은 해석적 추정값에 고정되며, 의도적으로 **포화점에는 고정되지 않습니다**. 포화는 합성 때 적용되어, 포화 슬라이더를 끌어도 수렴이 다시 시작되지 않게 합니다. 만약 이득이 포화와 함께 움직인다면, 버퍼에는 여전히 옛 이득으로 쓴 값이 있는데 합성은 새 이득으로 나누게 됩니다. 두 오차가 정확히 상쇄되어, 슬라이더가 아무 일도 하지 않는 것처럼 보이게 됩니다.

32비트 타깃에서는 이득이 항상 1입니다.

### 정밀도: 0에서 시작하는 부분 프레임 {#precision-partial-frames-from-zero}

가중치 1/n로 누적기에 합쳐지는 프레임은, 먼저 **임시 타깃**에 0에서 시작해 스플랫한 뒤 블렌딩합니다. 누적기에 1/n 가중치로 직접 스플랫하지 않습니다 ([누적](accumulation.md#why-each)). 직접 하면 각 스프라이트의 기여는 더해질 누적 합의 1/n 크기가 됩니다. 반정밀도는 그것을 반올림해서 없애 버리며, 픽셀이 밀집할수록 더 심합니다. 0에서 시작하면 모든 더해지는 값이 합하는 누적 합과 비교할 만하며, 이는 한 프레임이 이미 하고 있는 계산과 같습니다.

### 측정된 효과 {#measured-effect}

밀집된 합성 장면에서, 맞춘 단위로 장을 읽은 결과:

| | p50 | p90 | p99 | max |
|---|---|---|---|---|
| 32비트 (기준) | 6051 | 60742 | 121199 | 232744 |
| 16비트 이전 | 1372 | 6972 | 7840 | 7840 |
| 16비트 이후 | 5996 | 59666 | 118824 | 210357 |

최댓값은 30배 낮았던 것에서 0.90배가 되었고, 합성된 프레임은 평균 휘도의 0.1% 이내에서 32비트 프레임과 일치합니다.

### 테스트 {#testing-it}

`?heat=f16`은 두 백엔드 모두에서 이 경로를 강제합니다. 이 옵션이 없다면, 더 약한 GPU에서만 실행되는 계산은 그것을 돌리는 사람들만 테스트하게 됩니다. `npm run smoke:f16`은 이 옵션으로 브라우저 테스트 전체를 실행합니다.

읽기 과정에서 이득은 되돌려집니다. 자동 노출은 읽은 장을 이득으로 나누고, `engine.readHeatProbe()`는 이득을 렌더러에 넘깁니다. [자의 실시간 히트 표시](measure.md#notes)도 이렇게 읽힙니다.
