# 렌더링 내부 구조

뷰어는 수백만 개의 점을 빛나는 덩어리로 그리고 그것들을 더합니다. 이 절은 이를 빠르게 하는 기법과, 통계 오버레이의 숫자가 무엇을 뜻하는지 설명합니다. 뷰어가 느리게 느껴지거나 렌더러를 손보려 한다면 읽으세요.

```
data -> time window -> GPU filters -> sampling plan -> splat -> accumulate -> colour -> screen
```

내 컴퓨터가 어떻게 돌아가는지 보려면 뷰 오른쪽 위의 통계 상자를 보세요: [성능 패널과 통계 오버레이](performance-and-stats.md). 새 용어(GPU, 행, 스프라이트, 히트맵)는 [용어집](glossary.md)에 있습니다.

## 핵심 문제 {#the-core-problem}

겹치는 방사형 경사의 합은 프레임마다 *N* × π*r*² 개의 블렌딩 프래그먼트를 듭니다. 반지름 8px의 스프라이트 1억 개면 2 × 10¹⁰ 프래그먼트이고, 고성능 GPU에서 약 1초의 작업입니다. 이것을 매 프레임 무작정 계산할 수는 없으므로, 뷰어는 다음을 함께 씁니다.

- **시간순 정렬된 행** - 타임라인 구간은 이진 탐색 두 번이면 정해지므로, 재생 비용은 데이터셋 전체가 아니라 구간 안의 행을 따릅니다;
- **프레임마다 CPU에서 행별 작업 없음** - 행은 양자화되어 GPU 메모리에 있습니다. 필터, 그룹 부호, 수명 검사, 구간, 컬링, 단면 모두 버텍스 셰이더에서 계산합니다;
- **층화 샘플링**: 한 프레임에 모든 행을 그릴 수 없을 때 보상 가중치를 씁니다. 그리고 **점진적 누적**: 뷰가 정지해 있는 동안 모든 행을 쓴 정확한 결과로 수렴합니다 ([샘플링과 예산](sampling-and-budgets.md), [누적](accumulation.md));
- **두 단계 스로틀**: 프레임 속도를 위해 프레임당 스프라이트를 먼저 줄이고, 그다음 히트 해상도를 줄입니다 ([샘플링과 예산](sampling-and-budgets.md#the-adaptive-budget));
- **강제되는 메모리 예산**: 들어가지 않는 데이터셋은 충돌하지 않고, 눈에 보이게 잘립니다 ([GPU 메모리 상주](gpu-memory.md)).

## 프레임 하나 {#one-frame}

프레임 루프는 [`Engine.frame`](https://github.com/Holdi601/3DHeat/blob/main/src/render/engine.ts)입니다. 프레임 속도로 바뀌는 모든 것(카메라, 재생 헤드, 예산)은 애플리케이션 상태가 아니라 엔진에 있으므로, 프레임에는 React 작업이 들지 않습니다. 상태는 프레임마다 한 번 읽고, 낮은 빈도의 표시값에만 다시 씁니다.

1. **새 데이터?** 새 데이터셋은 한 프레임에 알려지고(*Uploading N rows to the GPU*) 다음 프레임에 업로드됩니다. 작업이 스레드를 막기 전에 메시지가 그려지도록 하기 위함입니다. 새 레벨은 렌더러에 넘겨지고, 라인 히트 경로는 만들어지거나 해제됩니다.
2. **재생 헤드**가 진행합니다 (벽시계 시간으로 프레임당 최대 0.1초). 반복하거나 멈춥니다.
3. **카메라**가 키보드, 마우스, 게임패드를 읽습니다. 축 반전은 뷰 행렬에 합쳐지고, WebGPU에서는 깊이 재매핑 행렬이 three.js의 OpenGL 식 깊이 범위를 WebGPU의 것으로 바꿉니다.
4. **보이는 것**: 타임라인과 히스토리의 시간 범위, 그룹 부호 표(열로 나누기 때만 보임), 최대 네 개의 필터(열 필터와 개체 선택), 차이 분할.
5. **색과 곡선 표**는 설정이 바뀌었으면 다시 만듭니다.
6. **예산**: 적응형 컨트롤러가 이 프레임의 스프라이트 예산과 히트 해상도를 정합니다. *Draw every row each frame*이 켜져 있으면, 예산은 모든 후보 행을 포함하도록 올라갑니다.
7. **서명**은 누적 버퍼가 아직 무엇을 뜻하는지 결정합니다. 행이 기여하는 방식을 바꾸는 것(*geometry*), 시간 구간(*time window*), 또는 결과의 색만 바꾸는 것(*composite*)이 바뀌었는지 봅니다. [누적](accumulation.md#what-restarts-it)을 보세요.
8. **샘플링 계획**: 그릴 행 블록을 고릅니다 ([샘플링과 예산](sampling-and-budgets.md)).
9. **누적 모드**: 초기화, 확장, 이동 평균, 실행 평균, 또는 유휴.
10. **박스 재생 기하**(큐브, 궤적)는 CPU에서 계산합니다. 그 모드일 때, 유휴가 아닐 때에만 합니다.
11. **렌더**: 백엔드가 장면(레벨, 격자, 축, 상자, 궤적, 자)을 그리고, 히트를 히트 타깃에 스플랫하고, 누적기에 합치고, 히트를 장면 위에 합성해 캔버스에 보냅니다.
12. **자동 노출**은 카운트다운이 0이 되면 작동합니다. 자의 히트 탐침은 120ms마다 최대 한 픽셀을 읽고, 표시값을 게시합니다.

**유휴 프레임** - 수렴했고 바뀐 것이 없는 프레임 - 은 장면과 스플랫을 건너뛰지만 여전히 **다시 합성**합니다. `preserveDrawingBuffer` 없이 만든 WebGL 캔버스는 합성 후 내용이 정해지지 않으므로, 마지막 프레임이 그대로 보일 것이라고 믿으면 안 됩니다. 장면과 히트 타깃은 뷰어 자체의 프레임버퍼라서 내용을 유지하므로, 유휴 프레임은 전체 화면 패스 한 번만 듭니다.
