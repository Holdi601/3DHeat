# 게임패드와 HOTAS

키보드 대신 Xbox 방식 컨트롤러로 카메라를 날릴 수 있습니다. 큰 장면에서 몸을 뒤로 기대고 둘러보고 싶을 때 씁니다. 컨트롤러의 입력은 키보드 입력에 **더해지므로**, 둘을 동시에 쓸 수 있습니다.

## 컨트롤러 연결 {#connect-a-controller}

1. 컨트롤러를 꽂거나 페어링하세요.
2. 뷰를 클릭하고 컨트롤러의 아무 버튼이나 누르세요. 브라우저는 처음 입력을 받은 뒤에야 컨트롤러를 보여 줍니다.
3. **Camera & scene → Gamepad**를 여세요. 장치 목록에 `●`와 함께 표시됩니다.
4. 왼쪽 스틱을 밀면 날고, 오른쪽 스틱으로 둘러봅니다. 스틱을 가운데 두었는데 카메라가 흘러가면 **Deadzone**을 올리세요.

브라우저가 표준 게임패드 배치로 매핑하는 장치라면 어떤 것이든 동작합니다. 비행 조종간이나 스로틀(HOTAS)은 기본적으로 무시합니다. 아래를 보세요.

## 매핑 {#mapping}

| 컨트롤 | 효과 |
|---|---|
| 왼쪽 스틱 | 이동: 앞/뒤, 좌/우 평행 이동 |
| 오른쪽 스틱 | 둘러보기: 좌우 회전(요)과 상하(피치). 완전히 기울였을 때 초당 *Look speed* 도 회전 |
| `RT` / `LT` (아날로그) | 위 / 아래; 평행 투영에서는 확대 / 축소 |
| `RB` (누르고 있기) | 6배 빠르게 |
| `LB` (누르고 있기) | 15% 속도 |
| `A` (누르고 있기) | 3배 달리기 (RB/LB와 함께 쓸 수 있음) |
| `Y` (누르기) | 데이터 전체 보기 |

버튼 번호는 표준 배치를 따릅니다: A 0, Y 3, LB 4, RB 5, LT 6, RT 7. 스틱은 축 0-1(왼쪽), 2-3(오른쪽)입니다.

## 게임패드 설정 {#the-gamepad-settings}

**Camera & scene → Gamepad**에 있습니다. **Settings** / **Hide**로 조정 컨트롤을 열고 닫습니다.

| 컨트롤 | 기본값 | 범위 (조그) | 뜻 |
|---|---|---|---|
| **Enabled** | 켜짐 | | |
| Device status | | | 연결된 모든 장치. 따라가는 장치는 `●`, 따라가지 않는 장치는 `○`. 표준이 아닌 장치에는 *- not an XInput pad, ignored* 또는 *- not an XInput pad, used anyway*가 붙습니다. 아무것도 없으면: *No pad detected. Browsers only reveal a controller after it sends its first input - press a button on it.* |
| **Use device** | *XInput pads only (recommended)* | | 표준이 아닌 장치가 연결되어 있을 때 보입니다. 이름으로 장치를 골라 그 장치를 따라가게 할 수 있습니다. |
| **Look speed** | 150°/s | 20-540 (5000) | 오른쪽 스틱을 끝까지 기울였을 때의 회전 속도. |
| **Deadzone** | 12% | 0-50% (95%) | 방사형: 대각선으로 민 입력이 한 축으로만 새지 않습니다. 스틱을 가운데 두었는데 카메라가 흘러가면 올리세요. |
| **Stick curve** | x² | 선형 (1)에서 x⁴ (16)까지 | 데드존 뒤의 반응 지수: 가운데 근처에서 더 섬세하고, 끝에서는 여전히 최대 속도. |
| **Invert stick Y** | 꺼짐 | | |
| **Swap sticks** | 꺼짐 | | 이동을 오른쪽 스틱으로, 둘러보기를 왼쪽 스틱으로 합니다. |

스틱 모양 만들기: 편향 *m* (스틱 벡터의 길이)과 데드존 *d*가 있을 때, 출력 = ((m - d) / (1 - d)) ^ 곡선이며 스틱 방향을 따르고, 데드존 안에서는 0입니다.

## 기본으로 표준 패드만 쓰는 이유 {#why-only-standard-pads-by-default}

Gamepad API는 축이 있는 **모든** HID 장치를 보고합니다. 비행 조종간, 스로틀, 페달, 핸들이 모두 포함되고, 이들은 가운데에 머물지 않습니다. 비틀기 축이나 스로틀 레버는 아무도 만지지 않아도 최대 편향에 있습니다. 이것을 스틱으로 읽으면 어떤 데드존으로도 없앨 수 없는 상시 최대 속도 입력이 됩니다. 그러면 페이지가 로드되는 순간부터 카메라가 혼자 돌고, 모든 히트 모드도 고장 나 보입니다. 카메라가 움직이면 매 프레임 누적이 다시 시작되기 때문입니다.

그래서 장치는 브라우저가 `mapping: "standard"`라고 보고할 때만 따라갑니다. 이는 "축이 예상한 자리에 있는 XInput 방식 패드"라는 뜻입니다. 다른 장치는 목록에 나오지만 무시됨으로 표시됩니다. **Use device**로 하나를 명시적으로 고를 수 있습니다. 예를 들어 HOTAS로 카메라를 날리려면요. 패드를 따라가기 시작하면 카메라는 계속 그 패드를 따릅니다. 그래서 장치 열거 순서에 따라 두 컨트롤러가 카메라를 두고 다투지 않습니다.

**HOTAS:** 축 0-3(두 스틱)과 표준 버튼만 읽습니다. 다른 축의 스로틀이나 페달은 아무 일도 하지 않습니다. 가운데에 머물지 않는 축을 가진 스틱이나 스로틀은 더 큰 **Deadzone**이 필요할 수 있습니다.

브라우저는 컨트롤러가 첫 입력을 보내기 전까지 숨기므로, 연결만 되어 있고 아무도 건드리지 않은 패드는 페이지가 보기에 아직 존재하지 않습니다.
