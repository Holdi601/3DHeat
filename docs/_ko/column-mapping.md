# 열 매핑

파일은 표이고, 3DHeat는 어떤 열이 동서 방향 위치를 담고, 어떤 열이 시간을 담고, 어떤 열이 플레이어 이름을 담는지 알아야 합니다. 이 패널은 3DHeat가 무엇을 추측했는지 알려 주고, 틀린 추측을 고치는 곳입니다.

![Parquet 파일을 불러온 뒤의 열 매핑 패널: 모든 칸이 이미 채워짐 - 1 X, 2 Y, 3 Z, 4 시간, 5 사람 ID, 6 세션 / 매치, 7 팀 / 그룹](../assets/img/en/column-mapping-panel.webp)

*파일이 자기 열 이름을 가지고 있어서, 모든 칸이 이미 채워져 있습니다.*

예를 들어, 머리글이 `x,y,z,t,player,team`인 CSV는 스스로 매핑됩니다. x, y, z는 위치가 되고, `t`는 시간, `player`는 [사람](glossary.md), `team`은 [그룹](glossary.md)이 됩니다.

파일을 고르면 소스 패널 아래에 **열 매핑** 패널이 열립니다. 각 열이 어떤 역할을 하는지 보여 줍니다. 자동으로 채워지며, **불러오기**를 누르기 전에 모든 칸을 바꿀 수 있습니다. 매핑은 불러올 때 읽으므로, 나중에 바꾸려면 다시 불러와야 합니다.

## 칸들 {#the-fields}

열 메뉴에는 모두 첫 파일의 모든 열과 *- 없음 -*이 나옵니다.

| 칸 | 역할 | 메모 |
|---|---|---|
| **구분자** | CSV만: 필드 구분 문자. | 메뉴: *쉼표 ,*, *세미콜론 ;*, *탭*, *파이프 \|*, *공백*. *또는 한 글자 입력*에 아무 한 글자나 입력할 수 있습니다. 자동으로 감지합니다(아래를 보세요). 바꾸면 자동 매핑을 다시 실행하므로, 그 전에 한 수정은 사라집니다. |
| **X**, **Y**, **Z** | 위치. | 최소 두 개가 필요합니다. 매핑하지 않은 셋째 축은 0입니다(데이터가 평면 위에 놓임). 같은 열이 두 축에 있으면 오류입니다. |
| **소스의 위쪽 축** | 소스의 어느 축이 위를 가리키는지. | *Z가 위(대부분의 게임 엔진)* 또는 *Y가 위(그래픽 관례)*. [축, 단위, 시간](axes-units-and-time.md)을 보세요. |
| **단위 배율** | 모든 위치에 곱합니다. | *1 (m)*과 *0.01 (cm→m)* 버튼, 또는 값을 직접 입력합니다. |
| **X / Y / Z 뒤집기** | 소스 축의 부호를 바꿉니다. | 위치와 바라보는 방향 벡터에 적용합니다. |
| **시간** | 시간 축. | 선택 사항입니다. 없으면 타임라인도 없습니다. |
| **시간 단위** | 시간 열을 어떻게 읽을지. | 일곱 가지 단위가 있습니다. [축, 단위, 시간](axes-units-and-time.md#time)을 보세요. Parquet의 `TIMESTAMP`/`DATE` 열에는 적용하지 않으며, 패널이 그렇게 알려 줍니다. |
| **사람 ID** | 행이 누구 또는 무엇에 속하는지. | 선택 사항입니다. 트랙, 수명, 상자 리플레이, 선 히트를 가능하게 합니다. |
| **세션 / 매치** | 행이 어느 매치, 레이드, 라운드, 런 또는 랩에 속하는지. | 선택 사항입니다. 세션이 바뀌는 곳을 가로질러 위치를 보간하거나, 흔적을 그리거나, 경로로 잇지 않습니다. [세션, 사람, 그룹](sessions-persons-groups.md)을 보세요. |
| **팀 / 그룹** | 값의 종류가 적은 아무 열. | 선택 사항입니다. 그룹 색, 팀 히트, 그룹별 차이 분할을 움직입니다. |
| **시선 방향** | *없음*, *요 / 피치 열* 또는 *방향 벡터 열*. | 요/피치일 때: **요**, **피치**, **각도 단위**(*도* / *라디안*). 벡터일 때: **방향 X**, **방향 Y**, **방향 Z**. [상자 리플레이](box-replay.md)의 바라보는 광선에 씁니다. |
| **필터링용으로 유지** | 메모리에 남기는 추가 열. | 열마다 체크박스가 있고, 체크한 열은 *범위*(숫자) 또는 *범주*를 고릅니다. 행마다 4바이트를 쓰고, 불러올 때 해석하는 한 번의 패스가 필요합니다. 유지된 열만 [필터](filters.md)하거나, [차이 분할](difference.md)에 쓰거나, [선 히트](line-heat.md)의 이벤트 열로 쓸 수 있습니다. |
| **샘플 행 보기** | 처음 샘플한 행 12개, 모든 열의 표. | 추측을 확인하는 데 씁니다. |

명시적으로 정하지 않은, 체크한 필터 열은 *범위*로 읽습니다. 숫자처럼 보이는 ID 열은 *범주*로 두는 편이 흔히 더 유용합니다. 필터는 한 번에 4개만 켤 수 있습니다([필터](filters.md)).

## 자동 매핑의 추측 방식 {#how-the-auto-mapping-guesses}

추측은 [`src/data/automap.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/automap.ts)에 있습니다. 열 이름을 보고, 샘플한 행에서 어떤 열이 숫자인지(비어 있지 않은 값의 90%를 넘게 숫자로 읽히는지) 보고, 샘플에서 각 열이 가진 서로 다른 값의 수를 보고, Parquet 논리 타입도 봅니다. 이름 패턴은 대소문자를 구분하지 않고 순서대로 시도하며, 아직 비어 있는 열과 맞는 첫 패턴이 이깁니다.

### 위치 {#position}

| 축 | 이름 패턴, 순서대로(숫자 열만) |
|---|---|
| X | `x`, `…_x` / `… x`, `pos…x`, `x…pos`, `loc…x`, `lon…`, `longitude` |
| Y | `y`, `…_y`, `pos…y`, `y…pos`, `loc…y`, `lat…`, `latitude` |
| Z | `z`, `…_z`, `pos…z`, `z…pos`, `loc…z`, `…alt…`, `…height…`, `…elev…` |

축이 아직 비어 있으면, 남는 첫 숫자 열들(`filename`, `level`, `year`, `month`, `day`, `hour`, `location`은 제외)이 순서대로 채웁니다. 틀린 추측은 화면에서 바로 보입니다. 빈 칸이면 뷰포트가 비어 버리기 때문입니다.

### 시간 {#time}

- **Parquet 타임스탬프 열이 먼저입니다.** 논리 타입이 `TIMESTAMP`나 `DATE`인 열 중에서, 점수로 가장 좋은 것을 고릅니다. 이름이 시간 패턴과 맞으면 +10,000, 평범한 `DATE`면 -5,000, 그리고 샘플의 서로 다른 값의 수를 더합니다. 하루 전체를 나타내는 날짜와 고정된 세션 시작 시각은 서로 다른 값이 거의 없으므로, 이벤트 순간이 이깁니다. 그러면 단위는 *Unix 타임스탬프(ms)*가 됩니다.
- **그 밖에는 이름으로:** `time`, `timestamp`, `ts`, `…event…time…`, `…time…stamp…`, `t`, `…date…time…`, `when`, `tick`, `…frame…`, 그다음 경과 시간 이름(`gdur`, `g_duration`, `…duration…`, `…elapsed…`, `…match time…`, `…round time…`, `…game time…`, `…minute from start…`, `…since start…`, `age`). 그러면 단위는 값에서 추측합니다. 값이 `YYYY-MM-DDT…` 또는 `YYYY-MM-DD …`처럼 보이면 ISO-8601입니다. 그 밖에는 가장 큰 크기로 정합니다. 10^17 나노초보다 크면 나노초, 10^14 마이크로초보다 크면 마이크로초, 10^11 Unix 밀리초보다 크면 밀리초, 10^8 Unix 초보다 크면 Unix 초, 10^6 밀리초보다 크면 밀리초, 그 밖에는 초입니다.

경과 시간 열을 고르면, 패널은 모든 세션이 자기 시작점에 맞춰진다고 알려 줍니다. 매치를 겹쳐 놓을 때는 좋지만, 실제 순서대로 보는 데는 맞지 않습니다.

### 세션, 사람, 그룹 {#session-person-group}

세션은 시간 축 **다음**, 사람과 그룹 **앞**에서 정합니다. 세션 열은 흔히 타임스탬프이기 때문입니다(매치의 모든 행에 적힌 매치 시작 순간).

| 역할 | 이름 패턴, 순서대로 |
|---|---|
| 세션 | `session` / `session_id`, `match…`, `round…`, `raid…`, `game…`, `run…`, `replay…`, `instance…`, `lap…`, `stint…` (각각 정확히 일치하며, `_id`가 붙을 수 있음) |
| 사람 | `name`, `…player…id/name…`, `…user…`, `…account…`, `persona…`, `…character…`, `victim`, `actor`, `…puuid…`, `…steam id…`, `subject…`, 그다음 `driver` / `driver_id` / `driver_name`, `car` / `car_id` / `car_name`(레이싱 데이터: 움직이는 것이 차량이기 때문) |
| 그룹 | `spawn_team`, `real_team`, `team` / `team_id` / `team_name`, `squad…`, `side`, `…faction…`, `clan…`, `party…`, `alliance…`, `car_class` |
| 그룹, 대체 | `…victim_ai…`, `…killer_ai…`, `…is_ai/bot/npc…`, `target_type`, `survived`, `outcome`, `result` |

샘플 행 대부분에서 서로 다른 값을 가지는 그룹 후보(max(48, 샘플의 60%)보다 많음)는 그룹이 아니라 ID입니다. 사람 열이 없으면 그것이 사람 열이 되고, 그룹으로는 쓰지 않습니다. 그룹 열을 전혀 찾지 못하면, 숫자가 아닌 열 중에서 서로 다른 값이 2개에서 12개 사이로 가장 적은 열을 씁니다.

### 시선 방향 {#look-direction}

`yaw`, `…rot…yaw…`, `…heading…`, `azimuth…`, `…view…yaw…`, `rot_z` / `rotation_z`라는 이름의 숫자 열이 있으면, 시선 방향을 요/피치로 바꿉니다. 피치는 `pitch`, `…rot…pitch…`, `…elevation…angle…`, `…view…pitch…`로 찾습니다. 샘플한 요의 절댓값이 7을 넘으면 도로 보고, 그 밖에는 라디안으로 봅니다. 방향 벡터는 추측하지 않습니다. 아래 힌트에서 오거나, 여러분이 정합니다.

### 필터 열 {#filter-columns}

자동으로 최대 **6**개 열을 유지합니다. 순위는 다음과 같습니다.

1. `region`, `sessionMode`, `actor` - 필터하려고 있는 열(점수 1200);
2. 샘플에서 값이 바뀌는 범주 열, 서로 다른 값이 적은 순(1000에서 개수를 뺌);
3. 샘플에서는 값이 같지만, 파일을 여러 개 불러올 때만 쓰는 열. 지역이나 테스트 실행 ID처럼 파일마다 다를 수 있기 때문입니다(600);
4. 숫자 열(500).

이미 역할을 맡은 열, 위의 잡음 이름, 파일 하나를 불러올 때 값이 같은 열, 그리고 자유 텍스트 열(서로 다른 값이 max(16, 샘플의 절반)보다 많음)은 자동으로 제시하지 않습니다. 그래도 어떤 열이든 손으로 체크할 수 있습니다.

### 위쪽 축 {#up-axis}

세 축을 모두 매핑했다면, 샘플에서 Y와 Z의 퍼짐이 더 작은 축을 위로 봅니다(지도는 높이보다 훨씬 넓기 때문입니다). 그 밖에는 Z가 위라고 가정합니다.

## Parquet 푸터의 `heat3d` 힌트 {#the-heat3d-hints-in-a-parquet-footer}

Parquet 파일은 자기를 어떻게 읽어야 하는지 말할 수 있습니다. 파일 푸터의 키/값 메타데이터에 키 **`heat3d`** 항목이 있으면, 그 값을 JSON으로 해석해서 추측 위에 덮어씁니다([`applyHints`](https://github.com/Holdi601/3DHeat/blob/main/src/data/automap.ts)). CS2 데모 변환기가 이런 항목을 씁니다. 그래서 그 표들은 플레이어가 사람으로, 진영이 그룹으로, 각 라운드가 세션으로 열리고, 시선 방향이 켜지며, 월드가 올바른 방향으로 열립니다.

힌트는 선택한 파일 중 **첫** 파일에서만 읽습니다. 모든 항목은 선택 사항입니다. 힌트로 준 값은 패널에 그대로 나오며 바꿀 수 있습니다. 스키마의 전체 설명, 예시, 쓰는 방법은 [데이터 형식 참조](data-formats.md#the-heat3d-hints)에 있습니다.

규칙을 간단히 정리하면 다음과 같습니다.

- 힌트가 이름을 준 열은, 파일에 그 열이 있을 때만 적용합니다.
- `lookMode: "vector"`는 `dirX`, `dirY`, `dirZ`가 모두 설정된 경우에만 적용합니다. `"yawPitch"`는 `yaw`가 설정된 경우에만 적용합니다.
- `extra`가 있으면 자동 필터 목록을 대체합니다(알 수 없는 이름과 이미 역할을 맡은 열은 버립니다). 각 항목의 범위/범주 종류는 그 열이 숫자처럼 보였는지에 따릅니다. 없으면 자동 목록을 유지하되, 힌트가 역할을 준 열은 뺍니다.
- `axes.up`은 `"y"` 또는 `"z"`여야 합니다. 뒤집기는 참/거짓이어야 합니다. `scale`은 양수여야 합니다.
- `entity.size`가 양수이면, 파일 단위로 추적 대상 하나의 크기입니다([개체 크기](sessions-persons-groups.md#entity-size)). 설정하는 유일한 방법입니다.

## 알려진 문제: CSV 구분자 덮어쓰기 {#known-issue-overriding-the-csv-separator}

구분자를 감지된 것과 다른 것으로 바꿔도, 열 목록과 샘플 행은 바뀌지 않습니다(미리보기는 여전히 감지된 구분자로 나눕니다). 선택한 구분자는 실제 불러오기에서는 그대로 씁니다. 감지된 구분자가 틀렸다면:

1. 파일을 텍스트 편집기에서 여세요.
2. 구분자를 모든 곳에서 쉼표로 바꾸세요(소수점 쉼표는 점으로).
3. 저장하고 파일을 다시 불러오세요.

원인은 [`previewSource`](https://github.com/Holdi601/3DHeat/blob/main/src/data/sourcePreview.ts)에 있습니다.
