# 지도 이미지

지도 이미지는 평평한 그림입니다. 미니맵, 위성 사진, 평면도 같은 것입니다. 데이터 아래에 깔아서 히트가 어디에 있는지 볼 수 있게 합니다. 그림의 두 점을 세계의 두 장소에 고정하여("앵커") 그림이 어디에 놓여야 하는지 뷰어에게 알려 줍니다.

## 지도 이미지 불러오고 놓기 {#load-and-place-a-map-image}

1. 먼저 데이터를 불러옵니다([데이터 가져오기](getting-data-in.md)).
2. **배경 / 레벨**에서 **맵 이미지…**를 누르고 그림을 고릅니다. 그림은 데이터 영역에 맞게 늘어납니다.
3. 그림을 옮겼다면 **데이터 범위에 맞추기**를 누릅니다. 앵커 1은 그림의 왼쪽 위 모서리에, 앵커 2는 오른쪽 아래 모서리에, 데이터의 가장자리에 놓입니다.
4. 히트가 그림과 맞지 않으면, 멀리 떨어진 랜드마크 두 개를 고르십시오(예: 건물의 대각선 두 모서리나 교차로 두 곳). 각각의 그림에서 픽셀 위치를 읽고, 세계 위치를 읽으십시오([자](measure.md)를 올려 놓으면 **X**와 **Z**가 보입니다).
5. **배치**에 입력합니다. **앵커 1**에는 랜드마크의 **px**, **py**, **세계 X**, **세계 Z**를, **앵커 2**에도 같은 방식으로 넣습니다.
6. 확인하십시오. 도로 위에 있는 것을 아는 궤적이나 핫스팟이 이제 그 도로 위에 있어야 합니다. 맞을 때까지 숫자를 조정하십시오.

![두 앵커가 있는 배치 섹션과, 지도 그림 위에 그려진 히트](../assets/img/en/map-images-placement.webp)

두 랜드마크는 픽셀 열과 픽셀 행이 모두 달라야 합니다. 그렇지 않으면 패널이 *두 앵커가 같은 픽셀 행이나 열에 있습니다*라고 말합니다.

## 불러오기 {#loading}

브라우저가 해석할 수 있는 모든 이미지 형식입니다. 긴 변이 **8192 px**보다 큰 이미지는 8192로 축소됩니다(GPU가 보관하도록 요청받는 가장 큰 변). 패널은 *W×H에서 w×h로 축소됨*이라고 말합니다.

불러오면 이미지는 데이터의 X-Z 범위에 늘어나고(데이터가 없으면 ±1000 단위), 북쪽이 위를 향하며, 데이터의 가장 낮은 Y에 놓입니다. 기본값은 **불투명도** 100%, **밝기** 0.7, **채도 낮추기** 100%, **남북 뒤집기** 켜짐입니다. 채도를 낮추고 어둡게 합니다. 배경의 역할은 핫스팟을 찾게 하는 것이지, 핫스팟과 경쟁하는 것이 아니기 때문입니다.

## 조절 {#controls}

| 조절 | 기본값 | 범위 | 뜻 |
|---|---|---|---|
| **불투명도** | 100% | 0-100% | |
| **밝기** | 0.7 | 0-2(조그 64) | |
| **채도 낮추기** | 100% | 0-100% | 회색 배경, 채도가 있는 히트. 지도의 색이 데이터의 색과 경쟁하지 않게 합니다. |
| **남북 뒤집기** | 켜짐 | | 이미지의 어느 행이 세계의 최대 Z인지. 데이터를 불러 둔 상태에서 이것을 바꾸면 앵커도 데이터 범위에 다시 맞춥니다. |
| **배치**: 앵커 1, 앵커 2 | 데이터 범위에 맞춘 이미지 모서리 | | 각 앵커는 이미지 위의 픽셀입니다. **px**(왼쪽에서, 0부터 너비까지)와 **py**(위에서, 0부터 높이까지)이며, 그 자리의 세계 좌표는 **세계 X**와 **세계 Z**입니다. 축척과 오프셋은 이 두 쌍에서 정해집니다. |
| **데이터 범위에 맞추기** | | | 앵커 1을 이미지 왼쪽 위 모서리에, 앵커 2를 오른쪽 아래 모서리에, 데이터의 X-Z 범위에 맞춥니다. 정확한 배치를 위한 출발점입니다. 데이터가 필요합니다. |
| **고도** | 데이터의 가장 낮은 Y | 데이터 최소 Y - 500 ~ 최대 Y + 500(조그 최대 Y + 100,000) | 지도 평면의 높이. 데이터 바로 아래에 두면 아무것도 가려지지 않습니다. |

이름 줄은 `너비×높이 px · x × z m/px`를 보여 줍니다. 각 축에서 픽셀 하나가 나타내는 세계 크기입니다.

## 장면 안에서 {#in-the-scene}

이미지는 고도에 놓인 텍스처가 입혀진 사각형 하나입니다. 불투명도 100%에서는 깊이를 쓰므로, 지면처럼 [가려짐](depth-and-culling.md)에 참여합니다. 100% 아래에서는 섞여 그려지고 깊이를 쓰지 않으므로, 아무것도 가리지 않습니다. [자](measure.md)는 그 평면 위에서 잽니다. [레벨 라이브러리](level-library.md)는 이미지 레벨을 앵커와 함께 저장합니다.

## Dota 2 맵 {#dota-2-map}

**맵 이미지…** 옆의 **Dota 2 map**은 [OpenDota](https://www.opendota.com)이 경기 페이지에 보여 주는 현재 Dota 2 맵의 그림을 가져와서, [Watcher](https://github.com/Holdi601/3DHeat-Watcher)가 Dota 2 리플레이에서 쓴 표 아래에 놓습니다([`dotaMap.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/tactics/dotaMap.ts)). 이미지는 버튼을 누를 때 opendota.com에서 가져오며, 3DHeat의 일부가 아닙니다. 가장 최근 패치의 그림은 OpenDota 자체 목록에서 고르고, 목록을 읽을 수 없으면 7.40 그림을 씁니다.

| | |
|---|---|
| 원본 | `opendota.com/assets/images/dota2/map/detailed_<patch>.webp`, 900×900 px |
| 배치 | OpenDota의 보정값: 이미지는 두 축 모두 Dota 세계 단위 -8192부터 8064까지에 걸치며(128단위 셀 64-191), 북쪽이 위입니다. 리플레이 표의 축(Z가 위, Y 뒤집힘)으로는 세계 X -8192부터 8064까지, 세계 Z -8064부터 8192까지입니다. 픽셀당 약 18단위입니다. |
| 고도 | 0. 영웅들은 0에서 약 600 사이에 서 있습니다. |
| 모습 | 밝기 0.8, 채도 낮추기 50%. |

패치 7.40의 공개 경기 리플레이로 확인했습니다. 모든 영웅의 궤적이 그려진 길을 따라갔고, 리플레이가 놓은 타워, 막사, 고대 유적이 그려진 기지 위에 떨어졌습니다. **위** 보기는 지도를 북쪽이 화면 아래쪽에 오게 보여 줍니다. Y가 뒤집힌 Z가 위인 표를 어떤 것이든 보여 주는 방식과 같습니다.

그림은 OpenDota의 것이며, 원작은 Valve의 지도입니다. Valve는 3DHeat를 보증하지 않습니다. Dota의 3D 지도는 게임이 설치되어 있어야 합니다. Dota 2 리플레이에 관한 Watcher의 안내를 보십시오.

## 개발자용 {#for-developers}

### 앵커가 이미지를 놓는 법 {#how-the-anchors-place-the-image}

[`mapQuadFromAnchors`](https://github.com/Holdi601/3DHeat/blob/main/src/render/level.ts)에서, 앵커 *a*와 *b*를 쓰면:

```
scaleX = (b.worldX - a.worldX) / (b.px - a.px)
scaleZ = (b.worldZ - a.worldZ) / (b.py - a.py)
pixel (0, 0) sits at  (a.worldX - a.px × scaleX,  a.worldZ - a.py × scaleZ)
```

두 앵커는 각 축에서 축척과 오프셋을 독립적으로 정합니다. 그래서 지도는 X와 Z에서 다르게 늘어날 수 있지만, 회전은 할 수 없습니다. 앵커는 두 픽셀 좌표가 **모두** 달라야 합니다. 행이나 열을 공유하면 축척을 구할 수 없고, 지도는 그려지지 않으며, 패널은 *두 앵커가 같은 픽셀 행이나 열에 있습니다*라고 말합니다.
