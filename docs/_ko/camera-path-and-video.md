# 카메라 경로와 영상

데이터로 영화를 만듭니다. 카메라를 몇 군데에 놓으면, 뷰어가 그 사이를 날아다니며 동영상을 저장합니다. 모든 프레임은 아주 깨끗하며 잡음이 없습니다. 카메라와 재생 위치가 함께 움직이므로, 같은 패널로 타임랩스도 만듭니다([`PathPanel.tsx`](https://github.com/Holdi601/3DHeat/blob/main/src/ui/panels/PathPanel.tsx), [`campath.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/campath.ts), [`record.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/record.ts)).

## 비행 장면 만들기 {#make-a-flythrough}

1. 영화가 시작할 곳으로 날아가서 **카메라 경로와 렌더링**의 **여기에 키프레임 추가**를 누릅니다.
2. 다음 지점으로 날아가서 다시 누릅니다. 각 정류장마다 반복합니다.
3. **경로를 따라 미리 보기**를 켜고 **경로 위의 위치**를 끌어서 움직임을 확인합니다.
4. **길이**(동영상의 길이)를 정합니다. 움직임은 맞지만 너무 빠르면 길이를 늘리기만 하면 됩니다.
5. **동영상 렌더링**을 누릅니다. 진행 줄을 기다리십시오. 끝나면 파일이 내려받아집니다.

![키프레임 셋, 부드럽게 보간, 12초, 30 fps, 16 Mbps를 보여 주는 카메라 경로와 렌더링 패널](../assets/img/en/camera-path-panel.webp)

## 키프레임 {#keyframes}

| 조절 | 효과 |
|---|---|
| **여기에 키프레임 추가** | 현재 카메라 위치, 요, 피치, 시야각을 키프레임으로 덧붙입니다. |
| **지우기** | 키프레임을 모두 제거합니다. |
| 키프레임 목록 | 키마다 한 줄: 번호(누르면 카메라가 그곳으로 날아가며 시야각도 맞춤), 위치, `요° / 피치°`, 그리고 제거하는 **×**. |

키를 추가하거나 제거할 때마다, 키는 0에서 1까지 정규화된 경로 축을 따라 **고르게** 간격을 둡니다. 출력 길이가 전체 움직임을 늘리므로, 맞지만 너무 빠른 장면은 길이만 늘리면 됩니다. 키 사이에서 요는 펼쳐져서, 카메라가 짧은 쪽으로 돕니다.

키프레임이 없으면, 렌더링은 클립 전체 동안 현재 카메라를 가만히 둡니다. 이것도 훌륭한 타임랩스입니다.

## 경로 설정 {#path-settings}

| 조절 | 기본값 | 범위(조그) | 뜻 |
|---|---|---|---|
| **보간**(키 2개 이상) | *부드럽게* | *부드럽게* / *직선* | *부드럽게*: 키를 지나는 3차 에르미트 곡선입니다. 접선은 이웃 키에서 가져오므로, 각 키를 지날 때 속도가 맞고 구간이 만나는 곳에서 덜컹거리지 않습니다. *직선*: 키 사이를 곧은 선으로 잇습니다. 예측 가능하지만, 키마다 모서리가 보입니다. 시야각은 항상 선형으로 보간됩니다. |
| 이동선(키 2개 이상) | | | `N 단위 이동 - 이 길이에서 초당 M`, 또는 키가 모두 한곳에 있다는 주석. |
| **경로를 따라 미리 보기**(키 1개 이상) | 꺼짐 | | 경로에서 뷰포트 카메라를 움직이고, 렌더링할 때처럼 재생 위치도 함께 움직입니다. 그래서 렌더링하기 전에 움직임을 판단할 수 있습니다. |
| **경로 위의 위치**(미리 보는 동안) | 0% | 0-100% | 경로의 어느 지점을 미리 볼지. |
| **길이** | 12 s | 1-120 s(3600) | 동영상의 길이. |
| **프레임 레이트** | 30 fps | 6-60(240) | |
| **비트레이트** | 16 Mbps | 1-60 Mbps, 로그(400) | 낮은 비트레이트에서는 히트 그라데이션에 띠가 심하게 생깁니다. 코덱이 오류를 숨길 세부 정보가 거의 없기 때문입니다. |
| **수렴 대기 상한** | 240프레임 | 2-600(10,000) | 출력 프레임 하나가 정확해질 때까지 기다릴 수 있는 가장 긴 시간. 이 상한에 걸린 프레임도 기록되며, 따로 셉니다. |
| 요약 | | | `N 프레임 · 창: 누적/고정/수명`, 그리고 타임라인이 전체 모드일 때: *(렌더링은 재생점이 의미를 갖도록 전체를 재생으로 바꿉니다)*. |
| **동영상 렌더링** / **취소** | | | 렌더링을 시작합니다. 실행하는 동안 `프레임 i / n · 대기 w · X MB`와 정확하지 않았던 프레임 수를 보여 줍니다. 데이터셋이 필요합니다. |

## 팁 {#tips}

- 출력 크기는 장치 픽셀 기준 캔버스 크기입니다(화면의 픽셀 비율, 최대 2). 크기를 바꾸려면 브라우저 창 크기를 조절하십시오.
- 누적 기록은 클립 동안 히트를 쌓아 올립니다. 창이나 수명 기록은 움직이는 시간 조각을 보여 줍니다.
- 키프레임 위치는 화면 좌표입니다. [뒤집힌 세계 축](camera.md#invert-world-axis)이 있으면, 바꾸기 전에 만든 키는 바꾼 뒤에 다른 곳을 가리킵니다.

## 개발자용 {#for-developers}

### 렌더링이 하는 일 {#what-a-render-does}

1. 프레임의 시험 캡처를 찍어 장치 픽셀 기준의 정확한 출력 크기를 알아냅니다.
2. WebCodecs로 코덱을 고릅니다. 먼저 **VP9**(`vp09.00.10.08`), 안 되면 **VP8**이며, 고른 비트레이트와 프레임 레이트를 씁니다. `VideoEncoder`가 없으면 *이 브라우저에는 VideoEncoder가 없습니다. 동영상을 쓰려면 WebCodecs가 필요합니다*라고 말하며 멈춥니다. 두 코덱 모두 없으면 *지원되는 동영상 코덱이 없습니다(VP9, VP8 시도)*.
3. 렌더링에 필요한 설정을 가져옵니다. 재생을 일시정지하고, **적응형 예산을 끄고**, **점진적 개선을 켜고**, 스프라이트 예산을 프레임당 6,400만으로 맞춥니다(적응형 예산은 프레임 레이트를 지키는데, 여기서는 잘못된 목표입니다. 수렴이 느린 프레임 하나하나를 행을 덜 찍을 이유로 읽어서, 수렴하는 데 프레임이 더 많이 필요해지기 때문입니다). 그리고 타임라인을 **전체**에서 **재생**으로 바꿉니다. 기록 설정(누적, 창, 수명)은 그대로 둡니다. 렌더링은 여러분이 보고 있던 것을 재생하며 기록하는 것이어야 하기 때문입니다.
4. 출력 프레임 *f* / *n*마다, *u* = f / (n - 1)에서:
   - 카메라를 *u*에서의 경로 자세에 둡니다(키가 있으면);
   - 재생 위치를 타임라인 범위의 같은 비율 *u*로 옮깁니다(상자 리플레이에서는 선택한 세션의 구간);
   - 카메라가 움직이지 않았더라도 새 추정을 강제합니다. 이전 프레임의 누적을 물려받으면 이전 창의 유령이 남기 때문입니다;
   - 그림이 정확해질 때까지(후보 행을 모두 한 프레임에 그리거나 누적이 끝날 때까지) 프레임마다 기다립니다. 대기 상한까지입니다;
   - 합성된 프레임을 캡처해 인코딩합니다. 출력 2초마다 키프레임을 두어 파일을 탐색할 수 있게 합니다.
5. 프레임을 WebM 파일로 묶습니다([`webm.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/render/webm.ts)). 타임스탬프는 프레임 레이트로 정합니다. 각 프레임이 걸린 벽시계 시간은 상관없습니다.
6. 예산, 시야각, 타임라인 모드, 재생 위치, 재생 중이었는지 여부를 되돌립니다.
7. 동영상을 `3dheat-<width>x<height>-<frames>f.webm`으로 내려받고, `N 프레임, W×H, X MB - 모든 프레임이 정확함`이라고 알리거나, 대기 상한에 걸린 프레임 수를 알립니다.

**취소**는 현재 프레임 뒤에 멈추고(*렌더링이 취소되었습니다.*), 설정을 되돌립니다.
