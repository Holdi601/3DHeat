# Референца за формати на податоци

Оваа страница ги наведува сите видови датотеки што 3DHeat може да ги отвори и како мора да изгледа табелата во нив. Табелата се состои од редови и колони, како табеларна листа: секој ред вели каде нешто било и, ако го знаете, кога и кој.

Што ја чита картичката Топлинска карта, колона по колона, и какви подсетници може да носи една Parquet датотека. (Картичката Анализа на трки ги чита датотеките со кругови, а картичката Натпревар ги чита резимеата на натпреварите; видете [Анализа на трки](race-analysis.md) и [Анализа на натпревари](match-analysis.md).)

## Датотеки {#files}

Ова е единствената целосна листа на датотеки што може да се вчитаат. Панелот **Извор** (**Датотеки…**, **Папка…** или влечење и пуштање) прифаќа точно овие:

| Наставка | Што е | Чита со |
|---|---|---|
| `.parquet`, `.pq` | Parquet табела | читачот на Parquet (подолу) |
| `.csv`, `.tsv`, `.txt` | Текст со разделувачи | читачот на текст (подолу) |
| `.3dheat` | Еден натпревар во една датотека (ZIP што ја содржи табелата и нејзините дополнителни податоци) | се вчитува како табелата што ја содржи - [Една датотека за натпревар](container.md) |
| `.acmi` (и `.txt.acmi`, `.zip.acmi`) | Tacview снимка на лет | сопствен читач - [Tacview снимки](tacview-acmi.md) |
| `.json`, `.json.gz` | OCAP снимка (како за Arma) | сопствен читач |
| `.gpx`, `.kml`, `.kmz`, `.nmea`, `.nma`, `.igc`, `.fit` | GPS траси: GPX, KML/KMZ, NMEA дневници, IGC дневници за једрење, FIT датотеки за спорт | сопствен читач; позициите се земаат од географската ширина и должина |

Не се вчитуваат како позиции: малите JSON датотеки што стојат покрај табелата и ја опишуваат (имиња што завршуваат на `.match.json`, `.course.json`, `.level.json`, `.meta.json`, `.summary.json`, `.session.json`, `.hints.json`), и дополнителните табели на конверторот (`<натпревар>.events.parquet` и слични, видете [Конвертори](converters.md)), освен ако не ги изберете посебно. Сè друго се прескокнува со причина. Како се филтрира еден избор е објаснето во [Вчитување датотеки](loading-files.md#which-files-are-kept).

Празните датотеки се прескокнуваат. Во избор што содржи датотеки `movement*.<ext>`, се вчитуваат само тие ([Вчитување датотеки](loading-files.md#which-files-are-kept)).

Податоците се **по еден ред за примерок**: позиција во еден момент, по избор и кој, која група, која сесија, каде гледал и уште колони. Настани (убиство, поставување, истрел) може да бидат во истата табела со редовите за позиција, а се разликуваат по колона за настан.

## Текст со разделувачи (CSV, TSV, TXT) {#delimited-text-csv-tsv-txt}

Најмалата корисна датотека, три реда:

```
x,y,z,t,player,team
10.5,2.0,-30.2,0.00,Blue 1,Blue
11.0,2.0,-29.8,0.25,Blue 1,Blue
-4.2,1.5,18.9,0.00,Red 3,Red
```

Колоните се поврзуваат сами ([Поврзување колони](column-mapping.md)).

Се чита со брз скенер по бајт што ги декодира само поврзаните колони ([`csv.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/csv.ts)).

| Особина | Правило |
|---|---|
| Заглавие | Првиот непразен ред ги содржи имињата на колоните. Празно име станува `column_N`. |
| Разделувач | Се открива од првите 20 непразни реда од првите 1 MiB, меѓу запирка, точка-запирка, табулатор и вертикална црта, по **доследност**: разделувачот што дава ист број полиња во секој проверен ред победува, па оној што дава повеќе полиња. Празното место никогаш не се открива, но може да се избере; може да се внесе кој било знак ([Поврзување колони](column-mapping.md#the-fields)). |
| Наводници | RFC 4180: полињата може да бидат во двојни наводници, `""` во наводници е буквален навод. |
| Празни места | Празните места, табулаторите и наводниците на почетокот и на крајот на полето се отстрануваат. |
| Полиња по ред | Највеку 4.096; повеќе е грешка (*дали разделувачот е точен?*). |
| Броеви | Незадолжителен знак, цифри, незадолжителна точка и децимали, незадолжителен експонент (`1.5e-3`). Децималната запирка (`1,5`), разделувачите на илјади и единиците по бројот (`12 m`) не се читаат и се сметаат за недостасувачки. Ако вашата датотека има децимални запирки, замените ги со точки пред вчитување (наоѓање и замена во текстуален уредувач работи). |
| Нумеричка колона | Колоната се нуди како нумеричка кога повеќе од 90% од непразните вредности во првите 50 реда се читаат како броеви. |
| Број на редови | Се проценува пред вчитување од просечната должина на редот во првиот 1 MiB. |
| Кодирање на текст | UTF-8. |

## Parquet {#parquet}

Се чита со [hyparquet](https://github.com/hyparam/hyparquet), дел по дел од колона, во типизирани низи, барајќи само поврзаните колони ([`parquet.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/parquet.ts), [`ingestParquet.ts`](https://github.com/Holdi601/3DHeat/blob/main/src/data/ingestParquet.ts)).

| Особина | Правило |
|---|---|
| Број на редови | Точен, од крајот на датотеката, пред вчитување. |
| Преглед | Првите 50 реда, декодирани како објекти; нивните вредности одлучуваат кои колони изгледаат нумерички. |
| Цели броеви | `INT32` и `INT64` (декодирани како BigInt) стануваат броеви. |
| Децимални броеви | `FLOAT`, `DOUBLE`. |
| Логички вредности | 1 и 0. |
| Текст | Се користи за колоните на лице, група, сесија и категорија; низа што изгледа како број се прифаќа за нумеричките улоги. |
| Типови `TIMESTAMP` и `DATE` | Се декодираат во моменти (милисекунди од 1970); кога се користат како временска оска, поставката за единица се занемарува. |
| Вгнездени колони | Колоните struct и list не се наменети ни за една улога (се прикажуваат како JSON текст); не се тестирани. |
| Метаподатоци на крајот | Клучот `heat3d` се чита како подсетници за поврзување (подолу). |

Позиција, време или колона за поглед што содржи нешто друго освен број се декодира како недостасувачка.

## Улоги и типови на колони {#column-roles-and-types}

| Улога | Тип во датотеката | Задолжително | Се чува како | Ограничувања |
|---|---|---|---|---|
| X, Y, Z | број | две од три | 32-битен децимален број, по [мапирањето на оските](axes-units-and-time.md) | Ред без употреблива позиција се отфрла. |
| Време | број во една од [единиците за време](axes-units-and-time.md#time-units), временски печат на Parquet или текст ISO-8601 | не | 32-битни децимални секунди од најраниот ред | Подредувањето се одбива над 400.000.000 редови ([зошто](memory-and-budgets.md#the-sort-ceiling)). |
| Лице | било што; кодирано со речник | не | 32-битен id | |
| Сесија | било што; кодирано со речник | не | 32-битен id | Ознаки се наведуваат до 100.000 сесии. |
| Група | било што; кодирано со речник | не | 16-битен id | До 4.096 групи, инаку групирањето се отфрла. |
| Yaw, pitch | број, степени или радијани | не | 32-битен децимален број во радијани | |
| Direction X, Y, Z | број | не (сите три заедно) | се претвора во yaw и pitch | |
| Колона за филтер, *опсег* | број | не | 32-битен децимален број | До 4 филтри активни истовремено. |
| Колона за филтер, *категорија* | било што; кодирано со речник | не | 32-битен id | До 4.096 вредности, инаку колоната не се чува. |

Колона `TIMESTAMP` на Parquet што се чува како колона за филтер е **опсег** на милисекунди од епохата - лизгач, а не листа.

## Подсетниците `heat3d` {#the-heat3d-hints}

Parquet датотеката може да ги носи своите упатства за читање во метаподатоците на крајот, како вредност на клуч во JSON објект, под клучот **`heat3d`** ([`MappingHints`](https://github.com/Holdi601/3DHeat/blob/main/src/data/automap.ts)). Прегледачот ги применува над своите погодоци кога датотеката е првата од еден избор; секој запис е незадолжителен и секој резултат се уште се прикажува и може да се уреди во панелот [Поврзување колони](column-mapping.md#the-heat3d-hints-in-a-parquet-footer). Што не може да се прочита како JSON објект се занемарува.

### Шема {#schema}

```
{
  "columns": {
    "x": string, "y": string, "z": string,          имиња на колони за позицијата
    "time": string,                                  колоната за време
    "timeUnit": "seconds" | "milliseconds" | "microseconds" | "nanoseconds"
              | "unix_seconds" | "unix_milliseconds" | "iso8601",
    "personId": string, "teamId": string, "sessionId": string,
    "lookMode": "none" | "yawPitch" | "vector",
    "yaw": string, "pitch": string,
    "dirX": string, "dirY": string, "dirZ": string,
    "angleUnit": "degrees" | "radians",
    "extra": [string, ...]                           колони за филтер што се чуваат, најкорисните први
  },
  "axes": {
    "up": "y" | "z",
    "flipX": boolean, "flipY": boolean, "flipZ": boolean,
    "scale": number                                  мора да е > 0
  },
  "entity": {
    "size": number                                   големина на една следена работа во единиците на датотеката, > 0
  }
}
```

| Запис | Се применува кога | Дејство |
|---|---|---|
| `columns.x` … `columns.dirZ`, `time`, `personId`, `teamId`, `sessionId` | наведената колона постои во датотеката | ја поставува таа улога. |
| `columns.timeUnit` | е една од седумте единици | ја поставува единицата за време. |
| `columns.angleUnit` | `"degrees"` или `"radians"` | ја поставува единицата за агол. |
| `columns.lookMode` | `"vector"` со поставени сите dirX, dirY и dirZ; `"yawPitch"` со поставен yaw; `"none"` | го поставува режимот на поглед. |
| `columns.extra` | е низа | ја заменува автоматската листа за филтри, задржувајќи само постоечки колони што не се користат за улога; секоја е *опсег* ако изгледала нумеричка во прегледот, инаку *категорија*. Без него, автоматската листа се задржува без колоните што подсетникот им ги доделил на улоги. |
| `axes.up` | `"y"` или `"z"` | горна оска. |
| `axes.flipX/Y/Z` | логичка вредност | превртувања. |
| `axes.scale` | број > 0 | скала на единиците. |
| `entity.size` | број > 0 | [Големина на ентитет](sessions-persons-groups.md#entity-size) (се множи со скалата на единиците при вчитување). Единствениот начин да се постави. |

### Пример {#example}

Измислен извоз од шутер: оска Z нагоре, сантиметри, лев свет, играчи широки околу 72 см.

```json
{
  "columns": {
    "x": "pos_x", "y": "pos_y", "z": "pos_z",
    "time": "t", "timeUnit": "seconds",
    "personId": "player", "teamId": "side", "sessionId": "round_id",
    "lookMode": "yawPitch", "yaw": "view_yaw", "pitch": "view_pitch", "angleUnit": "degrees",
    "extra": ["event", "weapon", "map"]
  },
  "axes": { "up": "z", "flipY": true, "scale": 0.01 },
  "entity": { "size": 72 }
}
```

### Запишување {#writing-it}

Со pyarrow, посебните метаподатоци на шемата се запишуваат во метаподатоците на датотеката како двојки клуч и вредност:

```python
import json
import pyarrow as pa
import pyarrow.parquet as pq

table = pa.table({...})
hints = {"columns": {"x": "pos_x", "y": "pos_y", "z": "pos_z", "time": "t"}, "axes": {"up": "z"}}
meta = dict(table.schema.metadata or {})
meta[b"heat3d"] = json.dumps(hints).encode("utf-8")
pq.write_table(table.replace_schema_metadata(meta), "movement.parquet")
```

`npm run inspect -- file.parquet` ја печати шемата на датотеката, што е брз начин да ги проверите имињата на колоните на кои се однесуваат подсетниците.

## Што запишува картичката Топлинска карта {#what-the-heatmap-tab-writes}

Ништо не се запишува назад во податоците. Излезите се:

- видеа, како WebM (VP9 или VP8) - [Патека на камерата и видео](camera-path-and-video.md);
- поглед на камерата, копиран во клипбордот како текст - [Камера](camera.md#pose);
- нивоа зачувани во [библиотеката на нивоа](level-library.md) во прелистувачот.
